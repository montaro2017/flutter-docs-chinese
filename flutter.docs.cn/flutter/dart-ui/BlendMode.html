BlendMode

BlendMode enum

在画布上绘制时使用的算法。

在画布上绘制形状或图像时，可以使用不同算法混合像素。BlendMode 的不同取值分别指定了不同算法。

每种算法都有两个输入：源是正在绘制的图像，目标是用于合成源图像的图像。目标通常也称为背景。源和目标都包含四个颜色通道：红、绿、蓝和 alpha 通道，通常以 0.0 到 1.0 之间的数值表示。算法的输出也包含这四个通道，其值由源和目标计算得出。

下文对每个取值的说明都会介绍相应算法的工作方式。 每种情况下， 配图都展示了将源图像与目标图像混合后的结果。 图中， 目标由带有水平线和不透明风景照片的图像表示； 源由带有垂直线（同一组线条旋转后的效果）和鸟类剪贴画的图像表示。 src 模式只显示源图像，dst 模式只显示目标图像。下文使用棋盘格表示透明度。clear 模式会同时丢弃源和目标，因此输出完全透明（以纯棋盘格表示）。

这些图中的水平条和垂直条依次展示：不透明度不同的红、绿、蓝通道； 不透明度相同且变化的三个颜色通道； 值均为零且不透明度变化的三个颜色通道； 红绿蓝循环渐变的两条色带（第一条完全不透明， 第二条部分透明）； 最后是一条颜色通道均为零、但不透明度呈循环渐变的色带。

在 Canvas API 中的应用

使用 Canvas.saveLayer 和 Canvas.restore 时，传给 Canvas.saveLayer 的 Paint 的混合模式会在调用 Canvas.restore 时应用。每次调用 Canvas.saveLayer 都会创建一个新图层，形状和图像会绘制到该图层上；调用 Canvas.restore 时，该图层会合成到父图层上，其中源是最近绘制的形状和图像，目标则是父图层。（第一次调用 Canvas.saveLayer 时，父图层就是画布本身。）

另请参阅：

  • Paint.blendMode，它使用 BlendMode 定义合成策略。

Values

clear → const BlendMode

同时丢弃源图像和目标图像，不留下任何内容。

这对应 Porter-Duff 的“clear”运算符。

src → const BlendMode

丢弃目标图像，只绘制源图像。

从概念上说，先清除目标图像，再绘制源图像。

这对应 Porter-Duff 的“Copy”运算符。

dst → const BlendMode

丢弃源图像，只绘制目标图像。

从概念上说，丢弃源图像，目标图像保持不变。

这对应 Porter-Duff 的“Destination”运算符。

srcOver → const BlendMode

将源图像合成到目标图像上方。

这是默认值，也是最直观的情况：形状绘制在下方内容之上，透明区域则显示目标图层。

这对应 Porter-Duff 的“Source over Destination”运算符，也称为画家算法。

dstOver → const BlendMode

将源图像合成到目标图像下方。

这与 srcOver 相反。

这对应 Porter-Duff 的“Destination over Source”运算符。

当源图像本应先于目标图像绘制、但无法这样做时，此模式很有用。

srcIn → const BlendMode

仅在两张图像重叠的区域显示源图像。目标图像不会被绘制，而只作为遮罩使用。目标图像的颜色通道会被忽略，只有不透明度会产生作用。

若要显示目标图像，可考虑使用 dstIn。

若要反转遮罩语义（仅在目标图像不存在时显示源图像，而非目标图像存在时显示），可考虑使用 srcOut。

这对应 Porter-Duff 的“Source in Destination”运算符。

dstIn → const BlendMode

仅在两张图像重叠的区域显示目标图像。源图像不会被绘制，而只作为遮罩使用。源图像的颜色通道会被忽略，只有不透明度会产生作用。

若要显示源图像，可考虑使用 srcIn。

若要反转遮罩语义（仅在目标图像存在时显示源图像，而非目标图像不存在时显示），可考虑使用 dstOut。

这对应 Porter-Duff 的“Destination in Source”运算符。

srcOut → const BlendMode

仅在两张图像不重叠的区域显示源图像。目标图像不会被绘制，而只作为遮罩使用。目标图像的颜色通道会被忽略，只有不透明度会产生作用。

若要显示目标图像，可考虑使用 dstOut。

若要反转遮罩语义（仅在目标图像存在时显示源图像，而非目标图像不存在时显示），可考虑使用 srcIn。

这对应 Porter-Duff 的“Source out Destination”运算符。

dstOut → const BlendMode

仅在两张图像不重叠的区域显示目标图像。源图像不会被绘制，而只作为遮罩使用。源图像的颜色通道会被忽略，只有不透明度会产生作用。

若要显示源图像，可考虑使用 srcOut。

若要反转遮罩语义（仅在源图像存在时显示目标图像，而非源图像不存在时显示），可考虑使用 dstIn。

这对应 Porter-Duff 的“Destination out Source”运算符。

srcATop → const BlendMode

仅在源图像与目标图像重叠的区域，将源图像合成到目标图像上方。

这对应 Porter-Duff 的“Source atop Destination”运算符。

这基本等同于 srcOver 运算符，但输出不透明度通道会设为目标图像的不透明度，而不是将两张图像的不透明度组合起来。

若要使用目标图像位于源图像上方的变体，请参阅 dstATop。

dstATop → const BlendMode

仅在目标图像与源图像重叠的区域，将目标图像合成到源图像上方。

这对应 Porter-Duff 的“Destination atop Source”运算符。

这基本等同于 dstOver 运算符，但输出不透明度通道会设为源图像的不透明度，而不是将两张图像的不透明度组合起来。

若要使用源图像位于目标图像上方的变体，请参阅 srcATop。

xor → const BlendMode

对源图像和目标图像应用按位 xor 运算符。两者重叠的位置会变为透明。

这对应 Porter-Duff 的“Source xor Destination”运算符。

plus → const BlendMode

将源图像和目标图像的分量相加。

如果其中一张图像的像素包含透明度，该图像对相应输出像素的贡献就会减少，效果如同该图像中该像素的颜色变暗。

这对应 Porter-Duff 的“Source plus Destination”运算符。

这是两张图像交叉淡化时适用的混合模式。设图像为 A 和 B，插值变量为 t（范围从 0.0 到 1.0）。要交叉淡化两张图像，应先将 A 以不透明度 1.0 - t 绘制到新图层，并使用 BlendMode.srcOver；再将 B 绘制到同一图层上方，不透明度设为 t，并使用 BlendMode.plus。

modulate → const BlendMode

将源图像和目标图像的颜色分量相乘。

结果只会保持原色或变暗（乘以白色 1.0 不会改变颜色；乘以黑色 0.0 则得到黑色）。

合成两张不透明图像时，效果类似于将两张透明胶片叠放在投影仪上。

如果需要同时乘以 alpha 通道，可考虑使用 multiply。

另请参阅：

  • screen，其计算方式相似，但会将结果取反。
  • overlay，它结合 modulate 和 screen，使混合结果偏向目标图像。
  • hardLight，它结合 modulate 和 screen，使混合结果偏向源图像。
screen → const BlendMode

将源图像和目标图像各分量的反值相乘，再对结果取反。

对分量取反时，完全饱和的通道（不透明白色）会视为 0.0；通常视为 0.0 的值（黑色、透明）则视为 1.0。

这与 modulate 混合模式基本相同，但会先反转颜色值再相乘，并在绘制前再次反转结果。

结果只会保持原色或变亮（乘以黑色 1.0 不会改变颜色；乘以白色 0.0 则得到白色）。alpha 通道也只会变得更加不透明。

效果类似于两台投影仪同时将图像投射到同一块屏幕上。

另请参阅：

  • modulate，其计算方式相似，但不会反转数值。
  • overlay，它结合 modulate 和 screen，使混合结果偏向目标图像。
  • hardLight，它结合 modulate 和 screen，使混合结果偏向源图像。
overlay → const BlendMode

调整分量以偏向目标图像后，再将源图像和目标图像的分量相乘。

具体来说，如果目标值较小，就将其与源值相乘；如果源值较小，则将源值和目标值的反值相乘，再对结果取反。

对分量取反时，完全饱和的通道（不透明白色）会视为 0.0；通常视为 0.0 的值（黑色、透明）则视为 1.0。

另请参阅：

  • modulate，它始终将数值相乘。
  • screen，它始终将数值的反值相乘。
  • hardLight，它与 overlay 类似，但更偏向源图像而非目标图像。
darken → const BlendMode

合成源图像和目标图像时，为每个颜色通道选取较小值。

输出图像的不透明度计算方式与 srcOver 相同。

lighten → const BlendMode

合成源图像和目标图像时，为每个颜色通道选取较大值。

输出图像的不透明度计算方式与 srcOver 相同。

colorDodge → const BlendMode

用目标图像除以源图像的反值。

对分量取反时，完全饱和的通道（不透明白色）会视为 0.0；通常视为 0.0 的值（黑色、透明）则视为 1.0。

colorBurn → const BlendMode

用源图像除以目标图像的反值，再对结果取反。

对分量取反时，完全饱和的通道（不透明白色）会视为 0.0；通常视为 0.0 的值（黑色、透明）则视为 1.0。

hardLight → const BlendMode

调整分量以偏向源图像后，再将源图像和目标图像的分量相乘。

具体来说，如果源值较小，就将其与目标值相乘；如果目标值较小，则将目标值和源值的反值相乘，再对结果取反。

对分量取反时，完全饱和的通道（不透明白色）会视为 0.0；通常视为 0.0 的值（黑色、透明）则视为 1.0。

另请参阅：

  • modulate，它始终将数值相乘。
  • screen，它始终将数值的反值相乘。
  • overlay，它与 hardLight 类似，但更偏向目标图像而非源图像。
softLight → const BlendMode

源值小于 0.5 时使用 colorDodge，大于 0.5 时使用 colorBurn。

这会产生与 overlay 类似但更柔和的效果。

另请参阅：

  • color，它的着色效果更柔和。
difference → const BlendMode

对每个通道，用较大值减去较小值。

合成黑色不会产生影响；合成白色会反转另一张图像的颜色。

输出图像的不透明度计算方式与 srcOver 相同。

效果类似于 exclusion，但更强烈。

exclusion → const BlendMode

从两张图像的分量之和中减去它们乘积的两倍。

合成黑色不会产生影响；合成白色会反转另一张图像的颜色。

输出图像的不透明度计算方式与 srcOver 相同。

效果类似于 difference，但更柔和。

multiply → const BlendMode

将源图像和目标图像的分量（包括 alpha 通道）相乘。

结果只会保持原色或变暗（乘以白色 1.0 不会改变颜色；乘以黑色 0.0 则得到黑色）。

由于 alpha 通道也会相乘，如果其中一张图像的像素完全透明（不透明度为 0.0），输出中的对应像素也会完全透明。这与 dstIn 类似，但会合并颜色。

如果要相乘颜色但不相乘 alpha 通道，可考虑使用 modulate。

hue → const BlendMode

取源图像的色相，以及目标图像的饱和度和亮度。

效果是用源图像为目标图像着色。

输出图像的不透明度计算方式与 srcOver 相同。源图像中完全透明的区域会从目标图像获取色相。

另请参阅：

  • color，它也会应用源图像的饱和度，因此效果类似但更强烈。
  • HSVColor，它允许使用色相而非 Color 的红、绿、蓝通道来表示颜色。
saturation → const BlendMode

取源图像的饱和度，以及目标图像的色相和亮度。

输出图像的不透明度计算方式与 srcOver 相同。源图像中完全透明的区域会从目标图像获取饱和度。

另请参阅：

  • color，它还会应用源图像的色相。
  • luminosity，它会将源图像的亮度应用到目标图像。
color → const BlendMode

取源图像的色相和饱和度，以及目标图像的亮度。

效果是用源图像为目标图像着色。

输出图像的不透明度计算方式与 srcOver 相同。源图像中完全透明的区域会从目标图像获取色相和饱和度。

另请参阅：

  • hue，它的效果相似但较弱。
  • softLight，它的着色效果类似，但也会对白色着色。
  • saturation，它只应用源图像的饱和度。
luminosity → const BlendMode

取源图像的亮度，以及目标图像的色相和饱和度。

输出图像的不透明度计算方式与 srcOver 相同。源图像中完全透明的区域会从目标图像获取亮度。

另请参阅：

  • saturation，它会将源图像的饱和度应用到目标图像。
  • ImageFilter.blur，它可以与 BackdropFilter 配合使用，以实现相关效果。
