onReportTimings

onReportTimings 属性

TimingsCallback? get onReportTimings

最近完成光栅化的帧报告其 FrameTiming 时调用的回调。

读取此值会返回 PlatformDispatcher 单例中的值。因此，建议改为从 WidgetsBinding.instance.platformDispatcher 获取此值；如果无法使用 WidgetsBinding，则可从 PlatformDispatcher.instance 获取。此值转发到 PlatformDispatcher，是为了方便只使用单个主窗口的应用。

建议使用 SchedulerBinding.addTimingsCallback，而不是直接使用 PlatformDispatcher.onReportTimings，因为 SchedulerBinding.addTimingsCallback 允许注册多个回调。

可以通过 FrameTiming.buildDuration 和 FrameTiming.rasterDuration 检查窗口是否丢帧，也可以通过 FrameTiming.totalSpan 检查是否存在较高延迟。

与 Timeline 不同，此处的计时信息在发布模式下也可用（此外，在 profile 和 debug 模式下也可用）。因此，可以用它监控应用在实际运行环境中的性能。

此回调接收 FrameTiming 列表，因为它不一定会在每帧结束后立即触发。Flutter 会尝试将多帧合并，并一次发送所有帧的计时信息，以降低开销（此功能在发布模式下也可用）。列表按时间升序排列，即最早的帧在前。即使没有后续帧可供合并，每帧的计时信息也会在约 1 秒内发送（profile/debug 模式下为 100 毫秒内）。第一帧的计时信息会立即发送，不进行合并。

如果此值为 null，则不会执行额外工作。如果不为 null，Flutter 每秒会花费不到 0.1 毫秒来报告计时信息（在 iPhone 6S 上测得）。0.1 毫秒约占 16 毫秒的 0.6%（60 fps 的帧预算），相当于每秒 0.01% 的 CPU 使用率。

实现

TimingsCallback? get onReportTimings => platformDispatcher.onReportTimings;
set onReportTimings (TimingsCallback? callback)

实现

set onReportTimings(TimingsCallback? callback) {
  platformDispatcher.onReportTimings = callback;
}
