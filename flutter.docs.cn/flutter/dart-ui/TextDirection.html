TextDirection

TextDirection enum

文本流动的方向。

有些语言从左向右书写（例如英语、泰米尔语或中文），另一些语言则从右向左书写（例如阿拉姆语、希伯来语或乌尔都语）。还有些语言混合使用两种方向；例如阿拉伯语主要从右向左书写，但数字从左向右书写。

必须向负责呈现文本或水平布局框的 API 提供文本方向，以便它们确定从哪个方向开始：从右向左，即 TextDirection.rtl；或从左向右，即 TextDirection.ltr。

设计讨论

Flutter 的设计旨在满足使用当今各种语言编写应用的需求，无论其书写方向是从右向左还是从左向右。Flutter 不支持其他书写模式，例如竖排文本或反向耕作式书写，因为这些模式在计算机程序中很少使用。

开发用户界面框架时，通常会选定一种默认文本方向——一般是从左向右，因为这是框架工程师最熟悉的方向——这样可以简化平台应用的开发。不幸的是，这往往会让平台产生意料之外的从左向右偏向或假设，因为工程师通常会漏掉需要支持从右向左文本的地方，最终导致只在从右向左环境中出现的错误。

为尽量减少 Flutter 遇到此类问题，Flutter 框架的底层不设默认文本阅读方向。凡是需要阅读方向的地方，例如显示文本或解释依赖书写方向的值时，都必须明确指定阅读方向。在可行的情况下，例如编写 switch 语句时，会先列出从右向左的情形，以免给人留下它是事后才考虑的印象。

在较高层（具体来说，从 widgets 库开始），框架会引入环境中的 Directionality 并提供默认方向。因此，例如，位于 MaterialApp 组件作用域内的 widgets.Text 组件不需要显式指定书写方向。可以使用静态方法 Directionality.of，获取特定 BuildContext 的环境文本方向。

Flutter 中已知的从左向右偏向

尽管设计意图如上所述，Flutter 的设计中仍然出现了一些从左向右的偏向，包括：

  • Canvas 的原点位于左上角，x 轴向右递增。

  • widgets 和 material 库的默认本地化语言是美国英语，其书写方向为从左向右。

视觉属性与方向属性

Flutter 框架中的许多类都提供两个版本：面向视觉位置的变体，以及依赖文本方向的变体。例如，EdgeInsets 使用上、左、右、下描述边距；而 EdgeInsetsDirectional 使用上、起始、结束、下描述边距，其中在从右向左文本中，起始和结束分别对应右和左；在从左向右文本中，则分别对应左和右。

这两类变体分别适用于不同场景。

依赖文本方向的变体适用于需要随文本方向“翻转”的用户界面。例如，英语段落通常左对齐，引文缩进左侧；阿拉伯语则通常右对齐，引文缩进右侧。这两种情况都可由依赖方向的 TextAlign.start 和 EdgeInsetsDirectional.start 表示。

相比之下，如果文本方向已知且不受阅读方向影响，则适合使用面向视觉位置的变体。例如，提供驾驶路线的应用可能会在左侧显示“左转”箭头、在右侧显示“右转”箭头；无论应用本地化为从左向右书写的法语，还是从右向左书写的希伯来语，箭头位置都相同。

实际上，也可以预期许多开发者只面向一种语言；在这种情况下，用视觉位置来思考可能更简单。
