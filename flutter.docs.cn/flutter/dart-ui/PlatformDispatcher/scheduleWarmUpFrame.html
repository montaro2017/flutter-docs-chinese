尽快安排一帧运行，而不是等待引擎响应系统“Vsync”信号来请求帧。

应用启动后即可调用此方法，让首帧（通常开销较大）提前几毫秒开始。在其他情况下使用可能导致意外结果，例如屏幕撕裂。根据平台和具体情况，预热帧可能会也可能不会实际渲染到屏幕上。

有关预热帧的更多介绍，请参阅 SchedulerBinding.scheduleWarmUpFrame。

此方法使用提供的回调作为帧开始回调和帧绘制回调，而不是使用 onBeginFrame 和 onDrawFrame。

另请参阅：

  • SchedulerBinding.scheduleWarmUpFrame 使用此方法，并对预热帧作了更详细的介绍。
  • scheduleFrame 会在下一个合适的时机安排帧，应当用于渲染常规帧。

实现

void scheduleWarmUpFrame({required VoidCallback beginFrame, required VoidCallback drawFrame}) {
  // We use timers here to ensure that microtasks flush in between.
  Timer.run(beginFrame);
  Timer.run(() {
    drawFrame();
    _endWarmUpFrame();
  });
}
