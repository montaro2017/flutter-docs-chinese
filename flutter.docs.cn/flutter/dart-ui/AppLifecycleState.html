AppLifecycleState

AppLifecycleState enum

应用运行后可能处于的状态。

平台不支持的状态会由框架在支持的状态之间转换时合成，从而让所有实现共用同一状态机。

初始状态为 detached。平台首次发送生命周期更新后，状态会更新为当前状态（通常是 resumed）。

由于历史原因以及名称冲突，Flutter 的应用状态名称与各个平台的状态名称并非一一对应。例如，在 Android 上，操作系统调用 Activity.onPause 时，Flutter 会进入 inactive 状态；而 Android 调用 Activity.onStop 时，Flutter 会进入 paused 状态。各状态的文档分别说明了它们在不同平台上的含义。

可以通过 SchedulerBinding.instance.lifecycleState 获取当前应用状态。若要监听状态变化，可以创建 AppLifecycleListener，也可以使用 WidgetsBindingObserver 并重写 WidgetsBindingObserver.didChangeAppLifecycleState 方法。

应用不应假定一定会收到所有可能的通知。

例如，如果任务管理器终止应用、应用收到终止信号、用户拔掉设备电源，或设备突然意外拆解，应用可能会在未收到任何通知的情况下突然终止，并且某些状态可能会被跳过。

另请参阅：

  • AppLifecycleListener 是用于观察生命周期状态并提供状态转换回调的对象。
  • WidgetsBindingObserver 是用于从 widgets 层观察生命周期状态的机制。
  • iOS 的 UIKit 活动 生命周期文档。
  • Android 的 Activity 生命周期文档。
  • macOS 的 AppKit 活动 生命周期文档。

Values

detached → const AppLifecycleState

应用仍由 Flutter 引擎承载，但已与所有宿主视图分离。

应用初始化前默认处于此状态；所有视图分离后（适用于 Android、iOS 和 Web），应用也可能进入此状态。

应用处于此状态时，引擎正在运行，但没有视图。

此状态只会在 iOS、Android 和 Web 上进入，不过在所有平台上，它都是应用开始运行前的默认状态。

resumed → const AppLifecycleState

在所有平台上，此状态表示应用处于默认运行模式，拥有输入焦点且可见。

在 Android 上，此状态表示 Flutter 宿主视图已获得焦点（调用了 Activity.onWindowFocusChanged，参数为 true），且 Android 处于“resumed”状态。如果应用失去焦点（调用了 Activity.onWindowFocusChanged，参数为 false），但尚未调用 Activity.onPause，Flutter 应用仍可能处于 inactive 状态，而 Android 仍处于 “onResume” 状态。

在 iOS 和 macOS 上，此状态表示应用正在前台运行且处于活动状态。

inactive → const AppLifecycleState

应用至少有一个视图可见，但没有视图拥有输入焦点。除此之外，应用仍正常运行。

在非 Web 桌面平台上，此状态表示应用不在前台，但仍有可见窗口。

在 Web 上，此状态表示应用运行在一个没有输入焦点的窗口或标签页中。

在 iOS 和 macOS 上，此状态表示 Flutter 宿主视图在前台运行，但处于非活动状态。接听电话、响应 TouchID 请求、打开应用切换器或控制中心，以及承载 Flutter 应用的 UIViewController 正在转换时，应用都会进入此状态。

在 Android 上，此状态对应 Flutter 宿主视图处于 Android 的 paused 状态（即已调用 Activity.onPause），或处于 Android 的“resumed”状态（即已调用 Activity.onResume），但窗口没有焦点。应用部分被遮挡、其他 Activity 获得焦点、应用在分屏中运行但并非当前活动应用、应用被电话中断、应用处于画中画模式、显示系统对话框或其他视图时，都可能进入此状态。通知栏下拉面板或应用切换器显示时，应用也会处于非活动状态。

在 Android 和 iOS 上，应用处于此状态时应假定它随时可能进入 hidden 和 paused 状态。

hidden → const AppLifecycleState

应用的所有视图都已隐藏：在 iOS 和 Android 上，应用即将暂停；在非 Web 桌面平台上，应用已最小化或移至不可见的桌面；在 Web 上，应用所在的窗口或标签页已不可见。

在 iOS 和 Android 上，为了让所有平台使用相同的状态机，从 inactive 状态进入 paused 状态前，会先合成一次进入此状态的转换；从 paused 状态进入 inactive 状态前也会如此。这样，希望获知应用在概念上处于“隐藏”状态的跨平台实现只需编写一个处理函数。

paused → const AppLifecycleState

应用当前对用户不可见，也不会响应用户输入。

应用处于此状态时，引擎不会调用 PlatformDispatcher.onBeginFrame 和 PlatformDispatcher.onDrawFrame 回调函数。

此状态只会在 iOS 和 Android 上进入。
