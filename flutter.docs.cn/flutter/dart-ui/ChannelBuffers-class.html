ChannelBuffers

ChannelBuffers 类

用于缓冲和分发消息的机制：消息由引擎侧的插件发送给框架侧对应的插件代码。

某个通道的消息会一直存储，直到通过 setListener 为该通道设置监听器。每个通道只能设置一个监听器。

通常，在 Flutter 框架的 BinaryMessenger 上设置回调后，这些缓冲区就会被清空（参见 setListener）。

通道名称

按照惯例，通道通常使用反向 DNS 前缀、斜线和领域专用名称组成。例如：com.example/demo。

通道名称不能包含 U+0000 NULL 字符，因为名称会传递给使用以 null 结尾字符串的 API。

缓冲区容量与溢出

每个通道的缓冲区容量有限；超出容量时，消息会按先进先出（FIFO）的顺序被删除。

默认情况下，每个通道的缓冲区只存储一条消息。消息溢出时，调试模式下会在控制台打印提示，内容如下：

com.example 通道中的一条消息在得到处理前已被丢弃。
这是因为插件在框架有机会注册监听器之前就向框架侧发送了消息。有关如何配置通道以容纳更多消息或允许丢弃消息的详情，请参见 ChannelBuffers API 文档：https://api.flutter.dev/flutter/dart-ui/ChannelBuffers-class.html

缓冲区容量的设置各有取舍。应根据通道的语义选择合适的容量。插件可以按照下文所述，通过控制通道发送消息来更改容量。

如果引擎和框架就绪前发送的消息应被忽略，则容量设为 0 是合适的。例如，辐射传感器检测到电离事件时会通知框架的插件，可以将容量设为零，因为过去发生的电离事件通常没有意义，只有即时读数值得跟踪。

对于电平触发型插件，容量设为 1 较为合适。例如，持续向框架报告压力传感器当前值的插件可以将容量保持为 1（默认值）。框架侧插件在通道上注册后，会立即收到最新值，之前的消息则已被丢弃。

如果每条消息都很重要，则适合将容量设为大于 1。例如，插件本身向另一个系统注册，而该系统会缓冲事件；插件注册后立即转发所有先前缓冲的事件，此时通常应避免丢失任何消息。在这种情况下，应选择足以避免溢出的容量。还应考虑框架侧可能永远无法完全初始化的情况（例如，用户启动应用后很快就将其终止，使插件的平台侧有时间运行，而框架侧却没有）。

控制通道

插件可以向控制通道 dev.flutter/channel-buffers 发送消息，以配置其通道的缓冲区（参见 kControlChannelName）。

可以向此控制通道发送两种消息，用于调整缓冲区大小和关闭溢出警告。有关这些消息的详情，请参见 handleMessage。
