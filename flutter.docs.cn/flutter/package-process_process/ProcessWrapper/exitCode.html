exitCode

exitCode 属性

  1. @重写
Future<int> get exitCode
重写

进程结束时以退出码完成的 Future。

对于以 ProcessStartMode.detached 或 ProcessStartMode.detachedWithStdio 模式运行的进程，退出码不可用；使用此 getter 会抛出 StateError。

退出码的处理方式因平台而异。

在 Linux 和 OS X 上，正常退出码是 [0..255] 范围内的正数。如果进程因信号终止，退出码是 [-255..-1] 范围内的负数，其绝对值就是信号编号。例如，进程因段错误崩溃时，退出码为 -11，因为 SIGSEGV 信号编号是 11。

在 Windows 上，进程可以报告任意 32 位退出码。返回退出码时，会将其转换为有符号数。某些特殊值用于表示系统事件导致的终止。例如，进程因访问冲突崩溃时，32 位退出码为 0xc0000005，返回值则是负数 -1073741819。要获取原始 32 位值，请使用 (0x100000000 + exitCode) & 0xffffffff。

返回的 future 完成时，stdout 和 stderr 不一定已经输出完进程缓冲的数据。若要确保捕获全部输出，请等待这些流的 done 事件。

实现

@override
Future<int> get exitCode => _delegate.exitCode;
