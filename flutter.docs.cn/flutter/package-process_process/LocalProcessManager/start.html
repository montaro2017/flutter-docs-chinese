运行指定的 command 来启动进程。

command 的第一个元素将作为要运行的可执行文件，其后的元素将作为参数传递给该文件。支持哪些类型的元素由具体实现决定，并依据 command 列表中的内容处理。

成功启动进程后，返回一个以 Process 实例完成的 Future<Process>。该 Process 对象可用于与进程交互。如果进程无法启动，返回的 Future 会以异常完成。

使用 workingDirectory 设置进程的工作目录。请注意，在某些平台上，会先切换目录再启动进程，因此可执行文件或参数使用相对路径时可能受到影响。

使用 environment 设置进程的环境变量。如果未设置，则继承父进程的环境。目前只支持 US-ASCII 环境变量；如果传入包含 US-ASCII 范围以外码点的环境变量，可能会出错。

如果 includeParentEnvironment 为 true，进程环境会包含父进程环境，且 environment 中的值优先。默认值为 true。

如果 runInShell 为 true，则会通过系统 shell 启动进程。Linux 和 OS X 使用 /bin/sh；Windows 使用 %WINDIR%\system32\cmd.exe。

用户必须读取通过 start 启动的进程在 stdout 和 stderr 流中输出的所有数据。如果未读取全部数据，仍有待处理内容，底层系统资源就不会释放。

以下代码展示了如何在 Linux 上使用 start 在 test.dart 文件中搜索 main。

ProcessManager mgr = new LocalProcessManager();
mgr.start(['grep', '-i', 'main', 'test.dart']).then((process) {
  stdout.addStream(process.stdout);
  stderr.addStream(process.stderr);
});

如果 mode 为 ProcessStartMode.normal（默认值），则会启动一个与 stdin、stdout 和 stderr 相连的子进程。

如果 mode 为 ProcessStartMode.detached，则会创建一个分离进程。分离进程与父进程没有连接，父进程退出后它仍可独立运行。分离进程唯一可用的信息是其 pid。它不会连接到 stdin、stdout 或 stderr，终止后也不会提供退出码。

如果 mode 为 ProcessStartMode.detachedWithStdio，则会创建一个分离进程，并连接其 stdin、stdout 和 stderr。创建者可以通过这些流与子进程通信。即使关闭这些通信通道，分离进程仍会继续运行。进程终止后不会提供退出码。

mode 的默认值为 ProcessStartMode.normal。

实现

@override
Future<Process> start(
  List<Object> command, {
  String? workingDirectory,
  Map<String, String>? environment,
  bool includeParentEnvironment = true,
  bool runInShell = false,
  ProcessStartMode mode = ProcessStartMode.normal,
}) {
  try {
    return Process.start(
      _getExecutable(command, workingDirectory, runInShell),
      _getArguments(command),
      workingDirectory: workingDirectory,
      environment: environment,
      includeParentEnvironment: includeParentEnvironment,
      runInShell: runInShell,
      mode: mode,
    );
  } on ProcessException catch (exception) {
    throw ProcessPackageException.fromProcessException(
      exception,
      workingDirectory: workingDirectory,
    );
  }
}
