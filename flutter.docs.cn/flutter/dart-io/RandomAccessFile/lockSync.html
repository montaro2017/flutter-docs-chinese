void lockSync([
  1. FileLock mode = FileLock.exclusive,
  2. int start = 0,
  3. int end = -1
])

同步锁定文件或文件的一部分。

默认会获取排他锁，但可以通过 mode 参数更改此行为。

锁定文件中从 start 到 end 的字节范围，不包括位置 end 处的字节。如果未指定参数，则锁定整个文件；如果只指定 start，则从文件的 start 字节位置锁定到文件末尾，无论文件之后增长到多大。也可以将 end 显式指定为大于当前文件长度的值。

要获取文件的排他锁，必须以写入方式打开该文件。

如果 mode 为 FileLock.exclusive 或 FileLock.shared，无法获取锁时会发出错误。如果 mode 为 FileLock.blockingExclusive 或 FileLock.blockingShared，该调用会一直阻塞，直到成功获取锁。

注意：文件锁在不同平台上的行为略有差异：

在 Linux 和 OS X 上使用的是建议锁，其行为有一点出人意料：进程关闭该文件的任意文件描述符时，与该文件关联的所有锁都会被移除。请注意，这并不会阻止对文件的访问。另外，建议锁的作用范围是整个进程。这意味着同一进程中的多个 isolate 可以同时获取同一文件的排他锁。

在 Windows 上，用于加锁和解锁的区域必须一致；否则，解锁时会出现操作系统错误：“The segment is already unlocked”（该区域已解锁）。

在 Windows 上，文件锁与获取锁时使用的特定文件句柄关联。如果再次打开同一文件并使用不同句柄（即使在同一进程中），尝试通过新句柄写入被锁定区域会失败。为确保加锁后能够成功写入，后续写操作应使用获取该锁的同一个 RandomAccessFile 对象。
