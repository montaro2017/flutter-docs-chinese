Future<Process> start(
  1. String executable,
  2. List<String> arguments, {
  3. String? workingDirectory,
  4. Map<String, String>? environment,
  5. bool includeParentEnvironment = true,
  6. bool runInShell = false,
  7. ProcessStartMode mode = ProcessStartMode.normal,
})

使用指定的 arguments 启动运行 executable 的进程。

返回一个 Future<Process>；进程成功启动后，该 future 会以 Process 实例完成。可以使用此 Process 对象与进程交互。如果无法启动进程，返回的 Future 会以异常完成。

建议为 executable 使用绝对路径，因为可执行文件路径的解析方式因平台而异。在 Windows 上，解析 executable 路径时，会忽略 PATH（在 environment 映射参数中设置）以及 workingDirectory 参数中设置的路径，并忽略其中的 executable 路径。

使用 workingDirectory 设置进程的工作目录。请注意，在某些平台上，会先切换目录再执行进程；使用相对路径指定可执行文件和参数时，这可能会产生影响。

使用 environment 设置进程的环境变量。如果未设置，则继承父进程的环境。目前仅支持 US-ASCII 环境变量；如果传入包含 US-ASCII 范围之外码点的环境变量，可能会发生错误。

如果 includeParentEnvironment 为 true，进程的环境将包含父进程的环境，且 environment 中的设置优先。默认值为 true。

如果 runInShell 为 true，进程将通过系统 shell 启动。在 Linux 和 OS X 上使用 /bin/sh；在 Windows 上使用 %WINDIR%\system32\cmd.exe。

注意：在 Windows 上，如果 executable 是批处理文件（.bat 或 .cmd），无论 runInShell 的值如何，操作系统都可能通过系统 shell 启动它。因此，参数可能会按照 shell 规则解析。例如：

void main() async {
  // Will launch notepad.
  Process.start('test.bat', ['test&notepad.exe']);
}

用户必须读取通过 Process.start 启动的进程的 stdout 和 stderr 流中的所有数据。如果未读取流中的全部数据，底层系统资源将无法释放，因为仍有数据待处理。

以下代码在 Linux 上使用 Process.start 在 test.dart 文件中搜索 main。

var process = await Process.start('grep', ['-i', 'main', 'test.dart']);
stdout.addStream(process.stdout);
stderr.addStream(process.stderr);

如果 mode 为 ProcessStartMode.normal（默认值），则会启动一个子进程，并将其 stdin、stdout 和 stderr 连接到父进程。只要子进程仍在运行，父进程就不会退出，除非父进程调用 exit。如果父进程调用 exit，父进程会终止，但子进程会继续运行。

如果 mode 为 ProcessStartMode.detached，则会创建一个分离进程。分离进程与父进程没有连接，即使父进程终止，它也可以独立继续运行。分离进程仅提供 pid 信息。它与 stdin、stdout 或 stderr 均无连接，终止时也不会提供进程退出代码。

如果 mode 为 ProcessStartMode.detachedWithStdio，则会创建一个分离进程，并连接其 stdin、stdout 和 stderr。创建方可以通过这些流与子进程通信。即使这些通信通道关闭或父进程终止，分离进程仍会继续运行。进程终止时不会提供退出代码。

mode 的默认值为 ProcessStartMode.normal。
