在现有连接上启动 TLS。

使用已连接的 socket 启动客户端 TLS 握手，以保护通信。返回的 future 完成时，SecureSocket 的 TLS 握手也已完成。使用此函数要求连接的另一端已准备好进行 TLS 握手。

如果 socket 已有订阅，该订阅将不再接收任何事件。大多数情况下，在开始 TLS 握手前对此订阅调用 StreamSubscription.pause 是合适的做法。

给定的 socket 会被关闭，之后不得再使用。

如果提供了 host 参数，则将其用作 TLS 握手的主机名。如果未提供 host，则使用 socket 中的主机名。host 可以是 String 或 InternetAddress。

onBadCertificate 是用于处理无法验证证书的可选回调。该回调会收到 X509Certificate，可以检查证书并决定（或让用户决定）是否接受连接。若要继续建立 SecureSocket 连接，回调应返回 true。

keyLog 是一个可选回调；与服务器交换新的 TLS 密钥时会调用它。每次调用时，keyLog 都会收到一行 NSS Key Log Format 格式的文本。将这些文本行写入文件后，工具（例如 Wireshark）便可解密通过此套接字发送的内容。此功能用于在网络层调试安全套接字，不应在生产代码中使用。例如：

final log = File('keylog.txt');
final socket = await SecureSocket.connect('www.example.com', 443,
    keyLog: (line) => log.writeAsStringSync(line, mode: FileMode.append));

supportedProtocols 是可选的协议列表，按优先级从高到低排列，用于与服务器进行 ALPN 协商。示例值包括 "http/1.1" 和 "h2"。可以通过 SecureSocket.selectedProtocol 获取选定的协议。

调用此函数不会执行 DNS 主机查找。如果传入的 host 是 String，则生成的 SecureSocket 的 InternetAddress 会将传入的 host 作为主机值，并将已连接套接字的互联网地址作为地址值。

有关这些参数的更多信息，请参见 connect。

实现

static Future<SecureSocket> secure(
  Socket socket, {
  host,
  SecurityContext? context,
  bool onBadCertificate(X509Certificate certificate)?,
  void keyLog(String line)?,
  List<String>? supportedProtocols,
}) {
  return socket
      ._detachRaw()
      .then<RawSecureSocket>((detachedRaw) {
        return RawSecureSocket.secure(
          detachedRaw[0] as RawSocket,
          subscription: detachedRaw[1] as StreamSubscription<RawSocketEvent>?,
          host: host,
          context: context,
          onBadCertificate: onBadCertificate,
          keyLog: keyLog,
          supportedProtocols: supportedProtocols,
        );
      })
      .then<SecureSocket>((raw) => SecureSocket._(raw));
}
