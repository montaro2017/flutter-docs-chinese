重写

创建新的安全客户端套接字，并将其连接到指定主机的指定端口。

连接成功并可开始订阅后，返回的 Future 会以 RawSecureSocket 完成。

服务器提供的证书会根据 SecurityContext 对象中设置的受信任证书进行验证。如果客户端通过 SecurityContext.useCertificateChain 和 SecurityContext.usePrivateKey 设置了证书和密钥，且服务器要求客户端证书，则该客户端证书会发送给服务器。

onBadCertificate 是用于处理无法验证证书的可选回调。该回调会收到 X509Certificate，可以检查证书并决定（或让用户决定）是否接受连接。若要继续建立 RawSecureSocket 连接，回调应返回 true。

onBadCertificate 是用于处理无法验证证书的可选回调。该回调会收到 X509Certificate，可以检查证书并决定（或让用户决定）是否接受连接。若要继续建立 SecureSocket 连接，回调应返回 true。

keyLog 是一个可选回调；与服务器交换新的 TLS 密钥时会调用它。每次调用时，keyLog 都会收到一行 NSS Key Log Format 格式的文本。将这些文本行写入文件后，工具（例如 Wireshark）便可解密通过此套接字发送的内容。此功能用于在网络层调试安全套接字，不应在生产代码中使用。例如：

final log = File('keylog.txt');
final socket = await SecureSocket.connect('www.example.com', 443,
    keyLog: (line) => log.writeAsStringSync(line, mode: FileMode.append));

supportedProtocols 是可选的协议列表，按优先级从高到低排列，用于与服务器进行 ALPN 协商。示例值包括 "http/1.1" 和 "h2"。可以通过 RawSecureSocket.selectedProtocol 获取选定的协议。

static Future<RawSecureSocket> connect(
  host,
  int port, {
  SecurityContext? context,
  bool onBadCertificate(X509Certificate certificate)?,
  void keyLog(String line)?,
  List<String>? supportedProtocols,
  Duration? timeout,
}) {
  _RawSecureSocket._verifyFields(host, port, false, false);
  return RawSocket.connect(host, port, timeout: timeout).then((socket) {
    return secure(
      socket,
      context: context,
      onBadCertificate: onBadCertificate,
      keyLog: keyLog,
      supportedProtocols: supportedProtocols,
    );
  });
}
