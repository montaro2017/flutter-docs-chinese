rebuild 方法

  1. bool force = false,

继承

使 widget 更新自身。在调试构建中，还会验证各项不变量。

在 BuildOwner.scheduleBuildFor 将此元素标记为脏状态后，BuildOwner 会调用此方法；元素首次构建时，mount 会调用此方法；widget 发生变化时，update 也会调用此方法。

只有当 dirty 为 true 时，此方法才会重建。若要忽略 dirty 标志并强制重建，请将 force 设为 true。在 update 期间强制重建很方便，因为此时 dirty 为 false。

何时发生重建

术语

Widget 表示 Element 的配置。每个 Element 都有一个 widget，由 Element.widget 指定。严格来说，某些场合用“element”更准确，但人们常常会统称为“widget”。

Element 虽然始终关联着当前的 Widget，但随着时间推移，该 widget 可能会被其他 widget 替换。例如，支撑 ColoredBox 的 element 起初可能关联一个 ColoredBox，其 ColoredBox.color 为蓝色，之后则关联一个新的绿色 ColoredBox。

在同一棵树中的任意时刻，多个 Element 都可能关联同一个 Widget。例如，同一个绿色 ColoredBox 可以同时用于 widget 树中的多个位置，每个位置都由不同的 Element 支撑。

将元素标记为脏状态

Element 可以在帧与帧之间被标记为脏状态。造成这种情况的原因有多种，例如：

  • StatefulWidget 的 State 可以通过调用 State.setState，使其 Element 被标记为脏状态。

  • InheritedWidget 发生变化时，之前订阅了它的后代会被标记为脏状态。

  • 执行热重载时，所有 element 都会被标记为脏状态（通过 Element.reassemble）。

重建

脏元素会在下一帧中重建。具体方式取决于元素的类型。StatelessElement 会调用其 widget 的 StatelessWidget.build 方法进行重建。StatefulElement 会调用其 widget 状态的 State.build 方法进行重建。RenderObjectElement 则通过更新其 RenderObject 来重建。

在许多情况下，重建的结果是一个子 widget；对于 MultiChildRenderObjectElement，结果则是一个子 widget 列表。

这些子 widget 会用于更新子 element 的 widget 属性。如果新 Widget 与现有 Element 具有相同的 Type 和 Key，则认为两者相对应。（对于 MultiChildRenderObjectElement，框架也会尝试追踪顺序发生变化的 widget；参见 RenderObjectElement.updateChildren。）

如果没有对应的旧子项，就会创建新的 Element（调用 Widget.createElement）；随后会递归地构建该元素。

如果之前存在子项，但构建结果中没有对应的新子项可供更新，则旧子项会被丢弃；如果涉及 GlobalKey 重挂接，也可能在元素树的其他位置复用。

不过，最常见的情况是存在对应的旧子项。此时会让子 Element 使用新的子 Widget 更新自身。对于 StatefulElement，这会触发 State.didUpdateWidget。

不进行重建

在通知 Element 使用新的 Widget 更新自身之前，会使用 operator == 比较新旧对象。

通常，这相当于使用 identical 比较，检查两个对象是否确实为同一个实例。如果是，并且该元素没有因其他原因被标记为脏状态，那么元素会跳过更新，因为可以确定更新自身或其后代没有价值。

强烈建议不要为 Widget 对象重写 operator ==。这样做看似能提高性能，但对于非叶子 widget，实际会导致 O(N²) 的复杂度。这是因为比较时必须比较子 widget；如果这些子 widget 也实现了 operator ==，最终就要遍历整棵 widget 树，并且在树的每一层重复遍历。实际上，直接重建成本更低。（此外，只要应用中使用的任意 Widget 子类实现了 operator ==，编译器就无法在任何位置内联该比较，因为必须将调用视为虚调用，以防实例恰好重写了运算符。）

避免不必要重建的最佳方式，是缓存从 State.build 返回的 widget，使每一帧都重复使用同一批 widget，直到它们确实发生变化。框架提供了多种机制来鼓励这种做法：例如，const widget 是一种自动缓存形式（使用 const 关键字构造 widget 时，之后使用相同参数构造它都会返回同一个实例）。

另一个例子是 AnimatedBuilder.child 属性；即使 AnimatedBuilder.builder 回调重新创建了子树中的其他组件，该属性也能让其中不参与动画的部分保持不变。

实现

@pragma('dart2js:tryInline')
@pragma('vm:prefer-inline')
@pragma('wasm:prefer-inline')
void rebuild({bool force = false}) {
  assert(_lifecycleState != _ElementLifecycle.initial);
  if (_lifecycleState != _ElementLifecycle.active || (!_dirty && !force)) {
    return;
  }
  assert(() {
    debugOnRebuildDirtyWidget?.call(this, _debugBuiltOnce);
    if (debugPrintRebuildDirtyWidgets) {
      if (!_debugBuiltOnce) {
        debugPrint('Building $this');
        _debugBuiltOnce = true;
      } else {
        debugPrint('Rebuilding $this');
      }
    }
    return true;
  }());
  assert(_lifecycleState == _ElementLifecycle.active);
  assert(owner!._debugStateLocked);
  Element? debugPreviousBuildTarget;
  assert(() {
    debugPreviousBuildTarget = owner!._debugCurrentBuildTarget;
    owner!._debugCurrentBuildTarget = this;
    return true;
  }());
  try {
    performRebuild();
  } finally {
    assert(() {
      owner!._debugElementWasRebuilt(this);
      assert(owner!._debugCurrentBuildTarget == this);
      owner!._debugCurrentBuildTarget = debugPreviousBuildTarget;
      return true;
    }());
  }
  assert(!_dirty);
}
