Focus 类

一个用于管理 FocusNode 的 widget，使此 widget 及其后代能够获得键盘焦点。

获得或失去焦点时，会调用 onFocusChange。

对于键盘事件，如果此 widget 的 focusNode 的 FocusNode.hasFocus 为 true，则会调用 onKey 和 onKeyEvent；但如果已获得焦点的后代所对应的 onKey 或 onKeyEvent 回调返回了 KeyEventResult.handled，则不会调用。

此 widget 不会显示焦点变化。若需要视觉反馈，应在调用 onFocusChange 时自行更新界面。

若要访问最近祖先 Focus widget 的 FocusNode，并建立焦点变化时触发重建的依赖关系，请使用静态方法 Focus.of 和 FocusScope.of。

若要访问最近的 Focus widget 当前是否拥有焦点，可在 build 方法中读取 FocusNode.hasFocus。这也会在调用方 widget 与该 Focus widget 之间建立依赖，使调用方在焦点变化时重建。

管理 FocusNode 包括管理其生命周期、监听焦点变化，以及在需要时重新设置父节点，使焦点层级与 widget 层级保持同步。此 widget 会替你完成这些工作。如果没有使用 Focus widget 而需要自行管理节点，请参阅 FocusNode 了解详情。

使用 Focus 默认构造函数时，此 widget 会管理传入的 focusNode，并在 widget 更新时，将 FocusNode.onKey、FocusNode.onKeyEvent、FocusNode.skipTraversal、FocusNode.canRequestFocus 和 FocusNode.descendantsAreFocusable 的值写入该 focusNode。此操作会在 Focus widget 更新时执行。

若使用 Focus.withExternalFocusNode，则 onKey、onKeyEvent、skipTraversal、canRequestFocus 和 descendantsAreFocusable 的返回值来自外部焦点节点；更新 widget 时也不会覆盖外部节点的值。

若要将一组子树节点收集到一个独占组中，并将焦点遍历限制在组内，请使用 FocusScope。若要为子树节点指定遍历顺序，同时允许遍历离开该组，请使用 FocusTraversalGroup。

若要移动焦点，请调用 FocusNode 上的方法：通过 of 方法获取 FocusNode 后即可使用。例如，调用 Focus.of(context).nextFocus() 可将焦点移至遍历顺序中的下一个节点；调用 Focus.of(context).unfocus() 可让 widget 失去焦点。
