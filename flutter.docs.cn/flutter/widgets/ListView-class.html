ListView 类

沿线性方向排列组件的可滚动列表。

ListView 是最常用的滚动组件。它会沿滚动方向依次显示子组件。在交叉轴方向上，子组件必须填满 ListView。

如果 itemExtent 不为 null，则会强制子组件在滚动方向上具有给定的范围。

如果 prototypeItem 不为 null，则会强制子组件在滚动方向上与给定组件具有相同的范围。

指定 itemExtent 或 prototypeItem，比让子组件自行确定范围更高效，因为滚动机制可以利用已知的子组件范围减少工作量，例如滚动位置发生较大变化时。

You can't specify both itemExtent 和 prototypeItem, only one or none of them.

构建 ListView 有四种方式：

  1. 默认构造函数接收显式的子组件 List<Widget>。它适用于子组件数量较少的列表视图，因为构造 List 时，必须为列表中所有可能显示的子组件执行工作，而不只是当前可见的子组件。

  2. ListView.builder 构造函数接收一个 IndexedWidgetBuilder，按需构建子组件。它适用于子组件数量较多（或无限）的列表视图，因为 builder 只会为当前可见的子组件调用。

  3. ListView.separated 构造函数接收两个 IndexedWidgetBuilder：itemBuilder 按需构建列表项，separatorBuilder 则按需构建列表项之间的分隔组件。此构造函数适用于子组件数量固定的列表视图。

  4. ListView.custom 构造函数接收 SliverChildDelegate，借此可以自定义子组件模型的其他方面。例如，SliverChildDelegate 可以控制用于估算当前不可见子组件尺寸的算法。

若要控制滚动视图的初始滚动偏移量，请提供一个 controller，并设置其 ScrollController.initialScrollOffset 属性。

默认情况下，ListView 会根据 MediaQuery 的 padding 自动为列表可滚动区域的两端添加内边距，以避开部分遮挡。若要停用此行为，可将 padding 属性设为零。

此示例使用 ListView 的默认构造函数，它接收显式的子组件 List<Widget> 列表。此 ListView 的子组件由包含 Text 的 Container 组成。

link 
ListView(
  padding: const EdgeInsets.all(8),
  children: <Widget>[
    Container(
      height: 50,
      color: Colors.amber[600],
      child: const Center(child: Text('Entry A')),
    ),
    Container(
      height: 50,
      color: Colors.amber[500],
      child: const Center(child: Text('Entry B')),
    ),
    Container(
      height: 50,
      color: Colors.amber[100],
      child: const Center(child: Text('Entry C')),
    ),
  ],
)

此示例与前一个示例相对应，使用 ListView.builder 构造函数创建相同的列表。通过 IndexedWidgetBuilder，子组件会按需构建，数量也可以是无限的。

link 
final List<String> entries = <String>['A', 'B', 'C'];
final List<int> colorCodes = <int>[600, 500, 100];

Widget build(BuildContext context) {
  return ListView.builder(
    padding: const EdgeInsets.all(8),
    itemCount: entries.length,
    itemBuilder: (BuildContext context, int index) {
      return Container(
        height: 50,
        color: Colors.amber[colorCodes[index]],
        child: Center(child: Text('Entry ${entries[index]}')),
      );
    }
  );
}

此示例延续前面的做法，使用 ListView.separated 创建类似的列表，并使用 Divider 作为分隔组件。

link 
final List<String> entries = <String>['A', 'B', 'C'];
final List<int> colorCodes = <int>[600, 500, 100];

Widget build(BuildContext context) {
  return ListView.separated(
    padding: const EdgeInsets.all(8),
    itemCount: entries.length,
    itemBuilder: (BuildContext context, int index) {
      return Container(
        height: 50,
        color: Colors.amber[colorCodes[index]],
        child: Center(child: Text('Entry ${entries[index]}')),
      );
    },
    separatorBuilder: (BuildContext context, int index) {
      return const SizedBox(
        height: 1.0,
        width: double.infinity,
        child: ColoredBox(color: Color(0xFF000000)),
      );
    },
  );
}

子元素的生命周期

创建

布局列表时，会根据现有组件（例如使用默认构造函数时）或按需提供的组件（例如使用 ListView.builder 构造函数时），延迟创建可见子项的元素、状态和渲染对象。

销毁

子项滚出视口时，与之关联的元素子树、状态和渲染对象都会被销毁。滚回列表中的相同位置时，会连同新的元素、状态和渲染对象一起按需重新创建该子项。

减少销毁影响

为了在子元素滚入或滚出视野时保留其状态，可以采用以下选项：

  • 将驱动复杂 UI 状态的业务逻辑移出列表子项子树。例如，如果列表包含帖子，且点赞数来自缓存的网络响应，可在列表外部的数据模型中保存帖子列表和点赞数。让列表子项的 UI 子树能够根据真实数据源模型对象轻松重建。子组件子树中使用的 StatefulWidget 应只保存瞬时 UI 状态。

  • 对于需要保留的列表子项子树，可将 KeepAlive 设为其根组件。KeepAlive 组件会将子树顶部渲染对象的子项标记为需要保活。当关联的顶部渲染对象滚出视口时，列表会将该子项的渲染对象（以及与之关联的元素和状态）保存在缓存列表中，而不是销毁它们。滚回视口时，将按原样重新绘制该渲染对象（前提是此期间未将其标记为需要重新布局或绘制）。

    This only works if addAutomaticKeepAlives 和 addRepaintBoundaries are false since those parameters cause the ListView to wrap each child widget subtree with other widgets.

  • 使用 AutomaticKeepAlive 组件（当 addAutomaticKeepAlives 为 true 时默认插入）。AutomaticKeepAlive 允许后代组件控制是否实际保留子树。此行为与 KeepAlive 不同，后者会无条件保留子树。

    例如，EditableText 组件会在文本字段获得输入焦点时，通知列表中的子项元素子树保持活动状态。如果它失去焦点，且没有其他后代通过 KeepAliveNotification 请求保活，那么该子项元素子树滚出视口时就会被销毁。

    AutomaticKeepAlive 的后代通常会通过 AutomaticKeepAliveClientMixin 通知它们需要保持存活，然后实现 AutomaticKeepAliveClientMixin.wantKeepAlive getter，并调用 AutomaticKeepAliveClientMixin.updateKeepAlive。

转换为 CustomScrollView

ListView 本质上是一个 CustomScrollView，其 CustomScrollView.slivers 属性中只包含一个 SliverList。

当 ListView 无法满足需求时，例如滚动视图需要同时包含列表和网格，或列表需要与 SliverAppBar 组合时，可以轻松地将代码从 ListView 改为直接使用 CustomScrollView。

ListView 的 key、scrollDirection、reverse、controller、primary、physics 和 shrinkWrap 属性，分别直接对应 CustomScrollView 中同名的属性。

CustomScrollView.slivers 属性应为一个列表，其中包含以下任一内容：

  • a SliverList if both itemExtent 和 prototypeItem were null;
  • a SliverFixedExtentList if itemExtent was not null; or
  • a SliverPrototypeExtentList if prototypeItem was not null.

The childrenDelegate property on ListView corresponds to the SliverList.delegate （或 SliverFixedExtentList.delegate) property. The ListView constructor's children argument corresponds to the childrenDelegate being a SliverChildListDelegate with that same argument. The ListView.builder constructor's itemBuilder 和 itemCount arguments correspond to the childrenDelegate being a SliverChildBuilderDelegate with the equivalent arguments.

padding 属性相当于在 CustomScrollView.slivers 中放入 SliverPadding，并将 SliverList 作为 SliverPadding 的子组件，而不是直接放在列表中。

CustomScrollViews don't automatically avoid obstructions from MediaQuery like ListViews do. To reproduce the behavior, wrap the slivers in SliverSafeArea。

将代码改为使用 CustomScrollView 后，还可以将其他 sliver（例如 SliverGrid 或 SliverAppBar）放入 CustomScrollView.slivers 列表。

Here are two brief snippets showing a ListView and its equivalent using CustomScrollView:
link 
ListView(
  padding: const EdgeInsets.all(20.0),
  children: const <Widget>[
    Text("I'm dedicating every day to you"),
    Text('Domestic life was never quite my style'),
    Text('When you smile, you knock me out, I fall apart'),
    Text('And I thought I was so smart'),
  ],
)

link 
CustomScrollView(
  slivers: <Widget>[
    SliverPadding(
      padding: const EdgeInsets.all(20.0),
      sliver: SliverList(
        delegate: SliverChildListDelegate(
          <Widget>[
            const Text("I'm dedicating every day to you"),
            const Text('Domestic life was never quite my style'),
            const Text('When you smile, you knock me out, I fall apart'),
            const Text('And I thought I was so smart'),
          ],
        ),
      ),
    ),
  ],
)

空列表的特殊处理

常见的设计模式是为空列表显示自定义 UI。在 Flutter 中，最好的实现方式是在构建时根据条件，将 ListView 替换为显示空列表状态所需的组件：

Example of simple empty list interface:
link 
Widget build(BuildContext context) {
  return Scaffold(
    appBar: AppBar(title: const Text('Empty List Test')),
    body: itemCount > 0
      ? ListView.builder(
          itemCount: itemCount,
          itemBuilder: (BuildContext context, int index) {
            return ListTile(
              title: Text('Item ${index + 1}'),
            );
          },
        )
      : const Center(child: Text('No items')),
  );
}

ScrollView 通常会装饰 Scrollbar 和过度滚动指示器，这些行为由继承的 ScrollBehavior 管理。在 ScrollView 上方放置 ScrollConfiguration 可以修改该 ScrollView 的行为；也可以通过为 MaterialApp.scrollBehavior 或 CupertinoApp.scrollBehavior 提供 ScrollBehavior，统一管理整个应用的行为。

在会话期间保留滚动位置

滚动视图会尝试使用 PageStorage 保存滚动位置。若要停用此功能，可将 controller 的 ScrollController.keepScrollOffset 设为 false。如果启用了此功能，建议将 PageStorageKey 用作此组件的 key，以便区分不同的滚动视图。
