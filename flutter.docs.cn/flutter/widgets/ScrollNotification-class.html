ScrollNotification 类 抽象

与滚动相关的 Notification。

Scrollable 组件会向其祖先通知滚动相关变化。这些通知的生命周期如下：

  • A ScrollStartNotification, which indicates that the widget has started scrolling.
  • Zero or more ScrollUpdateNotifications, which indicate that the widget has changed its scroll position, mixed with zero or more OverscrollNotifications, which indicate that the widget has not changed its scroll position because the change would have caused its scroll position to go outside its scroll bounds.
  • Interspersed with the ScrollUpdateNotifications and OverscrollNotifications are zero or more UserScrollNotifications, which indicate that the user has changed the direction in which they are scrolling.
  • A ScrollEndNotification, which indicates that the widget has stopped scrolling.
  • A UserScrollNotification, with a UserScrollNotification.direction of ScrollDirection.idle.

通知会沿组件树向上传递，因此给定的 NotificationListener 会收到所有后代 Scrollable 组件发出的通知。若只关注最近的 Scrollable 后代发出的通知，请检查通知的 depth 属性是否为零。

NotificationListener 收到滚动通知时，监听器所在组件的构建和布局已经完成，因此再调用 State.setState 为时已晚。尝试根据滚动通知调整构建或布局，会导致布局落后一个帧，用户体验不佳。因此，滚动通知主要适用于绘制效果（绘制发生在布局之后）。使用滚动通知的绘制效果示例包括 GlowingOverscrollIndicator 和 Scrollbar。

此示例展示使用 ScrollController，或使用类型为 ScrollNotification 的 NotificationListener 来监听滚动活动的区别。切换 Radio 按钮即可切换两种方式。使用 ScrollNotification 可获取滚动活动详情及 ScrollPosition 的指标，但无法直接访问滚动位置对象。使用 ScrollController 监听时，则可以直接访问该对象。这两种通知都只会由滚动触发。
link

要使用此代码示例创建本地项目，请运行：
flutter create --sample=widgets.ScrollNotification.1 mysample

若要根据滚动位置驱动布局，可直接监听 ScrollPosition（或通过 ScrollController 间接监听）。但当指定滚动位置的 ScrollMetrics 发生变化时（例如窗口大小调整导致 Viewport 尺寸变化），这种方式不会发出通知。若要监听滚动指标变化，请使用监听 ScrollMetricsNotification 的 NotificationListener。此通知与 ScrollNotification 不同，它不关联滚动活动，而是关联可滚动区域的尺寸。
