onExit 属性

PointerExitEventListener? onExit
final

此 widget 仍处于挂载状态时，鼠标指针离开该 widget 会触发。

当指针（无论是否按下按钮）不再位于此 widget 的区域内时，会触发此回调；因该 widget 消失而导致的退出除外。具体来说，以下情况会触发此回调：

  • A pointer that is hovering this widget has moved away.
  • A pointer that is hovering this widget has been removed.
  • This widget, which is being hovered by a pointer, has moved away.

以下情况则不会触发：

  • This widget, which is being hovered by a pointer, has disappeared.

因此，MouseRegion.onExit 可能没有对应的 MouseRegion.onEnter。

This restriction aims to prevent a common misuse: if State.setState is called during MouseRegion.onExit without checking whether the widget is still mounted, an exception will occur. This is because the callback is triggered during the post-frame phase, at which point the widget has been unmounted. Since State.setState is exclusive to widgets, the restriction is specific to MouseRegion, and does not apply to its lower-level counterparts, RenderMouseRegion 和 MouseTrackerAnnotation.

有几种方法可以缓解此限制：

  • If the hover state is completely contained within a widget that unconditionally creates this MouseRegion, then this will not be a concern, since after the MouseRegion is unmounted the state is no longer used.
  • Otherwise, the outer widget very likely has access to the variable that controls whether this MouseRegion is present. If so, call onExit at the event that turns the condition from true to false.
  • In cases where the solutions above won't work, you can always override State.dispose and call onExit, or create your own widget using RenderMouseRegion.

另请参阅：

  • onEnter，当鼠标指针进入该区域时触发。
  • RenderMouseRegion 和 MouseTrackerAnnotation.onExit, which are how this callback is internally implemented, but without the restriction.
