针对给定的 widget 调用 ParentDataWidget.applyParentData，并将此元素最终负责其父数据的 RenderObject 传入该方法。

这样可以在不触发构建的情况下修改渲染对象的 RenderObject.parentData。通常不建议这样做，但在以下情形中是合理的：

  • 当前正在进行构建和布局，但相关的 ParentData 不会影响布局，而且要应用的值无法在构建和布局之前确定（例如，它取决于某个后代的布局）。

  • 当前正在进行绘制，但相关的 ParentData 不会影响布局或绘制，而且要应用的值无法在绘制之前确定（例如，它取决于合成阶段）。

上述任一情形下，下一次构建都应会使此元素配置为给定的新 widget（或数据等效的 widget）。

只有当 ParentDataWidget.debugCanApplyOutOfTurn 返回 true 时，才能以这种方式应用该 ParentDataWidget。

新 widget 必须与当前 widget 包含相同的 child。

AutomaticKeepAlive widget 就使用了这种方式。例如，在某个后代构建期间，如果它收到通知，得知必须保持其子项存活，就会在常规时机之外应用 KeepAlive widget。这是安全的，因为按定义该子项已经存活，因此本帧中不会改变父级的行为。与仅为更新 KeepAlive widget 而额外请求一帧相比，这种做法效率更高。

实现

void applyWidgetOutOfTurn(ParentDataWidget<T> newWidget) {
  assert(newWidget.debugCanApplyOutOfTurn());
  assert(newWidget.child == (widget as ParentDataWidget<T>).child);
  _applyParentData(newWidget);
}
