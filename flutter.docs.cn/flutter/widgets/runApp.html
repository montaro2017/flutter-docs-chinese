runApp function

void runApp(
  1. Widget app
)

膨胀给定的 widget，并将其附加到 view。

runApp 方法会将提供的 app widget 包装在 View widget 中，并渲染到 PlatformDispatcher.implicitView，由此为应用建立渲染树。需要自行控制内容渲染到哪个 FlutterView 的应用可以改用 runWidget。

布局期间，widget 会收到填满整个 view 的约束。如果要将 widget 对齐到 view 的一侧（例如顶部），可以使用 Align widget。也可以使用 Center widget 将其居中。

再次调用 runApp 会从 view 分离之前的根 widget，并在原位置附加给定的 widget。新旧 widget 树会进行比较，差异会应用到底层渲染树；这与 StatefulWidget 调用 State.setState 后重建时的处理方式类似。

如有必要，会使用 WidgetsFlutterBinding 初始化 binding。

应用关闭

应用关闭时不会拆除此 widget 树，因为无法预知应用何时关闭。例如，用户可能直接切断设备电源，应用可能意外崩溃，也可能被设备上的恶意软件强制终止进程。

应用应确保自身即使在快速且非计划的终止情况下也能妥善处理。

若要监听平台关闭消息（以及其他生命周期变化），可以使用 AppLifecycleListener API。

若要人为地销毁整个组件树，可考虑调用 runApp 并传入诸如 SizedBox.shrink 这样的组件。

通过平台原生方法关闭 Flutter 界面

应用可能同时包含 Flutter 界面和非 Flutter 界面。如果应用调用非 Flutter 方法移除基于 Flutter 的界面（例如通过平台原生 API 操作平台原生导航栈），框架无法判断开发者是否希望立即释放资源。Widget 树会保持挂载状态，并在界面再次显示时立即恢复渲染。

若要更早释放资源，请建立 platform channel，并在框架需要处置当前 widget 树时，通过该通道调用 runApp，传入类似 SizedBox.shrink 的 widget。

另请参阅：

  • runWidget, which bootstraps a widget tree without assuming the FlutterView into which it will be rendered.
  • WidgetsBinding.attachRootWidget, which creates the root widget for the widget hierarchy.
  • RenderObjectToWidgetAdapter.attachToRenderTree, which creates the root element for the element hierarchy.
  • WidgetsBinding.handleBeginFrame, which pumps the widget pipeline to ensure the widget, element, and render trees are all built.

/// against the previous widget tree and any differences are applied to the

void runApp(Widget app) {
  final WidgetsBinding binding = WidgetsFlutterBinding.ensureInitialized();
  _runWidget(binding.wrapWithDefaultView(app), binding, 'runApp');
}
