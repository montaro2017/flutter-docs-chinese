void dispose()
重写

当此对象被永久移出树时调用。

当此 State 对象今后不再构建时，框架会调用此方法。框架调用 dispose 后，此 State 对象会被视为已卸载，且 mounted 属性为 false。此时调用 setState 会导致错误。生命周期到此结束：已释放的 State 对象无法重新挂载。

子类应重写此方法，以释放此对象保留的资源（例如停止所有正在运行的动画）。

如果 State 的 build 方法依赖某个自身状态也可能变化的对象（例如 ChangeNotifier 或 Stream），或依赖其他可订阅并接收通知的对象，请务必在 initState、didUpdateWidget 和 dispose 中正确订阅和取消订阅：

    在 initState 中订阅该对象。 在 didUpdateWidget 中，如果更新后的 widget 配置需要替换该对象，则取消订阅旧对象并订阅新对象。 在 dispose 中取消订阅该对象。

此方法的实现应以调用继承的方法结束，例如 super.dispose()。

注意事项

在开发者可能预期会调用此方法的某些时机，例如应用关闭或通过平台原生方法关闭界面时，实际上并不会调用它。

应用关闭

无法预测应用何时关闭。例如，用户的电池可能起火，用户可能把设备掉进游泳池，或者操作系统可能因内存压力而单方面终止应用进程。

即使应用突然、非计划地终止，应用也有责任确保自身行为良好。

若要人为触发整个 widget 树的释放，可以考虑使用 runApp 并传入诸如 SizedBox.shrink 这样的组件。

若要监听平台关闭消息（以及其他生命周期变化），可以使用 AppLifecycleListener API。

通过平台原生方法关闭 Flutter 界面

一个应用可能同时包含 Flutter 界面和非 Flutter 界面。如果应用调用非 Flutter 方法来移除基于 Flutter 的界面（例如调用平台原生 API 操作平台原生导航栈），框架并不知道开发者是否打算立即释放资源。widget 树仍会保持挂载，并在界面再次显示时随时可以渲染。

有关如何更积极地释放资源，请参阅用于启动应用的方法（例如 runApp 或 runWidget）。

另请参阅：

  • deactivate, which is called prior to dispose.

实现

@protected
@override
void dispose() {
  _internalScrollController?.dispose();
  _currentAutofillScope?.unregister(autofillId);
  widget.controller.removeListener(_didChangeTextEditingValue);
  _floatingCursorResetController?.dispose();
  _floatingCursorResetController = null;
  _closeInputConnectionIfNeeded();
  assert(!_hasInputConnection);
  _cursorTimer?.cancel();
  _cursorTimer = null;
  _backingCursorBlinkOpacityController?.dispose();
  _backingCursorBlinkOpacityController = null;
  _selectionOverlay?.dispose();
  _selectionOverlay = null;
  widget.focusNode.removeListener(_handleFocusChanged);
  WidgetsBinding.instance.removeObserver(this);
  _liveTextInputStatus?.removeListener(_onChangedLiveTextInputStatus);
  _liveTextInputStatus?.dispose();
  clipboardStatus.removeListener(_onChangedClipboardStatus);
  clipboardStatus.dispose();
  _cursorVisibilityNotifier.dispose();
  _appLifecycleListener.dispose();
  FocusManager.instance.removeListener(_unflagInternalFocus);
  FocusManager.instance.removeListener(_resetJustResumed);
  _disposeScrollNotificationObserver();
  super.dispose();
  assert(_batchEditDepth <= 0, 'unfinished batch edits: $_batchEditDepth');
}
