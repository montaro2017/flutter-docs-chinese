重写

描述此 widget 所表示的用户界面部分。

框架会在多种不同情况下调用此方法。例如：

  • 调用 initState 后。
  • 调用 didUpdateWidget 后。
  • 收到对 setState 的调用后。
  • 此 State 对象的依赖项发生变化后（例如，上一次 build 中引用的 InheritedWidget 发生变化）。
  • 调用 deactivate 后，再将 State 对象重新插入树中的其他位置后。

此方法可能每一帧都会被调用，除构建 widget 外不应产生任何副作用。

框架会将此 widget 下方的子树替换为此方法返回的 widget。根据返回的 widget 是否能够更新现有子树的根节点（由调用 Widget.canUpdate 判定），框架会更新现有子树，或移除它并重新创建子树。

通常，实现会返回一组新创建的 widget，并根据此 widget 的构造参数、给定的 BuildContext 以及此 State 对象的内部状态进行配置。

给定的 BuildContext 包含此 widget 在树中构建位置的信息。例如，context 会提供该位置上的继承型 widget 集合。BuildContext 参数始终与此 State 对象的 context 属性相同，并且在此对象的整个生命周期内保持不变。此处重复提供 BuildContext 参数，是为了使此方法与 WidgetBuilder 的签名一致。

设计讨论

为什么 build 方法位于 State 上，而不是 StatefulWidget 上？

将 Widget build(BuildContext context) 方法放在 State 上，而不是将 Widget build(BuildContext context, State state) 方法放在 StatefulWidget 上，可以让开发者在继承 StatefulWidget 时拥有更大的灵活性。

例如，AnimatedWidget 是 StatefulWidget 的子类，它为子类引入了一个抽象的 Widget build(BuildContext context) 方法供其实现。如果 StatefulWidget 已经有一个 build 方法，该方法接收 State 参数，那么 AnimatedWidget 就不得不向子类提供自己的 State 对象，尽管其 State 对象只是 AnimatedWidget 的内部实现细节。

从概念上说，StatelessWidget 也可以类似地实现为 StatefulWidget 的子类。如果 build 方法位于 State 上，而不是 StatefulWidget 上，这种实现方式就不再可行。

将 build 函数放在 State 上而非 StatefulWidget 上，还有助于避免一类与闭包隐式捕获 this 有关的错误。如果在 StatefulWidget 的 build 函数中定义闭包，该闭包会隐式捕获 this（即当前 widget 实例），并能访问此实例不可变的字段：

// (this is not valid Flutter code)
class MyButton extends StatefulWidgetX {
  MyButton({super.key, required this.color});

  final Color color;

  @override
  Widget build(BuildContext context, State state) {
    return SpecialWidget(
      handler: () { print('color: $color'); },
    );
  }
}

例如，假设父级以蓝色 color 构建 MyButton，那么打印函数中的 $color 会如预期一样指向蓝色。之后，假设父级以绿色重新构建 MyButton。第一次构建时创建的闭包仍会隐式引用原来的 widget，因此 $color 仍会打印蓝色，尽管 widget 已更新为绿色；如果该闭包的生命周期超过了原 widget，它打印的信息就会过时。

相反，如果 build 函数位于 State 对象上，那么在 build 期间创建的闭包会隐式捕获 State 实例，而不是 widget 实例：

class MyButton extends StatefulWidget {
  const MyButton({super.key, this.color = Colors.teal});

  final Color color;
  // ...
}

class MyButtonState extends State<MyButton> {
  // ...
  @override
  Widget build(BuildContext context) {
    return SpecialWidget(
      handler: () { print('color: ${widget.color}'); },
    );
  }
}

现在，当父级以绿色重新构建 MyButton 时，第一次构建时创建的闭包仍会引用在重建过程中保持不变的 State 对象；但框架已将该 State 对象的 widget 属性更新为新的 MyButton 实例，因此 ${widget.color} 会如预期一样打印绿色。

另请参阅：

  • StatefulWidget, which contains the discussion on performance considerations.

@override
Widget build(BuildContext context) {
  assert(
    axisDirectionToAxis(widget.verticalDetails.direction) == Axis.vertical,
    'TwoDimensionalScrollable.verticalDetails are not Axis.vertical.',
  );
  assert(
    axisDirectionToAxis(widget.horizontalDetails.direction) == Axis.horizontal,
    'TwoDimensionalScrollable.horizontalDetails are not Axis.horizontal.',
  );

  final Widget result = RestorationScope(
    restorationId: widget.restorationId,
    child: _VerticalOuterDimension(
      key: _verticalOuterScrollableKey,
      // For gesture forwarding
      horizontalKey: _horizontalInnerScrollableKey,
      axisDirection: widget.verticalDetails.direction,
      controller: widget.verticalDetails.controller ?? _verticalFallbackController!,
      physics: widget.verticalDetails.physics,
      clipBehavior:
          widget.verticalDetails.clipBehavior ??
          widget.verticalDetails.decorationClipBehavior ??
          Clip.hardEdge,
      incrementCalculator: widget.incrementCalculator,
      excludeFromSemantics: widget.excludeFromSemantics,
      restorationId: 'OuterVerticalTwoDimensionalScrollable',
      dragStartBehavior: widget.dragStartBehavior,
      diagonalDragBehavior: widget.diagonalDragBehavior,
      hitTestBehavior: widget.hitTestBehavior,
      viewportBuilder: (BuildContext context, ViewportOffset verticalOffset) {
        return _HorizontalInnerDimension(
          key: _horizontalInnerScrollableKey,
          verticalOuterKey: _verticalOuterScrollableKey,
          axisDirection: widget.horizontalDetails.direction,
          controller: widget.horizontalDetails.controller ?? _horizontalFallbackController!,
          physics: widget.horizontalDetails.physics,
          clipBehavior:
              widget.horizontalDetails.clipBehavior ??
              widget.horizontalDetails.decorationClipBehavior ??
              Clip.hardEdge,
          incrementCalculator: widget.incrementCalculator,
          excludeFromSemantics: widget.excludeFromSemantics,
          restorationId: 'InnerHorizontalTwoDimensionalScrollable',
          dragStartBehavior: widget.dragStartBehavior,
          diagonalDragBehavior: widget.diagonalDragBehavior,
          hitTestBehavior: widget.hitTestBehavior,
          viewportBuilder: (BuildContext context, ViewportOffset horizontalOffset) {
            return widget.viewportBuilder(context, verticalOffset, horizontalOffset);
          },
        );
      },
    ),
  );

  // TODO(Piinks): Build scrollbars for 2 dimensions instead of 1,
  //  https://github.com/flutter/flutter/issues/122348

  return _TwoDimensionalScrollableScope(twoDimensionalScrollable: this, child: result);
}
