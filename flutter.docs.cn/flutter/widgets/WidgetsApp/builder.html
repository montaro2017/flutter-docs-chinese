builder 属性

TransitionBuilder? builder
final

用于在 Navigator 上方插入组件的构建器；使用 WidgetsApp.router 构造函数时，则在 Router 上方、WidgetsApp 创建的其他组件下方插入组件。也可完全替换 Navigator/Router。

例如，通过传入此方法的 BuildContext，可以访问 Directionality、Localizations、DefaultTextStyle、MediaQuery 等。也可覆盖它们，使更改影响 Navigator 或 Router 中的所有路由。

此功能很少需要，但可用于希望覆盖这些默认设置的应用，例如强制英文应用采用从右到左的布局，或覆盖 MediaQuery 的尺寸信息（例如为 OEM 代码中的插件显示的广告预留空隙）。

如果要根据 Localizations 特别设置 title，请考虑改用 onGenerateTitle。

builder 回调会收到两个参数：BuildContext（即 context）以及 Navigator 或 Router Widget（即 child）。

如果没有通过 home、routes、onGenerateRoute 或 onUnknownRoute 为常规 WidgetsApp 构造函数提供路由，则 child 为 null，builder 需要负责提供应用的路由机制。

如果通过上述一个或多个属性为常规 WidgetsApp 构造函数提供了路由，或者使用了 WidgetsApp.router 构造函数，则 child 不为 null，返回值应在 Widget 子树中包含 child。否则，应用将没有 Navigator 或 Router，并且路由相关属性（即 navigatorKey、home、routes、onGenerateRoute、onUnknownRoute、initialRoute、navigatorObservers、routeInformationProvider、backButtonDispatcher、routerDelegate 和 routeInformationParser）都会被忽略。

如果 builder 为 null，效果相当于指定了一个直接返回 child 的 builder。若其为 null，则必须使用上文列出的其他属性之一提供路由。

必须提供一个 Navigator：可以由 builder 为 null 时隐式提供，也可以由 builder 在返回内容中包含 child，或由 builder 显式提供自己的 Navigator，也可以由 routerDelegate 构建。否则，Hero、Navigator.push 和 Navigator.pop 等组件与 API 将无法工作。
