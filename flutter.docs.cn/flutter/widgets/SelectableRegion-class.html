SelectableRegion 类

用于创建用户选区区域的 widget。

Flutter widgets are not selectable by default. Wrapping a widget subtree with a SelectableRegion widget enables selection for widgets in the subtree that participate in selection. For example, Text widgets automatically look for selectable regions to enable selection, while widgets such as RichText must be configured with a SelectionRegistrar 和 RichText.selectionColor. The wrapped subtree can be selected by users using mouse or touch gestures, e.g. users can select widgets by holding the mouse left-click and dragging across widgets, or they can use long press gestures to select words on touch devices.

SelectableRegion widget 需要配置，尤其必须提供特定的 selectionControls。

SelectionArea widget（来自 material 库）会根据平台配置 SelectableRegion（例如在 Android 上使用 Material 工具栏，在 iOS 上使用 Cupertino 工具栏）。因此，相较于直接使用 SelectableRegion，使用该 widget 可能更简单。

选区系统概览

SelectableRegion 下的每个 Selectable 都可以被选中。它们会组成一个选区树来处理选择操作。

SelectableRegion 是 SelectionContainer 的封装。它会监听用户手势，并将相应的 SelectionEvent 发送给它创建的 SelectionContainer。

SelectionContainer 是一个单独的 Selectable，代表其子树中的子级 Selectable 处理 SelectionEvent。它会使用自己的 SelectionContainer.delegate 创建 SelectionRegistrarScope，以收集子级 Selectable；并将从父级 SelectionRegistrar 收到的 SelectionEvent 发送给相应的子级 Selectable。这样，它会向父级 SelectionRegistrar 抽象出一个接口，使父级看起来像是在与单个 Selectable 交互。

The SelectionContainer created by SelectableRegion is the root node of a selection tree. Each non-leaf node in the tree is a SelectionContainer, and the leaf node is a leaf widget whose render object implements Selectable. They are connected through SelectionRegistrarScopes created by SelectionContainer。

SelectionContainer 和叶级 Selectable 若要参与选区，都需要向从 SelectionContainer.maybeOf 获取的 SelectionRegistrar 注册。与 SelectionContainer.maybeOf 一起使用的 BuildContext 必须位于 widget 树中提供该注册器的 SelectionContainer、SelectableRegion 或 SelectionArea 下方。

使 widget 可选中

一些叶级 widget（例如 Text）会自动接入所有选区逻辑，只要位于 SelectableRegion 下方，就可以被选中。

要创建自定义的可选中 widget，其渲染对象需要混入 Selectable，并实现处理 SelectionEvent 所需的 API，同时绘制适当的选区高亮。

渲染对象还需要向 SelectionRegistrar 注册。在大多数情况下，可以使用 SelectionRegistrant 自动向通过 SelectionContainer.maybeOf 返回的注册器注册，如下例所示。

复杂布局

默认情况下，选区顺序采用屏幕上的排列顺序。如果一组 Selectable 需要使用不同的选择顺序，可考虑用 SelectionContainer 包裹它们，以自定义选区行为。

若要创建与父级选区区域分离的选区系统，可用另一个 SelectableRegion 包裹子树的一部分。子选区区域的选区不能超出其子树范围，父选区区域的选区也不能延伸到子选区区域内部。

选区状态

SelectableRegion 的 SelectableRegionSelectionStatus 用于指示 SelectableRegion 是否正在更改选区，或已完成选区。例如，鼠标按下并拖动期间，SelectableRegionSelectionStatus 会设为 SelectableRegionSelectionStatus.changing；松开鼠标后，状态会设为 SelectableRegionSelectionStatus.finalized。

SelectableRegion 的选区状态默认值为 SelectableRegionSelectionStatus.finalized。

要访问父级 SelectableRegion 的 SelectableRegionSelectionStatus，请使用 SelectableRegionSelectionStatusScope.maybeOf，并从 ValueListenable 获取其值。

也可以通过向 SelectableRegionSelectionStatusScope.maybeOf 返回的 ValueListenable 添加 ValueListenable.addListener 监听器，监听 SelectableRegionSelectionStatus 的变化。在有状态 widget 中，通常在 State.didChangeDependencies 中添加监听器；不再需要时，通常通过有状态 widget 的 State.dispose 方法使用 ValueListenable.removeListener 移除监听器。

测试

在测试中，可以通过模拟拖动事件（例如使用 WidgetTester.dragFrom）来选择区域；也可以向区域内带有 GlobalKey 的 widget 发送 intent，例如：

Actions.invoke(key.currentContext!, const SelectAllTextIntent(SelectionChangedCause.keyboard));

  • SelectableText, which enables selection on a single run of text.
  • SelectionHandler, which contains APIs to handle selection events from the SelectableRegion.
  • Selectable, which provides API to participate in the selection system.
  • SelectionRegistrar, which Selectable needs to subscribe to receive selection events.
  • SelectionContainer, which collects selectable widgets in the subtree and provides api to dispatch selection event to the collected widget.
  • SelectionListener, which enables accessing the SelectionDetails of the selectable subtree it wraps.
