RestorationMixin<S extends StatefulWidget> mixin

管理 State 对象的状态恢复数据；该对象属于 StatefulWidget。

状态恢复数据可以序列化保存，并在之后用于将 State 对象中的有状态成员恢复为生成数据时的值。

此 mixin 使用 RestorableProperty 组织 State 对象的状态恢复数据。State 对象希望在状态恢复时恢复的所有信息，都必须保存在 RestorableProperty 子类中。例如，计数器应用要恢复计数值时，应将其保存在 RestorableInt 类型的成员变量中，而不是普通的 int 类型成员变量中。

此 mixin 会确保将 RestorableProperty 的当前值序列化为状态恢复数据的一部分。State 负责确保属性中保存的数据始终是最新的。使用之前生成的状态恢复数据恢复组件时，RestorableProperty 的值会自动恢复为序列化数据时的值。

使用此 mixin 的 State 通常会实例化 RestorableProperty 来初始化成员变量。使用此 mixin 的类必须重写 restoreState，并在该方法中调用 registerForRestoration 注册预先实例化的 RestorableProperty。mixin 会在 State.initState 之后首次调用此方法。注册后，属性中保存的值要么恢复为之前的值，要么在没有可用恢复数据时初始化为该属性对应的默认值。State 生命周期结束时，必须在 State.dispose 中释放所有可恢复属性。

除了在 State.initState 之后调用外，当有新的状态恢复数据提供给 mixin 时，也会再次调用 restoreState。此时，State 对象必须再次通过 registerForRestoration 重新注册所有属性，以便根据新数据将它们恢复为之前的值。依赖可恢复属性当前值的所有初始化逻辑都应放在 restoreState 中，以确保 State 对象的生命周期内属性恢复为不同值时，这些逻辑会重新执行。

此 mixin 会在内部将所有已注册属性的状态恢复数据保存在 RestorationBucket 中；它通过 RestorationScope 获取该 bucket，使用 restorationId 标识，该 ID 由 State 提供。该 ID 在外围 RestorationScope 中必须唯一。如果 State 的 restorationId（restorationId）为 null，或外围不存在 RestorationScope，则会为使用此 mixin 的 State 对象禁用状态恢复。在这种情况下，不会恢复该 State 的已注册属性值。

已注册属性所用的 RestorationBucket 可通过 bucket getter 获取。通常不需要直接操作 bucket，但 State 对象可以将该 bucket（bucket）提供给后代，以便后代获取子 bucket。为此，可在 State.build 中借助 UnmanagedRestorationScope 将 bucket 注入组件树。

如果状态恢复已关闭，bucket getter 会返回 null。如果在组件生命周期内启用或关闭状态恢复（例如 restorationId 从 null 变为非 null），该 getter 返回的值也会在 null 与非 null 之间相应变化。mixin 会调用自身的 didToggleBucket 来通知 State 对象发生了此变化。只要 State 不直接操作 bucket，就无需重写此方法。

每当 restorationId 返回值发生变化时，都必须调用 didUpdateRestorationId，除非该变化已经触发了 didUpdateWidget 调用。
