InheritedModel<T> 类 抽象

一种 InheritedWidget，旨在作为模型的基类；模型的依赖项可能只依赖整个模型中的某一部分或某个“方面”。

继承组件发生变化时，根据 InheritedWidget.updateShouldNotify，其依赖项会无条件重建。此组件与之类似，但依赖项不会无条件重建。

依赖 InheritedModel 的组件会通过一个值声明其依赖的模型“方面”。模型重新构建时，也会重建依赖项，但只有当模型中与其声明方面对应的部分发生变化时才会重建。

类型参数 T 是模型方面对象的类型。

组件通过静态方法 InheritedModel.inheritFrom 创建对 InheritedModel 的依赖。该方法的 context 参数决定模型变化时需要重建的子树。通常会从模型专属的静态 maybeOf 或 of 方法中调用 inheritFrom；许多 Flutter 框架中用于查找对象的类都遵循这一惯例。例如：

class MyModel extends InheritedModel<String> {
  const MyModel({super.key, required super.child});

  // ...
  static MyModel? maybeOf(BuildContext context, [String? aspect]) {
    return InheritedModel.inheritFrom<MyModel>(context, aspect: aspect);
  }

  // ...
  static MyModel of(BuildContext context, [String? aspect]) {
    final MyModel? result = maybeOf(context, aspect);
    assert(result != null, 'Unable to find an instance of MyModel...');
    return result!;
  }
}

调用 MyModel.of(context, 'foo') 或 MyModel.maybeOf(context, 'foo') 表示只有当 MyModel 的 foo 方面发生变化时，才应重建 context。如果 aspect 为 null，则模型支持所有方面。

继承模型重新构建时，会使用 updateShouldNotify 和 updateShouldNotifyDependent 方法来决定要重建哪些内容。如果 updateShouldNotify 返回 true，则会针对每个依赖项及其依赖的方面对象集合调用继承模型的 updateShouldNotifyDependent 方法。该 updateShouldNotifyDependent 方法必须比较方面依赖集合与模型本身的变化。例如：
link 
class ABModel extends InheritedModel<String> {
  const ABModel({
   super.key,
   this.a,
   this.b,
   required super.child,
  });

  final int? a;
  final int? b;

  @override
  bool updateShouldNotify(ABModel oldWidget) {
    return a != oldWidget.a || b != oldWidget.b;
  }

  @override
  bool updateShouldNotifyDependent(ABModel oldWidget, Set<String> dependencies) {
    return (a != oldWidget.a && dependencies.contains('a'))
      || (b != oldWidget.b && dependencies.contains('b'));
  }

  // ...
}

在前一个示例中，updateShouldNotifyDependent 检查的依赖项只是传给 dependOnInheritedWidgetOfExactType 的方面字符串。它们以 Set 表示，因为一个 Widget 可以依赖模型的多个方面。如果组件依赖模型但没有指定方面，那么模型发生变化时，该组件将无条件重建。

此示例展示如何实现 InheritedModel，根据声明的依赖有选择地重建组件。点击“Resize Logo”按钮时，只重建 Logo 组件，背景组件不受影响。
