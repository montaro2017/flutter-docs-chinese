ScrollPosition 类 抽象

决定滚动视图中可见的内容部分。

pixels 值决定滚动视图使用的滚动偏移量，从而选择要显示的内容部分。用户滚动视口时，此值会变化，显示的内容也随之改变。

The ScrollPosition applies physics to scrolling, and stores the minScrollExtent 和 maxScrollExtent.

滚动由当前的 activity 控制，并通过 beginActivity 设置。ScrollPosition 本身不会启动任何活动。具体子类（例如 ScrollPositionWithSingleContext）通常会响应用户输入或 ScrollController 的指令启动活动。

此对象是一个 Listenable；当 pixels 变化时，它会通知监听器。

获取滚动信息

获取滚动和可滚动 widget 的信息有多种方式，但它们提供的信息各不相同，涉及滚动活动、位置以及 Viewport 的尺寸。

ScrollController 是一个 Listenable。每当任何已附加的 ScrollPosition 通知其监听器时（例如发生滚动时），它也会通知自己的监听器。这与使用 NotificationListener 监听 ScrollNotification 类型的通知非常相似；区别在于，通知监听器还会提供滚动活动的信息。通知监听器还可以监听特定的 ScrollNotification 子类，例如 UserScrollNotification。

This sample shows the difference between using a ScrollController or a NotificationListener of type ScrollNotification to listen to scrolling activities. Toggling the Radio button switches between the two. Using a ScrollNotification will provide details about the scrolling activity, along with the metrics of the ScrollPosition, but not the scroll position object itself. By listening with a ScrollController, the position object is directly accessible. Both of these types of notifications are only triggered by scrolling.

ScrollController does not notify its listeners when the list of ScrollPositions attached to the scroll controller changes. To listen to the attaching and detaching of scroll positions to the controller, use the ScrollController.onAttach 和 ScrollController.onDetach methods. This is also useful for adding a listener to the ScrollPosition.isScrollingNotifier when the position is created during the build method of the Scrollable.

滚动位置刚附加时，ScrollMetrics（例如 ScrollMetrics.maxScrollExtent）尚不可用。只有当 Scrollable 完成内容布局，并计算出内容的完整范围等信息后，这些值才会确定。可以通过 ScrollPosition.hasContentDimensions 判断这些度量是否已可用，也可以使用下文将介绍的 ScrollMetricsNotification。

从不同的上下文访问

如果需要从滚动 widget 内部的上下文获取滚动信息，请使用 Scrollable.of 获取 ScrollableState 及其 ScrollableState.position。它与附加到 ScrollController 的 ScrollPosition 是同一个对象。

如果需要从非滚动 widget 祖先的上下文获取滚动信息，请使用 ScrollNotificationObserver。AppBar 就使用它来实现内容滚动到其下方时的效果。由于 Scaffold.appBar 和 Scaffold.body 属于不同子树，滚动通知不会冒泡到 app bar。可以使用 ScrollNotificationObserverState.addListener，监听当前上下文之外发生的滚动通知。

尺寸变化

最后，监听 ScrollController 或 ScrollPosition 时，不会在给定滚动位置的 ScrollMetrics 发生变化时收到通知；例如窗口大小变化会改变 Viewport 的尺寸以及前面提到的可滚动范围。若要监听滚动度量的变化，请使用类型为 ScrollMetricsNotification 的 NotificationListener。此类通知与 ScrollNotification 不同：它不表示滚动活动，而是表示可滚动区域的尺寸变化，例如窗口大小变化。

继承 ScrollPosition

随着时间推移，一个 Scrollable 可能会拥有多个不同的 ScrollPosition 对象。例如，如果 Scrollable.physics 的类型发生变化，Scrollable 会使用新的 physics 创建新的 ScrollPosition。要将状态从旧实例传递到新实例，子类需要实现 absorb。详情请参阅 absorb。

每当 userScrollDirection 的值发生变化时，子类还需要调用 didUpdateScrollDirection。

另请参阅：

  • Scrollable, which uses a ScrollPosition to determine which portion of its content to display.
  • ScrollController, which can be used with ListView, GridView and other scrollable widgets to control a ScrollPosition.
  • ScrollPositionWithSingleContext, which is the most commonly used concrete subclass of ScrollPosition.
  • ScrollNotification 和 NotificationListener, which can be used to watch the scroll position without using a ScrollController.
