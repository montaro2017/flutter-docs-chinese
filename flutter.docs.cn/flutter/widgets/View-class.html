View 类

为提供的 FlutterView 引导并构建渲染树。

The content rendered into that view is determined by the provided child. Descendants within the same LookupBoundary can look up the view they are rendered into via View.of 和 View.maybeOf.

提供的 child 会被包裹在由给定 view 构造的 MediaQuery、一个 FocusScope 和一个 RawView widget 中。

大多数情况下，使用 MediaQuery.of 或其相关的“...Of”方法来获取 FlutterView 提供的信息会更合适。例如，使用 MediaQuery.sizeOf 会提供设备的逻辑尺寸（MediaQueryData.size），而不是物理尺寸（FlutterView.physicalSize）。类似地，虽然 FlutterView.padding 传达了操作系统提供的信息，但通过 MediaQuery.paddingOf 获取的 MediaQueryData.padding 属性会进一步根据 widget 的上下文调整这些信息；例如，Scaffold widget 会为其各个子项调整相应的值。

每个 FlutterView 在 widget 树中最多只能关联一个 View 或 RawView widget。同一时刻，同一棵 widget 树中不得存在两个或更多使用相同 FlutterView 配置的 View 或 RawView widget。此限制通过 GlobalObjectKey 强制实施，该键根据提供给此 widget 的 view 推导其标识。

由于 View widget 使用内嵌的 RawView 引导独立的渲染树，因此它及其所有后代都不会向现有渲染树插入 RenderObject。因此，View widget 只能用于不需要参与周围渲染树构建的 widget 树区域。换言之，它只能用于 widget 树中的非渲染区域（关于渲染区域和非渲染区域的定义，请参阅 WidgetsBinding）。

实际使用中，此 widget 通常位于 widget 树根部，不嵌套在其他 View 或 RawView widget 中；也可以作为 ViewCollection widget 的子项，或放在 ViewAnchor widget 的 ViewAnchor.view 插槽中。它不必是直接子项，因为这些 widget 之间允许存在其他非 RenderObjectWidget（例如 InheritedWidget、Builder，或只生成非 RenderObjectWidget 的 StatefulWidget/StatelessWidget），然后再到 View widget。

另请参阅：

  • RawView, the workhorse that View uses to create the render tree, but without the MediaQuery 和 FocusScope that View adds.
  • Element.debugExpectsRenderObjectForSlot, which defines whether a View widget is allowed in a given child slot.
