重写

从给定的 ScrollPosition 接管当前仍适用的状态。

构造函数收到 oldPosition 时会调用此方法。other 参数的 runtimeType 可能与此对象不同。

此方法可能会破坏另一个 ScrollPosition 的状态。调用此对象构造函数的一方必须在调用后立即处置另一个对象（在同一次调用栈中，并且在微任务解析之前）。

如果旧的 ScrollPosition 对象与此对象的 runtimeType 不同，则会对新接管的 ScrollActivity 调用 ScrollActivity.resetActivity 方法。

重写

重写此方法时，必须先设置与度量或活动相关的状态，再调用 super.absorb，因为此方法可能会重启活动，而滚动活动重启时通常会使用这些度量值。

如果无法接管另一个 ScrollPosition 的活动，重写此方法时可能需要启动一个 IdleScrollActivity。

如果被接管的滚动活动将自身用作 ScrollActivityDelegate，重写此方法时可能还需要更新这些活动的委托对象。

实现

@override
void absorb(ScrollPosition other) {
  super.absorb(other);
  if (other is! ScrollPositionWithSingleContext) {
    goIdle();
    return;
  }
  activity!.updateDelegate(this);
  _userScrollDirection = other._userScrollDirection;
  assert(_currentDrag == null);
  if (other._currentDrag != null) {
    _currentDrag = other._currentDrag;
    _currentDrag!.updateDelegate(this);
    other._currentDrag = null;
  }
}
