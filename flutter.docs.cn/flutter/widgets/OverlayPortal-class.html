OverlayPortal 类

一种在 Overlay 上绘制 overlay 子项的 widget。

overlay 子项最初处于隐藏状态，直到对关联的 controller 调用 OverlayPortalController.show。OverlayPortal 使用 overlayChildBuilder 构建 overlay 子项，并将其绘制到指定的 Overlay 上，效果如同通过 OverlayEntry 插入一样；同时，该子项可以依赖与此 widget 相同的一组 InheritedWidget（例如 Theme）。

显示 overlay 子项时，widget 树中必须存在 Overlay 祖先。overlay 子项由该 Overlay 祖先绘制，而非由此 widget 绘制。这样一来，overlay 子项就可以悬浮在其他 widget 上方，不受其在 widget 树中位置的影响。

调用 OverlayPortalController.hide 后，使用 overlayChildBuilder 构建的 widget 会在 widget 树下次重建时被移除。因此，overlay 子树中的有状态后代可能会丢失状态。

此示例使用 OverlayPortal 构建提示框，用户点击 child widget 后，提示框便会显示。OverlayPortal 上方有一个 DefaultTextStyle，用于控制 child widget 以及 overlayChildBuilder 所构建 widget 的 TextStyle；如果将提示框作为 OverlayEntry 添加，则无法实现这一点。

绘制顺序

在 Overlay 中，overlay 子项会绘制在与其 OverlayPortal 关联的 OverlayEntry 之后（即 widget 树中离 OverlayPortal 最近的 OverlayEntry，通常代表包围它的 Route），并绘制在下一个 OverlayEntry 之前。

当一个 OverlayEntry 关联多个 OverlayPortal 时，它们的 overlay 子项按照调用 OverlayPortalController.show 的先后顺序绘制。最后调用 show 的 OverlayPortal 会将其 overlay 子项绘制在前景。

语义信息

overlay 子项生成的语义子树会被视为附属于 OverlayPortal，而不是目标 Overlay。即使 overlay 子项仍然可见，OverlayPortal 的语义子树也可能因不可见而从语义树中移除（例如，OverlayPortal 在 ListView 中完全不可见，但由 KeepAlive widget 保持存活）。发生这种情况时，即使 overlay 子项仍显示在屏幕上，它生成的语义子树也会一并移除。

OverlayPortal 与 OverlayEntry 的区别

OverlayEntry 与 OverlayPortal 的主要区别在于：OverlayEntry 会将 widget 子树构建为目标 Overlay 的子项，而 OverlayPortal 则使用 OverlayPortal.overlayChildBuilder 将子 widget 构建为自身的子项。这样，OverlayPortal 的 overlay 子项可以依赖与 OverlayPortal 相同的一组 InheritedWidget；同时还能保证 overlay 子项的生命周期不会超出其 OverlayPortal。

另一方面，OverlayPortal 的实现更复杂。例如，在全局键重新挂接期间，它比常规 widget 需要执行更多工作。如果要显示在 Overlay 上的内容并不需要成为 OverlayPortal 子树的一部分，请考虑改用 OverlayEntry。

另请参阅：

  • OverlayEntry, an alternative API for inserting widgets into an Overlay.
  • Positioned, which can be used to size and position the overlay child in relation to the target Overlay's boundaries.
  • CompositedTransformFollower, which can be used to position the overlay child in relation to the linked CompositedTransformTarget widget.
