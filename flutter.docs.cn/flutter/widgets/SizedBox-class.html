SizedBox 类

具有指定尺寸的盒子。

如果提供了子项，此 widget 会在父项约束允许的范围内，尽量让子项的尺寸接近指定的 height 和 width。如果 width 或 height 为 null，此 widget 会尝试让自身在对应维度上的尺寸与子项一致。如果子项的尺寸取决于父项的尺寸，则必须同时指定 height 和 width。

如果没有子项，SizedBox 会在父项约束允许的范围内，尽量采用指定的宽度和高度。如果 height 或 width 为 null 或未指定，则会按零处理。

SizedBox.expand 构造函数可用于创建一个会自行调整尺寸以适应父项的 SizedBox。这等同于将 width 和 height 都设为 double.infinity。

此代码片段展示了一个 Card，其中包含若干 Text 子项；在父级约束允许的情况下，子项尺寸会设为 200×300：
link 
const SizedBox(
  width: 200.0,
  height: 300.0,
  child: Card(child: Text('Hello World!')),
)

问题排查

为什么我的 SizedBox 会被忽略？

在 Flutter 的布局协议中，约束向下传递，尺寸向上传递。widget 必须遵守父项传入的约束，因此 SizedBox 的尺寸值可能会被忽略：

此代码片段将 ColoredBox 的尺寸设为 200×200。内部 100×100 的尺寸会被忽略，因为它与父级要求精确为 200×200 的约束不兼容：
link 
const SizedBox(
  width: 200.0,
  height: 200.0,
  child: SizedBox( // Ignored!
    width: 100.0,
    height: 100.0,
    child: ColoredBox(color: Colors.green),
  ),
)

可以将子项 SizedBox 包裹在允许其尺寸不超过父项尺寸的 widget 中来解决此问题，例如 Center 或 Align。

另请参阅：

  • ConstrainedBox 是此类更通用的版本，可接受任意 BoxConstraints，无需明确指定宽度和高度。
  • UnconstrainedBox，一种会尝试让子组件不受约束地绘制的容器。
  • FractionallySizedBox 是一种会将子项尺寸设为可用空间某一比例的 widget。
  • AspectRatio 会尝试在父项约束范围内调整自身尺寸，同时使子项符合指定的宽高比。
  • FittedBox 会根据给定的 BoxFit 规则调整并定位子项，使其适应父项。
  • The 布局组件目录.
  • 理解约束，一篇深入介绍 Flutter 布局的文章。
