重写

描述此 widget 所表示的用户界面部分。

框架会在多种情况下调用此方法，例如：

  • After calling initState.
  • After calling didUpdateWidget.
  • After receiving a call to setState.
  • After a dependency of this State object changes (e.g., an InheritedWidget referenced by the previous build changes).
  • After calling deactivate and then reinserting the State object into the tree at another location.

此方法可能在每一帧中调用，因此除了构建组件外不应产生任何副作用。

框架会将此 widget 下方的子树替换为此方法返回的 widget。根据返回的 widget 是否能够更新现有子树的根节点（由调用 Widget.canUpdate 判定），框架会更新现有子树，或移除它并重新创建子树。

通常，实现会返回一组新建的组件，并依据当前组件的构造函数、给定的 BuildContext 和此 State 对象的内部状态提供的信息进行配置。

给定的 BuildContext 包含此组件在树中构建位置的信息。例如，context 会提供该位置上的继承组件集合。BuildContext 参数始终与此 State 对象的 context 属性相同，并在该对象的整个生命周期内保持不变。这里重复提供 BuildContext 参数，是为了使此方法与 WidgetBuilder 的签名一致。

设计讨论

为什么将 build 方法定义在 State 上，而不是 StatefulWidget 上？

将 Widget build(BuildContext context) 方法放在 State 上，而不是将 Widget build(BuildContext context, State state) 方法放在 StatefulWidget 上，可以让开发者在继承 StatefulWidget 时拥有更高的灵活性。

例如，AnimatedWidget 是 StatefulWidget 的子类，它引入了抽象的 Widget build(BuildContext context) 方法供其子类实现。如果 StatefulWidget 已经有一个接收 build 参数的 State 方法，那么即使 State 对象只是 AnimatedWidget 的内部实现细节，AnimatedWidget 也不得不向子类提供该 State 对象。

从概念上说，StatelessWidget 也可以用类似方式实现为 StatefulWidget 的子类。如果将 build 方法放在 StatefulWidget 上而不是 State 上，就无法再这样实现。

将 build 函数放在 State 上而不是 StatefulWidget 上，也有助于避免闭包隐式捕获 this 所导致的一类错误。如果在 StatefulWidget 上定义的 build 函数中创建闭包，该闭包会隐式捕获 this（即当前组件实例），并能访问该实例不可变的字段：

// (this is not valid Flutter code)
class MyButton extends StatefulWidgetX {
  MyButton({super.key, required this.color});

  final Color color;

  @override
  Widget build(BuildContext context, State state) {
    return SpecialWidget(
      handler: () { print('color: $color'); },
    );
  }
}

例如，假设父组件使用 MyButton 并将 color 设为蓝色，那么打印函数中的 $color 会如预期地引用蓝色。之后父组件用绿色重新构建 MyButton 时，首次构建创建的闭包仍隐式引用原来的组件，因此 $color 仍会打印蓝色，尽管组件颜色已更新为绿色；若该闭包在组件销毁后仍被调用，它会打印过时的信息。

相较之下，将 build 函数放在 State 对象上时，在 build 期间创建的闭包会隐式捕获 State 实例，而不是组件实例：

class MyButton extends StatefulWidget {
  const MyButton({super.key, this.color = Colors.teal});

  final Color color;
  // ...
}

class MyButtonState extends State<MyButton> {
  // ...
  @override
  Widget build(BuildContext context) {
    return SpecialWidget(
      handler: () { print('color: ${widget.color}'); },
    );
  }
}

父组件用绿色重新构建 MyButton 时，首次构建创建的闭包仍引用跨重建保留的 State 对象；框架已更新该 State 对象的 widget 属性，使其指向新的 MyButton 实例，因此 ${widget.color} 会按预期打印绿色。

@override
Widget build(BuildContext context) {
  assert(debugCheckHasOverlay(context));
  Widget result = SelectableRegionSelectionStatusScope._(
    selectionStatusNotifier: _selectionStatusNotifier,
    child: SelectionContainer(registrar: this, delegate: _selectionDelegate, child: widget.child),
  );
  if (_webContextMenuEnabled) {
    result = PlatformSelectableRegionContextMenu(child: result);
  }
  return TapRegion(
    groupId: SelectableRegion,
    onTapOutside: (PointerDownEvent event) {
      // To match the native web behavior, this selectable region is
      // unfocused when tapping outside of it causing the selection to
      // be dismissed.
      //
      // Tapping outside the selectable region does not unfocus
      // the region on non-web platforms.
      if (kIsWeb) {
        _focusNode.unfocus();
      }
    },
    child: CompositedTransformTarget(
      link: _toolbarLayerLink,
      child: RawGestureDetector(
        gestures: _gestureRecognizers,
        behavior: HitTestBehavior.translucent,
        excludeFromSemantics: true,
        child: Actions(
          actions: _actions,
          child: Focus.withExternalFocusNode(
            includeSemantics: false,
            focusNode: _focusNode,
            child: result,
          ),
        ),
      ),
    ),
  );
}
