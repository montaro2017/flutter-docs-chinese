rebuild 方法

void rebuild({
  1. bool force = false,
})
继承

使 widget 更新自身。在调试构建中，还会检查各种不变量。

BuildOwner 调用此方法的情形包括：BuildOwner.scheduleBuildFor 将此 element 标记为 dirty 时；element 首次构建时由 mount 调用；以及 widget 发生变化时由 update 调用。

只有 dirty 为 true 时才会重建。若要忽略 dirty 标记并强制重建，请将 force 设为 true。在 update 中强制重建很方便，因为此时 dirty 为 false。

何时发生重建

术语

Widget 表示 Element 的配置。每个 Element 都有一个 widget，通过 Element.widget 指定。严格来说，许多场合应使用“element”一词，但人们经常会说“widget”。

Element 虽然始终关联一个当前的 Widget，但随着时间推移，该 widget 可能会被其他 widget 替换。例如，支撑 ColoredBox 的 element 起初可能关联一个 ColoredBox widget，其 ColoredBox.color 为蓝色；之后则会关联一个新的 ColoredBox，其颜色为绿色。

在同一时刻，同一棵树中的多个 Element 可以关联相同的 Widget。例如，同一个绿色的 ColoredBox 可以同时用于 widget 树中的多个位置，每个位置都由不同的 Element 支撑。

将 element 标记为 dirty

Element 可以在帧与帧之间被标记为 dirty，原因包括：

  • StatefulWidget 的 State 可以通过调用 State.setState，将其 Element 标记为 dirty。

  • InheritedWidget 发生变化时，先前订阅了它的后代会被标记为 dirty。

  • 热重载期间，每个 element 都会被标记为 dirty（通过 Element.reassemble）。

重建

dirty element 会在下一帧重建。具体方式取决于 element 的类型。StatelessElement 使用其 widget 的 StatelessWidget.build 方法进行重建。StatefulElement 使用其 widget 所对应 state 的 State.build 方法进行重建。RenderObjectElement 则通过更新其 RenderObject 完成重建。

很多情况下，重建的最终结果是一个子 widget；对于 MultiChildRenderObjectElement，结果则是一个子 widget 列表。

这些子 widget 用于更新子 element 的 widget 属性。如果新 Widget 与现有 Element 具有相同的 Type 和 Key，就会认为两者相对应。（对于 MultiChildRenderObjectElement，即使 widget 顺序发生变化，也会尽力跟踪它们；参见 RenderObjectElement.updateChildren。）

如果没有可对应的旧子级，就会创建新的 Element（使用 Widget.createElement），然后递归地构建该 element。

如果之前存在子级，但本次构建没有提供对应的子级来更新它，则旧子级会被丢弃；若涉及 GlobalKey 重新挂接父子关系，也可能在 element 树的其他位置复用。

不过，最常见的情况是存在对应的旧子级。此时会让子 Element 使用新的子 Widget 更新自身。对于 StatefulElement，这会触发 State.didUpdateWidget。

不发生重建

在通知 Element 使用新的 Widget 更新自身之前，会使用 operator == 比较新旧对象。

通常，这相当于使用 identical 比较两个对象是否确实为同一个实例。如果是，而且 element 没有因其他原因被标记为 dirty，就会跳过更新，因为可以确定更新自身或其后代不会带来任何价值。

强烈建议不要为 Widget 对象重写 operator ==。虽然这样看起来可能提高性能，但对于非叶子 widget，实际会产生 O(N²) 的行为。由于比较必须包含对子 widget 的比较，如果子 widget 也实现了 operator ==，最终就会遍历完整棵 widget 树；而且每一层都会重复遍历。实际情况下，直接重建开销更低。（此外，只要应用中使用的任一 Widget 子类实现了 operator ==，编译器就无法在任何位置内联该比较，因为调用必须按虚方法处理，以防实例恰好重写了该运算符。）

避免不必要重建的更好方式，是缓存从 State.build 返回的 widget，让每一帧都复用同一批 widget，直到它们确实发生变化。可以使用多种机制实现这一点：例如，const widget 是一种自动缓存形式（使用 const 关键字构造 widget 时，之后使用相同参数再次构造会返回同一个实例）。

另一个例子是 AnimatedBuilder.child 属性。即使 AnimatedBuilder.builder 回调重新创建其他组件，它也能让子树中不参与动画的部分保持不变。

实现

@pragma('dart2js:tryInline')
@pragma('vm:prefer-inline')
@pragma('wasm:prefer-inline')
void rebuild({bool force = false}) {
  assert(_lifecycleState != _ElementLifecycle.initial);
  if (_lifecycleState != _ElementLifecycle.active || (!_dirty && !force)) {
    return;
  }
  assert(() {
    debugOnRebuildDirtyWidget?.call(this, _debugBuiltOnce);
    if (debugPrintRebuildDirtyWidgets) {
      if (!_debugBuiltOnce) {
        debugPrint('Building $this');
        _debugBuiltOnce = true;
      } else {
        debugPrint('Rebuilding $this');
      }
    }
    return true;
  }());
  assert(_lifecycleState == _ElementLifecycle.active);
  assert(owner!._debugStateLocked);
  Element? debugPreviousBuildTarget;
  assert(() {
    debugPreviousBuildTarget = owner!._debugCurrentBuildTarget;
    owner!._debugCurrentBuildTarget = this;
    return true;
  }());
  try {
    performRebuild();
  } finally {
    assert(() {
      owner!._debugElementWasRebuilt(this);
      assert(owner!._debugCurrentBuildTarget == this);
      owner!._debugCurrentBuildTarget = debugPreviousBuildTarget;
      return true;
    }());
  }
  assert(!_dirty);
}
