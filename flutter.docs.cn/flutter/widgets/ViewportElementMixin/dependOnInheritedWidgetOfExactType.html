继承

返回给定类型 T 的最近祖先 widget，并建立对此 widget 的依赖；如果找不到合适的 widget，则返回 null。

找到的 widget 将是具体 InheritedWidget 子类。调用 dependOnInheritedWidgetOfExactType 会将此 build context 注册为依赖于返回的 widget。当该 widget 发生变化（或新增同类型 widget，或该 widget 被移除）时，此 build context 会重建，以便获取该 widget 的新值。

通常会从 of() 静态方法中隐式调用此方法，例如 Theme.of。

不应从 widget 构造函数或 State.initState 方法中调用此方法。虽然调用此方法实际上会将 BuildContext 注册为依赖项，以便后续重建，但构造函数和 State.initState 受生命周期限制，在 element 初次创建时只执行一次。

如果继承值之后发生变化，框架会正确地再次调用 State.build，但无法重新运行构造函数或 State.initState。因此，如果这些只执行一次的方法使用继承值的“快照”初始化了内部变量、控制器或副作用，它们会保留原先已过时的值。这会造成状态不同步：widget 的 State.build 可能使用更新后的数据，而内部逻辑仍依赖在 State.initState 中捕获的旧数据。

为确保 widget 保持同步，应在 build 方法、布局和绘制回调中直接或间接调用此方法，或在 State.didChangeDependencies 中调用。

State.didChangeDependencies 会在 State.initState 之后立即调用；只要此 context 所依赖的继承 widget 发生变化，它就会再次调用，直到该 widget 或其某个祖先下次移动为止（例如添加或移除祖先）。这样，在调用 State.build 之前，State 可以更新内部变量或执行依赖继承值的初始化逻辑。

当时元素树已不再稳定，因此不能在 State.dispose 中调用此方法。若要在该方法中引用祖先，应在 State.didChangeDependencies 中保存对祖先的引用。可以在 State.deactivate 中安全地调用此方法；每当组件从树中移除时都会调用该方法。

也可以在交互事件处理器（例如手势回调）或定时器中调用此方法来获取一次性值，前提是之后不缓存或重复使用该值。

也可以在交互事件处理程序（例如手势回调）或定时器中调用此方法，以获取一次性的值；前提是之后不缓存或重用该值。

aspect 参数仅在 T 为支持局部更新的 InheritedWidget 子类（例如 InheritedModel）时使用。它指定此 context 所依赖的继承 widget 的哪个“方面”。

实现

@override
T? dependOnInheritedWidgetOfExactType<T extends InheritedWidget>({Object? aspect}) {
  assert(_debugCheckStateIsActiveForAncestorLookup());
  final InheritedElement? ancestor = _inheritedElements?[T];
  if (ancestor != null) {
    return dependOnInheritedElement(ancestor, aspect: aspect) as T;
  }
  _hadUnsatisfiedDependencies = true;
  return null;
}
