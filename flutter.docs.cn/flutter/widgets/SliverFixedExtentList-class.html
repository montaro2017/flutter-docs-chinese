SliverFixedExtentList 类

沿主轴以线性数组方式放置多个盒子子项，并使它们具有相同主轴范围的 sliver。

关于 sliver 的更多信息，请参阅 CustomScrollView.slivers。

SliverFixedExtentList 会从偏移量 0 开始，沿主轴无间隙地线性排列子项。每个子项在主轴方向上的范围都被强制设为 itemExtent，在交叉轴方向上的范围则被强制设为 SliverConstraints.crossAxisExtent。

SliverFixedExtentList 比 SliverList 更高效，因为 SliverFixedExtentList 无需对子项进行布局即可获取它们在主轴上的范围。

This example, which would be inserted into a CustomScrollView.slivers list, shows an infinite number of items in varying shades of blue:
link 
SliverFixedExtentList(
  itemExtent: 50.0,
  delegate: SliverChildBuilderDelegate(
    (BuildContext context, int index) {
      return Container(
        alignment: Alignment.center,
        color: Colors.lightBlue[100 * (index % 9)],
        child: Text('list item $index'),
      );
    },
  ),
)

子元素的生命周期

创建

布局列表时，可见子项的元素、状态和渲染对象会根据现有 widget（例如 SliverChildListDelegate）或延迟提供的内容（例如 SliverChildBuilderDelegate）按需创建。

销毁

子项滚出视野时，与其关联的元素子树、状态和渲染对象会被销毁。滚动回来时，sliver 会在相同位置按需重新创建子项及其元素、状态和渲染对象。

减少销毁影响

为了在子元素滚入或滚出视野时保留其状态，可以采用以下选项：

  • 将驱动复杂 UI 状态的业务逻辑移出 sliver 子项子树。例如，若列表中的帖子及其获赞数来自缓存的网络响应，可将帖子列表和获赞数存放在列表之外的数据模型中。让 sliver 子项 UI 子树能够根据真实数据模型轻松重建。子 widget 子树中的 StatefulWidget 只用于保存即时 UI 状态。

  • 将 KeepAlive 设为需要保留的 sliver 子项 widget 子树的根 widget。KeepAlive 会将子树顶部的渲染对象子项标记为需要保持活动状态。当关联的顶部渲染对象滚出视野时，sliver 会将子项渲染对象（以及相应的元素和状态）保存在缓存列表中，而不是销毁它们。滚回视野时，渲染对象会按原样重新绘制（如果期间没有被标记为脏）。

    This only works if the SliverChildDelegate subclasses don't wrap the child widget subtree with other widgets such as AutomaticKeepAlive 和 RepaintBoundary via addAutomaticKeepAlives 和 addRepaintBoundaries.

  • 使用 AutomaticKeepAlive widget（默认由 SliverChildListDelegate 或 SliverChildListDelegate 插入）。AutomaticKeepAlive 允许后代 widget 控制是否实际保留子树。此行为不同于 KeepAlive，后者会无条件保留子树。

    例如，EditableText widget 会在文本字段获得输入焦点时，通知其 sliver 子项元素子树保持活动状态。如果它失去焦点，且没有其他后代通过 KeepAliveNotification 请求保持活动状态，那么该 sliver 子项元素子树会在滚出视野时被销毁。

    AutomaticKeepAlive 的后代通常会通过 AutomaticKeepAliveClientMixin 通知它们需要保持存活，然后实现 AutomaticKeepAliveClientMixin.wantKeepAlive getter，并调用 AutomaticKeepAliveClientMixin.updateKeepAlive。

在一个 Viewport 中使用多个委托对象

如果在单个滚动视图中使用多个委托对象，即使每个委托对象的第一个子项超出当前可视区域，也始终会对其进行布局。这是因为必须至少有一个子项，才能估算整个滚动视图的 estimateMaxScrollOffset；该估算会根据当前已构建的子项来推算其余子项的范围。

另请参阅：

  • SliverPrototypeExtentList，与SliverFixedExtentList类似，但使用原型列表项而非像素值来定义每个项目在主轴方向上的范围。
  • SliverVariedExtentList, which supports children with varying (but known upfront) extents.
  • SliverFillViewport，根据 SliverConstraints.viewportMainAxisExtent 确定 itemExtent。
  • SliverList，其子项在主轴方向上无需具有相同尺寸。
