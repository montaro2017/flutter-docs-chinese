Opacity 类

一种使子 widget 部分透明的 widget。

此类会先将子 widget 绘制到中间缓冲区，再将其以部分透明的方式混合回场景中。

当 opacity 既不是 0.0 也不是 1.0 时，此类开销相对较大，因为需要先将子 widget 绘制到中间缓冲区。opacity 为 0.0 时，完全不会绘制子 widget；为 1.0 时，则会立即绘制子 widget，不使用中间缓冲区。

默认具有透明背景的中间缓冲区可能会导致某些子 widget 的行为发生变化。例如，作为子 widget 的 BackdropFilter 只能对本 widget 与 backdrop 子 widget 之间的内容应用滤镜，而且可能需要调整 BackdropFilter.blendMode 属性才能得到预期效果。

This example shows some Text when the _visible member field is true, and hides it when it is false:
link 
Opacity(
  opacity: _visible ? 1.0 : 0.0,
  child: const Text("Now you see me, now you don't!"),
)

这比按需将子 widget 添加到树中或从树中移除更高效。

Opacity 动画的性能注意事项

直接为 Opacity widget 添加动画，会导致该 widget（以及可能的整个子树）每帧都重建，效率不高。可以考虑改用以下替代 widget：

  • AnimatedOpacity, which uses an animation internally to efficiently animate opacity.
  • FadeTransition, which uses a provided animation to efficiently animate opacity.

透明图像

如果只需将单个 Image 或 Color 以 0.0 到 1.0 之间的 opacity 进行合成，直接使用它们要比使用 Opacity widget 快得多。

例如，Container(color: Color.fromRGBO(255, 0, 0, 0.5)) 比 Opacity(opacity: 0.5, child: Container(color: Colors.red)) 快得多。

The following example draws an Image with 0.5 opacity without using Opacity:
link 
Image.network(
  'https://raw.githubusercontent.com/flutter/assets-for-api-docs/main/packages/diagrams/assets/blend_mode_destination.jpeg',
  color: const Color.fromRGBO(255, 255, 255, 0.5),
  colorBlendMode: BlendMode.modulate
)

直接绘制带透明度的 Image 或 Color，比在它们外层使用 Opacity 更快，因为 Opacity 可能需要对一组 widget 整体应用透明度，从而使用开销较大的离屏缓冲区。将内容绘制到离屏缓冲区还可能触发渲染目标切换，这种切换在较旧的 GPU 上尤其缓慢。

命中测试

将 opacity 设为零，并不会阻止对 Opacity 子孙节点进行命中测试。这可能让用户感到困惑：他们看不到任何内容，可能会以为 Opacity 隐藏 widget 的区域无法交互。

对于 Flow 这类仅在绘制时才计算位置的 widget，这实际上可能引发错误（从几何位置异常到抛出异常都有可能），因为 opacity 为零时，Opacity widget 完全不会绘制这些 widget。

为避免此类问题，将 opacity 设为零时，通常建议使用 IgnorePointer widget。这样可以阻止与子树中的任何子 widget 进行交互。

另请参阅：

  • Visibility, which can hide a child more efficiently (albeit less subtly, because it is either visible or hidden, rather than allowing fractional opacity values). Specifically, the Visibility.maintain constructor is equivalent to using an opacity widget with values of 0.0 or 1.0.
  • ShaderMask, which can apply more elaborate effects to its child.
  • Transform, which applies an arbitrary transform to its child widget at paint time.
  • SliverOpacity, the sliver version of this widget.
