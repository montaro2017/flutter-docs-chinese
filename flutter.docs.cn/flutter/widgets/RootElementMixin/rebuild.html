rebuild 方法

void rebuild({
  1. bool force = false,
})
继承

使组件更新自身。在调试构建中，还会检查各种不变量。

BuildOwner 调用 BuildOwner.scheduleBuildFor 将此元素标记为脏时、元素首次构建时的 mount 调用中，以及组件发生变化时的 update 调用中，都会调用此方法。

只有当 dirty 为 true 时，此方法才会执行重建。若要忽略 dirty 标记并强制重建，请将 force 设为 true。在 update 期间强制重建很方便，因为这时 dirty 为 false。

何时发生重建

术语

Widget 表示 Element 的配置。每个 Element 都有一个 widget，由 Element.widget 指定。严格来说，在某些上下文中“element”更准确，但通常也会使用“widget”一词。

Element 虽然有当前的 Widget，但随着时间推移，该 widget 可能会被其他 widget 替换。例如，某个 ColoredBox 对应的元素最初可能使用颜色为蓝色的 ColoredBox 作为 widget，之后则会被赋予一个颜色为绿色的新 ColoredBox，其 ColoredBox.color 属性也会相应改变。

在同一棵树中的某个时刻，多个 Element 可以拥有相同的 Widget。例如，绿色的同一个 ColoredBox 可以同时用于组件树中的多个位置，而每个位置都由不同的 Element 支持。

将元素标记为脏

元素树帧与帧之间，Element 可以被标记为脏。这可能由多种原因造成，包括以下情况：

  • State 可以调用 State.setState，从而将其 StatefulWidget 对应的 Element 标记为脏。

  • InheritedWidget 发生变化时，先前订阅了它的后代会被标记为脏。

  • 热重载期间，会通过 Element.reassemble 将每个元素标记为脏。

重建

脏元素会在下一帧中重建。具体方式取决于元素类型。StatelessElement 会使用其 widget 的 StatelessWidget.build 方法重建。StatefulElement 会使用其 widget 对应状态的 State.build 方法重建。RenderObjectElement 则通过更新其 RenderObject 来重建。

很多情况下，重建的最终结果是一个子组件；对于 MultiChildRenderObjectElement，则是一个子组件列表。

这些子组件用于更新子元素的 widget 属性。如果新 Widget 与现有 Element 具有相同的 Type 和 Key，就认为两者相对应。（对于 MultiChildRenderObjectElement，框架还会尽力跟踪顺序发生变化的 widget；参见 RenderObjectElement.updateChildren。）

如果没有与之前子元素对应的新子组件，就会使用 Widget.createElement 创建新的 Element，然后递归构建该元素。

如果之前存在子元素，但这次构建没有提供与之对应的子元素来更新它，那么旧子元素就会被丢弃（若涉及 GlobalKey 重新挂接，则可能在元素树的其他位置复用）。

不过，最常见的情况是存在对应的旧子元素。此时会让子 Element 使用新的子 Widget 更新自身。对于 StatefulElement，这会触发 State.didUpdateWidget。

不进行重建

在通知 Element 使用新的 Widget 更新自身之前，会使用 operator == 比较新旧对象。

通常，这相当于使用 identical 比较两个对象是否确实为同一个实例。如果是同一实例，并且该元素没有因其他原因被标记为脏，那么元素就会跳过更新，因为可以确定更新自身及其后代都没有价值。

强烈建议不要为 Widget 对象重写 operator ==。这样看似可以提升性能，但对于非叶子 widget，实际上会造成 O(N²) 开销。这是因为比较时必然要比较子 widget；如果这些子 widget 也实现了 operator ==，最终就会完整遍历组件树，并在树的每一层重复遍历。实际情况下，直接重建反而更便宜。（此外，只要应用中任意一个 Widget 子类实现了 operator ==，编译器就无法在任何位置内联该比较，因为必须将调用视为虚调用，以防实例恰好使用了重写版本。）

避免不必要重建的最佳方式，是缓存从 State.build 返回的 widget，这样在它们发生变化之前，每一帧都会复用相同的 widget。有多种机制可以帮助实现这一点，例如 const widget 就是一种自动缓存方式（如果使用 const 关键字构造 widget，那么每次使用相同参数构造时都会返回同一个实例）。

另一个例子是 AnimatedBuilder.child 属性：即使 AnimatedBuilder.builder 回调重新创建其他组件，它也能让子树中不执行动画的部分保持不变。

实现

@pragma('dart2js:tryInline')
@pragma('vm:prefer-inline')
@pragma('wasm:prefer-inline')
void rebuild({bool force = false}) {
  assert(_lifecycleState != _ElementLifecycle.initial);
  if (_lifecycleState != _ElementLifecycle.active || (!_dirty && !force)) {
    return;
  }
  assert(() {
    debugOnRebuildDirtyWidget?.call(this, _debugBuiltOnce);
    if (debugPrintRebuildDirtyWidgets) {
      if (!_debugBuiltOnce) {
        debugPrint('Building $this');
        _debugBuiltOnce = true;
      } else {
        debugPrint('Rebuilding $this');
      }
    }
    return true;
  }());
  assert(_lifecycleState == _ElementLifecycle.active);
  assert(owner!._debugStateLocked);
  Element? debugPreviousBuildTarget;
  assert(() {
    debugPreviousBuildTarget = owner!._debugCurrentBuildTarget;
    owner!._debugCurrentBuildTarget = this;
    return true;
  }());
  try {
    performRebuild();
  } finally {
    assert(() {
      owner!._debugElementWasRebuilt(this);
      assert(owner!._debugCurrentBuildTarget == this);
      owner!._debugCurrentBuildTarget = debugPreviousBuildTarget;
      return true;
    }());
  }
  assert(!_dirty);
}
