继承

返回最近的指定类型 T 的组件并对其建立依赖；如果找不到合适的组件，则返回 null。

找到的组件一定是具体的 InheritedWidget 子类。调用 dependOnInheritedWidgetOfExactType 会将此构建上下文注册到返回的组件。当该组件发生变化、出现该类型的新组件或原组件被移除时，此构建上下文会重新构建，以便从该组件获取新值。

通常会从 of() 等静态方法中隐式调用此方法，例如 Theme.of。

不应在组件构造函数或 State.initState 方法中调用此方法。虽然调用此方法会将 BuildContext 注册为依赖项，以便之后重新构建，但构造函数和 State.initState 受生命周期限制，在元素首次创建期间只会执行一次。

如果之后继承值发生变化，框架会正确地再次调用 State.build，但不会重新运行构造函数或 State.initState。因此，如果这些只执行一次的方法基于继承值的“快照”初始化了内部变量、控制器或副作用，它们仍会保留原有的过时值。这样就会造成状态不同步：组件的 State.build 可能使用更新后的数据，而内部逻辑仍依赖在 State.initState 中捕获的旧数据。

要确保组件保持同步，请在 build 方法、布局和绘制回调，或 State.didChangeDependencies 中直接或间接调用此方法。

State.didChangeDependencies 会在 State.initState 之后立即调用；每当此上下文所依赖的继承组件发生变化，也会再次调用，直到组件或其某个祖先下一次移动为止（例如添加或移除祖先）。这样，在调用 State.build 之前，State 就可以更新内部变量，或执行依赖继承值的初始化逻辑。

当时元素树已不再稳定，因此不能在 State.dispose 中调用此方法。若要在该方法中引用祖先，应在 State.didChangeDependencies 中保存对祖先的引用。可以在 State.deactivate 中安全地调用此方法；每当组件从树中移除时都会调用该方法。

也可以在交互事件处理器（例如手势回调）或定时器中调用此方法来获取一次性值，前提是之后不缓存或重复使用该值。

调用此方法的时间复杂度为 O(1)，常数开销较小，但会导致组件更频繁地重建。

只有当 T 是支持部分更新的 InheritedWidget 子类（例如 InheritedModel）时，才会使用 aspect 参数。它指定此上下文依赖该继承组件的哪个“方面”。

实现

@override
T? dependOnInheritedWidgetOfExactType<T extends InheritedWidget>({Object? aspect}) {
  assert(_debugCheckStateIsActiveForAncestorLookup());
  final InheritedElement? ancestor = _inheritedElements?[T];
  if (ancestor != null) {
    return dependOnInheritedElement(ancestor, aspect: aspect) as T;
  }
  _hadUnsatisfiedDependencies = true;
  return null;
}
