markNeedsLayout 方法

void markNeedsLayout()
继承

将此渲染对象的布局信息标记为脏状态；如果此对象是重新布局边界，则向其 PipelineOwner 注册，否则交由父对象处理。

背景

收到对渲染对象的写入时，我们不会立即更新布局信息，而是将其标记为脏状态并安排一次视觉更新。视觉更新过程中，渲染流水线会更新渲染对象的布局信息。

此机制会批量处理布局工作，将连续发生的多次写入合并，从而避免重复计算。

如果渲染对象的父对象表示在计算布局信息时会使用某个渲染子项的尺寸，那么对此子项调用此函数时，也会将父对象标记为需要布局。在这种情况下，父对象和子项都需要重新计算布局，因此渲染流水线只会收到父对象的通知；父对象完成布局时会调用子项的 layout 方法，子项也会随之布局。

对渲染对象调用 markNeedsLayout 后，debugNeedsLayout 会一直对该对象返回 true，直到流水线所有者调用该对象的 layout 后才恢复。

特殊情况

RenderObject 的部分子类（尤其是 RenderBox）还存在其他需要在子项变脏时通知父对象的情况，例如子项的固有尺寸或基线发生变化。这些子类会重写 markNeedsLayout：常规情况下调用 super.markNeedsLayout()；如果父对象和子项都需要重新布局，则调用 markParentNeedsLayout。

如果 sizedByParent 发生变化，应改为调用 markNeedsLayoutForSizedByParentChange，而不是 markNeedsLayout。

实现

void markNeedsLayout() {
  assert(_debugCanPerformMutations);
  if (_needsLayout) {
    assert(_debugRelayoutBoundaryAlreadyMarkedNeedsLayout());
    return;
  }
  _needsLayout = true;
  if (owner case final PipelineOwner owner? when (_isRelayoutBoundary ?? false)) {
    assert(() {
      if (debugPrintMarkNeedsLayoutStacks) {
        debugPrintStack(label: 'markNeedsLayout() called for $this');
      }
      return true;
    }());
    owner._nodesNeedingLayout.add(this);
    owner.requestVisualUpdate();
  } else if (parent != null) {
    markParentNeedsLayout();
  }
}
