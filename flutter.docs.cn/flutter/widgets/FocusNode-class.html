FocusNode 类

供有状态 widget 使用的对象，可用于获取键盘焦点并处理键盘事件。

请参阅 Focus 和 FocusScope widget；它们分别是管理自身 FocusNode 和 FocusScopeNode 的工具类 widget。若它们不适用，也可以直接管理 FocusNode，但这种情况并不常见。

FocusNode 是持久对象，它们构成一棵焦点树，用于表示层级中关注焦点的 widget。如果祖先的 Focus widget 需要控制子项的焦点，可能需要创建焦点节点并将其传入；如果未使用 widget 子系统，或 Focus 与 FocusScope widget 无法提供足够控制，也可能需要由 widget 托管焦点节点。

FocusNode 按焦点范围组织（参见 FocusScopeNode），形成节点子树，将遍历限制在一组节点内。在一个范围中，会记住最近获得焦点的节点；如果某个节点获得焦点后又失去焦点，先前的节点会再次获得焦点。

可通过 parent、children、ancestors 和 descendants 访问器遍历焦点节点层级。

FocusNode 是 ChangeNotifier，因此可以注册监听器，以便在焦点变化时收到通知。更新 skipTraversal、canRequestFocus、descendantsAreFocusable 和 descendantsAreTraversable 属性时，也会通知监听器。如果通过 Focus 和 FocusScope widget 管理这些节点，可考虑改为调用 Focus.of 或 FocusScope.of，从而建立对它们的 InheritedWidget 依赖。FocusNode.hasFocus 也能建立类似依赖，尤其适合只需在构建时确定 widget 是否拥有焦点的情况。

若要在调试控制台查看焦点树，请调用 debugDumpFocusTree。若要将焦点树获取为字符串，请调用 debugDescribeFocusTree。

生命周期

FocusNode/FocusScopeNode 的生命周期涉及多个参与者。由其拥有者创建和释放；由其宿主通过 FocusAttachment 附加、分离和重新指定父节点（宿主必须由 StatefulWidget 的 State 拥有）；并由 FocusManager 管理。FocusNode API 的不同部分分别面向这些参与者。

FocusNode（因此也包括 FocusScopeNode）是持久对象，属于焦点树的一部分。焦点树以稀疏结构表示层级中关注接收键盘事件的 widget。它们必须像其他持久状态一样管理，通常由拥有该节点的 StatefulWidget 管理。拥有焦点范围节点的有状态 widget 必须在其 State.dispose 方法中调用 dispose。

FocusNode 创建后，必须通过 FocusAttachment 对象附加到 widget 树。通常在 State.initState 方法中调用 attach 创建此附着。如果宿主 widget 更新后使用不同的焦点节点，则应在 State.didUpdateWidget 中先对旧的 FocusAttachment 调用 FocusAttachment.detach，再附加新节点。

由于 FocusNode 以稀疏结构表示 widget 树，因此每当 widget 树重建时，都必须更新焦点节点。通常由表示焦点区域的 widget 在 State.build 或 State.didChangeDependencies 中调用 FocusAttachment.reparent 来完成。这样便能跟踪分配给 FocusScopeNode 的 BuildContext（此 context 用于获取 RenderObject，进而确定焦点区域的几何信息）。

每次调用 State.build 都创建新的 FocusNode，会导致 widget 每次构建时焦点都丢失；这通常不是期望行为（若希望丢失焦点，请调用 unfocus）。

通常，宿主 StatefulWidget 同时也是焦点节点的拥有者；此时它也会在 State.dispose 中调用 dispose（这种情况下可以省略 FocusAttachment.detach，因为 dispose 会自动分离节点）。如果焦点节点由其他对象拥有，则该对象必须在节点不再使用时调用 dispose。

按键事件传播

FocusManager 从 HardwareKeyboard 接收按键事件，并将其传递给获得焦点的节点。它从主焦点节点开始，调用该节点的 onKeyEvent 回调。如果回调返回 KeyEventResult.ignored，表示未处理该事件，FocusManager 就会转到该节点的父节点并调用父节点的 onKeyEvent。如果该 onKeyEvent 回调返回 KeyEventResult.handled，事件传播便会停止。如果事件一路传到根 FocusScopeNode（FocusManager.rootScope），就会被丢弃。

焦点遍历

遍历（有时称为Tab 遍历）是指按特定顺序将焦点从一个 widget 移动到下一个 widget；这有时也称为Tab 顺序，因为 TAB 键通常绑定到移动到下一个 widget 的操作。

若要将焦点移至 UI 中逻辑顺序上的下一个或上一个 widget，请调用 nextFocus 或 previousFocus。若要沿特定方向将焦点移到 widget，请调用 focusInDirection。

哪个 widget 被视为下一个、上一个或特定方向上的目标，由当前生效的 FocusTraversalPolicy 决定。

环境策略通过沿 widget 层级查找 FocusTraversalGroup widget 并获取其中的焦点遍历策略来确定。不同焦点节点可以继承不同策略，因此应用的不同部分可以根据用例按预定义顺序遍历（使用 OrderedTraversalPolicy），也可以按阅读顺序遍历（使用 ReadingOrderTraversalPolicy）。

预定义策略包括 WidgetOrderTraversalPolicy、ReadingOrderTraversalPolicy、OrderedTraversalPolicy 和 DirectionalFocusTraversalPolicyMixin；也可以基于这些策略构建自定义策略。详情请参阅 FocusTraversalPolicy。
