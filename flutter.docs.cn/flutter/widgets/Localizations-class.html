Localizations 类

为其 child 及该子组件依赖的本地化资源定义 Locale。

定义本地化资源

以下类基于 Dart intl 包实现。使用 intl 包并非必需。
link 
class MyLocalizations {
  MyLocalizations(this.locale);

  final Locale locale;

  static Future<MyLocalizations> load(Locale locale) {
    return initializeMessages(locale.toString())
      .then((void _) {
        return MyLocalizations(locale);
      });
  }

  static MyLocalizations of(BuildContext context) {
    return Localizations.of<MyLocalizations>(context, MyLocalizations)!;
  }

  String title() => Intl.message('<title>', name: 'title', locale: locale.toString());
  // ... more Intl.message() methods like title()
}
基于 intl 包的类会导入生成的消息目录，其中提供 initializeMessages() 函数以及按区域设置存储的 Intl.message() 数据。 消息目录由 intl 工具生成，该工具会分析源代码，查找包含 Intl.message() 调用的类。此示例中只有 MyLocalizations 类。

也可以选择其他方式加载和查找本地化资源，同时仍遵循此示例的结构。

加载本地化资源

本地化资源由 LocalizationsDelegate 列表中的 delegates 加载。每个委托本质上都是一组本地化资源的工厂。应用内的本地化资源可能来自多个来源，因此会有多个委托。

委托通常是以下类的简单子类： LocalizationsDelegate，并会重写 LocalizationsDelegate.load。例如，为上文定义的 MyLocalizations 类创建的委托如下：

// continuing from previous example...
class _MyDelegate extends LocalizationsDelegate<MyLocalizations> {
  @override
  Future<MyLocalizations> load(Locale locale) => MyLocalizations.load(locale);

  @override
  bool isSupported(Locale locale) {
    // in a real implementation this would only return true for
    // locales that are definitely supported.
    return true;
  }

  @override
  bool shouldReload(_MyDelegate old) => false;
}

每个委托都可视为创建对象的工厂，这些对象封装一组本地化资源。可通过运行时类型使用 Localizations.of 获取这些对象。

WidgetsApp 类会创建 Localizations 组件，因此大多数应用无需自行创建。可通过 WidgetsApp.localizationsDelegates 初始化 WidgetsApp 的 Localizations 委托。MaterialApp 类也提供 localizationsDelegates 参数，并会将其传递给 WidgetsApp。

在用户界面中获取本地化资源

应用应使用 Localizations.of<MyLocalizations>(context, MyLocalizations) 获取本地化资源集合，其中 MyLocalizations 是应用自定义类，每种资源对应一个函数。通常，会在自定义本地化资源类（上例中的 MyLocalizations）中定义静态 .of 方法来完成此操作。

例如，使用上文定义的 MyLocalizations 类，可以按如下方式查找本地化标题字符串：

// continuing from previous example...
MyLocalizations.of(context).title()

如果 Localizations 使用新的 locale 重建，那么在加载相应资源后，与 BuildContext context 对应的组件子树也会重建。

此类本质上是一个 InheritedWidget。如果它使用新的 locale 或不同的委托列表重建，或者其任一委托的 LocalizationsDelegate.shouldReload() 方法返回 true，那么通过调用 Localizations.of(context) 建立依赖关系的组件会在新区域设置的资源加载完成后重建。

Localizations 组件还会实例化 Directionality，以便为本地化资源提供适当的 Directionality.textDirection。
