GestureDetector 类

用于检测手势的 widget。

尝试识别与其非 null 回调相对应的手势。

如果此 widget 有 child，其尺寸行为由 child 决定。如果没有 child，则会扩展以适应父级尺寸。

默认情况下，child 不可见的 GestureDetector 会忽略触摸事件；此行为可通过 behavior 控制。

GestureDetector 也会监听无障碍事件，并将其映射到相应回调。若要忽略无障碍事件，请将 excludeFromSemantics 设为 true。

更多信息请参阅 flutter.dev/to/gestures。

Material Design 应用通常会用墨水飞溅效果响应触摸。InkWell 类实现了此效果，可替代 GestureDetector 来处理点击。

此示例将一个黑色灯泡包裹在 GestureDetector. 点击“TURN LIGHT ON”按钮时，会通过设置 _lights 字段将灯泡变为黄色；再次点击“TURN LIGHT OFF”时则会关闭灯泡。

疑难排查

为什么没有调用父级的 GestureDetector.onTap 方法？

假设父级 GestureDetector 和子级 GestureDetector 都定义了 onTap 回调。当点击内部 GestureDetector 时，两个 GestureDetector 都会向手势竞技场提交一个 GestureRecognizer。这是因为指针坐标同时位于两个 GestureDetector 的边界内。在这种情况下，子级 GestureDetector 会获胜，因为它先进入竞技场；竞技场遵循先到先得原则来解决竞争。子级的 onTap 会被调用，而父级的不会，因为该手势已被消费。有关手势消歧的更多信息，请参阅：Gesture disambiguation。

将 GestureDetector.behavior 设为 HitTestBehavior.opaque 或 HitTestBehavior.translucent 不会改变父子关系：两个 GestureDetector 都会向手势竞技场提交 GestureRecognizer，但只有一个会获胜。

有些回调（例如 onTapDown）会在识别器赢得竞技场之前触发；另一些回调（例如 onTapCancel）即使识别器输掉竞争也会触发。因此，即使示例中的父级检测器在竞技场中落败，它的一些回调仍可能被调用。

此示例使用一个 GestureDetector，它包裹一个绿色的 Container，另一个 GestureDetector 包裹黄色 Container。第二个 GestureDetector 是绿色 Container 的子项。两个 GestureDetector 都定义了 onTap 回调。回调触发时，会给相应的 Container 添加红色边框。

点击绿色 Container 时，其父级 GestureDetector 会进入手势竞技场。由于没有其他 GestureDetector 与之竞争，它会获胜，绿色 Container 随即显示红色边框。点击黄色 Container 时，其父级 GestureDetector 会进入手势竞技场。包裹绿色 Container 的 GestureDetector 也会进入竞技场（指针事件坐标同时位于两个 GestureDetector 的边界内）。包裹黄色 Container 的 GestureDetector 会获胜，因为它先进入竞技场。

此示例将 debugPrintGestureArenaDiagnostics 设为 true。此标志会输出有关手势竞技场的实用信息。

将 GestureDetector.behavior 属性设为 HitTestBehavior.translucent 或 HitTestBehavior.opaque 不会产生影响：两个 GestureDetector 都会向手势竞技场提交一个 GestureRecognizer ，但最终只有一个会获胜。
