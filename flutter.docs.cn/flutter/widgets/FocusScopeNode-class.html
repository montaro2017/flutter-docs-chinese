FocusScopeNode 类

FocusNode 的子类，可作为其后代的范围，并维护当前或最近获得焦点的后代信息。

请参阅 FocusScope 和 Focus widget；它们分别是管理自身 FocusScopeNode 和 FocusNode 的工具类 widget。如果它们不适用，也可以直接管理 FocusScopeNode。

FocusScopeNode 会将 FocusNode 组织成范围。范围构成节点子树，可以作为一个整体进行遍历。在一个范围内，会记住最近获得焦点的节点；如果节点获得焦点后被移除，原先的节点会再次获得焦点。

对 FocusScopeNode 调用 setFirstFocus，会将给定的焦点范围设为此节点的 focusedChild；如果该范围尚未位于焦点树中，此调用还会将其纳入焦点树。

生命周期

FocusNode/FocusScopeNode 的生命周期涉及多个参与者。由其拥有者创建和释放；由其宿主通过 FocusAttachment 附加、分离和重新指定父节点（宿主必须由 StatefulWidget 的 State 拥有）；并由 FocusManager 管理。FocusNode API 的不同部分分别面向这些参与者。

FocusNode（因此也包括 FocusScopeNode）是持久对象，属于焦点树的一部分。焦点树以稀疏结构表示层级中关注接收键盘事件的 widget。它们必须像其他持久状态一样管理，通常由拥有该节点的 StatefulWidget 管理。拥有焦点范围节点的有状态 widget 必须在其 State.dispose 方法中调用 dispose。

FocusNode 创建后，必须通过 FocusAttachment 对象附加到 widget 树。通常在 State.initState 方法中调用 attach 创建此附着。如果宿主 widget 更新后使用不同的焦点节点，则应在 State.didUpdateWidget 中先对旧的 FocusAttachment 调用 FocusAttachment.detach，再附加新节点。

由于 FocusNode 以稀疏结构表示 widget 树，因此每当 widget 树重建时，都必须更新焦点节点。通常由表示焦点区域的 widget 在 State.build 或 State.didChangeDependencies 中调用 FocusAttachment.reparent 来完成。这样便能跟踪分配给 FocusScopeNode 的 BuildContext（此 context 用于获取 RenderObject，进而确定焦点区域的几何信息）。

每次调用 State.build 都创建新的 FocusNode，会导致 widget 每次构建时焦点都丢失；这通常不是期望行为（若希望丢失焦点，请调用 unfocus）。

通常，宿主 StatefulWidget 同时也是焦点节点的拥有者；此时它也会在 State.dispose 中调用 dispose（这种情况下可以省略 FocusAttachment.detach，因为 dispose 会自动分离节点）。如果焦点节点由其他对象拥有，则该对象必须在节点不再使用时调用 dispose。

按键事件传播

FocusManager 从 HardwareKeyboard 接收按键事件，并将其传递给获得焦点的节点。它从主焦点节点开始，调用该节点的 onKeyEvent 回调。如果回调返回 KeyEventResult.ignored，表示未处理该事件，FocusManager 就会转到该节点的父节点并调用父节点的 onKeyEvent。如果该 onKeyEvent 回调返回 KeyEventResult.handled，事件传播便会停止。如果事件一路传到根 FocusScopeNode（FocusManager.rootScope），就会被丢弃。

另请参阅：

  • Focus：管理 FocusNode，并向其后代 widget 提供焦点信息和操作。
  • FocusManager：管理主要焦点并向拥有焦点的节点分发按键事件的单例。
