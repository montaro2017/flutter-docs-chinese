继承

通知框架：此对象的内部状态已发生变化。

每当更改 State 对象的内部状态时，都应在传递给 setState 的函数中进行更改：

setState(() { _myState = newValue; });

提供的回调会立即同步执行。它不得返回 future（不能声明为 async），否则将无法确定状态究竟何时被设置。

调用 setState 会通知框架：此对象的内部状态已发生可能影响该子树用户界面的变化，因此框架会安排调用 build，以重建此 State 对象。

如果直接更改状态而不调用 setState，框架可能不会安排 build，该子树的用户界面也可能不会更新以反映新状态。

通常建议只用 setState 包裹对状态的实际修改，而不要包裹与修改相关的其他计算。例如，下面的代码先递增供 build 函数使用的值，再将变化写入磁盘，但只有递增操作放在 setState 中：

Future<void> _incrementCounter() async {
  setState(() {
    _counter++;
  });
  Directory directory = await getApplicationDocumentsDirectory(); // from path_provider package
  final String dirName = directory.path;
  await File('$dirName/counter.txt').writeAsString('$_counter');
}

Sometimes, the changed state is in some other object not owned by the widget State, but the widget nonetheless needs to be updated to react to the new state. This is especially common with Listenables, such as AnimationController。

在这种情况下，最好在传给 setState 的回调中添加注释，说明状态发生了什么变化：

void _update() {
  setState(() { /* The animation changed. */ });
}
//...
animation.addListener(_update);

框架调用 dispose 后再调用此方法会引发错误。可通过检查 mounted 属性是否为 true，判断此时能否调用。但更好的做法是取消可能触发 setState 的工作，而不是仅在调用前检查 mounted；否则会浪费 CPU 资源，避免仅在调用 setState 前做检查。

设计讨论

此 API 最初是一个名为 markNeedsBuild 的方法，以便与 RenderObject.markNeedsLayout、RenderObject.markNeedsPaint 等保持一致。

然而，Flutter 框架的早期用户测试发现，人们调用 markNeedsBuild() 的频率远超实际需要。实际上，他们把它当作护身符：只要不确定是否需要调用，就先调用再说。

这自然会导致应用出现性能问题。

后来 API 改为接收回调，这种做法便大幅减少。一种解释是：要求开发者在回调中实际更新状态，促使他们更仔细地思考究竟更新了什么，从而更清楚地理解应在何时调用此方法。

实际上，setState 的实现很简单：它会同步调用提供的回调，然后调用 Element.markNeedsBuild。

性能注意事项

调用此函数的直接开销很小，而且预计每帧最多调用一次，因此这点开销无关紧要。尽管如此，仍应避免冗余调用（例如在紧密循环中），因为调用会创建 closure 并执行它。此方法具有幂等性，每帧对每个 State 调用一次以上没有任何好处。

造成此函数调用的间接成本则很高：它会触发组件重建，可能导致以此组件为根的整个子树都重建，并进一步导致相应的 RenderObject 子树重新布局和重绘。

因此，只有在检测到状态变化后，build 方法会产生实质不同结果时，才应调用此方法。

实现

@protected
void setState(VoidCallback fn) {
  assert(() {
    if (_debugLifecycleState == _StateLifecycle.defunct) {
      throw FlutterError.fromParts(<DiagnosticsNode>[
        ErrorSummary('setState() called after dispose(): $this'),
        ErrorDescription(
          'This error happens if you call setState() on a State object for a widget that '
          'no longer appears in the widget tree (e.g., whose parent widget no longer '
          'includes the widget in its build). This error can occur when code calls '
          'setState() from a timer, from an animation callback, or after an '
          'asynchronous operation (such as an awaited network request or other '
          'Future) completes after the widget has been removed from the tree.',
        ),
        ErrorHint(
          'The preferred solution is '
          'to cancel the timer or stop listening to the animation in the dispose() '
          'callback. Another solution is to check the "mounted" property of this '
          'object before calling setState() to ensure the object is still in the '
          'tree.',
        ),
        ErrorHint(
          'This error might indicate a memory leak if setState() is being called '
          'because another object is retaining a reference to this State object '
          'after it has been removed from the tree. To avoid memory leaks, '
          'consider breaking the reference to this object during dispose().',
        ),
      ]);
    }
    if (_debugLifecycleState == _StateLifecycle.created && !mounted) {
      throw FlutterError.fromParts(<DiagnosticsNode>[
        ErrorSummary('setState() called in constructor: $this'),
        ErrorHint(
          'This happens when you call setState() on a State object for a widget that '
          "hasn't been inserted into the widget tree yet. It is not necessary to call "
          'setState() in the constructor, since the state is already assumed to be dirty '
          'when it is initially created.',
        ),
      ]);
    }
    return true;
  }());
  final Object? result = fn() as dynamic;
  assert(() {
    if (result is Future) {
      throw FlutterError.fromParts(<DiagnosticsNode>[
        ErrorSummary('setState() callback argument returned a Future.'),
        ErrorDescription(
          'The setState() method on $this was called with a closure or method that '
          'returned a Future. Maybe it is marked as "async".',
        ),
        ErrorHint(
          'Instead of performing asynchronous work inside a call to setState(), first '
          'execute the work (without updating the widget state), and then synchronously '
          'update the state inside a call to setState().',
        ),
      ]);
    }
    // We ignore other types of return values so that you can do things like:
    //   setState(() => x = 3);
    return true;
  }());
  _element!.markNeedsBuild();
}
