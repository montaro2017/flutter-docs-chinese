recommendDeferredLoading 方法

bool recommendDeferredLoading(
  1. double velocity,
  2. ScrollMetrics metrics,
  3. BuildContext context
)

提供一种启发式方法，用于判断是否应推迟耗时且受帧时限约束的任务。

velocity 参数可以是正数、负数或零。

context 参数通常是发起调用的 widget 的 BuildContext，例如 ListView 中的 Image widget。

可利用此方法判断是否应延迟解码或获取视口当前可见区域所需的复杂数据，以免执行的工作来不及在下一帧渲染前显示出来。

例如，图片列表可以使用此逻辑，等滚动速度足够慢、解码后的图片确实来得及显示在屏幕上时，再解码图片。

默认实现采用一种启发式方法：将当前滚动速度（以本地逻辑像素为单位）与窗口最长边（以物理像素为单位）进行比较。实现者可以重写此方法并向可滚动 widget 提供自定义物理效果，以调整该启发式规则。例如，应用通过较大的透视变换改变本地坐标系时，可以根据该变换是否增大了全局屏幕坐标系与本地可滚动坐标系之间的整体缩放比例，采用更激进或更保守的规则。

默认实现是无状态的，只会基于当前时刻判断可滚动组件的滚动速度。如果可滚动组件以高速来回循环播放动画，此方法总会返回 true。调用方应自行处理这种情况，或者编写自定义的有状态实现，以跟踪连续调用时速度的正负方向。

此方法返回 true 表示当前滚动速度足够快，因此应推迟会影响 UI 的耗时操作。

实现

bool recommendDeferredLoading(double velocity, ScrollMetrics metrics, BuildContext context) {
  if (parent == null) {
    final double maxPhysicalPixels = View.of(context).physicalSize.longestSide;
    return velocity.abs() > maxPhysicalPixels;
  }
  return parent!.recommendDeferredLoading(velocity, metrics, context);
}
