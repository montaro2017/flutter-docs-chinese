RepaintBoundary 类

为子组件创建独立显示列表的组件。

此组件会为其子组件创建独立的显示列表。如果子树重绘的时间与树中周围部分不同，这样做可以提升性能。

这是有用的，因为即使关联的 Widget 实例没有变化或重建，也可能触发 RenderObject.paint。只要与某个 RenderObject 共用同一 Layer 的任意 RenderObject 被标记为脏并需要绘制（参见 RenderObject.markNeedsPaint），该 RenderObject 就会重绘；例如祖先滚动，或祖先、后代执行动画时都可能发生。

因此，显式或隐式地使用 RepaintBoundary，将 RenderObject.paint 限制在渲染子树中实际发生视觉变化的部分，对于尽量减少冗余工作、提升应用性能至关重要。

当某个 RenderObject 通过 RenderObject.markNeedsPaint 被标记为需要绘制时，离它最近且设置了 RenderObject.isRepaintBoundary 的祖先 RenderObject（最远可能到应用根节点）会收到重绘请求。该祖先的 RenderObject.paint 方法会使同一图层中的所有后代 RenderObject 都重绘。

因此，RepaintBoundary 在渲染树中向上传播 markNeedsPaint 标记，以及通过 PaintingContext.paintChild 向下遍历渲染树时都会发挥作用，从而有策略地将重绘限制在发生视觉变化的渲染子树中，以提升性能。该组件会创建一个始终带有 Layer 的 RenderObject，使祖先和后代渲染对象彼此解耦。使用 RepaintBoundary 可创建该组件。

RepaintBoundary 还可能提示引擎进一步优化动画性能：如果其下方的渲染子树足够复杂，且保持静止，而周围的树频繁变化，引擎可能会一次性付出栅格化成本并缓存该子树的像素值，以便之后更快地通过 GPU 重新渲染。这个子树位于 RepaintBoundary 后方。

框架中的多个组件会插入 RepaintBoundary，在应用中标记自然的分隔点。例如，Material Design 抽屉中的内容通常不会在抽屉打开或关闭时发生变化，因此在过渡期间使用 Drawer 组件时，重绘会自动限制在抽屉内部或外部的区域。

另请参阅：

  • debugRepaintRainbowEnabled, a debugging flag to help visually monitor render tree repaints in a running app.
  • debugProfilePaintsEnabled, a debugging flag to show render tree repaints in Flutter DevTools' timeline view.
