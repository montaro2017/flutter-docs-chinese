void dispose()
重写

此对象从树中永久移除时调用。

当此 State 对象将不再构建时，framework 会调用此方法。framework 调用 dispose 后，此 State 对象会被视为已卸载，mounted 属性为 false。此时调用 setState 会出错。此生命周期阶段是终态：已 dispose 的 State 对象无法重新挂载。

子类应重写此方法，以释放此对象保留的资源（例如停止所有正在运行的动画）。

如果 State 的 build 方法依赖于一个自身状态可能变化的对象（例如 ChangeNotifier、Stream，或其他可订阅并接收通知的对象），请确保在 initState、didUpdateWidget 和 dispose 中正确订阅和取消订阅：

    在 initState 中订阅该对象。 在 didUpdateWidget 中，如果更新后的 widget 配置需要替换该对象，则取消订阅旧对象并订阅新对象。 在 dispose 中取消订阅该对象。

此方法的实现应以调用继承的方法结束，例如 super.dispose()。

注意事项

在开发者可能预期的某些情况下，不会调用此方法，例如应用关闭，或通过平台原生方法关闭界面。

应用关闭

无法预测应用何时关闭。例如，用户的电池可能起火，用户可能将设备掉进泳池，或者操作系统可能因内存压力而单方面终止应用进程。

应用必须确保即使面临突发的非计划终止，也能妥善运行。

若要人为触发整个 widget 树的销毁，可考虑调用 runApp，并传入类似 SizedBox.shrink 的 widget。

若要监听平台关闭消息（以及其他生命周期变化），可考虑使用 AppLifecycleListener API。

通过平台原生方法关闭 Flutter 界面

一个应用可以同时包含 Flutter 界面和非 Flutter 界面。如果应用调用非 Flutter 方法来移除基于 Flutter 的界面，例如调用平台原生 API 操作平台原生导航堆栈，framework 无法判断开发者是否希望立即释放资源。widget 树会继续保持挂载状态，并在界面再次显示时随时可以渲染。

关于如何更积极地释放资源，请参阅用于启动应用的方法（例如 runApp 或 runWidget）中的建议。

另请参阅：

  • deactivate，会在调用 dispose 前触发。

实现

@protected
@override
void dispose() {
  for (final GestureRecognizer recognizer in _recognizers!.values) {
    recognizer.dispose();
  }
  _recognizers = null;
  super.dispose();
}
