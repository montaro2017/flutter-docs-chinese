RootRestorationScope 类

将 RestorationManager.rootBucket 的子 bucket 插入 widget 树，并通过 RestorationScope.of 将其提供给后代。

此 widget 通常放在 widget 树靠近根的位置，以启用应用的状态恢复功能。其他使用场景请考虑改用常规的 RestorationScope。

根 restoration bucket 只能从 RestorationManager 异步获取。为确保提供的 child 首次构建时就能获得其恢复数据，根 bucket 可用之前，RootRestorationScope 会构建一个空的 Container，而不是实际的 child。为了不让用户看到这个空容器，显示容器期间 RootRestorationScope 还会延迟渲染第一帧。在启动时显示启动画面的平台上，启动画面会持续显示（隐藏空容器），直到 bucket 可用且 child 准备构建为止。

此 widget 的具体行为取决于其祖先：如果 RootRestorationScope 通过 RestorationScope.of 找不到祖先 restoration bucket，就会使用提供的 restorationId 从根 restoration bucket（RestorationManager.rootBucket）中获取一个子 bucket，并将其插入 widget 树，使后代能够通过 RestorationScope.of 访问。如果 RootRestorationScope 通过 RestorationScope.of 找到了非 null 的祖先 restoration bucket，则其行为与常规的 RestorationScope 相同：它会从该祖先获取子 bucket 并将其插入 widget 树。

与 RestorationScope widget 不同，只要 restorationId 不为 null 且 RestorationManager 能够提供根 bucket，RootRestorationScope 就会确保后代拥有可用于存储恢复数据的 bucket。换言之，只要 restorationId 不为 null，它就会为该子树强制启用状态恢复。

如果 restorationId 为 null，则不会向后代提供 bucket，这实际上会关闭此子树的状态恢复。
