描述此 widget 所表示的用户界面部分。

框架会在多种不同情况下调用此方法。例如：

  • After calling initState.
  • After calling didUpdateWidget.
  • After receiving a call to setState.
  • After a dependency of this State object changes (e.g., an InheritedWidget referenced by the previous build changes).
  • After calling deactivate and then reinserting the State object into the tree at another location.

此方法可能在每一帧中调用，因此除构建 widget 外不应产生任何副作用。

框架会将此 widget 下方的子树替换为此方法返回的 widget。根据返回的 widget 是否能够更新现有子树的根节点（由调用 Widget.canUpdate 判定），框架会更新现有子树，或移除它并重新创建子树。

通常，方法实现会返回一组新创建的 widget，并使用此 widget 构造函数提供的信息、给定的 BuildContext 以及此 State 对象的内部状态对其进行配置。

给定的 BuildContext 包含此 widget 在树中构建位置的信息。例如，它提供该位置上的继承 widget 集合。BuildContext 参数始终与此 State 对象的 context 属性相同，并且在对象的整个生命周期内保持不变。之所以在此重复提供 BuildContext 参数，是为了使此方法与 WidgetBuilder 的签名一致。

设计讨论

为什么 build 方法属于 State，而不属于 StatefulWidget？

将 Widget build(BuildContext context) 方法放在 State 上，而不是将 Widget build(BuildContext context, State state) 方法放在 StatefulWidget 上，可以让开发者在继承 StatefulWidget 时拥有更大的灵活性。

例如，AnimatedWidget 是 StatefulWidget 的子类，它引入了一个供子类实现的抽象 Widget build(BuildContext context) 方法。如果 StatefulWidget 已经有一个接收 State 参数的 build 方法，那么即使 AnimatedWidget 的 State 对象属于其内部实现细节，它也不得不将该 State 对象提供给子类，即使它是 AnimatedWidget 的内部实现细节。

从概念上讲，StatelessWidget 也可以用类似方式实现为 StatefulWidget 的子类。如果 build 方法属于 State 而非 StatefulWidget，这种实现方式就不再可行。

将 build 函数放在 State 而非 StatefulWidget 上，还能避免一类与闭包隐式捕获 this 有关的错误。如果在 StatefulWidget 的 build 函数中定义闭包，它会隐式捕获 this（即当前 widget 实例），并能访问该实例不可变的字段：

// (this is not valid Flutter code)
class MyButton extends StatefulWidgetX {
  MyButton({super.key, required this.color});

  final Color color;

  @override
  Widget build(BuildContext context, State state) {
    return SpecialWidget(
      handler: () { print('color: $color'); },
    );
  }
}

例如，假设父级构建 MyButton 时将 color 设为蓝色，打印函数中的 $color 会如预期那样引用蓝色。之后父级将 MyButton 重建为绿色时，第一次构建创建的闭包仍会隐式引用原始 widget，因此 $color 仍打印蓝色，即使 widget 已更新为绿色。如果该闭包的生命周期超过 widget，它就会输出过时信息。

相比之下，将 build 函数放在 State 对象上时，build 期间创建的闭包会隐式捕获 State 实例，而非 widget 实例：

class MyButton extends StatefulWidget {
  const MyButton({super.key, this.color = Colors.teal});

  final Color color;
  // ...
}

class MyButtonState extends State<MyButton> {
  // ...
  @override
  Widget build(BuildContext context) {
    return SpecialWidget(
      handler: () { print('color: ${widget.color}'); },
    );
  }
}

现在，当父级将 MyButton 重建为绿色时，第一次构建创建的闭包仍引用在多次构建间保持不变的 State 对象；但框架已更新该 State 对象的 widget 属性，使其指向新的 MyButton 实例，因此 ${widget.color} 会如预期那样输出绿色。
