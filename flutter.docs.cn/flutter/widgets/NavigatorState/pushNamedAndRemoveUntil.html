将具有给定名称的路由推入 Navigator，然后移除所有先前路由，直到 predicate 返回 true。

如果 Route.willHandlePopInternally 为 true，同一路由可能会多次应用该谓词。

若要移除路由，直到遇到具有指定名称的路由，请使用 RoutePredicate 返回的 ModalRoute.withName。

若要移除推入路由下方的所有路由，请使用始终返回 false 的 RoutePredicate（例如，(Route<dynamic> route) => false）。

被移除的路由不会完成，因此此方法不接收返回值参数。

新路由的名称（routeName）会传递给 Navigator.onGenerateRoute 回调。回调返回的路由将被推入 Navigator。

The new route and the route below the bottommost removed route (which becomes the route below the new route) are notified (see Route.didPush 和 Route.didChangeNext). If the Navigator has any Navigator.observers, they will be notified as well (see NavigatorObserver.didPush 和 NavigatorObserver.didRemove). The removed routes are disposed, once the new route has finished animating, and the futures that had been returned from pushing those routes will complete.

向当前路由推入新路由时，当前路由中正在进行的手势会被取消。

类型参数 T 表示新路由返回值的类型。

使用 pushNamedAndRemoveUntil 时，必须提供 Navigator.onGenerateRoute 回调。

返回一个 Future；当推入的路由从 Navigator 弹出时，该 Future 会完成，并携带传递给 pop 的 result 值。

提供的 arguments 会通过 RouteSettings.arguments 传递给被推入的路由。arguments 可以是任意对象（例如 String、int，或自定义的 MyRouteArguments 类实例）。通常使用 Map 传递键值对。

arguments 可用于 Navigator.onGenerateRoute 或 Navigator.onUnknownRoute，以构造路由。

典型用法如下：
link 
void _handleOpenCalendar() {
  navigator.pushNamedAndRemoveUntil('/calendar', ModalRoute.withName('/'));
}

另请参阅：

  • restorablePushNamedAndRemoveUntil, which pushes a new route that can be restored during state restoration.

实现

@awaitNotRequired
@optionalTypeArgs
Future<T?> pushNamedAndRemoveUntil<T extends Object?>(
  String newRouteName,
  RoutePredicate predicate, {
  Object? arguments,
}) {
  return pushAndRemoveUntil<T?>(_routeNamed<T>(newRouteName, arguments: arguments)!, predicate);
}
