将具有给定名称的路由推入距离给定 context 最近的 Navigator，然后移除所有先前路由，直到 predicate 返回 true。

与通过 pushNamedAndRemoveUntil 推入的 Route 不同，通过此方法推入的 Route 会按照 Navigator“状态恢复”一节中概述的规则，在状态恢复期间还原。

如果 Route.willHandlePopInternally 为 true，同一路由可能会多次应用该谓词。

若要移除路由，直到遇到具有指定名称的路由，请使用 RoutePredicate 返回的 ModalRoute.withName。

若要移除推入路由下方的所有路由，请使用始终返回 false 的 RoutePredicate（例如，(Route<dynamic> route) => false）。

被移除的路由不会完成，因此此方法不接收返回值参数。

新路由的名称（routeName）会传递给 Navigator.onGenerateRoute 回调。回调返回的路由将被推入 Navigator。

新路由和被移除路由中最底层路由下方的路由（该路由会成为新路由下方的路由）都会收到通知（参见 Route.didPush 和 Route.didChangeNext）。如果 Navigator 配置了 Navigator.observers，观察者也会收到通知（参见 NavigatorObserver.didPush 和 NavigatorObserver.didRemove）。新路由完成动画后，被移除的路由会被释放；推入这些路由时返回的 futures 也会完成。

向当前路由推入新路由时，当前路由中正在进行的手势会被取消。

类型参数 T 表示新路由返回值的类型。

使用 pushNamedAndRemoveUntil 时，必须提供 Navigator.onGenerateRoute 回调。

提供的 arguments 会通过 RouteSettings.arguments 传递给被推入的路由。可以传入任何可由 StandardMessageCodec 序列化的对象作为 arguments。通常使用 Map 传递键值对。

arguments 可用于 Navigator.onGenerateRoute 或 Navigator.onUnknownRoute，以构造路由。

该方法会返回一个不透明 ID，用于标识推入的路由。借助此 ID，RestorableRouteFuture 可以获取加入 Navigator 的实际 Route 对象及其返回值。如果不关心路由对象或其返回值，可以忽略此方法的返回值。

典型用法如下：
link 
void _openCalendar() {
  navigator.restorablePushNamedAndRemoveUntil('/calendar', ModalRoute.withName('/'));
}

实现

@optionalTypeArgs
String restorablePushNamedAndRemoveUntil<T extends Object?>(
  String newRouteName,
  RoutePredicate predicate, {
  Object? arguments,
}) {
  assert(
    debugIsSerializableForRestoration(arguments),
    'The arguments object must be serializable via the StandardMessageCodec.',
  );
  final _RouteEntry entry = _RestorationInformation.named(
    name: newRouteName,
    arguments: arguments,
    restorationScopeId: _nextPagelessRestorationScopeId,
  ).toRouteEntry(this, initialState: _RouteLifecycle.push);
  _pushEntryAndRemoveUntil(entry, predicate);
  return entry.restorationId!;
}
