从距离给定 context 最近的 Navigator 中弹出当前路由，并在其位置推入一个命名路由。

与通过 popAndPushNamed 推入的 Route 不同，通过此方法推入的 Route 会按照 Navigator“状态恢复”一节中概述的规则，在状态恢复期间还原。

先前路由的弹出操作按照 pop 的规则处理。

新路由的名称会传递给 Navigator.onGenerateRoute 回调。回调返回的路由将被推入 Navigator。

新路由、旧路由以及旧路由下方的路由（如果存在）都会收到通知（参见 Route.didPop、Route.didComplete、Route.didPopNext、Route.didPush 和 Route.didChangeNext）。如果 Navigator 配置了 Navigator.observers，观察者也会收到通知（参见 NavigatorObserver.didPop 和 NavigatorObserver.didPush）。弹出和推入动画会同时执行，因此即使新旧路由都是不透明的，下方路由也可能短暂可见（参见 TransitionRoute.opaque）。

向当前路由推入新路由时，当前路由中正在进行的手势会被取消。

类型参数 T 是新路由返回值的类型，TO 是旧路由返回值的类型。

使用 popAndPushNamed 时，必须提供 Navigator.onGenerateRoute 回调。

提供的 arguments 会通过 RouteSettings.arguments 传递给被推入的路由。可以传入任何可由 StandardMessageCodec 序列化的对象作为 arguments。通常使用 Map 传递键值对。

arguments 可用于 Navigator.onGenerateRoute 或 Navigator.onUnknownRoute，以构造路由。

该方法会返回一个不透明 ID，用于标识推入的路由。借助此 ID，RestorableRouteFuture 可以获取加入 Navigator 的实际 Route 对象及其返回值。如果不关心路由对象或其返回值，可以忽略此方法的返回值。

典型用法如下：
link 
void _end() {
  navigator.restorablePopAndPushNamed('/nyc/1776');
}

实现

@optionalTypeArgs
String restorablePopAndPushNamed<T extends Object?, TO extends Object?>(
  String routeName, {
  TO? result,
  Object? arguments,
}) {
  pop<TO>(result);
  return restorablePushNamed(routeName, arguments: arguments);
}
