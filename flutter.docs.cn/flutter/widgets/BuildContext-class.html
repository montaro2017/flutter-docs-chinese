BuildContext 类 抽象

用于指向 Widget 树中某个 Widget 所在位置的句柄。

此类提供一组方法，可在 StatelessWidget.build 方法以及 State 对象的方法中使用。

BuildContext 对象会传递给 WidgetBuilder 函数（例如 StatelessWidget.build），也可通过 State.context 成员访问。一些静态函数（例如 showDialog、Theme.of 等）也会接收 build context，以便代表调用它们的 Widget 执行操作，或获取特定于给定 context 的数据。

每个 Widget 都有自己的 BuildContext；它会成为 StatelessWidget.build 或 State.build 函数所返回 Widget 的父级。（对于 RenderObjectWidget，它同样是其所有子项的父级。）

具体来说，在 build 方法中，拥有该方法的 Widget 的 build context，与该方法返回的 Widget 所具有的 build context 并不相同。这可能导致一些棘手的情况。例如，Theme.of(context) 会查找给定 build context 最近的祖先 Theme。如果 Widget Q 的 build 方法在其返回的 Widget 树中包含一个 Theme，并使用自身的 context 调用 Theme.of，那么 Q 的 build 方法无法找到这个 Theme 对象，而会找到作为 Widget Q 祖先的 Theme。若需要返回树中某个子部分的 build context，可以使用 Builder Widget：传递给 Builder.builder 回调的 build context 就属于 Builder 本身。

例如，在下面的代码片段中，会对 build 方法自身创建的 Scaffold Widget 调用 ScaffoldState.showBottomSheet 方法。如果没有使用 Builder，而是使用 build 方法本身的 context 参数，就找不到 Scaffold，Scaffold.of 函数也会返回 null。

@override
Widget build(BuildContext context) {
  // here, Scaffold.of(context) returns null
  return Scaffold(
    appBar: AppBar(title: const Text('Demo')),
    body: Builder(
      builder: (BuildContext context) {
        return TextButton(
          child: const Text('BUTTON'),
          onPressed: () {
            Scaffold.of(context).showBottomSheet(
              (BuildContext context) {
                return Container(
                  alignment: Alignment.center,
                  height: 200,
                  color: Colors.amber,
                  child: Center(
                    child: Column(
                      mainAxisSize: MainAxisSize.min,
                      children: <Widget>[
                        const Text('BottomSheet'),
                        ElevatedButton(
                          child: const Text('Close BottomSheet'),
                          onPressed: () {
                            Navigator.pop(context);
                          },
                        )
                      ],
                    ),
                  ),
                );
              },
            );
          },
        );
      },
    )
  );
}

某个 Widget 的 BuildContext 可能会随着 Widget 在树中的移动而改变位置。因此，此类方法返回的值不应在单次同步函数执行结束后继续缓存。

避免存储 BuildContext 实例，因为关联的 Widget 从树中卸载后，这些实例可能失效。如果在异步间隔中（即执行异步操作之后）使用 BuildContext，请考虑先检查 mounted，确认 context 仍然有效，再与其交互：

  @override
  Widget build(BuildContext context) {
    return OutlinedButton(
      onPressed: () async {
        await Future<void>.delayed(const Duration(seconds: 1));
        if (context.mounted) {
          Navigator.of(context).pop();
        }
      },
      child: const Text('Delayed pop'),
    );
  }

BuildContext 对象实际上是 Element 对象。使用 BuildContext 接口是为了避免直接操作 Element 对象。
