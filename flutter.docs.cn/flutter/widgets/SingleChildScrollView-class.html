description

SingleChildScrollView 类

一个可滚动单个 widget 的区域。

当只有一个区域且通常可以完整显示时，此 widget 很有用，例如时间选择器中的钟面；但如果容器在某个方向（滚动方向）上变得过小，又需要确保内容可滚动。

如果需要在两个方向上都收缩包裹（主滚动方向和横轴方向），此 widget 也很有用，例如对话框或弹出菜单中的布局。此时可将 SingleChildScrollView 与 ListBody 子 widget 配合使用。

如果有多个子级且不需要横轴收缩包裹（例如宽度始终等于屏幕宽度的滚动列表），请考虑使用 ListView。与包含许多子级的 ListBody 或 Column 的 SingleChildScrollView 相比，ListView 的效率高得多。

示例代码：将 SingleChildScrollView 与 Column 配合使用

有时，布局会依赖 Column 的弹性属性设计，但某些情况下可能没有足够空间显示全部内容。例如，某些设备的屏幕特别小，应用可能会在屏幕比例与预期不同的横屏模式下运行，或应用可能显示在分屏模式的小窗口中。因此，可以考虑用 SingleChildScrollView 包裹此布局。

但这样通常会导致冲突：Column 往往会尽可能扩展，而 SingleChildScrollView 会为其子级提供无限空间。

如下所述，可以通过几种技巧解决这一表面上的冲突。这些技巧只适用于通常预期内容能在屏幕内完整显示的情况；在此情况下，基于 sliver 的 ListView 或 CustomScrollView 的延迟实例化预计不会带来性能收益。如果视口通常需要容纳超出屏幕尺寸的内容，SingleChildScrollView 会非常耗费资源（此时使用 ListView 可能比使用 Column 更合适）。

居中、留白或对齐固定高度的内容

如果内容尺寸固定（或为内在尺寸），但需要使用 Flex 布局模型通过 Column 进行留白、居中或其他定位，可使用以下技巧为 Column 提供最小尺寸，同时在空间不足以满足留白或对齐要求时，让其收缩包裹内容。

使用 LayoutBuilder 获取视口尺寸（间接通过 SingleChildScrollView 收到的约束获取，因为视口通常会扩展到最大高度约束）。然后在滚动视图内使用 ConstrainedBox 设置 Column 的最小高度。

Column 没有 Expanded 子级，因此它不会采用来自 BoxConstraints.maxHeight 的无限高度（视口不会提供最大高度约束），而是自动收缩到适合其子级的尺寸。不过它不能小于 BoxConstraints.minHeight，所以最终尺寸会取 ConstrainedBox 提供的最小高度与子级高度总和中的较大值。

如果子级不足以填满该最小尺寸，Column 就会有剩余空间，并按照其 Column.mainAxisAlignment 参数分配这些空间。

在此示例中，子级会均匀分布；如果空间不足，它们就会垂直堆叠并允许滚动。

When using this technique, Expanded 和 Flexible are not useful, because in both cases the "available space" is infinite (since this is in a viewport). The next section describes a technique for providing a maximum height constraint.

扩展内容以填满视口

以下示例基于前一个示例进行了扩展。除了为子级 Column 提供最小尺寸外，还使用 IntrinsicHeight widget 强制 Column 的尺寸恰好等于其内容高度。此约束与前面讨论的 ConstrainedBox 约束结合后，可确保 Column 的尺寸至少与视口一样大，也至少与内容一样大。

两种约束都必须使用，才能获得预期效果。如果只指定 IntrinsicHeight，当子级小于整个屏幕时，Column 不会扩展到填满视口。如果只使用视口尺寸，则子级大于视口时，Column 会溢出。

要扩展以填满剩余空间的 widget，需要用 Expanded widget 包裹。

此技巧开销很大，因为视口中的内容大致需要布局两次（一次用于计算内在尺寸，另一次用于实际布局）。因此，Column 中的 widget 数量应保持较少。或者，也可以将尺寸已知的子级子集放入 SizedBox，并施加严格的垂直约束，这样内在尺寸算法处理到子树这些部分时就能提前结束计算。

In this example, the column becomes either as big as viewport, or as big as the contents, whichever is biggest.

在会话期间保留滚动位置

滚动视图会尝试使用 PageStorage 持久化滚动位置。可通过将 ScrollController.keepScrollOffset 设为 false 来禁用此行为。若启用，建议将 PageStorageKey 用作此 widget 的 key，并通过 controller 配置，以便区分不同的滚动视图。
