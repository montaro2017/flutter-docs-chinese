RestorableProperty<T> 类 抽象

管理类型为 T 的对象，该对象的值是 State 状态对象希望在状态恢复期间恢复的内容。

此属性会包装类型为 T 的对象。它知道如何将该对象的值保存到状态恢复数据中，也知道如何根据之前保存的信息重新创建该对象。

如何将被包装对象保存到状态恢复数据中的逻辑由 toPrimitives 方法定义；如何根据这些数据重新创建对象的逻辑则由 fromPrimitives 方法定义。调用 toPrimitives 必须返回被包装对象的表示形式，且该形式可通过 StandardMessageCodec 序列化。如果返回了集合（例如 List、Map 等），则在 toPrimitives 返回这些集合后不得再修改它们。之后（可能是在应用重启后），可以将从 toPrimitives 获得的数据传回属性的 fromPrimitives 方法，以恢复数据所描述的先前状态。

必须使用在此 mixin 内唯一的状态恢复 ID，将 RestorableProperty 注册到 RestorationMixin。RestorationMixin 会提供并管理 RestorationBucket，并在其中保存 toPrimitives 返回的数据。

每当 toPrimitives 返回的值（或 enabled getter）发生变化，RestorableProperty 都必须调用 notifyListeners。这会触发 RestorationMixin 将存储在其 RestorationBucket 中的此属性数据更新为 toPrimitives 返回的最新信息。

将属性注册到 RestorationMixin 时，mixin 会检查是否有可用的状态恢复数据。如果有，mixin 会在属性上调用 fromPrimitives；该方法必须返回一个对象，与获取所提供恢复数据时该属性包装的对象相匹配，相关数据通过 toPrimitives 获得。如果没有可用于恢复被包装对象的数据，mixin 会调用 createDefaultValue。这两个方法之一返回的值随后会传给属性的 initWithValue 方法。

通常，RestorableProperty 的子类会保留通过 initWithValue 提供给它们的值，并将该值提供给拥有此属性的 State 对象使用。但这个 RestorableProperty 基类并不规定如何处理传给 initWithValue 的值。

在 RestorationMixin 的生命周期中，它可能多次调用 fromPrimitives（如果新状态恢复数据包含恢复属性所需的信息）或 createDefaultValue（如果新数据不包含相关信息），随后调用 initWithValue。每当向注册此属性的 RestorableProperty 提供新的状态恢复数据时，都会重复这一流程。每次调用 RestorationMixin、fromPrimitives 或 createDefaultValue 来获取新值，并随后调用 initWithValue 时，属性都应忘记旧的包装值，并使用新提供的值重新初始化；再次调用 initWithValue 也应按此规则初始化。

典型用法是：实例化 RestorableProperty 的子类，以初始化 State 对象的成员变量，或在 State.initState 中实例化；然后在 RestorationMixin 中将其注册到 RestorationMixin.restoreState，之后在 dispose 中调用 State.dispose。在较少见的用法中（例如，只有当 RestorableProperty 对象处于某种特定状态时才需要 State 中保存的值），首次调用 RestorableProperty 后的任意时间都可以将 RestorationMixin 注册到 RestorationMixin.restoreState。在所属的 RestorableProperty 对象释放之前，也可以通过调用 RestorationMixin 从 State 注销 RestorationMixin.unregisterFromRestoration。不过这种做法并不常见，而且会删除此属性写入状态恢复数据的信息（这意味着将来进行状态恢复时不会再恢复该属性的值）。
