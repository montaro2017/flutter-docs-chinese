OverlayEntry 类

Overlay 中可用于容纳 widget 的位置。

使用 OverlayState.insert 或 OverlayState.insertAll 函数将 Overlay 条目插入 Overlay。若要查找包围给定 BuildContext 的最近 Overlay，请使用 Overlay.of 函数。

一个 Overlay 条目同时最多只能属于一个 Overlay。要从所属 Overlay 中移除条目，请对该条目调用 remove 函数。

Because an Overlay uses a Stack layout, overlay entries can use Positioned 和 AnimatedPositioned to position themselves within the overlay.

例如，拖动开始后，Draggable 会使用 OverlayEntry 显示拖动头像，并让它跟随用户的手指在屏幕上移动。使用 Overlay 显示拖动头像，可使其浮在应用中其他 widget 上方。手指移动时，Draggable 会对该 Overlay 条目调用 markNeedsBuild 以触发重建。构建条目时，会包含一个 Positioned，并设置其 top 和 left 属性，将拖动头像定位在手指附近。拖动结束后，Draggable 会从 Overlay 中移除该条目，使拖动头像不再显示。

默认情况下，如果此条目上方有完全不透明的条目，就不会将此条目加入 widget 树（尤其是不会实例化 overlay 条目中的有状态 widget）。若要确保 overlay 条目即使不可见也仍然构建，请将 maintainState 设为 true。这样会增加开销，应谨慎使用。特别是，如果启用了 maintainState 的 overlay 条目中的 widget 反复调用 State.setState，会无谓地消耗用户设备的电量。

OverlayEntry 是一个 Listenable：当 builder 构建的 widget 挂载或卸载时，它会发出通知；具体状态可通过 mounted 查询。OverlayEntry 的所有者调用 remove，随后调用 dispose 后，widget 可能不会立即从 widget 树中移除。因此，当 widget 最终卸载时，OverlayEntry 的监听器可能会在 dispose 调用后最后收到一次通知。

OverlayPortal 与 OverlayEntry 的区别

The main difference between OverlayEntry 和 OverlayPortal is that OverlayEntry builds its widget subtree as a child of the target Overlay, while OverlayPortal uses OverlayPortal.overlayChildBuilder to build a child widget of itself. This allows OverlayPortal's overlay child to depend on the same set of InheritedWidgets as OverlayPortal, and it's also guaranteed that the overlay child will not outlive its OverlayPortal.

另一方面，OverlayPortal 的实现更复杂。例如，在全局键重新挂接期间，它比常规 widget 需要执行更多工作。如果要显示在 Overlay 上的内容并不需要成为 OverlayPortal 子树的一部分，请考虑改用 OverlayEntry。
