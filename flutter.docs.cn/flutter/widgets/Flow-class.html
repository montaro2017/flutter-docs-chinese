Flow 类

根据 FlowDelegate 中的逻辑，高效调整子项尺寸并确定其位置的 widget。

Flow 布局针对使用变换矩阵重新定位子项进行了优化。

Flow 容器的尺寸由委托的 FlowDelegate.getSize 函数独立确定。随后，根据 FlowDelegate.getConstraintsForChild 函数提供的约束，分别确定各子项的尺寸。

子项不会在布局阶段定位，而是在绘制阶段使用变换矩阵定位；这些矩阵由 FlowDelegate.paintChildren 函数提供。只需重新绘制 Flow 即可高效地重新定位子项，无需再次布局子项。（与此不同，Stack 会在布局阶段同时确定尺寸和位置。）

触发 Flow 重绘的最高效方式，是向 FlowDelegate 构造函数提供动画。Flow 会监听此动画，并在每次动画时钟触发时重绘，从而跳过流水线中的构建和布局阶段。

命中测试与隐藏的 Flow widget

Flow widget 会在绘制阶段（而非布局阶段）重新计算子项的位置（命中测试也使用这些位置）。

当子项因透明度为零而不可见时，Opacity 等 widget 会避免绘制这些子项。

遗憾的是，这意味着如果使用 Opacity widget 隐藏 Flow widget，用户尝试与隐藏区域交互（例如轻触或点击）时会出现错误。

这些错误可能表现为几何信息过期（轻触被发送给与当前指定的 FlowDelegate 不符的 widget），也可能表现为异常（例如，上次绘制 Flow 时指定的子项集合已不同）。

使用 Opacity（或 AnimatedOpacity 等类似 widget）隐藏 Flow 时，建议同时使用 IgnorePointer 禁用该 widget 的命中测试。无论如何，这通常都是好建议，因为对不可见 widget 进行命中测试往往会令用户困惑。

另请参阅：

  • Wrap：提供某些其他框架称为“flow”的布局模型；除此之外，它与 Flow 无关。
  • Stack：相对于容器边缘排列子项。
  • CustomSingleChildLayout：使用委托控制单个子项的布局。
  • CustomMultiChildLayout：使用委托定位多个子项。
  • 布局 widget 目录。
