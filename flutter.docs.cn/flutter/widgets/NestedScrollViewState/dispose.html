void dispose()
重写

此对象从树中永久移除时调用。

框架会在此 State 对象今后不再构建时调用此方法。调用 dispose 后，该 State 对象会被视为已卸载，mounted 属性也会变为 false。此时调用 setState 会导致错误。此生命周期阶段是终态：已释放的 State 对象无法重新挂载。

子类应重写此方法，以释放此对象保留的资源（例如停止正在运行的动画）。

如果 State 的 build 方法依赖可能自行改变状态的对象（例如 ChangeNotifier、Stream，或其他可订阅以接收通知的对象），请务必在 initState、didUpdateWidget 和 dispose 中正确订阅和取消订阅：

    在 initState 中订阅该对象。 在 didUpdateWidget 中，如果更新后的 widget 配置需要替换该对象，则取消订阅旧对象并订阅新对象。 在 dispose 中取消订阅该对象。

实现应以调用继承的方法结束，例如 super.dispose()。

注意事项

在开发者可能预期的某些情况下（例如应用关闭，或通过平台原生方法关闭界面），此方法不会被调用。

应用关闭

无法预测应用何时关闭。例如，用户的电池可能起火、设备可能掉进游泳池，或者操作系统可能因内存压力而单方面终止应用进程。

应用应确保自身即使在快速且非计划的终止情况下也能妥善处理。

若要人为地销毁整个组件树，可考虑调用 runApp 并传入诸如 SizedBox.shrink 这样的组件。

若要监听平台关闭消息（以及其他生命周期变化），可以使用 AppLifecycleListener API。

通过平台原生方法关闭 Flutter 界面

应用可能同时包含 Flutter 界面和非 Flutter 界面。如果应用调用非 Flutter 方法移除基于 Flutter 的界面（例如通过平台原生 API 操作平台原生导航栈），框架无法判断开发者是否希望立即释放资源。Widget 树会保持挂载状态，并在界面再次显示时立即恢复渲染。

关于如何更早释放资源的建议，请参阅用于启动应用的方法（例如 runApp 或 runWidget）。

另请参阅：

  • deactivate，会在调用 dispose 前触发。

实现

@protected
@override
void dispose() {
  _coordinator!.dispose();
  _coordinator = null;
  _absorberHandle.dispose();
  super.dispose();
}
