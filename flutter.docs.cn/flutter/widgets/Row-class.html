Row 类

沿水平方向排列并显示子 widget 的 widget。

如果要让子 widget 扩展以填满可用的水平空间，请将其包装在 Expanded widget 中。

Row widget 不会滚动（通常，子 widget 多到无法放入可用空间也会被视为错误）。如果 Row 中有一行 widget，并希望空间不足时可以滚动，请考虑使用 ListView。

垂直排列的对应 widget 是 Column。

如果只有一个子 widget，可以考虑使用 Align 或 Center 来定位它。

默认情况下，crossAxisAlignment 为 CrossAxisAlignment.center，会沿垂直轴居中排列子 widget。如果多个子 widget 包含文本，它们使用的字体度量不同（例如 TextStyle.fontSize 或其他 TextStyle 属性不同，或者因为使用不同书写系统而采用不同字体），文本可能会在视觉上错位。此时可以考虑改用 CrossAxisAlignment.baseline。

此示例将可用空间水平分为三份，在前两个区域中居中放置文本，并在第三个区域中居中放置 Flutter logo：

link 
const Row(
  children: <Widget>[
    Expanded(
      child: Text('Deliver features faster', textAlign: TextAlign.center),
    ),
    Expanded(
      child: Text('Craft beautiful UIs', textAlign: TextAlign.center),
    ),
    Expanded(
      child: FittedBox(
        child: FlutterLogo(),
      ),
    ),
  ],
)

问题排查

为什么我的 Row 上出现黄黑警告条纹？

如果 Row 中不可伸缩的内容（即未包装在 Expanded 或 Flexible widget 中的内容）合起来比 Row 本身更宽，就会发生溢出。发生溢出时，Row 没有剩余空间可分配给其 Expanded 和 Flexible 子 widget。Row 会在发生溢出的边缘绘制黄黑相间的警告框来报告问题。如果 Row 外侧还有空间，溢出量会以红色文字显示。

问题示例

例如，假设有如下代码：

const Row(
  children: <Widget>[
    FlutterLogo(),
    Text("Flutter's hot reload helps you quickly and easily experiment, build UIs, add features, and fix bug faster. Experience sub-second reload times, without losing state, on emulators, simulators, and hardware for iOS and Android."),
    Icon(Icons.sentiment_very_satisfied),
  ],
)

Row 首先要求第一个子 widget FlutterLogo 进行布局，大小由 logo 自行决定。这个 logo 很友好，欣然选择边长 24 像素。这样便为下一个子 widget 留出了充足空间。随后 Row 要求文本 widget 按它认为合适的大小进行布局。

此时文本并不知道多宽才算过宽，于是回答：“好吧，我就要这么宽。”然后它一路延伸，远远超出 Row 可用的空间，而且不换行。Row 便回应：“这不公平，我已经没有空间留给其他子 widget 了！”于是生气地显示出黄黑条纹。

解决方法是将第二个子 widget 包装在 Expanded widget 中，告诉 Row 应将剩余空间分配给该子 widget：

const Row(
  children: <Widget>[
    FlutterLogo(),
    Expanded(
      child: Text("Flutter's hot reload helps you quickly and easily experiment, build UIs, add features, and fix bug faster. Experience sub-second reload times, without losing state, on emulators, simulators, and hardware for iOS and Android."),
    ),
    Icon(Icons.sentiment_very_satisfied),
  ],
)

现在，Row 会先要求 logo 进行布局，再要求 icon 布局。和 logo 一样，Icon 也很乐意采用合理大小（同样为 24 像素；这并非巧合，因为 FlutterLogo 和 Icon 都遵循环境中的 IconTheme）。这样会留下一些剩余空间，于是 Row 会明确告知文本其宽度，也就是剩余空间的精确宽度。文本现在可以按合理要求换行，因此最终会得到分成多行的段落。

textDirection 属性控制子 widget 的渲染方向。TextDirection.ltr 是 Row 子 widget 默认的 textDirection，因此第一个子 widget 会渲染在 Row 的 start 端，也就是左侧；后续子 widget 依次排列在右侧。如果要让子 widget 按相反方向（从右向左）排列，可以将 textDirection 设为 TextDirection.rtl。下例展示了这种情况。

const Row(
  textDirection: TextDirection.rtl,
  children: <Widget>[
    FlutterLogo(),
    Expanded(
      child: Text("Flutter's hot reload helps you quickly and easily experiment, build UIs, add features, and fix bug faster. Experience sub-second reload times, without losing state, on emulators, simulators, and hardware for iOS and Android."),
    ),
    Icon(Icons.sentiment_very_satisfied),
  ],
)

布局算法

本节介绍框架如何渲染 Row。 有关盒约束布局模型的介绍，请参阅 BoxConstraints。

Row 的布局分为六个步骤：

  1. 使用不受限制的水平约束和传入的垂直约束对子项进行布局，例如没有 flex 因子或 flex 因子为零的子项（即非 Expanded 子项）。如果 crossAxisAlignment 为 CrossAxisAlignment.stretch，则改用与传入最大高度相匹配的紧垂直约束。
  2. 根据各自的 flex 因子，将剩余水平空间分配给 flex 因子非零的子项（例如 Expanded）。例如，flex 因子为 2.0 的子项会获得 flex 因子为 1.0 的子项两倍的水平空间。
  3. 按照第 1 步中相同的垂直约束对子项进行布局；不同之处在于，不使用不受限制的水平约束，而是根据第 2 步分配的空间设置水平约束。Flexible.fit 属性为 FlexFit.tight 的子项会受到紧约束（即必须填满分配的空间）；属性为 Flexible.fit 的子项若为 FlexFit.loose，则会受到宽松约束（无需填满分配的空间）。
  4. Row 的高度取其子项的最大高度（该高度始终满足传入的垂直约束）。
  5. Row 的宽度由 mainAxisSize 属性决定。如果 mainAxisSize 为 MainAxisSize.max，则 Row 的宽度等于传入约束所允许的最大宽度。如果 mainAxisSize 为 MainAxisSize.min，则 Row 的宽度等于所有子项宽度之和（同时受传入约束限制）。
  6. 根据 mainAxisAlignment 和 crossAxisAlignment 确定每个子项的位置。例如，如果 mainAxisAlignment 为 MainAxisAlignment.spaceBetween，尚未分配给子项的水平空间会被平均分配到各子项之间。

另请参阅：

  • Column 是垂直方向的对应组件。
  • 如果事先无法确定要采用水平排列还是垂直排列，请使用 Flex。
  • 使用 Expanded 表示子项应占据所有剩余空间。
  • 使用 Flexible 表示子项应共享剩余空间，但可以缩小尺寸，从而留下一部分未使用空间。
  • Spacer 是一个按其 flex 值成比例占用空间的组件。
  • 另请参阅：布局组件目录。
