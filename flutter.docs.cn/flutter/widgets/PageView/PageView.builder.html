创建一个按页面滚动的可滚动列表，子项会按需构建。

此构造函数适用于子项数量较多（或无限）的页面视图，因为只有实际可见的子项才会调用构建器。

提供非 null 的 itemCount 后，PageView 就能计算最大滚动范围。

itemBuilder 仅会收到大于或等于零且小于 itemCount 的索引。

itemBuilder 返回 null 是合法的。如果发生这种情况，即使尚未到达 itemCount，滚动视图也会停止调用 itemBuilder。由于返回了 null，除非用户已滚动到 ScrollPosition.maxScrollExtent 的末尾，否则 ScrollView 将不准确；这也可能导致 Scrollbar 随着用户滚动而增长。

若要获得更准确的 ScrollMetrics，请考虑指定 itemCount。

findChildIndexCallback 对应 SliverChildBuilderDelegate.findChildIndexCallback 属性。如果该回调为 null，当子节点构建器返回的子 Widget 顺序变化时，子 Widget 可能无法映射到现有的 RenderObject，从而导致状态丢失。如果子节点顺序之后可能发生变化，就必须实现此回调。

如果 allowImplicitScrolling 为 true，PageView 参与辅助功能滚动的方式会更像 ListView：隐式滚动操作会移至下一页，而不是滚入 PageView 的内容区域。

实现

PageView.builder({
  super.key,
  this.scrollDirection = Axis.horizontal,
  this.reverse = false,
  this.controller,
  this.physics,
  this.pageSnapping = true,
  this.onPageChanged,
  required NullableIndexedWidgetBuilder itemBuilder,
  ChildIndexGetter? findChildIndexCallback,
  int? itemCount,
  this.dragStartBehavior = DragStartBehavior.start,
  this.allowImplicitScrolling = false,
  ScrollCacheExtent? scrollCacheExtent,
  this.restorationId,
  this.clipBehavior = Clip.hardEdge,
  this.hitTestBehavior = HitTestBehavior.opaque,
  this.scrollBehavior,
  this.padEnds = true,
}) : assert(
       scrollCacheExtent == null || (scrollCacheExtent.value > 0.0) == allowImplicitScrolling,
       'scrollCacheExtent and allowImplicitScrolling must be consistent: '
       'scrollCacheExtent must be greater than 0.0 when allowImplicitScrolling is true, '
       'and must be 0.0 when allowImplicitScrolling is false.',
     ),
     scrollCacheExtent =
         scrollCacheExtent ?? ScrollCacheExtent.viewport(allowImplicitScrolling ? 1.0 : 0.0),
     childrenDelegate = SliverChildBuilderDelegate(
       itemBuilder,
       findChildIndexCallback: findChildIndexCallback,
       childCount: itemCount,
     );
