NestedScrollView
description

NestedScrollView 类

一种滚动视图，内部可以嵌套其他滚动视图，并将它们的滚动位置自然关联起来。

此 widget 最常见的用法是：在标题区域中放置包含 TabBar 的弹性 SliverAppBar（由 headerSliverBuilder 构建），并在 body 中放置 TabBarView，使滚动视图的内容随当前显示的标签页而变化。

设计动机

普通的 ScrollView 只有一组 sliver（即滚动视图的组成部分）。如果其中一个 sliver 承载了一个滚动方向相反的 TabBarView（例如，用户可以在标签页所代表的页面间水平滑动，而列表垂直滚动），那么该 TabBarView 内的列表就不会与外层 ScrollView 联动。例如，将内层列表快速滑动到顶部时，外层 ScrollView 中已折叠的 SliverAppBar 不会展开。

NestedScrollView 通过为外层 ScrollView 和内层 ScrollView（位于 TabBarView 内）提供自定义的 ScrollController 来解决此问题，并将它们连接起来，使用户看到的是一个连贯的滚动视图。

This example shows a NestedScrollView whose header is the combination of a TabBar in a SliverAppBar and whose body is a TabBarView. It uses a SliverOverlapAbsorber/SliverOverlapInjector pair to make the inner lists align correctly, and it uses SafeArea to avoid any horizontal disturbances (e.g. the "notch" on iOS when the phone is horizontal). In addition, PageStorageKeys are used to remember the scroll position of each tab's list.

SliverAppBar 与 NestedScrollView

在外层滚动视图中使用 SliverAppBar，或在 NestedScrollView 的 headerSliverBuilder 中使用它，可能需要特别配置，才能达到外层和内层合并为一个滚动视图（例如 CustomScrollView）时的效果。

固定的 SliverAppBar

固定的 SliverAppBar 在 NestedScrollView 中的工作方式与在其他滚动视图（例如 CustomScrollView）中完全相同。使用 SliverAppBar.pinned 时，应用栏会保持在滚动视图顶部。用户滚动时，应用栏仍可展开和收缩，但会一直保持可见，不会滚出视野。

这在 NestedScrollView 中可以自然实现，因为固定的 SliverAppBar 不需要进出视口的可见区域。内层或外层 Scrollable 移动时，应用栏会如预期般保持固定。

如果应用栏同时具有浮动、固定和扩展高度特性，请遵循下文介绍的浮动配置方式。

浮动的 SliverAppBar

将浮动的 SliverAppBar 放在外层可滚动区域或 headerSliverBuilder 中时，使用 SliverAppBar.floating 并不会使其自动浮动到内层滚动视图或 body 上方。

这是因为浮动应用栏会使用自身 Scrollable 的滚动偏移量来决定浮动行为。由于内层和外层是两个独立的 Scrollable，外层标题中的 SliverAppBar 无法感知内层 body 的滚动偏移量变化。

要使外层区域浮动，请使用 NestedScrollView.floatHeaderSlivers。将其设为 true 后，嵌套滚动协调器会优先滚动标题 sliver，再将剩余拖动量应用到 body。

如果应用栏同时具有浮动、固定和扩展高度特性，也应启用 floatHeaderSlivers 标志。在这种配置下，应用栏的弹性空间会展开和收起，而主要部分仍保持固定。

This simple example shows a NestedScrollView whose header contains a floating SliverAppBar. By using the floatHeaderSlivers property, the floating behavior is coordinated between the outer and inner Scrollables, so it behaves as it would in a single scrollable.

吸附式 SliverAppBar

浮动的 SliverAppBar 还可以执行吸附动画。如果 SliverAppBar.snap 为 true，滚动操作使浮动应用栏露出时，会触发动画，将整个应用栏滑入视野。同样，如果滚动操作使应用栏隐藏，动画会将其完全滑出视野。

NestedScrollView 可以只执行吸附动画，而不让应用栏浮入或浮出。不要启用 NestedScrollView.floatHeaderSlivers，应用栏就会吸附进出，而不会浮动。

The SliverAppBar.snap animation should be used in conjunction with the SliverOverlapAbsorber 和 SliverOverlapInjector widgets when implemented in a NestedScrollView. These widgets take any overlapping behavior of the SliverAppBar in the header and redirect it to the SliverOverlapInjector in the body. If it is missing, then it is possible for the nested "inner" scroll view below to end up under the SliverAppBar even when the inner scroll view thinks it has not been scrolled.

This simple example shows a NestedScrollView whose header contains a snapping, floating SliverAppBar. Without setting any additional flags, e.g NestedScrollView.floatHeaderSlivers, the SliverAppBar will animate in and out without floating. The SliverOverlapAbsorber 和 SliverOverlapInjector maintain the proper alignment between the two separate scroll views.

吸附与浮动的 SliverAppBar

目前，NestedScrollView 不支持让外层滚动区域同时执行浮动和吸附，例如同时使用 SliverAppBar.floating 与 SliverAppBar.snap。

拉伸的 SliverAppBar

目前，NestedScrollView 不支持拉伸外层滚动区域，例如使用 SliverAppBar.stretch 时。

另请参阅：

  • SliverAppBar, for examples on different configurations like floating, pinned and snap behaviors.
  • SliverOverlapAbsorber, a sliver that wraps another, forcing its layout extent to be treated as overlap.
  • SliverOverlapInjector, a sliver that has a sliver geometry based on the values stored in a SliverOverlapAbsorberHandle.
