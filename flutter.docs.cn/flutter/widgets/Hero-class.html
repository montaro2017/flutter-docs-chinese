Hero 类

将其子组件标记为可参与Hero 动画的组件。

通过 Navigator 推入或弹出 PageRoute 时，整个屏幕的内容都会被替换：旧路由消失，新路由出现。如果两个路由上有共同的视觉元素，让该元素在路由切换期间从一页移动到另一页，有助于用户理解界面变化。这种动画称为 Hero 动画。切换期间，Hero 组件会在 Navigator 的覆盖层中“飞行”；默认情况下，它们飞行时不会显示在新旧路由中的原位置。

要将组件标记为这样的视觉元素，请用 Hero 组件包裹它。发生导航时，HeroController 会识别各路由中的 Hero 组件。每一对具有相同标记的 Hero 组件都会触发 Hero 动画。

如果导航发生时某个 Hero 正在飞行，其飞行动画会重定向到新的目的地。默认情况下，切换期间显示的飞行组件是目标路由中 Hero 的子组件。

要触发 Hero 动画，Hero 必须在新页面动画的第一帧中就已存在。

每个路由中，每个 tag 最多只能对应一个 Hero。

此示例展示了在 ListTile 中使用 Hero 的方式。

点按由 Hero 包裹的矩形会推入新的 MaterialPageRoute，从而触发 Hero 动画。矩形的大小和位置都会发生变化。

两个组件使用相同的 Hero.tag。

Hero 组件会使用匹配的标记来识别并执行此动画。

讨论

要使整个过程正常运行，Hero 及 Navigator 的 Overlay、Stack 都必须与坐标轴对齐。每个动画 Hero 的左上角和右下角坐标会先转换为全局坐标，再转换到该 Stack 的坐标空间。在动画期间，整个 Hero 子树会从原位置移出并放置到该 Stack 上。如果 Hero 未与坐标轴对齐，动画可能会以很不理想的方式失败。请勿旋转 Hero！

要让动画效果自然，两个位置上的 Hero 组件树必须基本一致。默认情况下，过渡期间会使用目标组件：从路由 A 前往路由 B 时，路由 B 的 Hero 组件会覆盖在路由 A 的 Hero 组件上。此外，如果 Hero 子树的外观会随 InheritedWidget（例如 MediaQuery 或 Theme）变化，那么由于路由 A 和路由 B 提供的此类 InheritedWidget 不同，Hero 动画可能会在开始或结束时出现不连续。可以提供自定义的 flightShuttleBuilder 来确保平滑过渡。默认的 flightShuttleBuilder 会对 MediaQuery 的内边距进行插值。如果 Hero 使用自定义 InheritedWidget，且动画中出现不连续，请尝试提供自定义的飞行中过渡效果，并通过 flightShuttleBuilder 实现。

默认情况下，路由 A 和路由 B 中的 Hero 在过渡组件于两个路由上方飞行动画期间都会隐藏。动画起飞后，可以使用 placeholderBuilder 在原位置显示自定义组件。

过渡期间，过渡组件会动画移动到路由 B 中 Hero 的位置，然后插入路由 B。返回时，默认情况下，路由 A 的 Hero 组件会先放到路由 B 的 Hero 原位置上，再沿相反方向播放动画。

嵌套 Navigator

如果任一或两个路由都包含嵌套的 Navigator，只有这些最顶层路由（由 Route.isCurrent 确定）中的 Hero 会参与动画；此处的最顶层路由是指这些嵌套 Navigator 的最顶层路由。与非嵌套情况一样，嵌套的 Navigator 中包含这些 Hero 的最顶层路由必须是 PageRoute。
