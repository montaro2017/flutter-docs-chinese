EditableText 类

一个基础的文本输入框。

此组件通过 TextInput 服务与系统交互，使用户可以编辑其中的文本。它还提供滚动、选择和光标移动功能。

EditableText 是一个底层组件，旨在作为自定义组件集的构建模块。若要获得完整的用户体验，请考虑使用 TextField 或 CupertinoTextField。

处理用户输入

目前，用户可以通过键盘或文本选择菜单更改此组件中的文本。用户插入或删除文本时，你会收到通知，并有机会修改新的文本值：

  • 首先会对用户输入应用 inputFormatters。

  • 随后，controller 的 TextEditingController.value 会更新为格式化后的结果，并通知 controller 的监听器。

  • 如果指定了 onChanged 回调，它会最后调用。

输入操作

可以提供 TextInputAction，以自定义 Android 和 iOS 软键盘上操作按钮的外观。默认操作为 TextInputAction.done。

Android 和 iOS 上有许多常见的 TextInputAction。不过，如果在调试模式下提供了当前平台不支持的 textInputAction，相应的 EditableText 获得焦点时会抛出错误。例如，在 Android 设备上运行时提供 iOS 的“emergencyCall”操作，在调试模式下就会报错。在发布模式下，不兼容的 TextInputAction 会被替换：Android 上替换为“unspecified”，iOS 上替换为“default”。可以先检查当前平台，再选择合适的 textInputAction。

生命周期

编辑完成时（例如按下键盘上的“完成”按钮），会执行两个操作：

第一步：结束编辑。此步骤的默认行为包括调用 onChanged。可以覆盖此默认行为。详情请参阅 onEditingComplete。

第二步：使用用户输入的值调用 onSubmitted。

用户完成当前获得焦点的输入组件后，可以通过 onSubmitted 手动将焦点移至另一个输入组件。

此组件获得焦点时，会通过 AutomaticKeepAliveClientMixin.wantKeepAlive 阻止自身被释放，以避免丢失选区。移除焦点后，组件即可被释放。

不直接使用此组件也可以考虑使用 TextField。它是功能完整的 Material Design 文本输入框，支持占位文本、标签以及与 Form 集成。

文本编辑 Intent 及其默认 Action

此组件提供默认的 Action，用于处理常见文本编辑 Intent，例如在文本字段中删除、复制和粘贴。这些 Action 可以通过 Actions.invoke 或 Actions.maybeInvoke 方法直接调用。默认的文本编辑键盘 Shortcuts 通常由 DefaultTextEditingShortcuts 声明，它们也会使用这些 Intent 和 Action 执行所绑定的文本编辑操作。

可以在此组件上方放置 Actions 组件，以覆盖特定 Intent 的默认处理方式。有关如何覆盖预定义的可重写 Action 的更多信息，请参阅 Action 类和 Action.overridable 构造函数。

用于删除文本的 Intent 及其默认行为

Intent 类 存在选中文本时的默认行为 存在 插入光标（选区为 TextSelection.collapsed）时的默认行为
DeleteCharacterIntent 删除选中的文本 删除光标前或后的用户感知字符。
DeleteToNextWordBoundaryIntent 删除选中的文本，以及选区 TextSelection.extent 位置之前或之后的单词 从光标位置删除到前一个或后一个词边界
DeleteToLineBreakIntent 删除选中的文本，并从选区 TextSelection.extent 位置向行首或行尾删除 从光标位置删除到当前行的逻辑起点或终点

ExtendSelectionToNextWordBoundaryIntent(collapseSelection: true) 将选区折叠到 TextSelection.extent 位置之前或之后的词边界 将光标移到前一个或后一个词边界。

ExtendSelectionVerticallyToAdjacentLineIntent(collapseSelection: true) 将选区折叠到相邻上一行或下一行中最接近 TextSelection.extent 位置的点 将光标移到相邻上一行或下一行中最近的位置。

其他 Intent

Intent 类 默认行为
DoNothingAndStopPropagationTextIntent 在输入框中不执行任何操作，并阻止按键事件继续沿组件树传播。
ReplaceTextIntent 替换输入框当前的 TextEditingValue（由 TextEditingController 管理），并触发所有相关用户回调和 TextInputFormatter。
UpdateSelectionIntent 更新输入框 TextEditingController 中的当前选区，并触发 onSelectionChanged 回调。
CopySelectionTextIntent 将选中的文本复制或剪切到剪贴板
PasteTextIntent 将剪贴板中的文本插入光标位置之后；若选区未折叠，则替换选中的文本。

文本编辑 快捷键

也可以通过在组件树中将 Shortcuts 组件插入到此组件上方，直接将键盘快捷键重新映射到新的 Intent。使用 WidgetsApp 时，大量默认文本编辑键盘快捷键会在组件树靠上位置的 DefaultTextEditingShortcuts 中声明；它与此 EditableText 之间的任何 Shortcuts 组件都可以覆盖这些默认设置。

Shortcuts 与文本输入之间的交互

Shortcuts 会阻止文本输入字段将按键接收为文本输入。例如，在文本输入字段上方的组件树中放置 Shortcuts 组件，并为 LogicalKeyboardKey.keyA 创建快捷键，就会阻止该字段将此按键作为文本输入。换句话说，在字段中键入“A”会触发快捷键，而不会向字段插入字母“a”。

这是因为 Flutter 处理按键的方式如此：Flutter 引擎收到按键后，会先通过 SystemChannels.keyEvent 让框架有机会将其作为原始按键事件处理。Shortcuts 会通过其 FocusNode 间接监听该事件。如果未处理，框架就会尝试通过 SystemChannels.textInput 将其作为文本输入处理；EditableTextState 则通过 TextInputClient 监听文本输入。

如果快捷键阻止了某个字段的文本输入，可以在组件树更下方再放置一个 Shortcuts 组件，并将所需按键映射到 DoNothingAndStopPropagationIntent，以覆盖此行为。框架会将该按键事件报告为未处理，随后照常将其作为文本输入发送。

手势事件处理

当 rendererIgnoresPointer 为 false（默认值）时，此组件会为点击、长按和滚动等用户操作提供基础且跨平台的手势处理。

若要提供更完整的手势处理（包括双击选词、拖动选择，以及长按等平台特定手势的处理），可以考虑将 rendererIgnoresPointer 设为 true，并使用 TextSelectionGestureDetectorBuilder。

获得焦点时保持插入光标可见

获得焦点时，此组件会尝试在以下情况下保持文本区域及其插入光标可见（即使 showCursor 为 false）：

  • 用户聚焦此文本字段且它不是 readOnly 时。
  • 当用户更改文本字段的选区，或在文本字段未设为 readOnly 时更改文本。
  • 虚拟键盘弹出时。

滚动注意事项

如果此 EditableText 不在 Scaffold 子树中，且位于 Scrollable 或嵌套的 Scrollable 中，建议在包含此 EditableText 的根 Scrollable 上方放置 ScrollNotificationObserver，以确保 TextSelectionOverlay 等组件与 EditableText 正确协调滚动。

常见无障碍问题排查

自定义用户输入无障碍播报

若要自定义文本变化触发的用户输入无障碍播报，请使用 SemanticsService.sendAnnouncement 播报所需内容。

在 iOS 上，如果 TextInputFormatter 为货币文本字段插入千位分隔符，屏幕键盘可能会错误播报最近输入的内容。以下示例演示如何始终将文本字段内容作为美元金额播报，从而抑制默认的无障碍播报（\$ 会插入美元符号，$newText 会插入变量 newText 的值）：

onChanged: (String newText) {
  if (newText.isNotEmpty) {
    SemanticsService.sendAnnouncement(
      View.of(context),
      '\$$newText',
       Directionality.of(context),
    );
  }
}
