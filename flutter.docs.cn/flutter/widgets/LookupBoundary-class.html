LookupBoundary 类

查询边界用于控制边界提供的静态查询方法可让其后代看到哪些实体。

边界的静态查询方法与 BuildContext 上同名的查询方法相对应，可直接替代后者使用。与 BuildContext 的方法不同，这些方法不会查找给定 BuildContext 周围最近的 LookupBoundary 之外的祖先实体。树的根节点隐式构成一个查询边界。

在下面的示例中，LookupBoundary.findAncestorWidgetOfExactType 调用返回 null，因为 LookupBoundary 会“隐藏”MyWidget，使其无法被 BuildContext 查询到。
link 
MyWidget(
  child: LookupBoundary(
    child: Builder(
      builder: (BuildContext context) {
        MyWidget? widget = LookupBoundary.findAncestorWidgetOfExactType<MyWidget>(context);
        return Text('$widget'); // "null"
      },
    ),
  ),
)

LookupBoundary 只会影响该边界定义的静态查询方法的行为，不会影响 BuildContext 所定义查询方法的行为。

通常不会直接实例化 LookupBoundary。当组件树中的渲染树与元素树分离时（这种情况并不常见），会在相应位置插入查询边界。造成这种异常的原因可能是某些 RenderObjectElement 没有将其 RenderObject 附加到最近的祖先 RenderObjectElement，例如它们自行启动了独立的渲染树。这会破坏某些组件对渲染树结构的假设：这些组件可能会查找祖先组件，并假设其关联的 RenderObject 也是祖先，但异常情况下并非如此。在两棵树发生分离的位置，可以使用 LookupBoundary 对查询组件隐藏该祖先。例如，ViewAnchor 会将其 ViewAnchor.view 子组件包裹在 LookupBoundary 中，因为该子树生成的 RenderObject 并未附加到 ViewAnchor 所属的渲染树中。

例如，Material.of 依赖查询边界向某些后代按钮隐藏 Material 组件。按钮会查找其祖先 Material，以便在关联的渲染对象上绘制墨水飞溅效果。只有按钮的渲染对象是 Material 渲染对象的后代时，才能产生预期效果。如果上述异常导致元素树与渲染树不同步，情况就可能并非如此。为避免错误的视觉效果，Material 会使用查询边界，将自身从存在此类异常的子树后代的查询中隐藏。这些子树应提供自己的 Material 组件，供其中的按钮使用，而无需跨越查询边界。
