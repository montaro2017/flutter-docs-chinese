State<T extends StatefulWidget> 类 抽象

StatefulWidget 的逻辑和内部状态。

State 是一种信息：(1) 在构建 widget 时可以同步读取；(2) 在 widget 的生命周期内可能发生变化。widget 的实现者有责任确保状态变化时及时通知 State，通知方式是调用 State.setState。

当框架膨胀 StatefulWidget 并将其插入树中时，会调用 StatefulWidget.createState 来创建 State 对象。由于同一个 StatefulWidget 实例可以被多次膨胀（例如同时在树中的多个位置使用），一个 StatefulWidget 实例可能关联多个 State 对象。同样，如果 StatefulWidget 从树中移除后又重新插入，框架会再次调用 StatefulWidget.createState 创建新的 State 对象，从而简化 State 对象的生命周期管理。

State 对象具有以下生命周期：

  • 框架会调用 StatefulWidget.createState 来创建一个 State 对象。
  • 新创建的 State 对象会与 BuildContext 关联。这种关联是永久的：State 对象不会更换其 BuildContext。不过，BuildContext 本身可以连同其子树在树中移动。此时，该 State 被视为已 mounted。
  • 框架会调用 initState。State 的子类应重写 initState，执行依赖于 BuildContext 或 widget 的一次性初始化。在调用 initState 时，可以通过 context 和 widget 属性访问它们。
  • 框架会调用 didChangeDependencies。State 的子类应重写 didChangeDependencies，以执行涉及 InheritedWidget 的初始化。如果调用了 BuildContext.dependOnInheritedWidgetOfExactType，那么当继承的 widget 后续发生变化或该 widget 在树中移动时，会再次调用 didChangeDependencies。
  • 此时，State 对象已完全初始化。框架可能会多次调用其 build 方法，以获取此子树用户界面的描述。State 对象可以调用其 setState 方法，请求重新构建子树；这表示其内部状态发生了变化，并可能影响此子树中的用户界面。
  • 此时，父 widget 可能会重新构建，并要求更新树中的此位置，以显示具有相同 runtimeType 和 Widget.key 的新 widget。发生这种情况时，框架会将 widget 属性更新为指向新 widget，然后调用 didUpdateWidget 方法，并将之前的 widget 作为参数传入。State 对象应重写 didUpdateWidget，以响应其关联 widget 的变化（例如启动隐式动画）。框架始终会在调用 didUpdateWidget 后调用 build，因此在 didUpdateWidget 中调用 setState 是多余的。（另请参阅 Element.rebuild 中的讨论。）
  • 在开发过程中，如果发生热重载（通过命令行中的 flutter 工具按下 r，或从 IDE 发起），系统会调用 reassemble 方法。此时可以重新初始化在 initState 方法中准备的数据。
  • 如果包含 State 对象的子树从树中移除（例如，父级构建了具有不同 runtimeType 或 Widget.key 的 widget），框架会调用 deactivate 方法。子类应重写此方法，清理此对象与树中其他元素之间的所有链接（例如，你曾向某个祖先元素提供了指向后代 RenderObject 的指针）。
  • 此时，框架可能会将此子树重新插入树中的其他位置。如果发生这种情况，框架会确保调用 build，让 State 对象有机会适应新的位置。重新插入会在该子树被移除时所在动画帧结束前完成。因此，State 对象可以延迟释放大多数资源，直到框架调用 dispose 方法。
  • 如果框架未能在当前动画帧结束前重新插入此子树，就会调用 dispose，表示该 State 对象将不再构建。子类应重写此方法，以释放该对象保留的资源（例如停止正在运行的动画）。
  • 框架调用 dispose 后，State 对象会被视为已卸载，mounted 属性为 false。此时调用 setState 会导致错误。生命周期到此结束：已释放的 State 对象无法重新挂载。
