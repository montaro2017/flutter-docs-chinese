重写

描述此组件所表示的用户界面部分。

框架会在多种情况下调用此方法，例如：

  • After calling initState.
  • After calling didUpdateWidget.
  • After receiving a call to setState.
  • After a dependency of this State object changes (e.g., an InheritedWidget referenced by the previous build changes).
  • After calling deactivate and then reinserting the State object into the tree at another location.

此方法可能每一帧都会调用，因此除了构建组件外，不应产生任何副作用。

框架会将此组件下方的子树替换为此方法返回的组件：如果返回的组件可以更新现有子树的根节点，就更新现有子树；否则移除该子树并创建新子树。是否可以更新由调用 Widget.canUpdate 确定。

通常，实现会返回一组新创建的组件，并根据此组件的构造参数、给定的 BuildContext 以及此 State 对象的内部状态进行配置。

给定的 BuildContext 包含此组件在树中构建位置的信息。例如，context 会提供该位置可继承组件的集合。BuildContext 参数始终与此 State 对象的 context 属性相同，并且在此对象的整个生命周期内保持不变。这里冗余地提供 BuildContext 参数，是为了使此方法与 WidgetBuilder 的签名一致。

设计讨论

State 上为何有 build 方法，而 StatefulWidget 上没有？

将 Widget build(BuildContext context) 方法放在 State 上，而不是在 StatefulWidget 上定义 Widget build(BuildContext context, State state) 方法，可以让开发者在继承 StatefulWidget 时拥有更大的灵活性。

例如，AnimatedWidget 是 StatefulWidget 的子类，它引入了抽象方法 Widget build(BuildContext context)，供其子类实现。如果 StatefulWidget 已经有一个接收 State 参数的 build 方法，那么即使 State 对象只是 AnimatedWidget 的内部实现细节，AnimatedWidget 也不得不将该 State 对象提供给子类。

从概念上说，StatelessWidget 也可以用类似方式实现为 StatefulWidget 的子类。如果 build 方法位于 StatefulWidget 而不是 State 上，这种实现方式便不再可行。

将 build 函数放在 State 而非 StatefulWidget 上，也有助于避免闭包隐式捕获 this 所引发的一类错误。如果在 StatefulWidget 上定义的 build 函数中创建闭包，该闭包会隐式捕获 this（即当前组件实例），并能访问该实例中不可变的字段：

// (this is not valid Flutter code)
class MyButton extends StatefulWidgetX {
  MyButton({super.key, required this.color});

  final Color color;

  @override
  Widget build(BuildContext context, State state) {
    return SpecialWidget(
      handler: () { print('color: $color'); },
    );
  }
}

例如，假设父组件构建了一个 MyButton，其 color 为蓝色，那么打印函数中的 $color 会如预期那样显示蓝色。现在假设父组件重新构建 MyButton 并将颜色改为绿色。首次构建创建的闭包仍会隐式引用原来的组件，因此即使组件已更新为绿色，$color 打印的仍是蓝色；如果该闭包的生命周期超过组件，就会输出过时的信息。

相较之下，当 build 函数位于 State 对象上时，在 build 期间创建的闭包会隐式捕获 State 实例，而不是组件实例：

class MyButton extends StatefulWidget {
  const MyButton({super.key, this.color = Colors.teal});

  final Color color;
  // ...
}

class MyButtonState extends State<MyButton> {
  // ...
  @override
  Widget build(BuildContext context) {
    return SpecialWidget(
      handler: () { print('color: ${widget.color}'); },
    );
  }
}

现在，父组件将 MyButton 重新构建为绿色时，首次构建创建的闭包仍引用在多次构建间保留的 State 对象；但框架已将该 State 对象的 widget 属性更新为新的 MyButton 实例，因此 ${widget.color} 会如预期那样显示绿色。
