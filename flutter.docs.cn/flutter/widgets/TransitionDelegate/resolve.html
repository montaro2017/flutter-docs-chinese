Iterable<RouteTransitionRecord> resolve({
  1. required List<RouteTransitionRecord> newPageRouteHistory,
  2. required Map<RouteTransitionRecord?, RouteTransitionRecord> locationToExitingPageRoute,
  3. required Map<RouteTransitionRecord?, List<RouteTransitionRecord>> pageRouteToPagelessRoutes,
})

Navigator 更新 Navigator.pages 时会调用此方法，以决定路由如何过渡进入或离开屏幕。

newPageRouteHistory 列出更新完成后将位于 Navigator 历史栈中的所有基于页面的路由，并按栈中顺序排列。newPageRouteHistory如果其中某个路由的 RouteTransitionRecord.isWaitingForEnteringDecision 为 true，就需要明确决定该路由如何进入 Navigator。可调用 RouteTransitionRecord.markForPush 或 RouteTransitionRecord.markForAdd 作出决定。

locationToExitingPageRoute 包含页面更新后将从路由历史记录中移除的基于页面的路由。此映射记录待移除的路由，以及它们在更新前原始路由历史记录中的位置（locationToExitingPageRoute）。键表示原始路由历史中紧邻待移除路由下方的基于页面的路由，值表示要移除的基于页面的路由。如果要移除的是栈底路由，其位置为 null。如果其中某个路由的 RouteTransitionRecord.isWaitingForExitingDecision 为 true，就需要明确决定该路由如何离开 Navigator。可对待移除路由调用 RouteTransitionRecord.markForPop 或 RouteTransitionRecord.markForComplete 作出决定。locationToExitingPageRoute 中的路由也可能不需要作出决定：例如它们已在之前的页面更新中弹出，但退出动画仍未结束。这些路由仍会包含在 locationToExitingPageRoute 中，只是其 RouteTransitionRecord.isWaitingForExitingDecision 为 false，因此无需再作决定。

pageRouteToPagelessRoutes 记录基于页面的路由及其关联的无页面路由。如果某个基于页面的路由正在等待退出决定，其关联的无页面路由也需要明确决定如何离开屏幕。

作出所有决定后，此方法必须将待移除路由（无论是否需要决定）与 newPageRouteHistory 合并并返回结果。Navigator 会按照结果中的顺序更新路由历史。返回列表必须保留 newPageRouteHistory 中各路由的原有顺序；只要包含所有待移除路由，它们可以插入返回列表中的任意位置。

例如，考虑以下情况：

newPageRouteHistory = [A, B, C]

locationToExitingPageRoute = {A -> D, C -> E}

以下结果均有效：

result = [A, B ,C ,D ,E] 有效。result = [D, A, B ,C ,E] 也有效，因为退出路由可以插入任意位置。

以下结果无效：

result = [B, A, C ,D ,E] 无效，因为 B 必须排在 A 之后。result = [A, B, C ,E] 无效，因为结果中必须包含 D。

另请参阅：

  • RouteTransitionRecord.markForPush, which makes route enter the screen with an animated transition.
  • RouteTransitionRecord.markForAdd, which makes route enter the screen without an animated transition.
  • RouteTransitionRecord.markForPop, which makes route exit the screen with an animated transition.
  • RouteTransitionRecord.markForComplete, which completes the route and makes it exit the screen without an animated transition.
  • DefaultTransitionDelegate.resolve, which implements the default way to decide how routes transition in or out of the screen.
