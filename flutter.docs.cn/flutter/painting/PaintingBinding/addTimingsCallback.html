添加一个 TimingsCallback，以接收引擎发送的 FrameTiming。

此 API 使应用能够监控图形性能。引擎数据会批量整理为 FrameTiming 列表：release 模式下大约每秒报告一次，debug 和 profile 构建下大约每 100 毫秒报告一次。列表按时间升序排列（最早的帧在前）。第一帧的计时数据会立即发送，不进行批处理。

这些数据可用于检测漏帧（例如 FrameTiming.buildDuration 或 FrameTiming.rasterDuration 超过帧预算，如 60Hz 下的 16ms），也可用于检测高延迟（例如 FrameTiming.totalSpan 超过帧预算）。即使没有漏帧，延迟也可能超过一帧，例如 Flutter 引擎正在流水线化处理图形更新，导致 FrameTiming.buildDuration 与 FrameTiming.rasterDuration 之和超过帧预算。在这种情况下，动画仍然流畅，但触摸输入会显得更迟缓。

相比直接使用 dart:ui.PlatformDispatcher.onReportTimings，更推荐使用 addTimingsCallback，因为 dart:ui.PlatformDispatcher.onReportTimings API 只允许一个回调，这会阻止多个库同时注册监听器；而此 API 允许多个回调相互独立地注册。

此 API 基于 dart:ui.PlatformDispatcher.onReportTimings 实现。在 release 构建中，如果没有库通过此 API 注册，便不会设置 dart:ui.PlatformDispatcher.onReportTimings 回调，从而关闭性能跟踪，并将运行时开销降至约零。当注册了一个或多个回调（即启用跟踪）时，性能跟踪的开销约为每秒 0.01% 的 CPU 使用率（在 iPhone 6s 上测量）。

在 debug 和 profile 构建中，SchedulerBinding 本身会注册一个计时回调来更新 Timeline。

如果同一个回调被添加两次，它也会执行两次。

另请参阅：

  • removeTimingsCallback, which can be used to remove a callback added using this method.

实现

void addTimingsCallback(TimingsCallback callback) {
  _timingsCallbacks.add(callback);
  if (_timingsCallbacks.length == 1) {
    assert(platformDispatcher.onReportTimings == null);
    platformDispatcher.onReportTimings = _executeTimingsCallbacks;
  }
  assert(platformDispatcher.onReportTimings == _executeTimingsCallbacks);
}
