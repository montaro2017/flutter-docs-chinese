AssetImage 类

从 AssetBundle 获取图像，并根据当前上下文确定要使用的具体图像。

给定主资源和一组变体后，AssetImage 会根据当前上下文选择最合适的资源。上下文包括传递给 resolve 的配置中的设备像素比和尺寸。

如果要从资源包中显示特定图像而无需进行资源解析，请使用 AssetBundleImageProvider。

为不同像素密度匹配资源时的命名方式

主资源默认对应标称像素比 1.0。若要指定适用于其他像素比的资源变体，请将变体放入应用资源包中以“Nx”命名的子目录，其中 N 表示该资源对应的标称设备像素比。

例如，假设应用要使用名为“heart.png”的图标。该图标有像素比为 1.0 的主图标，以及像素比为 2.0 和 4.0 的变体。那么资源包中应包含以下资源：

heart.png
2.0x/heart.png
4.0x/heart.png

在设备像素比为 1.0 的设备上，将选择 heart.png；在设备像素比为 2.0 的设备上，将选择 2.0x/heart.png；在设备像素比为 4.0 的设备上，将选择 4.0x/heart.png。

如果设备像素比与现有资源都不完全匹配，系统会选择“最合适”的资源。最佳匹配取决于屏幕类型：设备像素比严格小于 2.0 的低分辨率屏幕使用不同于高分辨率屏幕的匹配算法。低分辨率屏幕上，用户能看到物理像素，因此放大造成的瑕疵（例如边缘模糊）更明显；所以只要有更高分辨率的资源，就会优先选择它。对于用户看不到单个物理像素的高分辨率屏幕，则会选择像素比最接近设备像素比的资源变体。

例如，设备像素比为 1.25 时会选择 2.0x/heart.png，尽管 heart.png（即 1.0）在数值上更接近，因为该屏幕被视为低分辨率屏幕。设备像素比为 2.25 时也会选择 2.0x/heart.png；因为该屏幕被视为高分辨率屏幕，将 2.0x 图像放大到 2.25x 不会产生可见的放大瑕疵。不过，当设备像素比为 3.25 时，会选择 4.0x/heart.png，因为它比 2.0x 更接近 3.25。

若选用远高于所需分辨率的图像，而屏幕像素比与图像像素比相差很大，可能会显著增加内存消耗。可以通过提供更多图像变体来降低内存使用量。在上述示例中，增加 3.0x/heart.png 变体可以降低设备像素比在 3.0 到 3.5 之间的屏幕上的内存消耗。

可以通过设置 ImageConfiguration.devicePixelRatio，使用 ImageConfiguration 自定义图像变体的选择。其默认值由 createLocalImageConfiguration 根据 MediaQueryData.devicePixelRatio 计算得出。

只要各变体位于对应的目录层级，资源所在目录的层级本身并不重要；也就是说，以下资源包结构同样有效：

icons/heart.png
icons/1.5x/heart.png
icons/2.0x/heart.png

assets/icons/3.0x/heart.png 可以作为 assets/icons/heart.png 的有效变体。

获取资源

获取应用自身提供的图像时，使用 assetName 参数指定要选择的资源。例如，假设使用上面的目录结构。首先，项目的 pubspec.yaml 应在 flutter 部分声明这些资源：

flutter:
  assets:
    - icons/heart.png

然后，使用以下方式获取图像：

const AssetImage('icons/heart.png')

以下示例展示了如何编写一个同时完整遵循 AssetImage 和 Widget 协议的 widget。它本质上是一个精简版的 Image widget，专门用于配合 AssetImage 使用。
link 
class MyImage extends StatefulWidget {
  const MyImage({
    super.key,
    required this.assetImage,
  });

  final AssetImage assetImage;

  @override
  State<MyImage> createState() => _MyImageState();
}

class _MyImageState extends State<MyImage> {
  ImageStream? _imageStream;
  ImageInfo? _imageInfo;

  @override
  void didChangeDependencies() {
    super.didChangeDependencies();
    // We call _getImage here because createLocalImageConfiguration() needs to
    // be called again if the dependencies changed, in case the changes relate
    // to the DefaultAssetBundle, MediaQuery, etc, which that method uses.
    _getImage();
  }

  @override
  void didUpdateWidget(MyImage oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (widget.assetImage != oldWidget.assetImage) {
      _getImage();
    }
  }

  void _getImage() {
    final ImageStream? oldImageStream = _imageStream;
    _imageStream = widget.assetImage.resolve(createLocalImageConfiguration(context));
    if (_imageStream!.key != oldImageStream?.key) {
      // If the keys are the same, then we got the same image back, and so we don't
      // need to update the listeners. If the key changed, though, we must make sure
      // to switch our listeners to the new image stream.
      final ImageStreamListener listener = ImageStreamListener(_updateImage);
      oldImageStream?.removeListener(listener);
      _imageStream!.addListener(listener);
    }
  }

  void _updateImage(ImageInfo imageInfo, bool synchronousCall) {
    setState(() {
      // Trigger a build whenever the image changes.
      _imageInfo?.dispose();
      _imageInfo = imageInfo;
    });
  }

  @override
  void dispose() {
    _imageStream?.removeListener(ImageStreamListener(_updateImage));
    _imageInfo?.dispose();
    _imageInfo = null;
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return RawImage(
      image: _imageInfo?.image, // this is a dart:ui Image object
      scale: _imageInfo?.scale ?? 1.0,
    );
  }
}

程序包中的资源

要从程序包获取资源，必须提供 包 参数。例如，假设上面的目录结构位于名为 my_icons 的程序包中。要获取图像，请使用：

const AssetImage('icons/heart.png', package: 'my_icons')

程序包自身使用的资源也应像上面那样通过 包 参数获取。

如果所需资源已在程序包的 pubspec.yaml 中声明，它会自动随应用打包。特别是，程序包自身使用的资源必须在该程序包的 pubspec.yaml 中声明。

程序包也可以选择在自身的 lib/ 文件夹中存放资源，而不必在 pubspec.yaml 中声明这些资源。若要将这些图像打包，应用必须指定要包含哪些图像。例如，名为 fancy_backgrounds 的程序包可以包含：

lib/backgrounds/background1.png
lib/backgrounds/background2.png
lib/backgrounds/background3.png

例如，若要包含第一张图像，应用的 pubspec.yaml 应在 assets 部分声明该图像：

  assets:
    - packages/fancy_backgrounds/backgrounds/background1.png

路径中默认包含 lib/，因此资源路径中不应再写入它。
