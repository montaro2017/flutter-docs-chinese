PaymentRequest 接口的 show() 方法会指示用户代理开始显示并处理面向用户的支付请求界面。

所有文档中同时只能处理一个支付请求。调用某个 PaymentRequest 的 show() 方法后，在其返回的 Promise 结束之前，其他任何 show() 调用都会因 AbortError 被拒绝。该 Promise 最终会通过 PaymentResponse（表示支付请求结果）兑现，或因错误而被拒绝。

注意：尽管规范规定不能这样做，实际上一些浏览器（包括 Firefox）支持同时存在多个活动的支付请求。

如果调用 show() 创建支付界面时，应用尚未准备好所有数据，可以指定 detailsPromise 参数，并提供一个在数据就绪后兑现的 Promise。提供此参数后，show() 不会允许用户操作支付界面，直到该 Promise 兑现；这样，用户开始支付流程前就可以更新数据。

处理结果以及必要时调用 PaymentResponse.retry 重试失败的支付，既可以同步完成，也可以异步完成，具体取决于需求。为了获得更好的用户体验，通常建议采用异步方式。MDN 等网站上的大多数示例会使用 async/await，在异步验证结果等操作期间等待。

实现

external JSPromise<PaymentResponse> show(
    [JSPromise<PaymentDetailsUpdate> detailsPromise]);
