Response clone()

Response 接口的 clone() 方法会创建一个与原响应对象完全相同的副本，并将其存储在另一个变量中。

与底层 ReadableStream.tee API 类似，克隆后 Response 的 Response.body 会按照两个正文中较快的使用者的速度施加背压；未读取的数据则会无限制地排入消费较慢的 body 队列中，且没有背压。背压是指数据流的使用者（此处为读取正文的代码）降低数据生产者（例如 TCP 服务器）的速度，从而避免大量等待应用程序使用的数据占用内存。如果只消费一个克隆分支，整个正文都会缓存在内存中。因此，clone() 可以用于依次读取响应两次，但不要用它以不同速度并行读取非常大的正文。

如果响应正文已被使用，clone() 会抛出 TypeError。实际上，clone() 存在的主要原因，就是允许多次使用只能读取一次的正文对象。

实现

external Response clone();
