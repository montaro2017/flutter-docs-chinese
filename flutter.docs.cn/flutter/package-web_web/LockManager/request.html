LockManager 接口的 request() 方法会请求一个 Lock 对象，并通过参数指定其名称和特性。请求到的 Lock 会传递给回调；此方法本身会返回一个 Promise，在锁释放后，该 Promise 会根据回调结果兑现或拒绝；如果请求被中止，则 Promise 会拒绝。

options 参数的 mode 属性可以是 "exclusive" 或 "shared"。

当某段代码同一时间只能由一个实例持有锁时，请求 "exclusive" 锁。此限制同时适用于标签页和 worker 中的代码。可以用它表示对某项资源的互斥访问。某个名称的 "exclusive" 锁被持有时，不能再持有任何同名锁。

当多个代码实例可以共享访问某项资源时，请求 "shared" 锁。某个名称的 "shared" 锁被持有时，可以授予其他同名 "shared" 锁，但不能持有或授予同名的 "exclusive" 锁。

这种共享/独占锁模式常见于数据库事务架构，例如允许多个读取者同时读取（每个读取者请求一个 "shared" 锁），但只允许一个写入者（请求单个 "exclusive" 锁）。这称为读者-写者模式。在 IndexedDB API 中，对应的事务模式为 "readonly" 和 "readwrite"，语义相同。
