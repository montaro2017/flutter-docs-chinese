RTCDataChannel

RTCDataChannel extension type

RTCDataChannel 接口表示一种网络通道，可用于在对等端之间双向传输任意数据。每个数据通道都关联一个 RTCPeerConnection；每个对等连接理论上最多可有 65,534 个数据通道（实际限制因浏览器而异）。

若要创建数据通道并邀请远端对等端加入，请调用 RTCPeerConnection 的 RTCPeerConnection.createDataChannel 方法。受邀交换数据的对等端会收到 RTCPeerConnection.datachannel_event 事件（类型为 RTCDataChannelEvent），从而得知数据通道已添加到连接中。

RTCDataChannel 是一种可转移对象。

API 文档内容来自 MDN Web 文档。

binaryType ↔ BinaryType
binaryType 属性属于 RTCDataChannel 接口，值为字符串，用于指定如何表示在 RTCDataChannel 上接收的二进制数据。此处也允许使用 WebSocket.binaryType 支持的值：blob（使用 Blob 对象）或 arraybuffer（使用 ArrayBuffer 对象）。默认值为 blob。
getter/setter 对
bufferedAmount → int
只读 RTCDataChannel 属性 bufferedAmount 返回当前已排队等待通过数据通道发送的数据字节数。调用 RTCDataChannel.send 后，队列可能会增长。此值仅包含用户代理自身缓冲的数据，不包括任何帧开销，也不包括操作系统或网络硬件所做的缓冲。
无 setter
bufferedAmountLowThreshold ↔ int
RTCDataChannel 属性 bufferedAmountLowThreshold 用于指定被视为“较低”的待发送缓冲数据字节数。默认值为 0。当待发送缓冲字节数（由 RTCDataChannel.bufferedAmount 指示）降至此值或更低时，会触发 RTCDataChannel.bufferedamountlow_event 事件。此事件可用于在缓冲区有空间时排队发送更多消息。可通过 RTCDataChannel.bufferedamountlow_event 或 EventTarget.addEventListener 添加监听器。

maxPacketLifeTime → int?
只读 RTCDataChannel 属性 maxPacketLifeTime 返回浏览器尝试传输消息所允许的最长时间（以毫秒为单位）。该值在创建数据通道时设定，也可能为 null。此值限制浏览器在放弃之前尝试发送和重新发送消息的时长。
无 setter
maxRetransmits → int?
RTCDataChannel 的只读属性 maxRetransmits 返回浏览器放弃之前尝试重新发送消息的最大次数。该值在创建数据通道时设定，也可能为 null，表示没有次数上限。只能在创建 RTCDataChannel 时设置：调用 RTCPeerConnection.createDataChannel，并使用指定 maxRetransmits 字段的 options。
无 setter
negotiated → bool
只读 RTCDataChannel 属性 negotiated 指示 RTCDataChannel 的连接是由 Web 应用（true）还是由 WebRTC 层（false）协商建立的。默认值为 false。

ordered → bool
只读 RTCDataChannel 属性 ordered 指示数据通道是否保证按顺序传递消息；默认值为 true，表示数据通道确实会按顺序传递消息。创建 RTCDataChannel 时，可通过设置 ordered 属性（位于传递给 RTCPeerConnection.createDataChannel 的 options 参数对象上）来设定此值。
