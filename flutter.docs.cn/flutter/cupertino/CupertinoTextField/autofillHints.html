autofillHints 属性

Iterable<String>? autofillHints
final

用于帮助自动填充服务识别此文本输入类型的字符串列表。

如果设为 null，此文本输入不会向平台发送自动填充信息，因此不会参与由其他 AutofillClient 触发的自动填充，即使它们位于同一个 AutofillScope 中也是如此。此外，在 Android 和 Web 上，将此值设为 null 会禁用此文本框的自动填充。

支持自动填充所需的平台最低 SDK 版本为：Android API 级别 26，iOS 10.0。

默认为空列表。

设置 iOS 自动填充：

若要获得最佳用户体验，并确保应用在 iOS 上完整支持密码自动填充，请按以下步骤操作：

  • Set up your iOS app's associated domains.
  • Some autofill hints only work with specific keyboardTypes. For example, AutofillHints.name requires TextInputType.name 和 AutofillHints.email works only with TextInputType.emailAddress. Make sure the input field has a compatible keyboardType. Empirically, TextInputType.name works well with many autofill hints that are predefined on iOS.

自动填充故障排除

自动填充服务提供商会大量依赖 autofillHints。请确认 autofillHints 中的条目受当前使用的自动填充服务支持（通常可在移动设备的系统设置中找到服务名称）。

点按文本框后，自动填充界面没有显示

检查设备的系统设置，确认自动填充功能已开启，并且自动填充服务中保存了可用的凭据。

  • iOS 密码自动填充：前往“设置”→“密码”，开启“自动填充密码”，然后点按右上角的“+”添加测试密码。如果应用尚未设置关联域名，可以使用任意“网站”。只要至少保存了一个密码，当密码相关文本框获得焦点时，软件键盘的快捷输入栏中就应显示钥匙形图标。

  • iOS 联系人信息自动填充：iOS 似乎会从当前设备关联的 Apple ID 获取联系人信息。前往“设置”→“Apple ID”（通常是第一个条目；如果尚未设置，则显示“登录 iPhone”），填写相关字段。若要测试更多联系人信息类型，可以前往“通讯录”→“我的名片”添加信息。

  • Android 自动填充：前往“设置”→“系统”→“语言和输入法”→“自动填充服务”。启用所需的自动填充服务，并确认其中存在与应用关联的可用凭据。

指定 InputDecoration.hintText 也可能帮助自动填充服务（例如 Samsung Pass）判断输入框预期的内容类型；不过通常在提供 autofillHints 后就不再需要此设置。

如果可自动填充的输入框需要使用会因平台而异的自定义提示，最简单的方法是根据 defaultTargetPlatform 的值返回不同的提示字符串。

列表中的每条提示（若未被忽略）都会转换为自动填充服务可识别的平台提示类型：

  • 在 iOS 上，仅使用列表中的第一条提示，并将其转换为 UITextContentType。

  • 在 Android 上，列表中的所有提示都会转换为 Android 提示字符串。

  • 在 Web 上，仅使用第一条提示，并将其转换为“autocomplete”字符串。

提供平台预定义的自动填充提示，并不会自动让输入框具备自动填充资格。最终由当前负责处理的自动填充服务决定输入框是否适合自动填充，以及提供哪些候选项。

另请参阅：

  • AutofillHints：至少在一个平台上预定义的自动填充提示字符串列表。

  • UITextContentType：iOS 上的对应类型。

  • Android 的 autofillHints：Android 上的对应属性。

  • Web 的 autocomplete 属性。
