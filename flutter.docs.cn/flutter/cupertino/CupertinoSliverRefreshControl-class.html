CupertinoSliverRefreshControl 类

实现 iOS 风格下拉刷新控件的 sliver 组件。

将其作为滚动视图中的第一个 sliver 插入，或放在其他仍允许滚动视图在其前方过度滚动的 sliver 后面（例如 CupertinoSliverNavigationBar），该组件将会：

  • 允许用户通过传入的 builder 在过度滚动区域中绘制内容。
  • 过度滚动距离超过 refreshTriggerPullDistance 时，触发所提供的 onRefresh 函数。
  • 在 onRefresh 返回的 Future 执行期间，持续保留 refreshIndicatorExtent 指定的空间，供 builder 继续在其中绘制内容。
  • onRefresh 返回的 Future 完成后，组件会随滚动移出。

调用 builder 函数时，会向其提供当前的 RefreshIndicatorMode；但如果处于 RefreshIndicatorMode.inactive 状态且没有可用空间，则无需构建任何内容，不会调用该函数。除此之外，只要可用空间发生变化（例如发生过度滚动，或 onRefresh 任务完成后 sliver 滑出），就会持续调用 builder 函数。

只有在上一次刷新完成且指示器 sliver 至少回缩了 90% 后，才能再次触发刷新。

此组件只能用于向下滚动且允许过度滚动的垂直列表。也就是说，使用 Scrollable 和 ClampingScrollPhysics 时无法触发刷新；Android 默认使用这种滚动物理效果。若要在 Android 上允许过度滚动，请使用 BouncingScrollPhysics 等支持过度滚动的物理效果。可以通过以下方式设置：

  • 构建滚动组件时，为其提供 BouncingScrollPhysics（也可以与 AlwaysScrollableScrollPhysics 组合使用）。
  • 在滚动组件上方插入一个配置了 BouncingScrollPhysics 的 ScrollConfiguration。
  • 使用 CupertinoApp；它无论运行在哪个平台，都会使用配置了 BouncingScrollPhysics 的 ScrollConfiguration。

在典型应用中，应将此 sliver 插入应用栏 sliver（例如 CupertinoSliverNavigationBar）与主要滚动内容的 sliver 之间。

当用户滚动超过 refreshTriggerPullDistance 后，此示例会显示默认的 iOS 下拉刷新指示器 1 秒，并在列表顶部添加一项。

buildRefreshIndicator(BuildContext context, RefreshIndicatorMode refreshState, double pulledExtent, double refreshTriggerPullDistance, double refreshIndicatorExtent) → Widget
Builds a refresh indicator that reflects the standard iOS pull-to-refresh behavior. Specifically, this entails presenting an activity indicator that changes depending on the current refreshState. As the user initially drags down, the indicator will gradually reveal individual ticks until the refresh becomes armed. At this point, the animated activity indicator will begin rotating. Once the refresh has completed, the activity indicator shrinks away as the space allocation animates back to closed.
