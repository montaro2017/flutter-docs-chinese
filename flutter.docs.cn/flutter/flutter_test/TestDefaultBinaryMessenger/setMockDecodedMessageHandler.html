为给定通道设置回调，以拦截发送到平台的消息。

被拦截的消息不会转发到平台。

如果该通道已注册回调，则给定回调会替换现有回调。若要完全停止拦截消息，请将 null 作为处理器传入。

消息会使用该通道的编解码器解码。

如果处理器的返回值非 null，则会先使用该通道的编解码器对其编码，再将其用作响应。

强烈建议此 API 使用的所有处理器都保持同步（无需等待微任务完成），因为 testWidgets 测试运行在 FakeAsync 区域中，除非显式推进时间（例如调用 WidgetTester.pump），否则微任务不会执行。因此，对 Future 使用 await 会导致测试挂起。

每次测试结束后都会清除已注册的回调。

另请参阅：

  • checkMockMessageHandler 可验证处理器是否仍处于注册状态，这在测试中有助于确保没有注册意外的处理器。

  • setMockMessageHandler 与此方法类似，但可直接访问底层原始字节。

  • setMockMethodCallHandler 与此方法类似，但会使用 MethodCodec 解码消息。

  • setMockStreamHandler 会封装 setMockMethodCallHandler，以处理 EventChannel 消息。

实现

void setMockDecodedMessageHandler<T>(
  BasicMessageChannel<T> channel,
  Future<T> Function(T? message)? handler,
) {
  if (handler == null) {
    setMockMessageHandler(channel.name, null);
    return;
  }
  setMockMessageHandler(channel.name, (ByteData? message) async {
    return channel.codec.encodeMessage(await handler(channel.codec.decodeMessage(message)));
  }, handler);
}
