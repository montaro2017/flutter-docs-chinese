重写

通过调用原生应用 API 方法来干净地退出应用。

这与调用 dart:io 的 exit 函数不同：此方法会让引擎有机会清理资源，避免退出时崩溃。因此始终应优先使用此方法，而不是调用 exit。此外，它还可让 handleRequestAppExit 的处理器有机会取消应用退出。

exitType 表示要执行的退出类型。对于 ui.AppExitType.cancelable（可取消）退出，系统会通过调用 handleRequestAppExit 询问应用，应用可以选择取消退出请求。如果 exitType 为 ui.AppExitType.required，则会立即退出，不再询问应用。

对于 ui.AppExitType.cancelable（可取消）退出，返回的响应值表示应用是否取消了退出。实际上，该响应永远不会是 ui.AppExitResponse.exit，因为等到结果返回时应用已经退出。

可选参数 exitCode 会作为应用退出代码，用于支持退出代码的平台。在其他平台上可能会被忽略。默认值为零。

另请参阅：

  • WidgetsBindingObserver.didRequestAppExit，可在 WidgetsBindingObserver 上重写此处理方法，以接收退出请求。

实现

@override
Future<ui.AppExitResponse> exitApplication(ui.AppExitType exitType, [int exitCode = 0]) async {
  switch (exitType) {
    case ui.AppExitType.cancelable:
      // The test framework shouldn't actually exit when requested.
      return ui.AppExitResponse.cancel;
    case ui.AppExitType.required:
      throw FlutterError('Unexpected application exit request while running test');
  }
}
