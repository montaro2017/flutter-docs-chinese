检查当前 Zone 是否与初始化 Binding 时使用的 zone 相同。

如果当前 zone（Zone.current）与初始化 Binding 时所在的 zone 不同，此方法会生成包含详细信息的 FlutterError 异常。根据 BindingBase.debugZoneErrorsAreFatal 的值，异常会直接抛出，或通过 FlutterError.reportError 报告。

若要消除 debugCheckZone 显示的消息，请确保调用 ensureInitialized() 和在其他上下文中调用框架（例如通过 runApp）时使用同一个 zone。例如，可以保存初始化 Binding 时所用 zone 的引用，并在调用框架时使用 Zone.run 重新进入该 zone。

用法

BindingBase.initInstances 执行后，Binding 才被视为已初始化；如果在此之前调用此方法，则会抛出 AssertionError。

entryPoint 参数是用于检查 zone 是否一致的 API 名称，例如 'runApp'。

如果没有抛出异常，此函数总是返回 true。预期应通过 Binding 实例调用，例如：

void startup() {
  WidgetsBinding binding = WidgetsFlutterBinding.ensureInitialized();
  assert(binding.debugCheckZone('startup'));
  // ...
}

如果 Binding 需要在多个 zone 中使用，则应重写此方法，使其始终返回 true 且不抛出异常。（例如，flutter_test 使用的 Binding 就是如此，因为它们大量使用 zone，通过人工时钟驱动框架，并捕获错误、将其报告为测试失败。）

实现

@override
bool debugCheckZone(String entryPoint) {
  // We skip all the zone checks in tests because the test framework makes heavy use
  // of zones and so the zones never quite match the way the framework expects.
  return true;
}
