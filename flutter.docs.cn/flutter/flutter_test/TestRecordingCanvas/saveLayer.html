重写

将当前变换和裁剪状态复制到保存栈，然后创建一个新组，后续调用都会成为该组的一部分。稍后弹出保存栈时，会将该组展平为图层，并应用给定 paint 的 Paint.colorFilter 和 Paint.blendMode。

这可以创建合成效果，例如让一组绘图命令呈现半透明。若不使用 saveLayer，组内每个部分都会单独绘制，因此重叠区域会比未重叠区域更暗。使用 saveLayer 将它们分组后，可以先以不透明颜色绘制整个组，再通过 saveLayer 的画笔使整个组变为透明。

调用 restore 可弹出保存栈，并将画笔应用到该组。

在裁剪区域中使用 saveLayer

如果矩形裁剪操作（通过 clipRect 执行）与栅格缓冲区的坐标轴不对齐，或裁剪操作不是矩形方向的（例如由 clipRRect 创建的圆角矩形裁剪，或由 clipPath 创建的任意复杂路径裁剪），就需要对裁剪边缘进行抗锯齿处理。

如果两个绘制调用在此类裁剪区域的边缘重叠且没有使用 saveLayer，第一次绘制会先与背景进行抗锯齿合成，然后第二次绘制会与第一次绘制和背景合成后的结果进行抗锯齿处理。相反，如果设置裁剪后立即使用 saveLayer，第二次绘制会在图层中覆盖第一次绘制；裁剪并合成图层时（即调用 restore 时），只有第二次绘制会与背景进行抗锯齿合成。

例如，以下 CustomPainter.paint 方法会绘制一个边缘清晰的白色圆角矩形：

void paint(Canvas canvas, Size size) {
  Rect rect = Offset.zero & size;
  canvas.save();
  canvas.clipRRect(RRect.fromRectXY(rect, 100.0, 100.0));
  canvas.saveLayer(rect, Paint());
  canvas.drawPaint(Paint()..color = Colors.red);
  canvas.drawPaint(Paint()..color = Colors.white);
  canvas.restore();
  canvas.restore();
}

相比之下，以下方法会绘制红色轮廓：红色画笔先在裁剪边缘与背景进行抗锯齿合成，随后白色画笔也会与包含已裁剪红色绘制内容的背景进行类似的抗锯齿合成：

void paint(Canvas canvas, Size size) {
  // (this example renders poorly, prefer the example above)
  Rect rect = Offset.zero & size;
  canvas.save();
  canvas.clipRRect(RRect.fromRectXY(rect, 100.0, 100.0));
  canvas.drawPaint(Paint()..color = Colors.red);
  canvas.drawPaint(Paint()..color = Colors.white);
  canvas.restore();
}

如果裁剪操作只影响一次绘制，则无需考虑这一点。例如，即使没有将裁剪放在单独的图层中，以下绘制方法仍会绘制出两个边缘清晰的白色圆角矩形：

void paint(Canvas canvas, Size size) {
  canvas.save();
  canvas.clipRRect(RRect.fromRectXY(Offset.zero & (size / 2.0), 50.0, 50.0));
  canvas.drawPaint(Paint()..color = Colors.white);
  canvas.restore();
  canvas.save();
  canvas.clipRRect(RRect.fromRectXY(size.center(Offset.zero) & (size / 2.0), 50.0, 50.0));
  canvas.drawPaint(Paint()..color = Colors.white);
  canvas.restore();
}

（顺带一提，绘制此类圆角矩形时，建议使用 clipRRect 和 drawPaint，而不是使用 drawRRect 方法。这里用 drawPaint 代表“复杂且会被裁剪的绘制操作”，以说明这一点。）

性能注意事项

一般来说，saveLayer 的开销相对较大。

GPU（图形处理器，即负责处理图形的硬件）有多种硬件架构，但大多数架构都会对命令进行批处理和重排以提高性能。使用图层时，渲染管线必须切换渲染目标（从一个图层切换到另一个图层）。切换渲染目标可能会刷新 GPU 命令缓冲区，通常会使大批量处理带来的优化失效。切换渲染目标还会造成大量内存搬运：GPU 需要将当前帧缓冲区内容从针对写入优化的内存区域复制出来，并在恢复上一个渲染目标（图层）时再复制回去。

另请参阅：

  • save 用于保存当前状态，但不会为后续命令创建新图层。
  • BlendMode 介绍了如何将 Paint.blendMode 与 saveLayer 配合使用。

实现

@override
void saveLayer(Rect? bounds, Paint paint) {
  _saveCount += 1;
  invocations.add(
    RecordedInvocation(
      _MethodCall(#saveLayer, <dynamic>[bounds, Paint.from(paint)]),
      stack: StackTrace.current,
    ),
  );
}
