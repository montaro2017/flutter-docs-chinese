spawnHybridUri function

StreamChannel spawnHybridUri(
  1. Object uri, {
  2. Object? message,
  3. bool stayAlive = false,
})

为给定的 uri 启动 VM isolate；该值可以是 Uri 或 String。

这样，浏览器测试就可以启动服务器并与之通信，从而测试客户端与服务器的交互。VM 测试也可以用它轻松启动 isolate。

uri 指向的 Dart 文件必须定义一个顶层 hybridMain() 函数，该函数接收 StreamChannel 参数，还可以选择接收一个 Object 参数，message 会传递给它。请注意，message 必须可编码为 JSON。例如：

import "package:stream_channel/stream_channel.dart";

hybridMain(StreamChannel channel, Object message) {
  // ...
}

如果 uri 是相对路径，它会相对于当前测试套件的 file: URL 解析。如果它是相对于根目录的路径（即以 / 开头），则会相对于包根目录解析（也就是包含 pubspec.yaml 的目录，而不是 test/ 目录）。如果它是 package: URL，则会根据当前包的依赖关系解析。

返回一个与传递给 hybridMain() 的通道相连的 StreamChannel。此通道只允许发送可编码为 JSON 的对象。如果通道关闭，hybrid isolate 就会被终止；如果 isolate 被终止，通道流会发出“done”事件。

加载或运行 hybrid isolate 时发生的任何未处理错误，都会作为错误通过通道流发出。在 hybrid isolate 中调用的任何 print()，都会像是由创建该 isolate 的测试打印的一样显示。

hybrid isolate 中的代码不被视为运行在测试上下文中，因此无法访问 expect() 和 expectAsync() 等测试函数。

默认情况下，测试结束时会自动终止 hybrid isolate。如果 stayAlive 为 true，则会等到整个测试套件运行结束后才终止。

注意：使用此 API 时，请确保添加对 stream_channel 包的依赖，因为你也在使用它的 API！

实现

StreamChannel spawnHybridUri(
  Object uri, {
  Object? message,
  bool stayAlive = false,
}) {
  if (uri is String) {
    // Ensure that it can be parsed as a uri.
    Uri.parse(uri);
  } else if (uri is! Uri) {
    throw ArgumentError.value(uri, 'uri', 'must be a Uri or a String.');
  }
  return _spawn(uri.toString(), message, stayAlive: stayAlive);
}
