TextInputAction enum

用户要求文本输入控件执行的操作。

每种操作都代表一种逻辑含义，同时会配置软键盘显示相应类型的操作按钮。同一操作按钮在不同操作系统版本中的外观可能不同。

尽管每种操作都有其逻辑含义，选择特定的 TextInputAction 并不一定会触发特定行为，除非在适当情况下改变焦点。开发者应确保按下所选操作按钮时执行的行为与该按钮相符。

例如，在 iOS 上，如果用户按下键盘上的“紧急呼叫”操作按钮，焦点就不应转移到下一个 TextField。对于标有“紧急呼叫”的按钮，这种行为在逻辑上并不恰当。

有关自定义操作按钮行为的更多信息，请参阅 EditableText。

Android 和 iOS 对大多数 TextInputAction 的支持程度相同。不过，Android 的 IME 输入类型与 iOS 键盘的回车键类型之间并非完全一一对应，因此某些 TextInputAction 不适用于其中一个平台。在调试模式下，如果开发者选择了不适用于当前平台的 TextInputAction，就会抛出错误。在发布模式下发生同样情况时，Android 会在平台端使用“unspecified”，iOS 则会使用“default”，而不会发送不适用的值。

另请参阅：

  • TextInput, which configures the platform's keyboard setup.
  • EditableText, which invokes callbacks when the action button is pressed.

Values

none → const TextInputAction

逻辑含义：当前输入源没有相关的输入操作，例如 TextField。

Android：对应 Android 的“IME_ACTION_NONE”。键盘布局由操作系统决定，通常会显示 Return 键。

iOS：iOS 没有类型为“none”的键盘 Return 键。在 iOS 上运行时，不应选择此 TextInputAction。

unspecified → const TextInputAction

逻辑含义：由操作系统决定最合适的操作。

Android：对应 Android 的“IME_ACTION_UNSPECIFIED”。操作系统会选择要显示的键盘操作，通常是 Done 按钮或 Return 键。

iOS：对应 iOS 的“UIReturnKeyDefault”。操作按钮显示的标题为“return”。

done → const TextInputAction

逻辑含义：用户已完成一组输入（例如表单），现在应执行某种收尾操作。

Android：对应 Android 的“IME_ACTION_DONE”。操作系统会显示表示完成的按钮，例如勾选按钮。

iOS：对应 iOS 的“UIReturnKeyDone”。操作按钮显示的标题为“Done”。

go → const TextInputAction

逻辑含义：用户输入了一段表示目的地的文本，例如餐厅名称。“go”按钮会将用户带到应用中与该目的地对应的部分。

Android：对应 Android 的“IME_ACTION_GO”。操作系统会显示表示前往用户所输入文本目标的按钮，例如向右箭头。

iOS：对应 iOS 的“UIReturnKeyGo”。操作按钮显示的标题为“Go”。

search → const TextInputAction

逻辑含义：执行搜索查询。

Android：对应 Android 的“IME_ACTION_SEARCH”。操作系统会显示表示搜索的按钮，例如放大镜按钮。

iOS：对应 iOS 的“UIReturnKeySearch”。操作按钮显示的标题为“Search”。

send → const TextInputAction

逻辑含义：发送用户撰写的内容，例如电子邮件或短信。

Android：对应 Android 的“IME_ACTION_SEND”。操作系统会显示表示发送的按钮，例如纸飞机按钮。

iOS：对应 iOS 的“UIReturnKeySend”。操作按钮显示的标题为“Send”。

next → const TextInputAction

逻辑含义：用户已完成当前输入源，并希望移至下一个输入源。

将焦点移至同一 FocusScope 中下一个可获得焦点的项目。

Android：对应 Android 的“IME_ACTION_NEXT”。操作系统会显示表示向前移动的按钮，例如向右箭头按钮。

iOS：对应 iOS 的“UIReturnKeyNext”。操作按钮显示的标题为“Next”。

previous → const TextInputAction

Logical meaning: The user wishes to return to the previous input source in the group, e.g., a form with multiple TextField。

将焦点移至同一 FocusScope 中上一个可获得焦点的项目。

Android：对应 Android 的“IME_ACTION_PREVIOUS”。操作系统会显示表示向后移动的按钮，例如向左箭头按钮。

iOS：iOS 没有类型为“previous”的键盘 Return 键。在 iOS 上运行时，不应选择此 TextInputAction。

continueAction → const TextInputAction

在 iOS 应用中，“Back”和“Continue”按钮通常显示在屏幕顶部。但键盘打开时，这些按钮往往会被遮挡在屏幕外。因此，iOS 上“Continue”Return 键的作用，是在用户输入文本时提供对“Continue”按钮的访问。

不考虑历史背景，只要“Continue”最适合描述某项操作，就可以使用 TextInputAction.continueAction。

Android：Android 没有类型为“continue”的 IME 输入操作。在 Android 上运行时，不应选择此 TextInputAction。

iOS：对应 iOS 的“UIReturnKeyContinue”。操作按钮显示的标题为“Continue”。此操作仅适用于 iOS 9.0 及更高版本。

此值的名称将“Action”放在后缀，是因为“continue”是 Dart 以及许多其他语言中的保留字。

join → const TextInputAction

逻辑含义：用户希望加入某项内容，例如无线网络。

Android：Android 没有类型为“join”的 IME 输入操作。在 Android 上运行时，不应选择此 TextInputAction。

iOS：对应 iOS 的“UIReturnKeyJoin”。操作按钮显示的标题为“Join”。

route → const TextInputAction

逻辑含义：用户需要路线选项，例如驾车路线。

Android：Android 没有类型为“route”的 IME 输入操作。在 Android 上运行时，不应选择此 TextInputAction。

iOS：对应 iOS 的“UIReturnKeyRoute”。操作按钮显示的标题为“Route”。

emergencyCall → const TextInputAction

逻辑含义：向紧急服务部门发起呼叫。

Android：Android 没有类型为“emergencyCall”的 IME 输入操作。在 Android 上运行时，不应选择此 TextInputAction。

iOS：对应 iOS 的“UIReturnKeyEmergencyCall”。操作按钮显示的标题为“Emergency Call”。

newline → const TextInputAction

逻辑含义：在获得焦点的文本输入中插入换行符，例如 TextField。

Android：对应 Android 的“IME_ACTION_NONE”。操作系统会显示用于换行的按钮，例如回车按钮。

iOS：对应 iOS 的“UIReturnKeyDefault”。操作按钮显示的标题为“return”。

Flutter 中存在 TextInputAction.newline，Android 和 iOS 中则没有。引入此术语是为了让开发者无需了解 Android 的各类 IME 操作和 iOS 的 Return 键，也能实现常见的插入换行行为。因此，TextInputAction.newline 是一个便捷术语，可避免开发者为了实现这一常见行为而了解底层平台细节。
