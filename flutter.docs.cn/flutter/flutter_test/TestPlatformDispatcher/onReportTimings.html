onReportTimings 属性

  1. @重写
TimingsCallback? get onReportTimings
重写

用于报告最近已栅格化帧的 FrameTiming 的回调。

建议使用 SchedulerBinding.addTimingsCallback，而不是直接使用 onReportTimings，因为 SchedulerBinding.addTimingsCallback 允许注册多个回调。

可以通过 FrameTiming.buildDuration 和 FrameTiming.rasterDuration 查看应用是否漏帧，也可以通过 FrameTiming.totalSpan 检查延迟是否过高。

与 Timeline 不同，此处的计时信息在 release 模式下也可用，debug 和 profile 模式下同样可用。因此，可以用它监测应用在实际运行环境中的性能。

由于回调可能不会在每帧结束后立即触发，因此它接收一个 FrameTiming 列表。Flutter 会尝试将多帧合并后一次性发送所有计时信息，以降低开销（此功能在 release 模式下也可用）。列表按时间升序排列，最早的帧排在最前。每帧的计时信息大约会在 1 秒内发送；即使没有后续帧可供合并，在 profile/debug 模式下也会在 100 毫秒内发送。第一帧的计时信息会立即发送，不进行合并。

如果此值为 null，则不会执行额外工作。如果此值非 null，Flutter 每秒花费不到 0.1 毫秒来报告计时信息（在 iPhone 6S 上测得）。0.1 毫秒约占 60 fps 帧预算（16 毫秒）的 0.6%，或每秒 CPU 使用率的 0.01%。

实现

@override
TimingsCallback? get onReportTimings => _platformDispatcher.onReportTimings;
