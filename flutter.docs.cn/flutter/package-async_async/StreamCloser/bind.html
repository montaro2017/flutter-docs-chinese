转换提供的 stream。

返回一个新流，其事件由提供的 stream 的事件计算得出。

StreamTransformer 接口完全通用，因此无法说明其子类会执行什么操作。每个 StreamTransformer 都应清楚说明它如何转换流（在用于访问转换器的类或变量上说明），以及与以下典型行为有何不同：

  • 有人开始监听返回的流时，转换器就会开始监听输入 stream。
  • 返回流的订阅会在合理时间内，将 StreamSubscription.pause 调用转发给输入 stream 的订阅。
  • 同样，取消返回流的订阅后，输入 stream 的订阅最终也会被取消（在合理时间内）。

“合理时间”取决于转换器和流。有些转换器（例如“超时”转换器）可能会让这些操作依赖某个时长。其他转换器可能完全不延迟，或者只延迟一个微任务。

转换器可以自行决定如何处理错误。实现可以选择传递错误、将错误转换为其他事件，或完全忽略错误；但如果忽略错误，应明确记录这一点。

实现

@override
Stream<T> bind(Stream<T> stream) {
  var controller = stream.isBroadcast
      ? StreamController<T>.broadcast(sync: true)
      : StreamController<T>(sync: true);

  controller.onListen = () {
    if (isClosed) {
      // Ignore errors here, because otherwise there would be no way for the
      // user to handle them gracefully.
      stream.listen(null).cancel().catchError((_) {});
      return;
    }

    var subscription = stream.listen(
      controller.add,
      onError: controller.addError,
    );
    subscription.onDone(() {
      _subscriptions.remove(subscription);
      _controllers.remove(controller);
      controller.close();
    });
    _subscriptions.add(subscription);

    if (!stream.isBroadcast) {
      controller.onPause = subscription.pause;
      controller.onResume = subscription.resume;
    }

    controller.onCancel = () {
      _controllers.remove(controller);

      // If the subscription has already been removed, that indicates that the
      // underlying stream has been cancelled by [close] and its cancellation
      // future has been handled there. In that case, we shouldn't forward it
      // here as well.
      if (_subscriptions.remove(subscription)) return subscription.cancel();
      return null;
    };
  };

  if (isClosed) {
    controller.close();
  } else {
    _controllers.add(controller);
  }

  return controller.stream;
}
