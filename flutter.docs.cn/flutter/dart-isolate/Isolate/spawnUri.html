启动一个运行 uri 所指定脚本文件的 isolate。

创建并启动一个新的 isolate，运行以 uri 文件作为入口点、并提供 main 方法的 Dart 程序。新 isolate 属于一个新的 isolate 组，与启动它的 isolate 所属组不同。

该 isolate 会开始执行给定 URI 对应库的顶层 main 函数。

目标 main 函数必须能够接受零个、一个或两个参数。示例：

  • main()
  • main(args)
  • main(args, message)

如果存在 args 参数，它会被设为提供的 args 列表。如果存在 message 参数，它会被设为初始 message。如果 message 参数的运行时类型无法赋给 main 方法的第二个参数，则会发生运行时错误。

如果 paused 参数设为 true，isolate 将以暂停状态启动，效果如同先调用了 isolate.pause(isolate.pauseCapability)。若要恢复 isolate，请调用 isolate.resume(isolate.pauseCapability)。

如果提供了 errorsAreFatal、onExit 和/或 onError 参数，isolate 启动运行前会分别按相应参数调用并处理 setErrorsFatal、addOnExitListener 和 addErrorListener，效果如同已执行这些调用。

也可以在返回的 isolate 上调用 setErrorsFatal、addOnExitListener 和 addErrorListener 方法；但除非该 isolate 以 paused 状态启动，否则这些方法完成前它可能已经终止。

checked 参数用于控制创建的 isolate 是否启用断言。在生产模式程序中，此参数会被忽略，所有 isolate 中的断言始终处于禁用状态。否则，如果提供 true 或 false，则会在新 isolate 中分别启用或禁用断言。如果提供 null 或未提供参数，则仅当启动方 isolate 启用了断言时，新 isolate 才会启用断言。

有时可能无法遵循 checked 参数。如果 isolate 代码已预编译，就可能无法动态更改断言模式设置。在这种情况下，checked 参数会被忽略。

如果提供了 packageConfig 参数，则会使用它查找新启动 isolate 的包解析配置文件位置。

如果提供了 automaticPackageResolution 参数，则会自动确定新启动 isolate 中包源代码的位置。

environment 是字符串到字符串的映射，新启动的 isolate 会用它查找 String.fromEnvironment 的值。系统也可能向环境中添加自己的条目。如果省略 environment，新 isolate 会沿用启动方 isolate 的环境声明。

警告：目前并非所有平台都实现了 environment 参数。

如果提供了 debugName，调试器和日志会使用此名称标识新启动的 Isolate。

返回一个 future：启动成功时以 Isolate 实例完成，否则以错误完成。
