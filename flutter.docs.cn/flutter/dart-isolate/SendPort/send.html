通过此发送端口，将异步 message 发送到与之对应的 ReceivePort。

如果发送方和接收方 isolate 不共享相同的代码（例如，使用 Isolate.spawnUri 创建的 isolate 与创建它的 isolate 不共享代码），那么 message 的传递闭包对象图只能包含以下类型的对象：

  • null
  • true 和 false
  • Instances of int, double, String
  • Instances created through list, map and set literals
  • Instances created by constructors of:
    • List, Map, LinkedHashMap, Set 和 LinkedHashSet
    • TransferableTypedData
    • Capability
  • SendPort instances from ReceivePort.sendPort or RawReceivePort.sendPort where the receive ports are created using those classes' constructors.
  • Instances of Type representing one of the types mentioned above, Object, dynamic, void 和 Never as well as nullable variants of all these types. For generic types type arguments must be sendable types for the whole type to be sendable.

如果发送方和接收方 isolate 共享相同的代码（例如，通过 Isolate.spawn 创建的 isolate），那么 message 的传递闭包对象图可以包含任意对象，但以下情况除外：

  • Objects with native resources (subclasses of e.g. NativeFieldWrapperClass1). A Socket object for example refers internally to objects that have native resources attached and can therefore not be sent.
  • ReceivePort
  • DynamicLibrary
  • Finalizable
  • Finalizer
  • NativeFinalizer
  • UserTag
  • MirrorReference

类本身带有 @pragma('vm:isolate-unsendable') 标记，或继承、实现了此类的实例，都不能通过端口发送。

除上述例外外，任何对象都可以发送。被识别为不可变的对象（例如字符串）会被共享，其他对象则会被复制。

发送会立即执行；复制传递闭包对象图可能需要线性时间。发送操作本身不会阻塞（也就是说，它不会等待接收方收到消息）。只要接收方 isolate 的事件循环已准备好分发消息，对应的接收端口就可以收到消息，而无需等待发送方 isolate 的状态。

注意：由于 Dart VM 对闭包捕获状态的表示方式作出了一项实现选择，闭包目前可能会捕获超出实际需要的状态，导致传递闭包比必要的更大。相关问题见：http://dartbug.com/36983
