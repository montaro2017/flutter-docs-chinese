StreamChannel

StreamChannel<T> 类 抽象

表示双向通信通道的抽象类。

用户应将 stream 发出“done”事件视为通道已关闭的权威标志。若要关闭通道，应关闭 sink；仅取消 stream 订阅并不足够。根据错误的根本原因，协议错误可以通过 stream 或 sink.done 发出。请注意，如果通道在调用 sink.close 之前关闭，sink 可能会静默丢弃事件。

强烈建议实现类混入或扩展 StreamChannelMixin，以获得各种实例方法的默认实现。如果同时向 StreamChannelMixin 添加对应实现，向此接口添加新方法将不视为破坏性变更。

实现必须满足以下保证：

  • stream 必须是单订阅流，并遵循单订阅流的所有保证。

  • 关闭 sink 后，stream 必须在发出更多事件之前关闭。

  • stream 关闭后，sink 会自动关闭。如果发生这种情况，在调用 sink.close 之前，sink 上的方法应静默丢弃其参数。

  • 如果 stream 在尚无监听器时关闭，sink 应尽可能静默丢弃事件。

  • 取消 stream 订阅不会影响 sink。即使订阅已取消，通道仍必须能够响应另一端关闭通道。

  • sink 要么将错误转发给另一端，要么在收到错误后立即关闭，并将该错误转发到 sink.done future。

这些保证让用户能够以统一方式与所有实现交互，并确保任一端关闭 stream 时都会产生一致的行为。
