BindingBase 类 抽象

提供单例服务的 mixin 基类。

Flutter 引擎（dart:ui）公开了一些底层服务，但通常不适合直接使用。例如，它们只提供单个回调，而应用可能需要对该回调进行多路复用，以支持多个监听者。

Bindings 为这些底层 API 与更高层的框架 API 提供连接。它们将两者绑定在一起，因此得名。Bindings 一词由此而来。

实现 binding mixin

库通常会创建新的 binding mixin，以公开 dart:ui 中的某项功能。一般很少需要这样做，但替代框架可能会这么做，例如用替代 API 替换 widgets 库，同时仍希望利用 services 和 foundation 库。

要创建 binding mixin，请声明一个 mixin，并通过 BindingBase 类及其他必要 Binding 的 on 子句，限定实现该 mixin 的具体 binding 类。

此 mixin 在应用生命周期内只会构造一次；这一点由 initInstances 保证。

binding mixin 至少必须实现以下功能：

  • initInstances 方法：必须调用 super.initInstances，并将静态字段 _instance 设为 this。
  • instance 静态 getter：必须通过 checkInstance 返回该字段。

此外，还应实现该库所需的单例相关功能。

一般来说，放在 binding 中的内容越少越好。应优先设计接收对象的 API，而不是引用全局单例。Binding 最好仅公开确实只存在一个实例的功能，例如 dart:ui 中的 API。

以下是实现这些功能的 binding 基本示例。它依赖另一个虚构的 Binding：BarBinding。
link 
mixin FooBinding on BindingBase, BarBinding {
  @override
  void initInstances() {
    super.initInstances();
    _instance = this;
    // ...binding initialization...
  }

  static FooBinding get instance => BindingBase.checkInstance(_instance);
  static FooBinding? _instance;

  // ...binding features...
}

实现 binding 类

用于编写应用的最顶层（例如 Flutter 的 widgets 库）会有一个具体类继承自 BindingBase，并使用各种 BindingBase mixin（例如 ServicesBinding）。Flutter 的 widgets 库提供了名为 WidgetsFlutterBinding 的 Binding。

binding 类应混入它希望公开的各层相关 Binding，并提供 ensureInitialized 方法：当该层 mixin 的 _instance 字段为 null 时，此方法会构造该类。这样，开发者可以根据具体需求替换 Binding，同时其他代码仍可在需要 Binding 时调用 ensureInitialized。

下面展示了典型的 binding 类。ensureInitialized 方法的返回类型是库的 binding mixin，而不是具体类。
link 
// continuing from previous example...
class FooLibraryBinding extends BindingBase with BarBinding, FooBinding {
  static FooBinding ensureInitialized() {
    if (FooBinding._instance == null) {
      FooLibraryBinding();
    }
    return FooBinding.instance;
  }
}
