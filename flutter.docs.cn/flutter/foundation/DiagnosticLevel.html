DiagnosticLevel enum

用于筛选显示或省略哪些诊断信息的各种优先级。

Flutter 诊断树可能非常庞大，因此筛选显示的诊断信息很重要。通常适合仅显示级别至少为 debug 的诊断信息。

在发布模式下，此级别可能不起作用，因为发布模式中的诊断信息会被压缩或截断，以减少二进制文件的体积。

Values

hidden → const DiagnosticLevel

不应显示的诊断信息。

如果用户选择显示 hidden 诊断信息，就不应期望其格式与其他诊断信息一致，并且应预期它们有时可能产生误导。例如，当属性 value 与具有自定义标志描述的值不匹配时，FlagProperty 和 ObjectFlagProperty 的格式会较为难看。可能产生误导的一个例子是：对象的其他属性设置导致某个隐藏属性不起作用，但仍显示该属性的诊断信息。

fine → const DiagnosticLevel

可能价值较低，但显示质量与更高级别诊断信息同样良好的诊断信息。

对于值与默认值相同的诊断属性，以及显示诊断信息不会增加太多价值的其他情况，应使用此级别。例如，值为空的 IterableProperty。

debug → const DiagnosticLevel

仅在对对象进行细致调试时才应显示的诊断信息。

与 fine 诊断信息不同，这些诊断信息提供了调试时可能需要的对象重要信息。适用于重要但属性值过于冗长（例如超过 300 个字符）、不适合以更高级别显示的属性。

info → const DiagnosticLevel

通常应显示的有用诊断信息。

warning → const DiagnosticLevel

表明属性值存在问题的非常重要的诊断信息。

例如，如果你会将属性描述消息全部用大写字母书写，就可以使用此级别。

hint → const DiagnosticLevel

提供最佳实践提示的诊断信息。

例如，描述修复错误的最佳实践的诊断信息。

summary → const DiagnosticLevel

概括其他现有诊断信息的诊断信息。

例如，用此级别提供一两行简短摘要，描述其他现有诊断信息。

error → const DiagnosticLevel

表明错误或意外情况的诊断信息。

例如，可用于计算属性值时抛出异常的情况。

off → const DiagnosticLevel

表示不应显示任何诊断信息的特殊级别。

不要为诊断信息指定此级别。此级别仅用于筛选要显示的诊断信息。
