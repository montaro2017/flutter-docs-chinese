AbstractNode 类

已弃用；框架不再使用此类，它将在未来的 Flutter 版本中移除。

如有需要，请将此类中所需的功能直接内联到子类中。

树中的抽象节点。

AbstractNode 具有深度、附着状态和父节点的概念，但不定义子节点模型。

当子类更改某个子节点的父节点时，应根据情况调用 parent.adoptChild(child) 或 parent.dropChild(child)。子类可按需公开操作树的 API（例如用于 child 属性的 setter，或用于操作列表的 add() 方法）。

当前父节点通过 parent 属性公开。

当前附着状态通过 attached 公开。对于任何应视为已附着的树，都应调用 attach 手动附着其根节点。除此之外，不应直接调用 attach 和 detach 方法；附着状态由前述 adoptChild 和 dropChild 方法自动管理。

具有子节点的子类必须按照相关方法文档中的说明，重写 attach 和 detach。

节点的 depth 始终大于其祖先节点的深度，但兄弟节点之间的深度关系没有保证。节点深度用于确保按深度顺序处理节点。子节点的 depth 与父节点的 depth 之差可以大于 1，因为 depth 值从不减小：只要大于父节点即可。考虑一棵具有根节点 A、子节点 B 和孙节点 C 的树。最初，A 的 depth 为 0，B 的 depth 为 1，C 的 depth 为 2。如果将 C 移为 A 的子节点、B 的兄弟节点，这些数值不会改变。C 的 depth 仍为 2。depth 由 adoptChild 和 dropChild 方法自动维护。
