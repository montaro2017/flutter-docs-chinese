ValueKey<T> 类

使用特定类型的值标识自身的键。

当且仅当两个 ValueKey 的值相等（使用 operator== 判断）时，一个 ValueKey 才与另一个相等。

可以通过继承此类创建值键，使其不与恰好使用相同值的其他值键相等。如果子类是私有的，得到的值键类型就不会与其他来源的键发生冲突。当备用键与其他 widget 提供的键处于同一作用域时，这种做法很有用。

从数据集合构建 widget 时，尤其当集合会随时间变化（例如插入、移除或重新排序元素）时，可以使用键来保留 widget 与底层数据之间的关联。

如果没有键，框架可能无法区分现有 widget 的数据变化与列表的结构变化。因此，widget 可能被错误地更新，StatefulWidget 保存的状态也可能被用于另一条数据。

指定键会将 widget 子树绑定到特定数据，使框架能够正确匹配新旧 widget，并按预期保留状态。

在这种情况下，通常适合使用 ValueKey，并为每个元素提供稳定且唯一的值，例如数据模型中的标识符。

键带来的差异

  • 不使用 Key：列表反转时，Flutter 会按位置匹配 widget。State（计数器）仍留在原位置，而 widget 的配置（颜色）会互换。因此，计数器看起来保持“静止”，颜色则在其后移动。
  • 使用键时：提供 ValueKey 后，Flutter 会通过 key（而非索引）将 State 与 Widget 匹配。反转列表时，State 会随颜色移动。

要查看差异，请找到 map 函数中的 ColoredWidgetsList widget，然后注释或取消注释 key: ValueKey(color) 这一行。
