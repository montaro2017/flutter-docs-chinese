继承

锁定异步事件和回调的分发，直到回调返回的 future 完成。

这会造成输入延迟，因此应尽可能避免。此方法主要用于无需用户交互的时段，例如让 reassembleApplication 在遍历树时阻止输入（该遍历有一部分是异步执行的）。

callback 参数返回的 Future 也会作为 lockEvents 的返回值。

gestures 绑定会将 PlatformDispatcher.onPointerDataPacket 包装在遵守此事件锁定机制的逻辑中。同样，通过 SchedulerBinding.scheduleTask 排队的任务，只有在事件未处于 locked 状态时才会开始执行。

实现

@protected
Future<void> lockEvents(Future<void> Function() callback) {
  developer.TimelineTask? debugTimelineTask;
  if (!kReleaseMode) {
    debugTimelineTask = developer.TimelineTask()..start('Lock events');
  }

  _lockCount += 1;
  final Future<void> future = callback();
  future.whenComplete(() {
    _lockCount -= 1;
    if (!locked) {
      if (!kReleaseMode) {
        debugTimelineTask!.finish();
      }
      try {
        unlocked();
      } catch (error, stack) {
        FlutterError.reportError(
          FlutterErrorDetails(
            exception: error,
            stack: stack,
            library: 'foundation',
            context: ErrorDescription('while handling pending events'),
          ),
        );
      }
    }
  });
  return future;
}
