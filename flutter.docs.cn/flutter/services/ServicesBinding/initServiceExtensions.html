initServiceExtensions 方法

  1. @重写
void initServiceExtensions()
重写

绑定初始化时调用，用于注册服务扩展。

若绑定希望公开服务扩展，应重写此方法，并通过以下调用注册扩展：registerSignalServiceExtension、registerBoolServiceExtension、registerNumericServiceExtension 和 registerServiceExtension（复杂度依次递增）。

此方法的实现必须调用其父类实现。

只有构建中包含 vm-service 时，注册的服务扩展才能启用；只有调试模式和性能分析模式的构建会包含 vm-service。服务扩展虽然不能在发布模式下使用，但其代码仍可能被包含在 Dart 快照中，增大二进制文件体积。因此，应使用可让 tree shaker 移除该代码的保护条件包裹它（参见下面的示例代码）。

以下代码会注册一个仅包含在调试构建中的服务扩展。
link 
void myRegistrationFunction() {
  assert(() {
    // Register your service extension here.
    return true;
  }());
}

通过以下代码片段注册的服务扩展在调试和性能分析模式下均可用。
link 
void myOtherRegistrationFunction() {
  // kReleaseMode is defined in the 'flutter/foundation.dart' package.
  if (!kReleaseMode) {
    // Register your service extension here.
  }
}

这两种保护条件都能确保 Dart 的 tree shaker 在发布构建中移除服务扩展代码。

另请参阅：

  • github.com/dart-lang/sdk/blob/main/runtime/vm/service/service.md#rpcs-requests-and-responses

实现

@override
void initServiceExtensions() {
  super.initServiceExtensions();

  assert(() {
    registerStringServiceExtension(
      name: ServicesServiceExtensions.evict.name,
      getter: () async => '',
      setter: (String value) async {
        evict(value);
      },
    );
    return true;
  }());

  if (!kReleaseMode) {
    registerBoolServiceExtension(
      name: ServicesServiceExtensions.profilePlatformChannels.name,
      getter: () async => debugProfilePlatformChannels,
      setter: (bool value) async {
        debugProfilePlatformChannels = value;
      },
    );
  }
}
