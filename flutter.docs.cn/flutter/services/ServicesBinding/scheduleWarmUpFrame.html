scheduleWarmUpFrame 方法

void scheduleWarmUpFrame()
继承

尽快安排一帧，而不是等待引擎响应系统的“Vsync”信号来请求帧。

应用启动时会使用此方法，让通常开销较大的首帧多获得几毫秒的运行时间。

在已安排的帧完成之前，事件分发会保持锁定。

如果已通过 scheduleFrame 或 scheduleForcedFrame 安排帧，此调用可能会延迟该帧。

如果已有帧开始处理，或者已经调用过另一个 scheduleWarmUpFrame，则会忽略此调用。

正常运行时，优先使用 scheduleFrame 更新显示。

设计讨论

Flutter 引擎收到操作系统的请求后，会提示框架生成帧；出于历史原因，此请求称为 vsync。不过，应用启动（或热重载）后的数毫秒内可能还不会收到该请求。为了利用首次配置 widget 树与引擎请求更新之间的时间，框架会安排一帧预热帧。

预热帧可能不会真正渲染（因为引擎没有请求它，因此没有可供绘制的有效上下文），但框架仍会执行构建、布局和绘制流程，这些步骤合计可能需要数毫秒。因此，当引擎请求真正的帧时，大部分工作已经完成，框架只需很少额外工作即可生成该帧。

启动时由 runApp 安排预热帧；热重载时则由 RendererBinding.performReassemble 安排。

框架解除阻塞时也会安排预热帧：这发生在调用 RendererBinding.allowFirstFrame 后，对应于此前调用 RendererBinding.deferFirstFrame 暂停渲染的情况。

实现

void scheduleWarmUpFrame() {
  if (_warmUpFrame || schedulerPhase != SchedulerPhase.idle) {
    return;
  }

  _warmUpFrame = true;
  TimelineTask? debugTimelineTask;
  if (!kReleaseMode) {
    debugTimelineTask = TimelineTask()..start('Warm-up frame');
  }
  final bool hadScheduledFrame = _hasScheduledFrame;
  PlatformDispatcher.instance.scheduleWarmUpFrame(
    beginFrame: () {
      assert(_warmUpFrame);
      handleBeginFrame(null);
    },
    drawFrame: () {
      assert(_warmUpFrame);
      handleDrawFrame();
      // We call resetEpoch after this frame so that, in the hot reload case,
      // the very next frame pretends to have occurred immediately after this
      // warm-up frame. The warm-up frame's timestamp will typically be far in
      // the past (the time of the last real frame), so if we didn't reset the
      // epoch we would see a sudden jump from the old time in the warm-up frame
      // to the new time in the "real" frame. The biggest problem with this is
      // that implicit animations end up being triggered at the old time and
      // then skipping every frame and finishing in the new time.
      resetEpoch();
      _warmUpFrame = false;
      if (hadScheduledFrame) {
        scheduleFrame();
      }
    },
  );

  // Lock events so touch events etc don't insert themselves until the
  // scheduled frame has finished.
  lockEvents(() async {
    await endOfFrame;
    if (!kReleaseMode) {
      debugTimelineTask!.finish();
    }
  });
}
