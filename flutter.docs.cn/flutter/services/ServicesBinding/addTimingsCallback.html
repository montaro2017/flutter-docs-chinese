添加一个 TimingsCallback，以接收引擎发送的 FrameTiming。

此 API 允许应用监控图形性能。引擎数据会批量收集到 FrameTiming 对象列表中：发布模式下大约每秒报告一次，调试和性能分析构建中大约每 100 毫秒报告一次。列表按时间升序排列（最早的帧在前）。第一帧的计时数据会立即发送，不进行批处理。

返回的数据可用于检测丢帧（例如检查 FrameTiming.buildDuration 或 FrameTiming.rasterDuration 是否超出帧预算，如 60Hz 下的 16 毫秒），也可用于检测高延迟（检查 FrameTiming.totalSpan 是否超出帧预算）。即使没有丢帧，延迟也可能超过一帧，例如 Flutter 引擎对图形更新进行流水线处理，导致 FrameTiming.buildDuration 与 FrameTiming.rasterDuration 之和超过帧预算。在这种情况下，动画仍然流畅，但触控输入会显得迟钝。

相比直接使用 dart:ui.PlatformDispatcher.onReportTimings，更推荐使用 addTimingsCallback。dart:ui.PlatformDispatcher.onReportTimings API 只允许设置一个回调，因此多个库无法同时注册监听器；而此 API 允许多个回调彼此独立地注册。

此 API 基于 dart:ui.PlatformDispatcher.onReportTimings 实现。在发布构建中，如果没有库注册此 API，则不会设置 dart:ui.PlatformDispatcher.onReportTimings 回调，从而关闭性能跟踪，使运行时开销几乎为零。注册一个或多个回调后（即启用性能跟踪时），其开销大约为每秒 0.01% 的 CPU 使用率（在 iPhone 6s 上测得）。

在调试和性能分析构建中，SchedulerBinding 自身会注册计时回调以更新 Timeline。

如果同一个回调添加两次，它也会执行两次。

另请参阅：

  • removeTimingsCallback, which can be used to remove a callback added using this method.

实现

void addTimingsCallback(TimingsCallback callback) {
  _timingsCallbacks.add(callback);
  if (_timingsCallbacks.length == 1) {
    assert(platformDispatcher.onReportTimings == null);
    platformDispatcher.onReportTimings = _executeTimingsCallbacks;
  }
  assert(platformDispatcher.onReportTimings == _executeTimingsCallbacks);
}
