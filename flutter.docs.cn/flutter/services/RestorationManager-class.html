RestorationManager 类

管理框架中的恢复数据，并使其与引擎保持同步。

恢复数据可以序列化保存，并在之后用于将应用恢复到序列化数据所描述的先前状态。移动操作系统通过状态恢复机制营造应用似乎会一直在后台运行的体验：应用进入后台后，用户随时可以返回并看到原来的状态。但实际上，操作系统可能会为了释放资源、供前台运行的其他应用使用而终止应用。发生这种情况之前，应用有机会序列化并保存恢复数据。用户返回后台应用时，应用会重新启动，操作系统再次提供已序列化的恢复数据。理想情况下，应用会利用这些数据恢复到用户将其切换到后台时的状态。

在 Flutter 中，恢复数据组织成一棵以 rootBucket 为根节点的 RestorationBucket 树。应用恢复当前状态所需的所有信息都必须存储在该层级中的 bucket 内。实体（例如 Widget）要在此层级存储数据，必须从父 bucket（可以是此 RestorationManager 提供的 rootBucket）认领子 bucket 的所有权。bucket 所有者可以存储任意值，前提是这些值能通过 StandardMessageCodec 序列化。值以恢复 ID 为键存储在 bucket 中。恢复 ID 是一个 String，必须在同一 bucket 中保持唯一。状态恢复期间，必须再次提供相同的恢复 ID 才能访问已存储的值。bucket 所有者还可以将 bucket 提供给其他实体，以便它们出于自身的恢复需求认领子 bucket。bucket 内的子 bucket 也通过唯一恢复 ID 标识；认领子 bucket 时必须提供该 ID。

向 RestorationManager 提供恢复数据时（例如应用重新进入前台并重新启动后），整个 bucket 层级及其中存储的数据都会恢复。实体可以使用最初存储数据时所用的恢复 ID 再次取回数据。

除了在应用启动时提供恢复数据，也可以向正在运行的应用提供恢复数据，使其恢复到先前状态（例如用户在 Web 浏览器中点击后退或前进按钮时）。此时，RestorationManager 会通知其监听器（通过 addListener 添加）新的 rootBucket 已可用。收到通知后，监听器必须停止使用旧 bucket，并根据新 rootBucket 中的信息恢复状态。

某些平台会限制恢复数据的大小。因此，只要仍足以让应用恢复当前状态，bucket 中存储的数据就应尽可能精简。可从其他服务（例如数据库或 Web 服务器）获取的数据不应包含在恢复数据中；应存储少量标识信息（例如 UUID、数据库记录编号或资源定位符），以便状态恢复期间从原始来源重新获取数据。

当 bucket 层级中的数据或其结构发生变化时，RestorationManager 会在该帧结束时将序列化后的 bucket 层级发送给引擎。引擎会缓存这些数据，直到操作系统需要时再使用。应用有责任始终更新 bucket 中的数据，使其反映当前状态。

讨论

由于 Flutter 的线程模型以及 Flutter 所运行平台的 API 限制，必须按照上述方式主动将恢复数据存储到 bucket 中。操作系统请求恢复数据时，会在平台线程上发出请求，并要求同步响应。为避免死锁风险，平台线程不能阻塞并调用 UI 线程（Dart 代码运行所在的线程）来获取恢复数据。因此，每当恢复数据发生变化时，RestorationManager 都会将 UI 线程上的最新数据副本发送到平台线程。这样，操作系统需要数据时，平台线程上始终已有可用的最新副本。

在 iOS 上恢复状态

要在 iOS 上启用状态恢复，必须为 FlutterViewController 分配恢复标识符。使用标准嵌入器（通过 flutter create 生成）时，可以按以下步骤进行：

  1. 在应用目录中，使用 Xcode 打开 ios/Runner.xcodeproj。
  2. 在左侧的项目导航器中，选择 Main.storyboard（位于 Runner/Runner 下）。
  3. 在视图层级中选择 Flutter View Controller（位于 Flutter View Controller Scene 下）。
  4. 在右侧面板中打开“标识检查器”。
  5. 在指定字段中输入唯一的恢复 ID。
  6. 保存项目。

热重启和热重载期间的开发

通过热重载和热重启应用的更改不会保存在设备上。应用被完全终止并重新启动（例如被操作系统终止）后，这些更改就会丢失。因此，在开发过程中，如果应用经过热重启或热重载，状态恢复可能无法正确工作。测试状态恢复时，务必在每次更改后完整重新编译应用（例如重新执行 flutter run）。

测试状态恢复

在 Android 上测试状态恢复：

  1. 启用“不保留活动”选项；用户离开后，该选项会立即销毁 Android Activity。设备启用“开发者选项”后，此选项才会出现。
  2. 在 Android 设备上运行代码示例。
  3. 例如，在手机应用中创建一些内存状态，比如导航到其他屏幕。
  4. 将 Flutter 应用移至后台后再返回。应用会重新启动并恢复其状态。

在 iOS 上测试状态恢复：

  1. 在 Xcode 中打开 ios/Runner.xcworkspace/。
  2. 仅限 iOS 14 及更高版本：切换到 profile 或 release 构建模式，因为无法在 debug 模式下从主屏幕启动应用。
  3. 在 Xcode 中按下“运行”按钮以构建并运行应用。
  4. 例如，在手机应用中创建一些内存状态，比如导航到其他屏幕。
  5. 将手机上的应用移至后台，例如返回主屏幕。
  6. 当应用在后台运行时，按下 Xcode 中的“停止”按钮将其终止。
  7. 在手机上重新打开应用（不要通过 Xcode 启动）。应用会重新启动并恢复其状态。

  • RestorationBucket 构成恢复数据层级结构。
  • RestorationMixin 会在幕后使用 RestorationBucket，使 StatefulWidget 的 State 对象能够恢复。
