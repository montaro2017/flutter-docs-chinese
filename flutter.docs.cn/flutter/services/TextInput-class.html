TextInput 类

用于访问系统文本输入控件的底层接口。

若要开始与系统文本输入控件交互，请调用 attach，在系统文本输入控件与 TextInputClient 之间建立 TextInputConnection。与文本输入控件交互的大多数命令都由返回的 TextInputConnection 提供。系统文本输入与 TextInputClient 之间的通信是异步的。

平台文本输入插件（代表系统文本输入）与 TextInputClient 通常分别维护自己的文本编辑状态（TextEditingValue）。只要 TextInputClient 处于连接状态，双方就必须保持同步。当任一方的文本编辑状态发生变化时，可以通过以下方法向另一方发送 TextEditingValue 以更新状态：

  • TextInput.attach 方法允许 TextInputClient 建立文本输入连接。其 configuration 参数中的可选字段可用于指定平台文本输入插件的初始 TextEditingValue。

  • TextInputClient 通过 TextInputConnection.setEditingState 将自己的 TextEditingValue 发送给平台文本输入插件。

  • 平台文本输入插件会通过“TextInput.setEditingState”消息，将自己的 TextEditingValue 发送给已连接的 TextInputClient。

  • 当自动填充发生在未连接的 TextInputClient 上时，平台文本输入插件会将 TextEditingValue 发送给已连接的 TextInputClient 的 AutofillScope；随后 AutofillScope 会将该值转发给正确的 TextInputClient。

同步 TextEditingValue 时，如果双方都尝试发送各自的更新，通信可能陷入无限循环。为缓解此问题，只有 TextInputClient 可以修改收到的 TextEditingValue；平台文本输入插件则必须原样接受收到的 TextEditingValue。具体规则如下：

  • When a TextInputClient receives a new TextEditingValue from the platform text input plugin, it's allowed to modify the value (for example, apply TextInputFormatters). If it decides to do so, it must send the updated TextEditingValue back to the platform text input plugin to keep the TextEditingValues in sync.

  • 平台文本输入插件从已连接的 TextInputClient 收到新值时，必须原样接受该值，以避免再发送回一个更新后的值。

另请参阅：

  • TextField, a widget in which the user may enter text.
  • EditableText, a TextInputClient that connects to TextInput when it wants to take user input from the keyboard.
