UiKitViewGestureBlockingPolicy enum

平台视图的触摸事件回调和手势识别器如何被阻止。

此枚举取代引擎 FlutterPlugin.h 中的 FlutterPlatformViewGestureRecognizersBlockingPolicy。

在 iOS 中，手势识别器（UIGestureRecognizer）是一种对象，它将识别一系列触摸动作（例如点击、捏合或滑动）的逻辑与识别后的响应分离。

当 Flutter 应用嵌入 iOS 平台视图（例如 WKWebView）时，Flutter 框架和原生 iOS 视图都会收到触摸事件。为防止两个系统同时响应同一次触摸（例如一次滚动手势同时滚动 Flutter ListView 和原生 UIScrollView），当 Flutter 判断应由框架处理手势时，需要一种机制来“阻止”原生视图的手势识别器。

Flutter 使用两种机制实现这一点：

  1. 同步阻止（命中测试）：在初始触摸（UIResponder.touchesBegan）期间，Flutter 会同步执行命中测试。如果触摸落在视觉上覆盖平台视图的 Flutter widget 上，Flutter 会立即阻止原生视图接收该触摸。
  2. 异步阻止（手势竞技场）：如果触摸直接落在平台视图上，Flutter 和原生视图都会开始跟踪该手势。Flutter 的手势竞技场会判定哪一方获胜。如果 Flutter 获胜（例如，用户正在滚动一个包含该平台视图的 Flutter ListView），Flutter 会异步取消原生视图的手势识别器。

默认策略（fallbackToPluginDefault，通常会解析为 eager）适用于大多数情况。不过，某些 Apple 或第三方原生视图存在缺陷：Flutter 异步阻止手势时若频繁取消手势，其内部识别器可能会卡在过时状态。遇到此类情况时，可以改用 doNotBlockGesture 或 waitUntilTouchesEnded 来绕过原生视图的问题。

更多详情请参阅：https://flutter.dev/go/ios-platform-view-touch-gesture-blocking。

Values

eager → const UiKitViewGestureBlockingPolicy

Flutter 一旦确定应阻止平台视图上的所有 UIGestureRecognizers，就会立即执行阻止。

此策略采用双重阻止机制：通过 hitTest 结果进行同步阻止，并通过框架的手势竞技场进行异步阻止。使用此策略时，可以保证所有 UIGestureRecognizers 的 touchesBegan 方法都会被调用。

waitUntilTouchesEnded → const UiKitViewGestureBlockingPolicy

Flutter 仅在调用 touchesEnded 后，才会阻止平台视图上的所有 UIGestureRecognizers。

这样一来，平台视图上的 UIGestureRecognizers 会看到完整的触摸序列，但永远不会识别该手势（也不会触发操作）。使用此策略可能导致平台视图错误地接收到本应被阻止的触摸事件。

doNotBlockGesture → const UiKitViewGestureBlockingPolicy

如果 iOS 引擎认为 Flutter 框架不应处理命中测试，就会阻止平台视图上的所有 UIGestureRecognizers。

与 eager 不同，此策略不依赖 Flutter 的手势竞技场。此策略用于解决平台视图的手势识别器卡在过期状态中的一些问题。详见：https://github.com/flutter/flutter/issues/175099。使用此策略可能导致平台视图错误地识别本应被阻止的手势。

fallbackToPluginDefault → const UiKitViewGestureBlockingPolicy

回退到 FlutterPlugin.h 中 Flutter 引擎 API registerViewFactory 设置的策略。
