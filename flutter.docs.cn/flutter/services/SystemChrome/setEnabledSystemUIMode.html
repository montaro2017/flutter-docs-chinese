指定应用运行时应显示的 SystemUiMode。

overlays 参数是一个 SystemUiOverlay 枚举值列表，用于在配置为 SystemUiMode.manual 时指定要显示的覆盖层。

如果平台不支持某种模式，则启用或禁用该模式的操作会被忽略。

当系统 UI 因功能需要而必须显示时，平台可能会覆盖此处的设置。

例如，在 Android 上，键盘显示时会启用导航栏和状态栏覆盖层。键盘关闭后，Android 不会恢复之前的 UI 可见性设置；并且为防止恶意软件锁死导航按钮，键盘关闭 1 秒内无法更改 UI 可见性。

输入文本后若要恢复“全屏”状态，可以至少等待 1 秒，再通过 restoreSystemUIOverlays 或再次调用此方法设置 UI 覆盖层。否则，只有在应用失去并重新获得焦点时，才会自动恢复原来的 UI 覆盖层设置。

也可以提供 SystemUiChangeCallback 来响应系统 UI 变化。例如，在 SystemUiMode.leanBack 模式下，用户点击屏幕显示系统覆盖层时会调用此回调。回调会提供一个布尔值，表示应用当前是否处于全屏模式，以便应用响应这些变化。systemOverlaysAreVisible 为 true 时，应用不处于全屏模式。若要在全屏应用中响应这些变化，请参阅 SystemChrome.setSystemUIChangeCallback。

如果应用面向 Android SDK 15（API 35），Flutter 应用在 Android 上默认使用 SystemUiMode.edgeToEdge。除非按照以下迁移指南完成迁移，否则设置其他 SystemUiMode 均不会生效：https://docs.flutter.dev/release/breaking-changes/default-systemuimode-edge-to-edge。

如果应用面向 Android SDK 16（API 36）或更高版本，Flutter 应用在 Android 上默认使用 SystemUiMode.edgeToEdge，设置其他 SystemUiMode 均不会生效，也无法退出 SystemUiMode.edgeToEdge。

实现

static Future<void> setEnabledSystemUIMode(
  SystemUiMode mode, {
  List<SystemUiOverlay>? overlays,
}) async {
  if (mode != SystemUiMode.manual) {
    await SystemChannels.platform.invokeMethod<void>(
      'SystemChrome.setEnabledSystemUIMode',
      mode.toString(),
    );
  } else {
    assert(mode == SystemUiMode.manual && overlays != null);
    await SystemChannels.platform.invokeMethod<void>(
      'SystemChrome.setEnabledSystemUIOverlays',
      _stringify(overlays!),
    );
  }
}
