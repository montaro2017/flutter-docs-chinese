textInput constant

MethodChannel const textInput

用于处理文本输入的 JSON MethodChannel。

此通道公开系统文本输入控件，以便与 IME（输入法编辑器，例如屏幕键盘）交互。系统只有一个控件，任一时刻只能有一个活动事务。事务用整数表示。通过 TextInput.setClient 开始新事务。发送的消息默认属于当前事务（即最近一次通过 TextInput.setClient 设置的“客户端”）。shell 端发来的消息会标明所属事务，以便忽略引用旧事务的过期消息。

在调试构建中，客户端 ID 为 -1 的消息始终会被接受。这样测试无需模拟引擎的文本处理即可传入消息（例如，集成测试仍可让引擎处理文本输入消息）。

下文介绍的方法由 TextInput 和 TextInputConnection 类封装为更便于使用的形式。

此通道定义了以下出站方法（通过 OptionalMethodChannel.invokeMethod 调用）：

  • TextInput.setClient：建立新事务。参数是一个 List：第一个值是此前未使用过的事务标识符（整数），第二个值是一个 String，其中包含 JSON 编码的对象，该对象有五个键，格式由 TextInputConfiguration.toJson 提供。必须先调用此方法，其他方法才能调用（TextInput.hide 除外）。参见 TextInput.attach。

  • TextInput.show：显示键盘。参见 TextInputConnection.show。

  • TextInput.setEditingState：更新文本编辑控件中的值。参数是一个 String，其中包含 JSON 编码的七键对象，格式由 TextEditingValue.toJSON 提供。参见 TextInputConnection.setEditingState。

  • TextInput.clearClient：结束当前事务。下一个调用的方法必须是 TextInput.setClient（或 TextInput.hide）。参见 TextInputConnection.close。

  • TextInput.hide：隐藏键盘。与其他方法不同，此方法可随时调用。参见 TextInputConnection.close。

此通道定义了以下入站方法（通过 MethodChannel.setMethodCallHandler 注册）。每个方法的第一个参数都是事务标识符。应忽略属于过期事务的调用。

  • TextInputClient.updateEditingState：用户更改了文本控件的内容。第二个参数是一个七键对象，格式与 TextEditingValue.fromJSON 期望的格式相同。

  • TextInputClient.updateEditingStateWithTag：平台的自动填充服务填充了一个或多个文本控件。第一个参数（客户端 ID）会被忽略；第二个参数是标签到对象的映射，格式与 TextEditingValue.fromJSON 期望的格式相同。有关标签的解释，请参见 AutofillScope.getAutofillClient。

  • TextInputClient.performAction：用户触发了某项操作。第二个参数是一个 String，其内容为 TextInputAction 枚举值之一的字符串表示。

  • TextInputClient.requestExistingInputState：嵌入器可能丢失了当前编辑客户端的内部状态（如果存在）。框架应再次调用 TextInput.setClient 和 TextInput.setEditingState，并提供最新信息。如果框架端没有现存状态，则此调用不产生效果。（此调用不带客户端 ID，实际上也不带任何参数。）

  • TextInputClient.onConnectionClosed：平台端的文本输入连接已关闭。例如，应用切换到后台或用户关闭虚拟键盘时会发生这种情况。此方法通知 TextInputClient 清除连接并结束编辑。清除连接后不会再调用 TextInput.clearClient 和 TextInput.hide，因为平台端的连接已经结束。

shell 端未实现的方法调用会被忽略（因此，即使相关插件可能缺失，调用这些方法也是安全的）。

实现

static const MethodChannel textInput = OptionalMethodChannel(
  'flutter/textinput',
  JSONMethodCodec(),
);
