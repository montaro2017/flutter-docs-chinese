RestorationBucket 类

RestorationBucket 保存应用某个部分恢复其状态所需的部分恢复数据。

有关 Flutter 状态恢复工作方式的总体介绍，请参阅 RestorationManager。

RestorationBucket 以树形结构组织，根节点为 RestorationManager.rootBucket，并由 RestorationManager 管理。该树可序列化，必须包含应用稍后恢复当前状态所需的全部数据。

RestorationBucket 以键值对形式存储恢复数据。键是一个 String，表示用于在 bucket 中唯一标识数据的恢复 ID。值可以是任何能通过 StandardMessageCodec 序列化的数据。此外，RestorationBucket 还可以包含子 bucket，子 bucket 也通过在其父 bucket 中唯一的恢复 ID 标识。

进行状态恢复时，之前存储在 RestorationBucket 层级中的数据会再次提供给应用，使其恢复到收集这些数据时的状态。恢复到之前状态可能发生在应用启动时（例如应用在后台运行期间正常终止后），也可能发生在应用已运行一段时间之后。

生命周期

通常不会直接通过构造函数实例化 RestorationBucket。实体需要向恢复 bucket 存储或读取数据时，通常会调用 claimChild，从父 bucket 获取子 bucket。如果没有父 bucket，可以将 RestorationManager.rootBucket 用作父级。认领子 bucket 时，认领方必须提供希望拥有的子 bucket 的恢复 ID。具有同一恢复 ID 的子 bucket 最多只能有一个所有者。如果另一个所有者尝试从同一父级认领相同 ID 的 bucket，就会抛出异常（详见 claimChild）。所有者用于认领子 bucket（以及在其中存储数据，见下文）的恢复 ID 必须在应用不同启动期间保持稳定，以便应用重启后能取回之前运行时保存的数据。

按照惯例，bucket 的所有者独占其中存储的值。所有者可以通过 read、write 和 remove 方法读取、添加、修改和删除值。通常，所有者应在 bucket 中保存恢复当前状态所需的全部数据；当前状态发生变化时，也必须更新其中的数据。同时，bucket 中的数据应尽量精简。例如，对于可从数据库或 Web 服务等其他来源获取的数据，只应保存重新获取这些数据所需的信息（如 ID 或资源定位符）。除了管理 bucket 中的数据，所有者还可以将 bucket 提供给其他实体，以便它们通过 claimChild 认领子 bucket，满足各自的恢复需求。

claimChild 返回的 bucket 可能包含所有者之前（例如在应用上一次运行时）存入的状态信息，也可能为空。如果 bucket 包含数据，所有者应使用之前存储的信息恢复状态。如果 bucket 为空，则可以将自身初始化为默认值。

当 bucket 中的数据不再用于恢复应用的当前状态时（例如 bucket 所有者不再显示在屏幕上），必须调用 dispose。这会从应用的恢复数据中移除 bucket 内的所有信息，应用日后恢复到此状态时也不会再提供这些信息。
