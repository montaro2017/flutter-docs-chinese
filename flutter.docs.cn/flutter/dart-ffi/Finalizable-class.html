Finalizable

Finalizable 类 抽象 interface

用于标记不应过早被终结的对象的接口。

任何静态类型包含 Finalizable 的局部变量，都保证在执行离开该变量所在的代码块之前保持存活。

如果满足以下任一条件，则类型包含 Finalizable：

  • the type is a non-Never subtype of Finalizable, or
  • the type is T? or FutureOr<T> where T includes Finalizable.

换言之，只要此类变量引用着某个对象，该对象就保证不会被视为不可达；即使变量最后一次被引用之后，变量本身也会在其整个作用域期间保持存活。

如果变量的类型没有此标记接口，只要确定变量之后不会再被引用，即使外围作用域尚未执行完毕，该变量的值也可能被垃圾回收。这反过来可能触发 NativeFinalizer 执行回调。当变量的类型包含 Finalizable 时，在当前使用该变量的代码执行完毕之前，不会运行 NativeFinalizer 回调。

例如，在执行 someNativeCall 期间，finalizable 会保持存活：

void myFunction() {
  final finalizable = MyFinalizable(Pointer.fromAddress(0));
  someNativeCall(finalizable.nativeResource);
}

void someNativeCall(Pointer nativeResource) {
  // ..
}

class MyFinalizable implements Finalizable {
  final Pointer nativeResource;

  MyFinalizable(this.nativeResource);
}

实现 Finalizable 的类，其方法会在方法执行期间保持 this 对象存活。this 值会被视为局部变量。

例如，在 myFunction 中执行 someNativeCall 期间，this 会保持存活：

class MyFinalizable implements Finalizable {
  final Pointer nativeResource;

  MyFinalizable(this.nativeResource);

  void myFunction() {
    someNativeCall(nativeResource);
  }
}

void someNativeCall(Pointer nativeResource) {
  // ..
}

最好将涉及可终结对象的逻辑实现为实现 Finalizable 的类的方法。

如果在声明该变量的代码块作用域内创建闭包，并且闭包引用了该变量，那么只要闭包对象存在，或者该闭包正在执行，其函数体就会使该变量保持存活。

例如，finalizable 会由闭包对象保持存活，并持续到闭包函数体执行结束：

void doSomething() {
  final resourceAction = myFunction();
  resourceAction(); // `finalizable` is alive until this call returns.
}

void Function() myFunction() {
  final finalizable = MyFinalizable(Pointer.fromAddress(0));
  return () {
    someNativeCall(finalizable.nativeResource);
  };
}

void someNativeCall(Pointer nativeResource) {
  // ..
}

class MyFinalizable implements Finalizable {
  final Pointer nativeResource;

  MyFinalizable(this.nativeResource);
}

闭包只会保持捕获的变量存活，不会保持所有变量存活。

例如，返回的闭包对象不会使 finalizable 保持存活：

void Function() myFunction() {
  final finalizable = MyFinalizable(Pointer.fromAddress(0));
  final nativeResource = finalizable.nativeResource;
  return () {
    someNativeCall(nativeResource);
  };
}

void someNativeCall(Pointer nativeResource) {
  // ..
}

class MyFinalizable implements Finalizable {
  final Pointer nativeResource;

  MyFinalizable(this.nativeResource);
}

如果从可终结对象中提取的资源逃逸出提取它的可终结变量的作用域，这很可能是错误。

Finalizable 变量的行为同样适用于异步函数。只要仍有代码可能在声明该变量的作用域内执行，或在捕获该变量的闭包中执行，这些变量就会保持存活；即使执行期间存在异步等待也一样。

例如，在 await someAsyncCall() 执行期间，finalizable 会保持存活：

Future<void> myFunction() async {
  final finalizable = MyFinalizable();
  await someAsyncCall();
}

Future<void> someAsyncCall() async {
  // ..
}

class MyFinalizable implements Finalizable {
  // ..
}

在异步代码中，如果从可终结对象提取的资源逃逸出提取它的 Finalizable 作用域，也很可能是错误。如果必须从 Finalizable 中提取资源，应确保定义 Finalizable 的作用域长于使用该资源的过程；可以通过 await 等待所有使用该资源的异步代码来实现。

例如，在 useAsync1 中，this 会一直保持存活，直到不再使用 resource；而在 useAsync2 和 useAsync3 中则不会：

class MyFinalizable {
  final Pointer<Int8> resource;

  MyFinalizable(this.resource);

  Future<int> useAsync1() async {
    return await useResource(resource);
  }

  Future<int> useAsync2() async {
    return useResource(resource);
  }

  Future<int> useAsync3() {
    return useResource(resource);
  }
}

/// Does not use [resource] after the returned future completes.
Future<int> useResource(Pointer<Int8> resource) async {
  return resource.value;
}

异步函数可能会在某个 await 处停滞，运行时系统可能因此确定该 await 不可能完成。在这种情况下，await 之后的代码永远不会执行，包括 finally 代码块；该变量也可能与其他内容一起被视为已失效。

如果不打算自行保持变量存活，请将可终结对象传递给其他函数，而不是只传递它的资源。

例如，finalizable 在 myFunction 执行到其作用域末尾后不会继续保持存活，此时 someAsyncCall 仍可能继续执行。不过，someAsyncCall 本身会使 finalizable 保持存活：

void myFunction() {
  final finalizable = MyFinalizable();
  someAsyncCall(finalizable);
}

Future<void> someAsyncCall(MyFinalizable finalizable) async {
  // ..
}

class MyFinalizable implements Finalizable {
  // ..
}
