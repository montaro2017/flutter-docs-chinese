Future<R> then<R>(
  1. FutureOr<R> onValue(
    1. void value
    ), {
  2. Function? onError,
})
重写

注册在此 future 完成时调用的回调。

此 future 以值完成时，会以该值为参数调用 onValue 回调。如果此 future 已经完成，回调不会立即调用，而会安排在稍后的微任务中执行。

如果提供了 onError，且此 future 以错误完成，则会以该错误及其堆栈跟踪为参数调用 onError 回调。onError 回调必须接受一个或两个参数，接受两个参数时，后一个参数为 StackTrace。如果 onError 接受两个参数，则传入错误和堆栈跟踪；否则仅传入错误对象。onError 回调必须返回可用于完成返回的 future 的值或 future，因此其返回结果必须能够赋值给 FutureOr<R>。

返回一个新的 Future，它会以调用 onValue（此 future 以值完成时）或 onError（此 future 以错误完成时）的结果完成。

如果被调用的回调抛出错误，返回的 future 会以该错误及其堆栈跟踪完成。对于 onError，如果抛出的异常与传给 onError 的错误参数满足 identical，且异常是同步抛出的，则视为重新抛出，并使用原始堆栈跟踪。要在异步回调中使用相同的堆栈跟踪重新抛出错误，请使用 Error.throwWithStackTrace。

如果回调返回一个 Future，则 then 返回的 future 会以与回调返回的 future 相同的结果完成。

如果未提供 onError，且此 future 以错误完成，该错误会直接转发给返回的 future。

在多数情况下，将 catchError 单独使用（也可传入 test 参数）比在一次 then 调用中同时处理值和错误更易读。

请注意，future 不会等到添加监听器后才报告错误。如果首次调用 then 或 catchError 时，此 future 已经以错误完成，该错误就会被报告为未处理的错误。参见 Future 的说明。

实现

@override
Future<R> then<R>(FutureOr<R> Function(void value) onValue, {Function? onError}) {
  return _primaryCompleter.future.then<R>(onValue, onError: onError);
}
