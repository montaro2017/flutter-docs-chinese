initServiceExtensions 方法

  1. @重写
void initServiceExtensions()
重写

binding 初始化时调用，用于注册服务扩展。

若 binding 要公开服务扩展，应重写此方法，并通过以下方法注册服务扩展：registerSignalServiceExtension、registerBoolServiceExtension、registerNumericServiceExtension 和 registerServiceExtension（复杂度依次增加）。

实现此方法时必须调用父类的实现。

只有构建中包含 vm-service 时，才能启用已注册的服务扩展；而 vm-service 仅包含在 debug 和 profile 模式中。尽管 release 模式下无法使用服务扩展，其代码仍可能进入 Dart 快照，增大二进制文件。如果没有用可让 tree shaker 移除代码的保护条件包裹，就会发生这种情况（参见以下示例代码）。

以下代码会注册一个仅包含在 debug 构建中的服务扩展。
link 
void myRegistrationFunction() {
  assert(() {
    // Register your service extension here.
    return true;
  }());
}

使用以下代码片段注册的服务扩展，在 debug 和 profile 模式下均可用。
link 
void myOtherRegistrationFunction() {
  // kReleaseMode is defined in the 'flutter/foundation.dart' package.
  if (!kReleaseMode) {
    // Register your service extension here.
  }
}

这两种保护条件都能确保 Dart 的 tree shaker 在 release 构建中移除服务扩展代码。

另请参阅：

  • github.com/dart-lang/sdk/blob/main/runtime/vm/service/service.md#rpcs-requests-and-responses

实现

@override
void initServiceExtensions() {
  super.initServiceExtensions();

  if (!kReleaseMode) {
    registerNumericServiceExtension(
      name: SchedulerServiceExtensions.timeDilation.name,
      getter: () async => timeDilation,
      setter: (double value) async {
        timeDilation = value;
      },
    );
  }
}
