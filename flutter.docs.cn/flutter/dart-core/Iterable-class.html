Iterable

Iterable<E> 类 抽象 mixin

可以按顺序访问的一组值或“元素”。

通过 iterator getter 获取 Iterator，即可访问 iterable 的元素，并使用它逐个遍历值。调用 Iterator.moveNext 可让迭代器前进；如果调用返回 true，迭代器就已前进到下一个元素，该元素可通过 Iterator.current 获取。如果返回 false，则没有更多元素。只有最近一次 Iterator.moveNext 调用返回 true 时，才能使用 Iterator.current 的值。首次对迭代器调用 Iterator.moveNext 之前，或调用返回 false 或抛出错误之后，读取 Iterator.current 可能会抛出异常，也可能返回任意值。

可以从同一个 Iterable 创建多个迭代器。每次读取 iterator 都会返回一个新迭代器，不同迭代器可以独立前进，并分别访问所有 iterable 元素。同一 iterable 的迭代器应当按相同顺序提供相同值（除非在迭代期间修改了底层集合；某些集合允许这样做）。

也可以使用 for-in 循环遍历 Iterable 中的元素；该结构在幕后使用 iterator getter。例如，可以遍历 Map 的所有键，因为 Map 的键是 iterable。

var kidsBooks = {'Matilda': 'Roald Dahl',
                 'Green Eggs and Ham': 'Dr Seuss',
                 'Where the Wild Things Are': 'Maurice Sendak'};
for (var book in kidsBooks.keys) {
  print('$book was written by ${kidsBooks[book]}');
}

List 和 Set 类都是 Iterable，dart:collection 库中的大多数类也一样。

某些 Iterable 集合可以修改。向 List 或 Set 添加元素会改变其中包含的元素；向 Map 添加新键会改变 Map.keys 的元素。在修改后创建的迭代器会提供新元素，但可能会也可能不会保留现有元素的顺序（例如，添加单个元素就可能彻底改变 HashSet 的顺序）。

通常不允许在迭代期间修改集合。这样做会破坏迭代，通常会在下次调用 Iterator.moveNext 时抛出 ConcurrentModificationError。集合修改不应影响 Iterator.current getter 的当前值，因为 current 值由上一次调用 Iterator.moveNext 时确定。

某些 iterable 会在每次迭代时动态计算元素，例如 Iterable.generate 返回的 iterable，或 sync* 生成器函数返回的 iterable。如果计算不依赖可能变化的其他对象，那么每次迭代生成的序列都应相同。

除了 iterator 本身之外，Iterable 的成员都通过查看 iterable 的元素来工作。它们可以通过遍历 iterator 实现，但有些类可能有更高效的方式来查找结果（例如 last 或 length 在 List 上的实现，或 contains 在 Set 上的实现）。

返回另一个 Iterable 的方法（例如 map 和 where）都是惰性的：每次遍历返回的 iterable 时，它们才会按需遍历原 iterable，在此之前不会遍历。

由于 iterable 可能会被遍历多次，不建议在迭代器中产生可观察到的副作用。对于 map 和 where 等方法，返回的 iterable 会在每次迭代时执行参数函数，因此这些函数也不应有副作用。

Iterable 声明提供了默认实现，可通过继承或混入它来实现 Iterable 接口。除 iterator getter 外，它会使用由 Iterator 通过 iterator getter 提供的迭代器实现所有成员。只要可行，Iterable 接口的实现就应为 Iterable 成员提供更高效的实现。
