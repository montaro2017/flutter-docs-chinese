Finalizer

Finalizer<T> 类 抽象 final

可以附加到 Dart 对象上的终结器。

终结器可以通过调用 attach，将自身与任意数量的 Dart 值建立关联。调用时还可以提供一个终结令牌和可选的分离键，它们都会成为关联的一部分。

当某个 Dart 值无法再被程序访问时，当前与该值关联的任一终结器可能会收到关联中的终结令牌，并调用其回调函数。

示例：

class Database {
  // Keeps the finalizer itself reachable, otherwise it might be disposed
  // before the finalizer callback gets a chance to run.
  static final Finalizer<DBConnection> _finalizer =
      Finalizer((connection) => connection.close());

  final DBConnection _connection;

  Database._fromConnection(this._connection);

  factory Database.connect() {
    // Wraps the connection in a nice user API,
    // *and* closes connection if the user forgets to.
    final connection = DBConnection.connect();
    final wrapper = Database._fromConnection(connection);
    // Calls finalizer callback when `wrapper` is no longer reachable.
    _finalizer.attach(wrapper, connection, detach: wrapper);
    return wrapper;
  }

  void close() {
    // User requested close.
    _connection.close();
    // Detach from finalizer, no longer needed.
    _finalizer.detach(this);
  }

  // Some useful methods.
}

此示例展示了需要清理的外部资源。当 API 的使用者不再能访问外部连接时，终结器会清理该连接。示例将同一个对象用作被关联对象和分离键；当每个关联对象都可以单独分离时，这是很有用的做法。作为分离键不会让对象保持存活。

不保证回调一定会被调用。唯一能保证的是：如果终结器回调收到特定终结令牌作为参数，那么至少有一个带有该令牌、且与该终结器关联的值已无法再被程序访问。

如果终结器本身变得不可达，就可以被垃圾回收，此后也不会再触发任何回调。只要仍需要使用终结器，就务必确保终结器本身保持可达。

如果多个终结器关联到同一个对象，或者同一个终结器多次关联到某个对象，而该对象后来无法再被程序访问，那么这些关联中任意数量（包括零个）都可能触发相应终结器的回调；不一定会全部触发，也不一定都不触发。

终结回调会作为事件发生。它们不会在其他代码执行期间发生，也不会作为微任务执行，而是类似定时器事件的高级事件。

终结回调不得抛出异常。

在 Dart 原生运行时中，如果回调是原生函数而非 Dart 函数，请改用 dart:ffi 的 NativeFinalizer。
