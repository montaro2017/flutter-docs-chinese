RegExp

RegExp 类 抽象 interface

正则表达式模式。

正则表达式（简称 regex 或 regexp）由一系列字符组成，用于指定针对文本输入执行匹配检查的算法。将正则表达式应用于输入文本后，它要么匹配（接受）该文本，要么拒绝该文本。如果正则表达式匹配文本，还会提供有关它如何匹配的信息。

Dart 正则表达式的语法和语义与 JavaScript 正则表达式相同。有关 JavaScript 正则表达式的更多信息，请参阅 ecma-international.org/ecma-262/9.0/#sec-regexp-regular-expression-objects。

Dart 通过 matchAsPrefix 提供基本的正则表达式匹配算法，用于检查正则表达式是否从输入的特定位置开始匹配。如果匹配，Dart 会将匹配详情作为 RegExpMatch 返回。

所有其他 RegExp 方法都可以基于这项基本匹配检查构建。

正则表达式最常见的用途是在输入中搜索匹配项。firstMatch 方法提供此功能。它会在字符串中搜索正则表达式首次匹配的位置。如果找到匹配项，Dart 同样会将详情作为 RegExpMatch 返回。

以下示例在字符串中查找正则表达式的第一个匹配项。

RegExp exp = RegExp(r'(\w+)');
String str = 'Parse my string';
RegExpMatch? match = exp.firstMatch(str);
print(match![0]); // "Parse"

使用 allMatches 在字符串中查找正则表达式的所有匹配项。

以下示例在字符串中查找正则表达式的所有匹配项。

RegExp exp = RegExp(r'(\w+)');
String str = 'Parse my string';
Iterable<RegExpMatch> matches = exp.allMatches(str);
for (final m in matches) {
  print(m[0]);
}

示例输出为：

Parse
my
string

前面的示例使用了原始字符串，即在字符串字面量前加上 r 前缀的一种字符串。使用原始字符串可以将字符串中的每个字符（包括 \ 和 $）都视为字面字符，并将其传递给 RegExp 解析器。应将原始字符串用作 RegExp 构造函数的参数。

性能提示：正则表达式无法神奇地解决问题。任何人都可能编写出在某些字符串输入上效率低下的正则表达式。这类表达式通常在小型或常见输入上表现良好，却会在大型或罕见输入上出现极端低效的性能。这种不一致会让性能问题更难在测试中发现。

使用正则表达式不一定比使用 String 操作检查字符串更快。正则表达式的优势在于能够用很少的字符指定相对复杂的模式；在大多数常见情况下，这些正则表达式效率合理。但简洁是以可读性为代价的。由于语法复杂，正则表达式不能视为自说明代码。

Dart 正则表达式遵循 ECMAScript RegExp 规范。该规范定义了常见且广为人知的正则表达式行为。将 Dart 编译为 Web 代码时，编译后的代码可以使用浏览器的正则表达式实现。

该规范使用回溯来定义 ECMAScript 正则表达式的行为。当正则表达式有多种匹配方式可选时，会按照模式中给出的顺序逐一尝试。例如：RegExp(r"(foo|bar)baz") 要检查 foo 或 bar，因此会先检查 foo。如果沿此路径继续无法匹配输入，正则表达式实现就会回溯：它会恢复到检查 foo 之前的原始状态，放弃之后完成的所有工作，然后尝试下一个选项；此例中即 bar。

该规范定义了这些选项及其尝试顺序。如果正则表达式可以用多种方式匹配输入，选项顺序会决定返回哪个匹配结果。常用正则表达式会安排匹配选项的顺序，以确保获得特定结果。ECMAScript 正则表达式规范限制了 Dart 实现正则表达式的方式：必须采用按特定顺序检查选项的回溯实现。Dart 不能选择其他正则表达式实现，否则匹配行为会发生变化。

回溯方法可行，但需要付出代价。对于某些正则表达式和输入，找到正确匹配可能需要尝试很多次。要拒绝一个与模式几乎匹配的输入，尝试次数可能更多。

一种广为人知的危险正则表达式模式是嵌套使用 * 等量词：

var re = RegExp(r"^(a*|b)*c");
print(re.hasMatch("aaaaaaaaaaaaaaaaaaaaaaaaaaaaa"));

由于输入中没有必需的 c，该正则表达式模式无法匹配仅由 a 组成的输入字符串。(a*|b)* 匹配所有这些 a 的方式数量呈指数级增长。回溯实现会尝试所有方式，之后才判定没有一种能构成完整匹配。输入中每增加一个 a，正则表达式返回 false 所需时间就会翻倍。（当回溯具有这种指数级增长的可能性时，称为“灾难性回溯”。）

连续使用量词是另一种危险模式，不过其复杂度“仅”为多项式级。

// Like `\w*-\d`, but check for `b` and `c` in that order.
var re = RegExp(r"^\w*(b)?\w*(c)?\w*-\d");
print(re.hasMatch("a" * 512));

同样，输入不匹配，但 RegExp 必须尝试 n3 种方式匹配这 n 个 a，之后才能判定这一点。输入长度翻倍，返回 false 所需时间就会增加到八倍。连续量词的数量越多，这个指数也越大。

将这两种模式简化成如此简单的正则表达式后，它们看起来都很简单。但这些“简单”模式经常会成为更复杂正则表达式的一部分，使问题更难发现。

一般而言，如果正则表达式可能具有超线性复杂度，就可以构造出需要耗费极长时间才能完成搜索的输入。若将存在漏洞的正则表达式应用于用户提供的输入，这些模式可能被用于拒绝服务攻击。

这个问题没有保证有效的通用解决方案。请谨慎使用执行时间可能超线性的正则表达式，尤其是程序可能将其用于无法保证匹配成功的输入时。

避免使用执行时间呈超线性增长的正则表达式，可以参考以下经验法则：

  • Whenever the regexp has a choice, try to make sure that the choice can be made based on the next character (or very limited look-ahead). This limits the need to perform a lot of computation along both choices.
  • When using quantifiers, ensure that the same string cannot match both one and more-than-one iteration of the quantifier's regular expression. (For (a*|b)*, the string "aa" can match both (a*|b){1} 和 (a*|b){2}.)
  • Most uses of Dart regular expressions search for a match, for example using firstMatch. If you do not anchor the pattern to the start of a line or input using ^, this search acts as if the regexp began with an implicit [^]*. Starting your actual regular expression with .* then results in potential quadratic behavior for the search. Use anchors or matchAsPrefix where appropriate, or avoid starting the regexp with a quantified pattern.
  • For experts only: Neither Dart nor ECMAScript have general “atomic grouping”. Other regular expression dialects use this to limit backtracking. If an atomic capture group succeeds once, the regexp cannot backtrack into the same match later. As lookarounds also serve as atomic groups, something similar can be achieved using a lookahead: var re = RegExp(r"^(?=((a*|b)*))\1d"); The preceding example does the same inefficient matching of (a*|b)*. Once the regexp has matched as far as possible, it completes the positive lookahead. Then it skips what the lookahead matched using a back-reference. After that, it can no longer backtrack and try other combinations of a。

尽量减少正则表达式匹配同一字符串的方式数量。这样可以减少正则表达式找不到匹配项时可能执行的回溯次数。网上有许多关于提升正则表达式性能的指南，也可以从中获取思路。
