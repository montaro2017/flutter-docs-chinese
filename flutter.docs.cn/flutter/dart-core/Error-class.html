Error

Error 类

程序发生故障时抛出的错误对象。

Error 对象表示程序中本应由程序员避免的故障。

例如，使用无效参数或错误数量的参数调用函数，或者在不允许调用的时机调用函数。

调用方不应预期会发生这些错误，也不应捕获它们——如果发生，说明程序存在错误，终止程序可能是最安全的处理方式。

如果决定让函数抛出错误，应清楚说明触发条件，并确保这些条件可检测且可预测，以便使用该函数的程序员能够避免触发错误。

此类说明通常会使用“必须”或“不得”等词语描述条件。如果函数文档中出现这类词语，不满足相应要求很可能会导致抛出错误。

示例（摘自 String.contains）：

`startIndex` must not be negative or greater than `length`.

在此示例中，如果 startIndex 为负数或过大，就会抛出错误。

如果无法在调用函数前检测这些条件，被调用的函数就不应抛出 Error。它仍可能抛出某个值，但调用方必须捕获该值，此时它实际上是另一种返回结果，而不是错误。如果是这种情况，我们会将抛出的对象视为异常而非错误。抛出的对象可以选择实现 Exception，以说明它表示异常情况而非程序错误；不过，除了文档说明外，实现 Exception 不会产生其他影响。

在 Dart 中，所有非 null 值都可以被抛出。继承 Error 类的对象会被特殊处理：第一次抛出时，抛出位置的堆栈跟踪会被记录并存储在错误对象中。可以通过 stackTrace getter 获取该跟踪信息。仅实现 Error 接口而不继承该类的错误对象不会自动存储堆栈跟踪。

Error 对象也用于表示堆栈溢出或内存不足等系统级故障，用户同样不应捕获或处理这些故障。

错误并非设计为供捕获，因此子类无需区分各种错误。创建子类是为了将相关错误归类，便于统一生成错误消息。例如，如果 String.contains 方法的 startIndex 不在 0..length 范围内，就会使用 RangeError，并可通过 RangeError.range(startIndex, 0, length) 轻松创建该错误。不应捕获 Error 的特定子类，在测试自己的代码之外尤其不应这样做。
