bool.hasEnvironment 构造函数

const bool.hasEnvironment(
  1. String name
)

name 是否在编译配置环境中声明。

编译配置环境由编译或运行 Dart 程序的外围工具提供。该环境是一个映射，其中包含一组字符串键及其对应的字符串值。对于单个程序，所有对 String.fromEnvironment、int.fromEnvironment、bool.fromEnvironment 和 bool.hasEnvironment 的调用中，与 name 关联的字符串值（或无关联值）必须保持一致。

如果编译配置环境中存在与 name 关联的值，此构造函数的结果为 true；否则为 false。如果存在关联值，可以使用 const String.fromEnvironment(name) 访问它。否则，String.fromEnvironment(name, defaultValue: someString) 会得到给定的 defaultValue。

String.fromEnvironment、int.fromEnvironment 和 bool.fromEnvironment 构造函数始终分别生成 String、int 或 bool，符合构造函数的要求。在大多数情况下，name 没有对应的配置环境值，仅表示代码应回退到默认行为；使用相同类型的默认值通常就能很好地表达这一点。

有时，使用不同类型的值（通常是 null）可能更适合表示没有选择。在这种情况下，可以先调用此构造函数检查值是否存在，再使用其他 fromEnvironment 构造函数。例如：

const int? indentOverride = bool.hasEnvironment("indent-override")
    ? int.fromEnvironment("indent-override")
    : null;
void indentLines(List<String> lines, int indentation) {
  int actualIndentation = indentOverride ?? indentation;
  // ... Do something to lines.
}

这种模式允许编译配置向程序提供覆盖值，也允许不提供；程序可以区分明确提供的值与未提供值的情况。

另一种用例是仅在所需值可用时执行额外操作。例如：

const Logger? logger = bool.hasEnvironment("logging-id")
    ? Logger(id: String.fromEnvironment("logging-id"))
    : null;

只有以 const 方式调用时，才能保证此构造函数正常工作。在某些运行时可访问编译器选项的平台上，非 const 调用可能也能工作，但大多数提前编译的平台无法获取这些信息。
