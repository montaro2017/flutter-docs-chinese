Record

Record 类 抽象 final

记录值。

Record 类是所有记录类型的超类型，但它本身并不是任何对象实例的运行时类型（它是抽象类）。所有实现 Record 的对象，其运行时类型都是某种记录类型。

由记录类型描述的记录值包含多个字段，每个字段都是位置字段或命名字段。

记录值和记录类型的书写形式类似于参数列表和简化的函数类型参数列表（不允许也不需要使用 required 修饰符，因为记录字段永远不是可选的）。例如：

(int, String, {bool isValid}) triple = (1, "one", isValid: true);

在语法上类似于：

typedef F = void Function(int, String, {bool isValid});
void callIt(F f) => f(1, "one", isValid: true);

每个记录及记录类型都有一个形状，由位置字段的数量和命名字段的名称决定。例如：

(double value, String name, {String isValid}) another = (
     3.14, "Pi", isValid: "real");

这是另一个具有相同形状的记录声明（两个位置字段，一个名为 isValid 的命名字段），但类型不同。位置字段上写出的名称纯粹用于文档说明，对程序没有影响（这与函数类型的位置参数名称相同，例如 typedef F = int Function(int value); 中的标识符 value 不产生影响）。

记录值主要通过模式进行解构，例如：

switch (triple) {
  case (int value, String name, isValid: bool ok): // ....
}

还可以使用命名 getter 访问各个字段：位置字段使用 $1、$2 等，命名字段则使用其名称。

int value = triple.$1;
String name = triple.$2;
bool ok = triple.isValid;

因此，某些标识符不能用作命名字段的名称：

  • The names of Object members: hashCode, runtimeType, toString 和 noSuchMethod.
  • The name of a positional getter in the same record, so (0, $1: 0) is invalid, but (0, $2: 0) is valid, since there is no positional field with getter $2 in that record shape. (It'll still be confusing, and should be avoided in practice.)
  • Also, no name starting with an underscore, _, is allowed. Field names cannot be library private.

记录对象的运行时类型是记录类型，因此它是 Record 的子类型，并传递地属于 Object 及其超类型。

记录值没有持久的 identical 行为。指向记录对象的引用随时可能变为指向另一个形状和字段值相同的记录对象。

除此之外，记录类型只能是具有相同形状的另一记录类型的子类型，并且只有当前者的字段类型分别是后者对应字段类型的子类型时才成立。例如，(int, String, {bool isValid}) 是 (num, String, {Object isValid}) 的子类型，因为它们形状相同，且各字段类型逐一构成子类型关系。形状不同的记录类型彼此无关。
