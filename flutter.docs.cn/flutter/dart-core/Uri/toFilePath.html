根据文件 URI 创建文件路径。

返回的路径采用 Windows 或非 Windows 语义。

对于非 Windows 语义，使用斜杠（“/”）分隔路径段。

对于 Windows 语义，使用反斜杠（“\”）分隔路径段。

如果 URI 是绝对 URI，路径会以路径分隔符开头；但在 Windows 语义下，如果第一个路径段是盘符，则例外。使用 Windows 语义时，URI 中的主机组件会被视为文件服务器，并返回 UNC 路径。

是否使用 Windows 语义由 Dart 运行的平台决定。在独立虚拟机中运行时，虚拟机会根据操作系统进行检测。在浏览器中运行时，始终使用非 Windows 语义。

要覆盖自动检测到的语义，请传入 windows 值。传入 true 将使用 Windows 语义；传入 false 将使用非 Windows 语义。

如果 URI 以斜杠结尾（即最后一个路径组件为空），返回的文件路径也会以斜杠结尾。

在 Windows 语义下，以盘符开头的 URI 不能相对于指定盘符上的当前驱动器。例如，对于 URI file:///c:abc，调用 toFilePath 会抛出异常，因为 Windows 路径段不能包含冒号。

使用非 Windows 语义的示例（注释中给出调用 toFilePath 的结果）：

Uri.parse("xxx/yyy");  // xxx/yyy
Uri.parse("xxx/yyy/");  // xxx/yyy/
Uri.parse("file:///xxx/yyy");  // /xxx/yyy
Uri.parse("file:///xxx/yyy/");  // /xxx/yyy/
Uri.parse("file:///C:");  // /C:
Uri.parse("file:///C:a");  // /C:a

使用 Windows 语义的示例（注释中给出结果 URI）：

Uri.parse("xxx/yyy");  // xxx\yyy
Uri.parse("xxx/yyy/");  // xxx\yyy\
Uri.parse("file:///xxx/yyy");  // \xxx\yyy
Uri.parse("file:///xxx/yyy/");  // \xxx\yyy\
Uri.parse("file:///C:/xxx/yyy");  // C:\xxx\yyy
Uri.parse("file:C:xxx/yyy");  // Throws as a path segment
                              // cannot contain colon on Windows.
Uri.parse("file://server/share/file");  // \\server\share\file

如果此 URI 不是文件 URI，调用此方法会抛出 UnsupportedError。

如果此 URI 无法转换为文件路径，调用此方法会抛出 UnsupportedError。
