控制器及其 stream 只支持一个订阅者。

如果 sync 为 true，返回的流控制器就是 SynchronousStreamController。使用时必须格外谨慎，以免违反 Stream 契约。如有疑问，请使用非同步版本。

使用异步控制器不会导致错误行为，但错误地使用同步控制器可能会使原本正确的程序出错。

同步控制器仅用于优化事件传递，适用于一个异步事件立即触发另一个异步事件的场景。只有在能够保证调用 add 或 addError 不会破坏 Stream 不变量时，才应使用它。

同步控制器仅应用于转发（可能经过转换的）另一个流或 future 中的事件。

在订阅者开始侦听之前，Stream 应保持惰性；可使用 onListen 回调开始产生事件。当没有用户侦听流时，Stream 不应泄漏资源（例如 WebSocket）。

控制器会缓冲所有传入事件，直到有订阅者注册；但只应在少数特殊情况下使用此功能。

流进入暂停状态时会调用 onPause 函数；流恢复时会调用 onResume。

流收到侦听器时会调用 onListen 回调；侦听器结束订阅时会调用 onCancel。如果 onCancel 需要执行异步操作，onCancel 应返回一个在取消操作完成时完成的 future。

如果控制器尚未需要数据，流就已被取消，则可能不会执行 onResume 调用。

实现

factory StreamController({
  void onListen()?,
  void onPause()?,
  void onResume()?,
  FutureOr<void> onCancel()?,
  bool sync = false,
}) {
  return sync
      ? _SyncStreamController<T>(onListen, onPause, onResume, onCancel)
      : _AsyncStreamController<T>(onListen, onPause, onResume, onCancel);
}
