其 stream 可以被多次侦听的控制器。

Stream 返回的 stream 是广播流，可以被多次侦听。

在订阅者开始侦听前，Stream 应保持惰性（可通过 onListen 回调开始产生事件）。没有用户侦听时，Stream 不应泄漏资源（例如 WebSocket）。

没有侦听器时，广播流不会缓冲事件。

调用 add、addError 或 close 时，控制器会将事件分发给当时所有已订阅的侦听器。在上一次调用返回前，不得再次调用 add、addError 或 close。控制器没有内部事件队列；添加事件或错误时如果没有侦听器，该事件或错误会直接丢弃。

每个侦听器订阅会独立处理。如果其中一个暂停，只有该侦听器会受影响。暂停的侦听器会在恢复或取消前将事件缓冲在内部。

如果 sync 为 true，在调用 add、addError 或 close 时，事件可能会由流订阅直接触发。此时返回的控制器是 SynchronousStreamController，使用时必须格外谨慎，以免违反 Stream 契约。关于何时可以使用同步分发，请参阅 Completer.sync。如有疑问，请保持控制器为非同步模式。

如果 sync 为 false，事件总会在添加事件的代码执行完毕后才触发。在这种情况下，不保证多个侦听器何时收到事件，但每个侦听器都会按正确顺序收到所有事件。每个订阅独立处理事件。异步控制器有两个侦听器且发送两个事件时，一个侦听器可能在另一个侦听器收到任何事件之前就已收到这两个事件。侦听器必须在事件发起时（即调用 add 时）和事件稍后传递时都处于订阅状态，才能收到该事件。

第一个侦听器订阅时会调用 onListen 回调；不再有任何活动侦听器时会调用 onCancel。如果在调用 onCancel 后又添加侦听器，系统会再次调用 onListen。

实现

factory StreamController.broadcast({
  void onListen()?,
  void onCancel()?,
  bool sync = false,
}) {
  return sync
      ? _SyncBroadcastStreamController<T>(onListen, onCancel)
      : _AsyncBroadcastStreamController<T>(onListen, onCancel);
}
