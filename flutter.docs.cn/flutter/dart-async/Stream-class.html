Stream

Stream<T> 类 抽象 mixin

异步数据事件的来源。

Stream 提供了一种接收事件序列的方式。每个事件要么是数据事件（也称为流的元素），要么是错误事件，用于通知某项操作失败。流发出所有事件后，会发送一个“done”事件，通知监听者流已结束。

调用 async* 函数即可生成一个流。该函数会返回流；使用此流时，函数会持续发出事件，直到函数结束并关闭流。你可以通过 await for 循环消费流，该循环可用于 async 或 async* 函数；也可以使用 yield* 在 async* 函数中 直接转发流的事件。示例：

Stream<T> optionalMap<T>(
    Stream<T> source , [T Function(T)? convert]) async* {
  if (convert == null) {
    yield* source;
  } else {
    await for (var event in source) {
      yield convert(event);
    }
  }
}

调用此函数时，它会立即返回一个 Stream<T> 对象。在有人尝试消费该流之前，不会发生其他操作。此时，async* 函数体才开始运行。如果省略 convert 函数，yield* 会监听 source 流，并将所有事件（数据和错误）转发到返回的流。source 流关闭时，yield* 结束，optionalMap 函数体也随之结束，从而关闭返回的流。如果提供了 convert，函数则会监听 source 流，并进入 await for 循环，反复等待下一个数据事件。收到数据事件时，它会将值传给 convert，并把结果发送到返回的流。如果 source 流没有发出错误事件，循环会在 source 流结束时退出；随后 optionalMap 函数体完成并关闭返回的流。如果 source 流发出错误事件，await for 会重新抛出该错误并中断循环。由于错误未被捕获，它会到达 optionalMap 函数体末尾，继而在返回的流上发出该错误并关闭流。

Stream 类还提供了相关功能，允许你手动监听流中的事件，或将流转换为另一个流或 Future。

forEach 函数对应于 await for 循环，就像 Iterable.forEach 对应普通的 for/in 循环一样。与循环相同，它会为每个数据事件调用函数，并在遇到错误时中断。

底层级别较低的 listen 方法是其他所有方法的基础。你可以对流调用 listen，表示要接收事件，并注册用于接收这些事件的回调。调用 listen 后会得到一个 StreamSubscription 对象，它负责提供事件，可用于停止监听，或暂时暂停此订阅的事件。

流分为两种：“单订阅”流和“广播”流。

单订阅流在整个生命周期中只允许一个监听者。在有监听者之前，它不会开始生成事件；监听者取消订阅后，即使事件源还能提供更多事件，它也会停止发送事件。由 async* 函数创建的流属于单订阅流，但每次调用该函数都会创建一个新的此类流。

单订阅流不允许被监听两次，即使第一次订阅已取消也不行。

单订阅流通常用于传输较大连续数据的分块，例如文件 I/O。

广播流允许任意数量的监听者；事件就绪时会立即发出，无论当时是否有监听者。

广播流用于独立事件或观察者。

如果多个监听者都需要监听单订阅流，请使用 asBroadcastStream，在非广播流之上创建广播流。

对于这两种流，流转换（例如 where 和 skip）都会返回与调用该方法的流相同类型的流，除非另有说明。

事件发出时，当时的监听者会收到该事件。如果事件正在发出时向广播流添加监听者，该监听者不会收到当前正在发出的事件。取消监听后会立即停止接收事件。监听广播流可以视为监听一个新流，该新流只包含调用 listen 时尚未发出的事件。例如，first getter 会监听流，然后返回该监听者收到的第一个事件。这不一定是流曾发出的第一个事件，而是广播流中剩余事件里的第一个。

发出“done”事件时，订阅者会在收到事件前取消订阅。事件发送后，流将不再有订阅者。此后仍可向广播流添加新订阅者，但它们会尽快收到一个新的“done”事件。

流订阅始终遵守“暂停”请求。如有必要，订阅需要缓冲输入；但通常最好直接请求输入源也暂停。

isBroadcast 的默认实现返回 false。继承 Stream 的广播流必须重写 isBroadcast，并在其行为类似广播流时返回 true。
