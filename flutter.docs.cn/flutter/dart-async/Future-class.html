Future

Future<T> 类 抽象 interface

异步计算的结果。

与会立即计算出结果的同步计算不同，异步计算在启动时无法立即提供结果。同步计算会通过返回值或抛出异常立即得出结果。异步计算可能需要等待程序外部的操作（例如读取文件、查询数据库或获取网页），而这些操作都需要时间。异步计算不会阻塞所有计算，直到结果可用，而是立即返回一个 Future，该 future 最终会以结果“完成”。

异步编程

要执行异步计算，请使用始终会产生 future 的 async 函数。在这种异步函数中，可以使用 await 操作暂停执行，直到另一项异步计算得到结果。等待函数暂停执行期间，程序不会被阻塞，仍可继续处理其他事情。

示例：

import "dart:io";
Future<bool> fileContains(String path, String needle) async {
   var haystack = await File(path).readAsString();
   return haystack.contains(needle);
}

这里，File.readAsString 方法是来自 dart:io 的异步函数，它返回 Future<String>。fileContains 函数在函数体前标记了 async，这表示可以在其中使用 await，并且它必须返回一个 future。调用 File(path).readAsString() 会开始将文件读入字符串，并产生一个最终包含读取结果的 Future<String>。随后 await 会等待该 future 以字符串完成（如果读取文件失败，则会以错误完成）。等待期间，程序可以处理其他事情。future 以字符串完成后，fileContains 函数会计算一个布尔值并返回；该值会使函数最初调用时返回的 future 完成。

如果 future 以错误完成，等待该 future 时会重新抛出该错误。在此示例中，可以添加错误检查：

import "dart:io";
Future<bool> fileContains(String path, String needle) async {
  try {
    var haystack = await File(path).readAsString();
    return haystack.contains(needle);
  } on FileSystemException catch (exception, stack) {
    _myLog.logError(exception, stack);
    return false;
  }
}

使用普通的 try/catch 捕获等待异步计算时发生的错误。

通常，编写异步代码时，future 产生后就应立即等待它，不要等到又经历一次异步延迟后才等待。这样可以及时接收该 future 可能产生的错误。这一点很重要，因为无人等待的异步错误属于未捕获错误，可能会终止正在运行的程序。

使用 Future API 编程

Future 类还提供了更直接、底层的功能来访问 future 完成时产生的结果。async 和 await 语言特性建立在此功能之上，有时直接使用这些功能更合适。有些事情无法仅通过逐个 await future 来完成。

借助 Future，可以手动注册回调，在值或错误可用时进行处理。例如：

Future<int> future = getFuture();
future.then((value) => handleValue(value))
      .catchError((error) => handleError(error));

Future 可以通过两种方式完成：异步计算成功时以值完成，或计算失败时以错误完成。因此，可以分别为其中一种或两种情况安装回调。

有时我们会说一个 future 以另一个 future 完成。这是简洁的说法，表示当另一个 future 完成后，此 future 会以相同的方式、相同的值或错误完成。平台库中大多数会完成 future 的函数（例如 Completer.complete 或 Future.value）也接受另一个 future，并会自动将其结果转发给正在完成的 future。

注册回调后会得到一个新的 Future。该 future 会以调用相应回调并传入原始 future 结果后得到的结果完成。如果被调用的回调抛出异常，新的 future 就会以错误完成。例如：

Future<int> successor = future.then((int value) {
    // Invoked when the future is completed with a value.
    return 42;  // The successor is completed with the value 42.
  },
  onError: (e) {
    // Invoked when the future is completed with an error.
    if (canHandle(e)) {
      return 499;  // The successor is completed with the value 499.
    } else {
      throw e;  // The successor is completed with the error e.
    }
  });

如果 future 以错误完成时没有注册任何处理器，它会将错误转发给“未捕获错误处理器”。这样可以避免错误被悄悄丢弃。不过，这也意味着应尽早安装错误处理器，确保 future 以错误完成时处理器已经就绪。以下示例展示了这个潜在问题：

var future = getFuture();
Timer(const Duration(milliseconds: 5), () {
  // The error-handler is not attached until 5 ms after the future has
  // been received. If the future fails before that, the error is
  // forwarded to the global error-handler, even though there is code
  // (just below) to eventually handle the error.
  future.then((value) { useValue(value); },
              onError: (e) { handleError(e); });
});

注册回调时，通常分别注册两个回调更易读：先使用一个参数调用 then（即值处理器），再使用 catchError 处理错误。每个回调都会把自己未处理的结果转发给后续回调，两者配合即可处理值和错误。这样做还有一个好处：catchError 也能处理值回调 then 中发生的错误。与并行处理相比，使用顺序排列的处理器通常更容易理解，也能让异步代码更接近同步代码：

// Synchronous code.
try {
  int value = foo();
  return bar(value);
} catch (e) {
  return 499;
}

基于 futures 的等效异步代码：

Future<int> asyncValue = Future(foo);  // Result of foo() as a future.
asyncValue.then((int value) {
  return bar(value);
}).catchError((e) {
  return 499;
});

与同步代码类似，这里的错误处理器（通过 catchError 注册）会处理 foo 或 bar 抛出的任何错误。如果将错误处理器作为 onError 参数注册到 then 调用中，它就无法捕获 bar 调用产生的错误。

一个 future 可以注册多组回调。每个后续回调组都会独立处理，效果如同它是唯一的一组后续回调。各后续回调完成的顺序未定义。

future 也可能永远无法完成。在这种情况下，不会调用任何回调。除非已清楚记录这种行为，否则通常应尽量避免。
