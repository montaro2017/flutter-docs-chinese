使用提供的 equals 函数作为相等性判断来创建哈希集合。

提供的 equals 必须定义稳定的等价关系，并且 hashCode 必须与 equals 保持一致。

如果省略 equals 或 hashCode，集合会使用元素自身的 Object.== 和 Object.hashCode。

如果提供了 equals 或 hashCode 其中之一，通常也应提供另一个。

有些 equals 或 hashCode 函数可能无法处理所有对象。如果提供了 isValidKey，它会用于检查潜在元素；该元素不一定是 E 的实例，例如类型为 Object? 的 contains 参数。如果 isValidKey 对某个对象返回 false，就不会调用 equals 和 hashCode 函数，也不会认为集合中存在与该对象相等的键。isValidKey 默认只检查对象是否为 E 的实例，也就是说：

HashSet<int>(equals: (int e1, int e2) => (e1 - e2) % 5 == 0,
             hashCode: (int e) => e % 5)

无需提供 isValidKey 参数，因为它默认只接受 int 值，而这些值可同时传给 equals 和 hashCode。

如果未提供 equals、hashCode 或 isValidKey，默认的 isValidKey 会接受所有值。默认的相等性比较和哈希码操作适用于所有对象。

同样，如果 equals 是 identical，hashCode 是 identityHashCode，并且省略 isValidKey，生成的集合就会基于对象标识；此时 isValidKey 默认接受所有键。也可以直接使用 HashSet.identity 创建这种映射。
