创建一个无序的、基于哈希表实现的 Map。

创建的映射没有任何顺序。遍历键或值时，迭代顺序未指定；只要映射没有发生更改，该顺序就会保持不变。

如果提供了 equals，就会用它将映射中的键与新键进行比较。如果省略 equals，则改用键自身的 Object.==。equals 函数不得更改用它进行相等性判断的映射；否则，结果行为未定义。

类似地，如果提供了 hashCode，就会用它生成键的哈希值，以便将键放入映射。如果省略 hashCode，则使用键自身的 Object.hashCode。hashCode 函数不得更改用它生成哈希码的映射；否则，结果行为未定义。

所用的 equals 和 hashCode 方法应始终保持一致：如果 equals(a, b) 为真，那么 hashCode(a) == hashCode(b) 也必须成立。对象的哈希值以及它与哪些对象相等，在该对象作为映射键期间都不应改变。如果对象的哈希码或相等性发生变化，结果行为未定义。

如果提供了 equals 或 hashCode 其中之一，通常也应提供另一个。

有些 equals 或 hashCode 函数可能无法处理所有对象。如果提供了 isValidKey，它会用于检查潜在的键；该键不一定是 K 的实例，例如类型为 Object? 的 operator []、remove 和 containsKey 的参数。如果 isValidKey 对某个对象返回 false，就不会调用 equals 和 hashCode 函数，也不会认为映射中存在与该对象相等的键。isValidKey 默认只检查对象是否为 K 的实例。

示例：

HashMap<int,int>(equals: (int a, int b) => (b - a) % 5 == 0,
                 hashCode: (int e) => e % 5)

此示例映射无需传入 isValidKey 函数。默认函数只接受 int 值，因此可以安全地将这些值传给 equals 和 hashCode 函数。

如果未提供 equals、hashCode 或 isValidKey，默认的 isValidKey 会接受所有键。默认的相等性比较和哈希码操作适用于所有对象。

同样，如果 equals 是 identical，hashCode 是 identityHashCode，并且省略 isValidKey，生成的映射就会基于对象标识；此时 isValidKey 默认接受所有键。也可以直接使用 HashMap.identity 创建这种映射。
