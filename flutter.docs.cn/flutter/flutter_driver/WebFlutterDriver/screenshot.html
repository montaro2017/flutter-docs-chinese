截取屏幕截图。

图像将以 PNG 格式返回。

警告：此功能并不可靠。

截屏前会人为延迟两秒。此延迟用于处理 driver 脚本与光栅线程（以前称为 GPU 线程）之间的竞争问题。问题在于，driver API 根据瞬时回调与框架同步，而这些回调与光栅线程不同步。

事件时间线示意图如下：

---------------------------------------------------------------
Without this delay:
---------------------------------------------------------------
UI    : <-- build -->
Raster:               <-- rasterize -->
Gap   :              | random |
Driver:                        <-- screenshot -->

上图中的间隔，是上一次 driver 操作（例如 tap()）与随后调用 screenshot() 之间的时间。由于它取决于 driver 进程与应用之间不可预测的通信通道，因此间隔时长是随机的。如果间隔太短（通常确实如此），光栅线程可能尚未完成当前帧的光栅化，截图就会截到上一帧，这并非预期结果。

---------------------------------------------------------------
With this delay, if we're lucky:
---------------------------------------------------------------
UI    : <-- build -->
Raster:               <-- rasterize -->
Gap   :              |    2 seconds or more   |
Driver:                                        <-- screenshot -->

两秒的间隔通常足以让光栅线程完成当前帧的光栅化，同时又不会过长，从而尽可能保持 driver 测试运行迅速。

---------------------------------------------------------------
With this delay, if we're not lucky:
---------------------------------------------------------------
UI    : <-- build -->
Raster:               <-- rasterize randomly slow today -->
Gap   :              |    2 seconds or more   |
Driver:                                        <-- screenshot -->

实际使用中，设备有时会在一段时间内非常繁忙，即使等待两秒也不够。因此这里仍存在竞态，可能导致测试偶发失败。

实现

@override
Future<List<int>> screenshot({ScreenshotFormat format = ScreenshotFormat.png}) async {
  if (format != ScreenshotFormat.png) {
    throw ArgumentError.value(format, 'format', 'Web Driver only supports PNG screenshot format');
  }
  await Future<void>.delayed(const Duration(seconds: 2));

  return _connection.screenshot();
}
