AppBar 类

Material Design 应用栏。

应用栏由工具栏组成，也可能包含其他组件，例如 TabBar 和 FlexibleSpaceBar。应用栏通常通过 IconButton 提供一个或多个常用 actions，并可在末尾放置 PopupMenuButton 来提供较少使用的操作（有时称为“溢出菜单”）。

应用栏通常放在 Scaffold.appBar 属性中，作为固定高度的组件显示在屏幕顶部。需要可滚动的应用栏时，请使用 SliverAppBar；它会将 AppBar 放入 sliver 中，以便用于 CustomScrollView。

leading、title 和 actions 等工具栏组件显示在 bottom（如果有）上方。bottom 通常用于放置 TabBar。如果指定了 flexibleSpace，它会叠放在工具栏和底部组件后方。下图展示了从左向右书写的语言（例如英语）中，各插槽在工具栏里的位置：

如果未提供 leading 组件，而 AppBar 位于包含 Drawer 的 Scaffold 中，则会插入用于打开抽屉的按钮。否则，如果最近的 Navigator 存在上一条路由，则会插入 BackButton。将 automaticallyImplyLeading 设为 false 可关闭此行为。此时 leading 组件为 null 会使中间/标题组件向起始端扩展。

如果未提供 actions 组件列表或列表为空，而 AppBar 位于包含末端 Drawer 的 Scaffold 中，则会插入用于打开末端抽屉的按钮。将 automaticallyImplyActions 设为 false 可关闭此行为。

AppBar 会根据当前环境 MediaQuery 的内边距调整内容位置，以避开系统 UI。将它用作 Scaffold.appBar 时，Scaffold 会负责处理这一点。为 AppBar 添加动画时，意外的 MediaQuery 变化（常见于 Hero 动画）可能导致内容突然跳动。可将 AppBar 包在 MediaQuery 组件中，并调整其内边距，使动画保持平滑。

故障排除

为什么 TextButton 操作按钮没有显示？

如果应用栏的 actions 中包含 TextButton，且其前景（文字）颜色与应用栏背景颜色相同，那么这些按钮将不可见。

在 Material v2（即 ThemeData.useMaterial3 为 false）中，如果整体主题亮度为 Brightness.light，应用栏默认的 backgroundColor 是整体主题的 ColorScheme.primary。遗憾的是，这与浅色主题下 TextButton 默认的 ButtonStyle.foregroundColor 相同。此时，文字按钮宜使用与 ColorScheme.primary 形成良好对比的 ColorScheme.onPrimary 作为前景色。可通过覆盖 TextButton.style 解决此问题：

Static Methods

preferredHeightFor(BuildContext context, Size preferredSize) → double
Used by Scaffold to compute its AppBar's overall height. The returned value is the same preferredSize.height unless AppBar.toolbarHeight was null and AppBarTheme.of(context).toolbarHeight is non-null. In that case the return value is the sum of the theme's toolbar height and the height of the app bar's AppBar.bottom widget.
