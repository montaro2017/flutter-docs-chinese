Scrollbar 类

Material Design 滚动条。

若要为 ScrollView 添加滚动条，可将滚动视图 widget 包装在 Scrollbar widget 中。

滚动条滑块用于指示 ScrollView 中实际可见的部分。

默认情况下，子滚动视图滚动时，滑块会淡入和淡出。若 thumbVisibility 为 true，滑块会一直显示，不执行淡出动画。此时必须将与该 Scrollable widget 关联的 ScrollController 提供给 controller，或者让该 Scrollable widget 使用 PrimaryScrollController。

如果滚动条包裹多个 ScrollView，默认情况下它只响应最近的 ScrollView，并显示对应的滑块。通过 notificationPredicate，可以自定义滚动条监听哪些 ScrollNotification。

如果子 ScrollView 无限延伸，RawScrollbar 将不会绘制。在这种情况下，滚动条无法准确表示可见区域的相对位置，也无法准确计算拖动滑块或点击轨道时应应用的滚动距离。

交互

滚动条支持交互；若未设置 controller，可使用 PrimaryScrollController。可以沿 ScrollView 的主轴拖动交互式滑块，以改变 ScrollPosition。点击滑块以外的轨道区域时，会根据点击位置相对于滑块的位置，触发一次 ScrollIncrementType.page 滚动。

使用 PrimaryScrollController 时，它不得同时连接多个 ScrollPosition。未指定 ScrollController 且 ScrollView.scrollDirection 为 Axis.vertical 的 ScrollView 会自动将其 ScrollPosition 连接到 PrimaryScrollController。此时应为每个 Scrollable 提供唯一的 ScrollController，以免多个 ScrollPosition 连接到同一个 PrimaryScrollController。

此示例展示同一路由中包含两个可滚动控件的应用。默认情况下，每个路由都有一个 PrimaryScrollController，且这两个控件的滚动方向都是 Axis.vertical，因此在移动平台上都会尝试连接到该控制器。Scrollbar 不支持同一控制器连接多个位置，所以我们为一个 ListView 及其 Scrollbar 配置了唯一的 ScrollController。桌面平台不会自动连接到 PrimaryScrollController；若要使用它，必须改为将 ScrollView.primary 设为 true。

或者，也可以在其中一个 ListView 上方创建一个新的 PrimaryScrollController。

桌面平台上的自动滚动条

在 TargetPlatformVariant.desktop 平台上，大多数 Scrollable widget 默认会添加滚动条。这是通过应用 ScrollConfiguration 中的 ScrollBehavior.buildScrollbar 实现的。未使用 PrimaryScrollController 或未提供 ScrollController 的 Scrollable 会获得一个专用的 ScrollController 供滚动条使用。此时，除非 interactive 为 false，否则只能有一个 Scrollable 使用 PrimaryScrollController。若要阻止 Axis.vertical 的 Scrollable 使用 PrimaryScrollController，可将 ScrollView.primary 设为 false。以下 Scrollable widget 不会自动应用滚动条：

  • EditableText
  • ListWheelScrollView
  • PageView
  • NestedScrollView
  • DropdownButton

将 ScrollBehavior 的 scrollbars 设为 false，即可在整个应用中禁用默认滚动条。

link 
MaterialApp(
  scrollBehavior: const MaterialScrollBehavior()
    .copyWith(scrollbars: false),
  home: Scaffold(
    appBar: AppBar(title: const Text('Home')),
  ),
)

此示例展示如何禁用 Scrollable widget 的默认滚动条，以避免在桌面平台上运行时出现重复滚动条。

在 iOS 平台上，默认会动态切换为 iOS 风格的 CupertinoScrollbar。

在桌面和 Web 平台上，滚动条滑块处于 WidgetState.dragged 或 WidgetState.hovered 状态时，颜色会改变。可以通过 ScrollbarThemeData.thumbColor 修改这些状态对应的颜色。

此示例展示一个会在滚动时执行淡出动画的 Scrollbar。用户滚动时，滚动条会淡入显示；停止滚动后则会淡出。

当 thumbVisibility 为 true 时，滚动条滑块会始终显示，不会淡出。此时必须向 controller 提供一个 ScrollController，或确保 PrimaryScrollController 可用。

当 ScrollView.scrollDirection 为 Axis.horizontal 时，建议始终显示 Scrollbar，因为水平滚动不易被用户发现。

link

若要使用此代码示例创建本地项目，请运行：
flutter create --sample=material.Scrollbar.2 mysample

可以使用 trackVisibility 添加滚动条轨道。也可以在悬停事件触发时绘制轨道，或使用 ScrollbarThemeData.trackVisibility 根据任意 WidgetState 控制轨道显示。

可以使用 thickness，根据 WidgetState 动态更改轨道和滚动条滑块的粗细；具体可通过 ScrollbarThemeData.thickness 设置。

另请参阅：

  • CupertinoScrollbar, an iOS style scrollbar.
  • ListView, which displays a linear, scrollable list of children.
  • GridView, which displays a 2 dimensional, scrollable array of children.
