SwitchListTile 类

包含 Switch 的 ListTile，也就是带标签的开关。

整个列表项都可以交互：点击列表项任意位置都会切换开关。点击并拖动 Switch 也会触发 onChanged 回调。

要确保 onChanged 正常触发，必须正确管理传入 value 的状态。通常会在 onChanged 中调用 State.setState 来切换状态值。

此控件的 value、onChanged、activeThumbColor、activeThumbImage 和 inactiveThumbImage 属性，与 Switch 控件中同名属性的作用相同。

title、subtitle、isThreeLine 和 dense 属性与 ListTile 中的同名属性类似。

此控件的 selected 属性与 ListTile.selected 类似。选中项的文字颜色使用此项的 activeThumbColor；如果它为 null，则使用主题的 SwitchThemeData.overlayColor。若 activeThumbColor 为 null，则采用上述主题颜色。

此控件不会自动协调 selected 状态和 value。若要在开关开启时让列表项显示为选中状态，请为这两个属性传入相同的值。

在从左到右书写的语言环境中，开关默认显示在右侧（即 ListTile.trailing 槽位），可通过 controlAffinity 更改位置。secondary 控件则放在 ListTile.leading 槽位。

此控件需要树中存在 Material 祖先，才能在其表面绘制；通常由应用的 Scaffold 提供。tileColor 和 selectedTileColor 并非由 SwitchListTile 自身绘制，而是由其 Material 祖先绘制。因此，可以在 SwitchListTile 外包裹一个 Material 控件，例如：

link 
ColoredBox(
  color: Colors.green,
  child: Material(
    child: SwitchListTile(
      tileColor: Colors.red,
      title: const Text('SwitchListTile with red background'),
      value: true,
      onChanged:(bool? value) { },
    ),
  ),
)

使用 Material 包裹 SwitchListTile 时的性能注意事项

逐个用 Material 包裹大量 SwitchListTile 会带来较高开销。只包裹确实需要的列表项，或尽可能让它们共用一个 Material 祖先；这样也能减少对 SwitchListTile 的逐项包裹。

若要将 SwitchListTile 显示为禁用状态，请将 onChanged 回调设为 null。

此控件展示了一个开关；切换开关时，会更改名为 _lights 的 bool 成员字段状态。

SwitchListTile 的语义

由于整个控件都可交互，因此它应作为一个单独的交互实体呈现。

为此，控件会用 MergeSemantics 包裹其子控件。MergeSemantics 会尝试将后代 Semantics 节点合并为语义树中的一个节点。因此，如果某个子控件需要独立的 Semantics 节点，就会抛出错误。

例如，不能将 RichText 作为此控件的后代控件。RichText 含有嵌入式手势识别器，需要独立的 Semantics 节点，这与将所有后代语义节点合并为一个节点的行为直接冲突。因此，类似场景可能需要创建自定义单选项控件来满足需求。
