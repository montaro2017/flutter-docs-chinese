Scaffold 类

实现 Material Design 的基础视觉布局结构。

此类提供用于显示抽屉和底部工作表的 API。

若要显示持久底部工作表，请通过 ScaffoldState，使用当前 BuildContext 获取 Scaffold.of，然后调用 ScaffoldState.showBottomSheet。

此示例展示一个包含 Scaffold、body 和 FloatingActionButton 的界面。body 是放置在 Center 中的 Text，用于让文本在 Scaffold 中居中。FloatingActionButton 关联了一个递增计数器的回调。

Scaffold 布局、键盘和屏幕凹口

Scaffold 会扩展以填满可用空间，通常会占据整个窗口或设备屏幕。设备键盘显示时，Scaffold 祖先组件中的 MediaQuery 的 MediaQueryData.viewInsets 会变化，从而触发 Scaffold 重建。默认情况下，Scaffold 会缩小 body，为键盘留出空间。若要阻止缩小，可将 resizeToAvoidBottomInset 设为 false。无论是否缩小，如果获得焦点的组件位于可滚动容器内，都会滚动到可见区域。

MediaQueryData.padding 定义可能无法完全显示的区域，例如 iPhone X 的屏幕凹口。Scaffold 的 body 不会自动按此内边距缩进，但 appBar 或 bottomNavigationBar 通常会使 body 避开这些区域。可在 Scaffold 的 body 中使用 SafeArea 避开屏幕凹口等区域。

带可拖动滚动底部工作表的悬浮操作按钮

如果 Scaffold.bottomSheet 是 DraggableScrollableSheet，设置了 Scaffold.floatingActionButton，并且将底部工作表拖动到覆盖 Scaffold 高度的 70% 以上，则以下两项会同时发生：

  • Scaffold 开始显示遮罩层（参阅 ScaffoldState.showBodyScrim）；
  • Scaffold.floatingActionButton 会通过 Curves.easeIn 动画缩小，并在底部工作表覆盖整个 Scaffold 时消失。

底部工作表缩回到覆盖 Scaffold 高度的 70% 以下时，遮罩层会消失，Scaffold.floatingActionButton 会通过动画恢复到正常尺寸。

嵌套 Scaffold

Scaffold 设计为 MaterialApp 的顶层容器。因此，在 Material 应用的每个路由中添加 Scaffold，就能为应用提供 Material 的基础视觉布局结构。

通常不需要嵌套 Scaffold。例如，在带标签页的界面中，bottomNavigationBar 是 TabBar，body 是 TabBarView；此时可能会想为每个标签页分别放置带不同标题 AppBar 的 Scaffold。更好的做法是为 TabController 添加监听器，并据此更新 AppBar。

为应用的标签控制器添加监听器，使得每次选择新标签时，都重置应用中唯一 AppBar 的标题。
link 
TabController(vsync: tickerProvider, length: tabCount)..addListener(() {
  if (!tabController.indexIsChanging) {
    setState(() {
      // Rebuild the enclosing scaffold with a new AppBar title
      appBarTitle = 'Tab ${tabController.index}';
    });
  }
})

尽管某些场景（例如展示嵌入式 Flutter 内容的演示应用）适合嵌套 Scaffold，但通常最好避免这样做。
