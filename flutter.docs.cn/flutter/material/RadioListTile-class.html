RadioListTile<T> 类

带有 Radio 的 ListTile。也就是说，这是一个带标签的单选按钮。

整个列表项都可交互：点击列表项的任意位置都会选中该单选按钮。

此 widget 通常有一个 RadioGroup 祖先，该祖先接收 RadioGroup.groupValue；其下与之匹配的 value 对应的 RadioListTile 会被选中。

title、subtitle、isThreeLine 和 dense 属性与 ListTile 中同名属性的作用类似。

此 widget 的 selected 属性与 ListTile.selected 属性类似。选中状态下的 fillColor 会用作已选项目的文本颜色。如果该值为 null，则使用 activeColor。

此 widget 不会协调 selected 状态与 checked 状态；若要在单选按钮被选中时让列表项也显示为选中状态，请在 value 与 RadioGroup.groupValue 匹配时将 selected 设为 true。

默认情况下，在从左向右书写的语言中，单选按钮显示在左侧（即起始边）。可以使用 controlAffinity 更改这一位置。secondary widget 会放在另一侧。这对应于 ListTile 的 ListTile.leading 和 ListTile.trailing 属性。

此 widget 需要树中有一个 Material 祖先来绘制自身，通常由应用的 Scaffold 提供。tileColor 和 selectedTileColor 并非由 RadioListTile 自身绘制，而是由 Material 祖先 widget 绘制。在这种情况下，可以在 RadioListTile 外层包裹一个 Material widget，例如：

link 
const ColoredBox(
  color: Colors.green,
  child: Material(
    child: RadioListTile<Meridiem>(
      tileColor: Colors.red,
      title: Text('AM'),
      value: Meridiem.am,
    ),
  ),
)

使用 RadioListTile 包裹 Material 时的性能注意事项

分别为大量 RadioListTile 包裹 Material 开销较大。可以只为确实需要的 RadioListTile 添加包装，或尽可能让它们共用一个 Material 祖先。

RadioListTile 中的语义

由于整个 RadioListTile 都可交互，因此它应将自身表示为单个可交互实体。

为此，RadioListTile widget 会用 MergeSemantics widget 包装其子项。MergeSemantics 会尝试将后代的 Semantics 节点合并为语义树中的一个节点。因此，如果 RadioListTile 的任何子项需要自己的 Semantics 节点，就会抛出错误。

例如，不能将 RichText widget 嵌套为 RadioListTile 的后代。RichText 内含手势识别器，需要自己的 Semantics 节点，这与 RadioListTile 希望将所有后代语义节点合并为一个节点直接冲突。因此，遇到类似用例时，可能需要创建自定义单选列表项 widget。
