ScaffoldMessengerState of(
  1. BuildContext context
)

返回包含给定 context 的最近此类实例中的状态。

通常会在响应用户手势或应用状态变化时调用 ScaffoldMessenger.of 函数。
link

若要使用此代码示例创建本地项目，请运行：
flutter create --sample=material.ScaffoldMessenger.of.1 mysample

一种不够优雅但更快捷的方案是为 ScaffoldMessenger 分配一个 GlobalKey，然后使用 key.currentState 属性获取 ScaffoldMessengerState，而不调用 ScaffoldMessenger.of。MaterialApp.scaffoldMessengerKey 指向默认提供的根 ScaffoldMessenger。

有时，生成 SnackBar 的代码无法直接访问有效的 BuildContext。例如，在 build 函数之外的方法中显示 SnackBar。此时可以为 ScaffoldMessenger 分配 GlobalKey。此示例展示如何使用 key 获取 MaterialApp 提供的 ScaffoldMessengerState。
link

若要使用此代码示例创建本地项目，请运行：
flutter create --sample=material.ScaffoldMessenger.of.2 mysample

如果当前作用域中没有 ScaffoldMessenger，调试模式下会触发断言，发布模式下则会抛出异常。

另请参阅：

  • maybeOf, which is a similar function but will return null instead of throwing if there is no ScaffoldMessenger ancestor.
  • debugCheckHasScaffoldMessenger, which asserts that the given context has a ScaffoldMessenger ancestor.

实现

static ScaffoldMessengerState of(BuildContext context) {
  assert(debugCheckHasScaffoldMessenger(context));

  final _ScaffoldMessengerScope scope = context
      .dependOnInheritedWidgetOfExactType<_ScaffoldMessengerScope>()!;
  return scope._scaffoldMessengerState;
}
