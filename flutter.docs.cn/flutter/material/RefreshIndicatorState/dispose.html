dispose 方法

  1. @protected

void dispose()
重写

此对象即将永久从树中移除时调用。

当此 State 对象不再构建时，框架会调用此方法。框架调用 dispose 后，此 State 对象会被视为已卸载，且 mounted 属性为 false。此时调用 setState 会出错。此生命周期阶段是终态：已释放的 State 对象无法重新挂载。

子类应重写此方法，以释放此对象持有的所有资源（例如停止正在运行的动画）。

如果 State 的 build 方法依赖于一个自身状态也可能变化的对象（例如 ChangeNotifier 或 Stream），或其他可订阅并接收通知的对象，请确保在 initState、didUpdateWidget 和 dispose 中正确订阅和取消订阅：

    在 initState 中订阅该对象。 在 didUpdateWidget 中，如果更新后的 widget 配置需要替换该对象，则取消订阅旧对象并订阅新对象。 在 dispose 中取消订阅该对象。

此方法的实现应以调用继承的方法结束，例如 super.dispose()。

注意事项

在开发者可能预期的某些时机，此方法不会被调用，例如应用关闭或通过平台原生方法关闭界面时。

应用关闭

无法预测应用何时关闭。例如，用户的电池可能起火，用户可能将设备掉入游泳池，或者操作系统可能因内存压力而单方面终止应用进程。

即使应用突然且未按计划终止，应用也有责任确保自身行为良好。

若要人为触发整个 Widget 树的释放，可以考虑使用 runApp 并传入诸如 SizedBox.shrink 这样的 Widget。

若要监听平台关闭消息（以及其他生命周期变化），可以使用 AppLifecycleListener API。

通过平台原生方法关闭 Flutter 界面

应用可能同时包含 Flutter 界面和非 Flutter 界面。如果应用调用非 Flutter 方法移除基于 Flutter 的界面（例如使用平台原生 API 操作原生导航栈），框架无法判断开发者是否希望立即释放资源。Widget 树仍会保持挂载状态，并在界面再次显示时随时可以渲染。

有关如何更及时地释放资源，请参阅用于启动应用的方法（例如 runApp 或 runWidget）中的建议。

另请参阅：

  • deactivate，会在调用 dispose 前触发。

实现

@protected
@override
void dispose() {
  _positionController.dispose();
  _scaleController.dispose();
  super.dispose();
}
