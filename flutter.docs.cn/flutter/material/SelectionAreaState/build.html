重写

描述此 widget 所表示的用户界面部分。

框架会在多种不同情况下调用此方法。例如：

  • 调用 initState 后。
  • 调用 didUpdateWidget 后。
  • 调用 setState 后。
  • 此 State 对象依赖的内容发生变化后（例如此前 build 中引用的 InheritedWidget 发生变化）。
  • 调用 deactivate 并将 State 对象重新插入树中的其他位置后。

此方法可能在每一帧中都被调用，因此除构建控件外，不应包含其他副作用。

框架会将此 widget 下方的子树替换为此方法返回的 widget。根据返回的 widget 是否能够更新现有子树的根节点（由调用 Widget.canUpdate 判定），框架会更新现有子树，或移除它并重新创建子树。

通常，具体实现会返回一组新创建的控件，并根据此控件的构造函数信息、给定的 BuildContext 以及此 State 对象的内部状态进行配置。

给定的 BuildContext 包含此控件在树中构建位置的信息。例如，它会提供该位置的继承控件集合。BuildContext 参数始终与此 State 对象的 context 属性相同，并在该对象的整个生命周期内保持不变。此处冗余地提供 BuildContext 参数，是为了使此方法与 WidgetBuilder 具有相同的签名。

设计讨论

为什么 build 方法属于 State，而不是 StatefulWidget？

将 Widget build(BuildContext context) 方法放在 State 上，而不是将 Widget build(BuildContext context, State state) 方法放在 StatefulWidget 上，可以让开发者在继承 StatefulWidget 时拥有更大的灵活性。

例如，AnimatedWidget 是 StatefulWidget 的子类，它提供一个抽象的 Widget build(BuildContext context) 方法供子类实现。如果 StatefulWidget 已有一个接收 State 参数的 build 方法，AnimatedWidget 就不得不把自己的 State 对象提供给子类，即使该 State 对象只是 AnimatedWidget 的内部实现细节。

从概念上说，StatelessWidget 也可以用类似方式实现为 StatefulWidget 的子类。如果 build 方法属于 StatefulWidget 而非 State，这种实现方式就不再可行。

将 build 函数放在 State 而非 StatefulWidget 上，也有助于避免闭包隐式捕获 this 所引发的一类错误。如果在 StatefulWidget 的 build 函数中定义闭包，该闭包会隐式捕获 this，也就是当前控件实例，并能访问该实例不可变的字段：

// (this is not valid Flutter code)
class MyButton extends StatefulWidgetX {
  MyButton({super.key, required this.color});

  final Color color;

  @override
  Widget build(BuildContext context, State state) {
    return SpecialWidget(
      handler: () { print('color: $color'); },
    );
  }
}

例如，假设父控件以蓝色 color 构建 MyButton，那么打印函数中的 $color 会如预期地引用蓝色。现在假设父控件以绿色重新构建 MyButton。第一次构建时创建的闭包仍会隐式引用原控件，因此即使控件已更新为绿色，$color 仍会打印蓝色。如果该闭包的生命周期超过控件，就会打印过时的信息。

相比之下，将 build 函数放在 State 对象上时，build 期间创建的闭包会隐式捕获 State 实例，而不是控件实例：

class MyButton extends StatefulWidget {
  const MyButton({super.key, this.color = Colors.teal});

  final Color color;
  // ...
}

class MyButtonState extends State<MyButton> {
  // ...
  @override
  Widget build(BuildContext context) {
    return SpecialWidget(
      handler: () { print('color: ${widget.color}'); },
    );
  }
}

现在，父控件以绿色重新构建 MyButton 时，第一次构建时创建的闭包仍会引用在重建期间保持不变的 State 对象。框架已将该 State 对象的 widget 属性更新为新的 MyButton 实例，因此 ${widget.color} 会如预期地打印绿色。

@override
Widget build(BuildContext context) {
  assert(debugCheckHasMaterialLocalizations(context));
  final TextSelectionControls controls =
      widget.selectionControls ??
      switch (Theme.of(context).platform) {
        TargetPlatform.android || TargetPlatform.fuchsia => materialTextSelectionHandleControls,
        TargetPlatform.linux || TargetPlatform.windows => desktopTextSelectionHandleControls,
        TargetPlatform.iOS => cupertinoTextSelectionHandleControls,
        TargetPlatform.macOS => cupertinoDesktopTextSelectionHandleControls,
      };
  return SelectableRegion(
    key: _selectableRegionKey,
    selectionControls: controls,
    focusNode: widget.focusNode,
    contextMenuBuilder: widget.contextMenuBuilder,
    magnifierConfiguration:
        widget.magnifierConfiguration ?? TextMagnifier.adaptiveMagnifierConfiguration,
    onSelectionChanged: widget.onSelectionChanged,
    child: widget.child,
  );
}
