重写

返回一个弹道滚动模拟，从给定位置以给定速度开始。

ScrollPositionWithSingleContext 会在 ScrollPositionWithSingleContext.goBallistic 方法中使用此方法。如果结果非 null，ScrollPositionWithSingleContext 会根据返回值启动 BallisticScrollActivity；否则会进入空闲活动状态。

给定的 position 仅在此方法调用期间有效。不要保留其引用供以后使用，因为它的值可能会更新、保持不变，或变为完全无关的另一个可滚动对象的值。

此方法可能每一帧都会调用，甚至可能在用户感知为一次连续弹道滚动的过程中调用。例如，在 ListView 中，先前位于屏幕外的条目进入视野并完成布局时，可能会使用新的 ScrollMetrics.maxScrollExtent 调用此方法。实现应确保：当预期仍是同一次弹道滚动时，这些调用不会改变物理效果，只会继续该运动。

通常，可以让 Simulation 遵循弹道飞行粒子的物理模型来保证这一点：作用于粒子的力只取决于其位置、速度和环境，而不取决于当前时间或任何内部状态。这意味着 Simulation.dx 对时间的导数应能仅用 Simulation.x、Simulation.dx 以及构造 Simulation 时使用的参数表示，且与时间无关。

实现

@override
Simulation? createBallisticSimulation(ScrollMetrics position, double velocity) {
  assert(
    position is _CarouselPosition,
    'CarouselScrollPhysics can only be used with Scrollables that uses '
    'the CarouselController',
  );

  final metrics = position as _CarouselPosition;
  if ((velocity <= 0.0 && metrics.pixels <= metrics.minScrollExtent) ||
      (velocity >= 0.0 && metrics.pixels >= metrics.maxScrollExtent)) {
    return super.createBallisticSimulation(metrics, velocity);
  }

  final Tolerance tolerance = toleranceFor(metrics);
  final double target = _getTargetPixels(metrics, tolerance, velocity);
  if (target != metrics.pixels) {
    return ScrollSpringSimulation(spring, metrics.pixels, target, velocity, tolerance: tolerance);
  }
  return null;
}
