BidiFormatter

BidiFormatter 类

Bidi 是双向文本（Bi-directional text）的缩写。根据 维基百科的定义：双向文本同时包含从右向左（RTL）和从左向右（LTR）两种方向的文字。通常指混合使用不同类型字母的文本，也可能指牛耕式书写，即每一行都改变书写方向。

此工具类用于在方向可能相反的上下文中格式化显示文本，避免布局错乱。它主要是 Closure 双向文本格式化库经过精简并适配 Dart 的移植版本。如果你希望此格式化器提供 Closure 库（或 ICU、其他库）中的某项功能，请联系 Dart 团队。

提供以下功能：

  1. 双向文本包装
    当一种语言的文本插入到使用另一种方向相反语言的文档中时（例如，将英文企业名称嵌入希伯来语网页），如果没有在插入内容周围使用“包装”明确声明其方向并在末尾重置方向，插入字符串及其后续文本都可能显示错误。可以使用 HTML 标记（例如 span dir=rtl 标签）包装；无法使用标记时，则可使用 Unicode 双向格式控制码（LRE|RLE 和 PDF）。提供这类包装服务是 BiDi 格式化器的主要用途。

  2. 方向估算
    如何判断即将插入周围文本中的字符串是否与其方向一致？很多情况下，编写插入代码时就已知答案，例如将本地化消息插入本地化页面。这时无需调用 BiDi 格式化器。其他情况下（例如字符串由用户输入或来自数据库），字符串的语言及其书写方向无法预先确定，需要在运行时估算。BiDi 格式化器会自动完成此操作。

  3. 转义
    将纯文本（即尚未成为 HTML 或经过 HTML 转义的文本）包装进 HTML 标记时，必须先对文本进行 HTML 转义，以防止 XSS 攻击等问题。虽然任何时候都应如此，但字符串一旦被包装进标记，就无法再进行转义。因此，BiDi 格式化器也提供转义服务，作为最后一道防线。

因此，格式化器可以通过一次调用，按指定方式转义输入字符串、判断其书写方向，并在需要时进行包装。调用方随后可将返回值插入输出内容。

构造函数

BidiFormatter.LTR([bool alwaysSpan = false])
创建指定方向的格式化对象。如果 alwaysSpan 为 true，即使输入方向为中性或与上下文方向一致，也始终使用 span 标签。这样，输出 DOM 结构就不会随方向组合而改变。

Estimates the directionality of text using the best known general-purpose method (using relative word counts). A TextDirection.UNKNOWN return value indicates completely neutral input. isHtml is true if text HTML or HTML-escaped.

wrapWithSpan(String text, {bool isHtml = false, bool resetDir = true, TextDirection? direction}) → String
将字符串按给定（或估算得出的）direction 格式化，以便在 HTML 中按上下文方向输出，避免方向相反的字符串显示错乱，或导致其后内容显示错乱。
wrapWithUnicode(String text, {bool isHtml = false, bool resetDir = true, TextDirection? direction}) → String
将 text 按已知（若提供）或估算出的 direction 格式化，以便在相应文字方向的纯文本上下文中使用，避免方向相反的文本显示混乱，或影响其后内容。与 wrapWithSpan 不同，此方法使用 Unicode 双向文本格式控制字符包装文本，而不是使用 span。RTL 文本返回的字符串形式为 RLE+text+PDF，LTR 文本则为 LRE+text+PDF。
