DateFormat

DateFormat 类

DateFormat 用于根据区域设置格式化和解析日期。

它允许用户从一组标准日期时间格式中选择，也可以在特定区域设置下指定自定义模式。不同区域的日期元素可能有所不同，包括月份名称、星期名称和字段顺序等。用户还可以使用任意自定义模式，在特定区域设置下解析或格式化日期时间字符串。

使用默认的 'en_US' 格式化日期无需初始化。例如：

print(DateFormat.yMMMd().format(DateTime.now()));

对于其他区域设置，必须先获取该区域的格式化数据。目前可通过三种方式完成，具体取决于导入的库。无论采用哪种方式，都必须调用 initializeDateFormatting 方法；该方法返回一个 Future，在区域数据可用时完成。无需关心 Future 的结果；完成后，该区域数据即可用于日期格式化与解析。

最简单的方式是从包含所有区域数据的库中导入本地数据。

import 'package:intl/date_symbol_data_local.dart';
initializeDateFormatting('fr_FR', null).then((_) => runMyCode());

如果程序运行在浏览器之外，可以从文件系统读取数据。

import 'package:intl/date_symbol_data_file.dart';
initializeDateFormatting('de_DE', null).then((_) => runMyCode());

如果程序运行在浏览器中，可以通过 XmlHttpRequest 机制从服务器读取数据。

import 'package:intl/date_symbol_data_http_request.dart';
initializeDateFormatting('pt_BR', null).then((_) => runMyCode());

获取区域数据后，需要指定具体格式。本库对完整格式和缩略的“骨架”格式都采用 ICU/JDK 日期时间模式规范。骨架格式也能适配不同区域设置，在可用时优先使用。

使用美国区域设置的示例：

 Pattern                           Result
 ----------------                  -------
 DateFormat.yMd()                 -> 7/10/1996
 DateFormat('yMd')                -> 7/10/1996
 DateFormat.yMMMMd('en_US')       -> July 10, 1996
 DateFormat.jm()                  -> 5:08 PM
 DateFormat.yMd().add_jm()        -> 7/10/1996 5:08 PM
 DateFormat.Hm()                  -> 17:08 // force 24 hour time

显式模式语法：也可以通过模式字符串指定格式。这适用于没有对应骨架的格式，但不会适配不同区域设置。例如，显式模式中的字母 'H' 和 'h' 分别表示 24 小时制和 12 小时制。显式模式无法实现 'j' 骨架的行为；'j' 会根据区域习惯选择 24 或 12 小时制，并在适当时包含上午/下午标记。因此，优先使用骨架更合适。

模式字母的数量决定格式。

文本：

  • 5 pattern letters--use narrow form for standalone. Otherwise not used.
  • 4 or more pattern letters--use full form,
  • 3 pattern letters--use short or abbreviated form if one exists
  • less than 3--use numeric form if one exists

数字：表示最少数字位数。较短的数字会在左侧补零至指定长度（例如，'m' 生成 '6'，而 'mm' 生成 '06'）。年份有特殊处理：若 'y' 的数量为 2，年份将截取为两位数字（例如，'yyyy' 生成 '1997'，'yy' 生成 '97'）。与其他字段不同，秒的小数部分会在右侧补零。

（文本与数字）：数量为 3 或更多时使用文本，否则使用数字。

模式中未出现的字符会被视为带引号的文本。例如，冒号、句点、空格、# 和 @ 等字符即使没有用单引号括起，也会原样出现在结果中。目前模式中并非所有字母都有含义，但强烈不建议不加引号地使用这些未定义字母，因为将来可能会把它们用作模式字符。

使用美国区域设置的示例：

Format Pattern                    Result
--------------                    -------
"EEE, MMM d, ''yy"                Wed, Jul 10, '96
'h:mm a'                          12:08 PM
'yyyyy.MMMM.dd GGG hh:mm aaa'     01996.July.10 AD 12:08 PM

使用两位年份模式（'yy'）解析日期字符串时，DateFormat 必须根据某个世纪来解释缩写年份。它会调整日期，使其落在调用解析函数时刻之前 80 年至之后 20 年的范围内。例如，使用模式 'MM/dd/yy'，并在 1997 年 1 月 1 日创建 DateFormat 实例时，字符串 '01/11/12' 会解析为 2012 年 1 月 11 日，而 '05/04/64' 会解析为 1964 年 5 月 4 日。解析时，只有恰好由两位数字组成的字符串才会按默认世纪解释；其他数字字符串（如一位或三位以上数字）都按其字面值解释。测试两位年份解析时，可以通过 package:clock 控制当前日期。

如果年份模式不恰好包含两个 'y' 字符，则无论数字位数多少，年份都按字面值解释。因此，使用模式 'MM/dd/yyyy' 时，'01/11/12' 会解析为公元 12 年 1 月 11 日。
