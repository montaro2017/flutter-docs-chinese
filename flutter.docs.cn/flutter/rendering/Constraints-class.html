Constraints 类 抽象

一组抽象的布局约束。

具体布局模型（例如盒子布局）会创建具体子类，用于在父级和子级之间传递布局约束。

编写 Constraints 子类

创建具有新布局协议的 RenderObject 子类时，通常还需要创建新的 Constraints 子类，以表示布局算法的输入。

Constraints 子类应为不可变类型（所有字段均为 final）。除特定布局协议所需的字段、构造函数和辅助方法外，还应实现以下成员：

  • isTight getter：如果对象表示 RenderObject 无法选择自身布局方式的情况，就应返回 true。例如，BoxConstraints 在最小和最大宽度相等、且最小和最大高度也相等时，会让 isTight 返回 true。

  • isNormalized getter：如果对象以规范形式表示其数据，就应返回 true。有时字段之间可能存在冗余，导致几种不同表示具有相同含义。例如，最小宽度大于最大宽度的 BoxConstraints 实例，等价于将最大宽度设为该最小宽度的实例（由于最小约束优先，2<w<1 等价于 2<w<2）。默认的 debugAssertIsValid 实现会使用此 getter。

  • debugAssertIsValid 方法：如果约束对象存在任何问题，就应触发断言。我们采用这种方式，而不在构造函数中断言，是为了让构造函数可以为 const，并允许在构建有效约束期间暂时创建无效约束。详细检查示例可参阅 BoxConstraints.debugAssertIsValid 的实现。

  • == 运算符和 hashCode getter：用于比较约束是否相等。如果传给渲染对象的约束与现有约束相等，且对象未标记为需要布局，渲染库就会避免再次布局该对象。

  • toString 方法：应描述约束，使其在 debugDumpRenderTree 的输出中易于阅读。
