RenderSliver 类 抽象

实现视口滚动效果的渲染对象基类。

RenderViewport 包含一组子 sliver。每个 sliver（字面意思是视口内容的一小片）依次进行布局，并逐步填充视口。每次都会布局所有 sliver，包括因滚出视口或位于视口末尾之外而范围为零的 sliver。

Sliver 遵循 sliver 协议：在布局期间，每个 sliver 接收一个 SliverConstraints 对象，并计算相应的 SliverGeometry，描述它在视口中的位置。这类似于 RenderBox 使用的 box 协议：它接收 BoxConstraints 作为输入，并计算出一个 Size。

Sliver 有一个起始边缘，即该 sliver 的 SliverConstraints.scrollOffset 所描述位置的起点。Sliver 有多个尺寸，其中最主要的是 SliverGeometry.paintExtent。它描述 sliver 沿主轴方向从起始边缘开始的范围，直到视口末端或 sliver 末端，以先到者为准。

Sliver 可以根据不断变化的约束以非线性方式改变尺寸，从而实现各种滚动效果。例如，SliverAppBar 基于多个 RenderSliverPersistentHeader 子类实现；这些子类可以让内容在滚动偏移变化时仍保持可见，或根据用户的滚动方向在不同偏移位置重新出现（SliverConstraints.userScrollDirection）。

编写 RenderSliver 子类

Sliver 可以包含 sliver 子节点，也可以包含来自其他坐标系（通常是 box 坐标系）的子节点。（有关 box 协议的详情，请参阅 RenderBox。）Sliver 也可以采用不同的子节点模型，通常包含一个子节点或一组子节点。

Sliver 示例

一个包含单个 sliver 子节点的典型示例是 RenderSliverPadding，它会在子节点周围添加内边距。此类 sliver 到 sliver 的渲染对象必须为子节点构造一个 SliverConstraints 对象，然后使用子节点的 SliverGeometry 来确定自身的几何信息。

另一种常见的单子节点 sliver 包含一个 RenderBox 子节点。例如，RenderSliverToBoxAdapter 会布局单个 box，并根据该 box 确定自身尺寸。此类 sliver 必须使用自己的 SliverConstraints 为子节点创建 BoxConstraints，再调用子节点的 layout 方法进行布局，最后使用子节点的 RenderBox.size 生成 sliver 的 SliverGeometry。

最常见的 sliver 类型是包含多个子节点的 sliver。最简单的示例是 RenderSliverList，它沿主轴方向依次排列子节点。与只有一个 box 子节点的 sliver 一样，它会使用自己的约束为子节点创建 BoxConstraints，再根据所有子节点的汇总信息生成自身的几何信息。不过，与单子节点类型不同，它会谨慎选择实际需要布局（之后也需要绘制）的子节点。例如，若滚动偏移为 1000 像素，且此前已确定前三个子节点的高度各为 400 像素，它就会跳过前两个子节点，从第三个子节点开始布局。

布局

布局时，sliver 会确定自己的几何信息，其中包括尺寸（SliverGeometry.paintExtent）、下一个 sliver 的位置（SliverGeometry.layoutExtent），以及各个子节点的位置。这些信息取决于视口传入的约束，例如滚动偏移（SliverConstraints.scrollOffset）。

例如，一个只绘制高 100 像素 box 的 sliver，在滚动偏移为零时会将 SliverGeometry.paintExtent 设为 100 像素；滚动偏移为 75 像素时，SliverGeometry.paintExtent 会设为 25 像素；滚动偏移达到或超过 100 像素时设为零。（假设 SliverConstraints.remainingPaintExtent 大于 100 像素。）

此系统的各种输入尺寸都包含在约束中。详情请参阅 SliverConstraints 类的文档。

performLayout 函数必须根据这些约束创建一个 SliverGeometry 对象，并将其赋给 geometry 属性。可配置的几何尺寸详情请参阅 SliverGeometry 类的文档。

绘制

除了实现布局，sliver 还必须实现绘制，方法是重写 paint 方法。

调用 paint 方法时，会传入一个 Offset，表示从 Canvas 原点到 sliver 左上角的偏移量，与轴方向无关。

子类还应重写 applyPaintTransform，以提供描述每个子节点相对于 sliver 位置的 Matrix4。（无障碍层等功能会使用它来确定子节点的边界。）

命中测试

要实现命中测试，可以重写 hitTestSelf 和 hitTestChildren 方法；对于更复杂的情况，也可以直接重写 hitTest 方法。

如需实际响应指针事件，可以实现 handleEvent 方法。该方法默认不执行任何操作。（手势通常由遵循 box 协议的 widget 处理，而不是直接由 sliver 处理。）

辅助方法

实现一些方法可以让 sliver 的其他方法更容易实现。下面列出的每个方法都有详细文档。此外，还可以混入 RenderSliverHelpers 类，以使用其中的辅助方法。

childScrollOffset

如果子类将子节点放置在滚动偏移零以外的位置，就应重写 childScrollOffset。例如，RenderSliverList 和 RenderSliverGrid 会重写此方法，而 RenderSliverToBoxAdapter 不会。

Scrollable.ensureVisible 等功能会使用此方法。

childMainAxisPosition

子类应实现 childMainAxisPosition，以描述子节点的位置。

childCrossAxisPosition

如果子类将子节点放置在交叉轴上零以外的位置，就应重写 childCrossAxisPosition。例如，RenderSliverGrid 会重写此方法。
