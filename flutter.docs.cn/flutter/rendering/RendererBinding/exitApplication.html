继承

调用原生应用 API 方法，以正常退出应用。

这与调用 dart:io 的 exit 函数不同：此方法会让引擎有机会清理资源，避免退出时崩溃，因此始终应优先使用此方法，而不是调用 exit。此外，它还可以让 handleRequestAppExit 的处理器有机会取消应用退出。

exitType 表示要执行哪种退出。对于 ui.AppExitType.cancelable 类型的退出，系统会通过调用 handleRequestAppExit 查询应用，应用可以选择取消退出请求。如果 exitType 为 ui.AppExitType.required，应用会立即退出，不会先进行查询。

对于 ui.AppExitType.cancelable 类型的退出，返回值是应用对是否取消退出所作出的响应。实际上，响应不会是 ui.AppExitResponse.exit，因为收到结果时应用已经退出。

如果平台支持退出代码，可选参数 exitCode 会作为应用的退出代码。在其他平台上，该参数可能会被忽略。默认值为零。

另请参阅：

  • WidgetsBindingObserver.didRequestAppExit，可在 WidgetsBindingObserver 上重写此处理方法，以接收退出请求。

实现

Future<ui.AppExitResponse> exitApplication(ui.AppExitType exitType, [int exitCode = 0]) async {
  final Map<String, Object?>? result = await SystemChannels.platform
      .invokeMethod<Map<String, Object?>>('System.exitApplication', <String, Object?>{
        'type': exitType.name,
        'exitCode': exitCode,
      });
  if (result == null) {
    return ui.AppExitResponse.cancel;
  }
  switch (result['response']) {
    case 'cancel':
      return ui.AppExitResponse.cancel;
    case 'exit':
    default:
      // In practice, this will never get returned, because the application
      // will have exited before it returns.
      return ui.AppExitResponse.exit;
  }
}
