drawFrame 方法

  1. @protected
void drawFrame()

驱动渲染流水线以生成一帧。

此方法由 handleDrawFrame 调用；当引擎需要布局并绘制一帧时，会自动调用后者。

每一帧都包含以下阶段：

  1. 动画阶段：由 handleBeginFrame 方法按注册顺序调用所有通过 scheduleFrameCallback 注册的临时帧回调；该方法已注册到 PlatformDispatcher.onBeginFrame。这些回调包括驱动 AnimationController 对象的所有 Ticker 实例，因此所有活动的 Animation 对象都会在此阶段更新。

  2. 微任务阶段：handleBeginFrame 返回后，由临时帧回调安排的微任务会开始运行。这通常包括本帧中已完成的 Ticker 和 AnimationController 所对应 Future 的回调。

在 handleBeginFrame 之后，会调用已注册到 dart:ui.PlatformDispatcher.onDrawFrame 的 handleDrawFrame。它会调用所有持久帧回调，其中最重要的是本方法 drawFrame；该方法按以下步骤执行：

  1. 布局阶段：系统中所有需要布局的 RenderObject 都会执行布局（参见 RenderObject.performLayout）。有关如何将对象标记为需要布局的详情，请参阅 RenderObject.markNeedsLayout。

  2. 合成位阶段：更新所有需要处理的 RenderObject 的合成位。详情请参阅 RenderObject.markNeedsCompositingBitsUpdate。

  3. 绘制阶段：重新绘制系统中所有需要绘制的 RenderObject（参见 RenderObject.paint），并生成 Layer 树。有关如何将对象标记为需要绘制的详情，请参阅 RenderObject.markNeedsPaint。

  4. 合成阶段：将图层树转换为 Scene 并发送到 GPU。

  5. 语义阶段：更新系统中所有需要处理的 RenderObject 的语义信息，并生成 SemanticsNode 树。有关如何将对象标记为需要更新语义的详情，请参阅 RenderObject.markNeedsSemanticsUpdate。

有关第 3 至第 7 步的详情，请参阅 PipelineOwner。

  1. The finalization phase: After drawFrame returns, handleDrawFrame then invokes post-frame callbacks (registered with addPostFrameCallback).

某些 binding（例如 WidgetsBinding）会在此列表中添加额外步骤（例如参阅 WidgetsBinding.drawFrame）。

实现

//
// When editing the above, also update widgets/binding.dart's copy.
@protected
void drawFrame() {
  rootPipelineOwner.flushLayout();
  rootPipelineOwner.flushCompositingBits();
  rootPipelineOwner.flushPaint();
  if (sendFramesToEngine) {
    for (final RenderView renderView in renderViews) {
      renderView.compositeFrame(); // this sends the bits to the GPU
    }
    rootPipelineOwner.flushSemantics(); // this sends the semantics to the OS.
    _firstFrameSent = true;
  }
}
