PipelineOwner
description

PipelineOwner 类 base

管线所有者负责管理渲染管线。

管线所有者提供驱动渲染管线的接口，并存储各个阶段中哪些渲染对象请求过遍历的状态。若要刷新管线，请按以下顺序调用这些函数：

  1. flushLayout 会更新需要计算布局的渲染对象。在此阶段，会计算每个渲染对象的尺寸和位置。渲染对象可能会在此阶段将自身的绘制状态或合成状态标记为脏。
  2. flushCompositingBits 会更新合成位为脏的渲染对象。在此阶段，每个渲染对象都会确定其子项是否需要合成。绘制阶段会使用这些信息来选择如何实现裁剪等视觉效果。如果渲染对象有合成子项，就需要使用 Layer 创建裁剪，才能将裁剪应用到该合成子项（该子项会绘制到自己的 Layer 中）。
  3. flushPaint 会遍历需要绘制的渲染对象。在此阶段，渲染对象可以将绘制命令记录到 PictureLayer 中，并构建其他合成 Layer。
  4. 最后，如果启用了语义功能，flushSemantics 会为渲染对象生成语义信息。辅助技术会使用这些语义信息来提升渲染树的可访问性。

RendererBinding 持有负责管理屏幕可见渲染对象的管线所有者。你也可以创建其他管线所有者来管理屏幕外的对象，并让它们独立刷新自己的管线。

可以将多个 PipelineOwner 组织成一棵树，以管理多棵渲染树；每个 PipelineOwner 负责其中一棵渲染树。要构建或修改这棵树，请调用 adoptChild 或 dropChild。在上述各刷新阶段中，PipelineOwner 会先在自己的渲染树中处理其管理的节点，然后再对其子节点调用相同的刷新方法。不得假定子 PipelineOwner 的刷新顺序。

PipelineOwner 也可以 attach 到 PipelineManifold，以访问通常由绑定提供的平台功能，同时不受特定绑定实现的限制。给定树中的所有 PipelineOwner 都必须附加到同一个 PipelineManifold。调用 adoptChild 时会自动完成此操作。
