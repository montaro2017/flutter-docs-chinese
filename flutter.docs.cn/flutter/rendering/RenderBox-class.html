RenderBox 类 抽象

采用二维笛卡尔坐标系的渲染对象。

每个 box 的尺寸由宽度和高度表示。每个 box 都有自己的坐标系，其左上角位于 (0, 0)，因此右下角位于 (width, height)。box 包含所有点，包括左上角；范围延伸到右下角，但不包含右下角。

Box 布局通过沿树向下传递 BoxConstraints 对象来完成。Box 约束为子节点的宽度和高度分别设定最小值和最大值。确定尺寸时，子节点必须遵守父节点提供的约束。

此协议足以表达多种常见的 box 布局数据流。例如，要实现“输入宽度、输出高度”的数据流，可以使用一组宽度为紧约束的 box 约束调用子节点的 layout 函数（并将 parentUsesSize 设为 true）。子节点确定高度后，再使用该高度确定自身尺寸。

编写 RenderBox 子类

要描述新的布局模型、绘制模型、命中测试模型或语义模型，同时仍遵循 RenderBox 协议定义的笛卡尔空间，可以实现一个新的 RenderBox 子类。

如需创建新协议，请考虑改为继承 RenderObject。

新 RenderBox 子类的构造函数和属性

构造函数通常会为类的每个属性接收一个命名参数。然后将值传给类的私有字段，并通过断言验证参数是否正确（例如，值不应为空时，断言其非空）。

属性通常由 getter、setter 和字段组成，形式如下：

AxisDirection get axis => _axis;
AxisDirection _axis = AxisDirection.down; // or initialized in constructor
set axis(AxisDirection value) {
  if (value == _axis) {
    return;
  }
  _axis = value;
  markNeedsLayout();
}

setter 通常以调用 markNeedsLayout 结束（如果布局使用了此属性），或者以调用 markNeedsPaint 结束（如果只有绘制函数使用此属性）。无需同时调用两者；markNeedsLayout 会隐含调用 markNeedsPaint。

布局和绘制都属于开销较大的操作；调用 markNeedsLayout 或 markNeedsPaint 时应谨慎。只有布局或绘制确实发生变化时才应调用它们。

子节点

如果渲染对象是叶节点，也就是不包含任何子节点，请忽略本节。（叶渲染对象的示例包括 RenderImage 和 RenderParagraph。）

对于包含子节点的渲染对象，有以下四种情况：

  • 单个 RenderBox 子节点。若渲染对象的尺寸与子节点一致，可考虑继承 RenderProxyBox；若子节点小于 box 且 box 会在内部对齐子节点，则可考虑继承 RenderShiftedBox。

  • 单个子节点，但它不是 RenderBox。请使用 RenderObjectWithChildMixin mixin。

  • 一组子节点。请使用 ContainerRenderObjectMixin mixin。

  • 更复杂的子节点模型。

使用 RenderProxyBox

默认情况下，RenderProxyBox 渲染对象会调整自身尺寸以适应子节点；如果没有子节点，则尽可能缩小。它会将所有命中测试和绘制操作传递给子节点，固有尺寸和基线测量也同样由子节点提供。

RenderProxyBox 的子类只需重写 RenderBox 协议中与自身相关的部分。例如，RenderOpacity 只重写 paint 方法（并重写 alwaysNeedsCompositing 以反映 paint 方法的行为，以及 visitChildrenForSemantics，以便子节点不可见时将其从无障碍工具中隐藏），同时添加 RenderOpacity.opacity 字段。

RenderProxyBox 假定子节点与父节点尺寸相同，并位于 (0,0)。如果不符合这一点，请改用 RenderShiftedBox。

有关继承 RenderProxyBox 的示例，请参阅 proxy_box.dart。

使用 RenderShiftedBox

默认情况下，RenderShiftedBox 的行为与 RenderProxyBox 类似，但它不假定子节点位于 (0,0)（而是使用子节点 parentData 字段中记录的实际位置），也不提供默认布局算法。

有关继承 RenderShiftedBox 的示例，请参阅 shifted_box.dart。

子节点类型和子节点专属数据

RenderBox 的子节点不一定是 RenderBox。也可以为 RenderBox 使用其他 RenderObject 子类作为子节点。请参阅 RenderObject 中的相关说明。

父节点可以拥有子节点的附加数据，但这些数据会通过子节点的 parentData 字段存储在子节点上。用于存储这些数据的类必须继承 ParentData。子节点挂接时，setupParentData 方法会初始化其 parentData 字段。

按照惯例，包含 RenderBox 子节点的 RenderBox 对象会使用 BoxParentData 类。该类提供 BoxParentData.offset 字段，用于存储子节点相对于父节点的位置。（RenderProxyBox 不需要此偏移量，因此是此规则的例外。）

使用 RenderObjectWithChildMixin

如果渲染对象包含一个子节点，但该节点不是 RenderBox，那么 RenderObjectWithChildMixin 类会很有用。这个 mixin 会处理管理子节点所需的样板代码。

这是一个只有一个类型参数的泛型类，该参数表示子节点的类型。例如，如果要创建包含单个 RenderBar 子节点的 RenderFoo 类，可以按如下方式使用此 mixin：

class RenderFoo extends RenderBox
  with RenderObjectWithChildMixin<RenderBar> {
  // ...
}

在此情况下，RenderFoo 类本身仍是一个 RenderBox，因此仍须实现 RenderBox 布局算法，以及固有尺寸、基线、绘制和命中测试等功能。

使用 ContainerRenderObjectMixin

如果一个 render box 可以包含多个子节点，可以使用 ContainerRenderObjectMixin mixin 来处理样板代码。它使用链表表示子节点，便于动态修改并能高效遍历。这种模型不适合随机访问；如果需要随机访问子节点，请参阅下一节介绍的更复杂子节点模型。

ContainerRenderObjectMixin 类有两个类型参数。第一个是子对象的类型，第二个是其 parentData 的类型。用于 parentData 的类本身必须混入 ContainerParentDataMixin；ContainerRenderObjectMixin 会在其中存储链表。ParentData 类可以继承 ContainerBoxParentData；它本质上是混入了 ContainerParentDataMixin 的 BoxParentData。例如，如果 RenderFoo 类需要维护一个由 RenderBox 子节点组成的链表，可以按如下方式创建 FooParentData 类：

class FooParentData extends ContainerBoxParentData<RenderBox> {
  // (any fields you might need for these children)
}

在 RenderBox 中使用 ContainerRenderObjectMixin 时，可以考虑同时混入 RenderBoxContainerDefaultsMixin。它提供一组工具方法，用于实现 RenderBox 协议中的常见部分，例如绘制子节点。

因此，RenderFoo 类本身的声明形式如下：

// continuing from previous example...
class RenderFoo extends RenderBox with
  ContainerRenderObjectMixin<RenderBox, FooParentData>,
  RenderBoxContainerDefaultsMixin<RenderBox, FooParentData> {
  // ...
}

遍历子节点时（例如布局期间），通常会使用以下模式；此处假设所有子节点都是 RenderBox 对象，并且该渲染对象使用 FooParentData 对象作为子节点的 parentData 字段：

// continuing from previous example...
RenderBox? child = firstChild;
while (child != null) {
  final FooParentData childParentData = child.parentData! as FooParentData;
  // ...operate on child and childParentData...
  assert(child.parentData == childParentData);
  child = childParentData.nextSibling;
}

更复杂的子节点模型

渲染对象可以采用更复杂的模型，例如以枚举为键的子节点映射、可高效随机访问的二维子节点网格，或多组子节点列表等。如果上述 mixin 无法处理某个模型，就必须按以下方式实现 RenderObject 子节点协议：

  • 每当移除子节点时，使用该子节点调用 dropChild。

  • 每当添加子节点时，使用该子节点调用 adoptChild。

  • 实现 attach 方法，并确保它对每个子节点调用 attach。

  • 实现 detach 方法，并确保它对每个子节点调用 detach。

  • 实现 redepthChildren 方法，并确保它对每个子节点调用 redepthChild。

  • 实现 visitChildren 方法，并确保它对每个子节点调用传入的回调，通常按绘制顺序遍历（从最靠后到最靠前）。

  • 实现 debugDescribeChildren，使其为每个子节点输出一个 DiagnosticsNode。

实现以上七项内容，基本上就涵盖了前述两个 mixin 的全部功能。

布局

RenderBox 类会实现布局算法。它们接收一组约束，并根据这些约束以及其他输入（例如子节点或属性）确定自身尺寸。

实现 RenderBox 子类时，必须先决定：它的尺寸是否完全由约束决定，还是还会使用其他信息？例如，仅根据约束确定尺寸的情况包括扩展自身以填满父节点。

仅根据约束确定尺寸可以让系统进行一些重要优化。采用这种方式的类应重写 sizedByParent 并使其返回 true，然后重写 computeDryLayout，仅根据约束计算 Size，例如：

@override
bool get sizedByParent => true;

@override
Size computeDryLayout(BoxConstraints constraints) {
  return constraints.smallest;
}

否则，应在 performLayout 函数中设置尺寸。

performLayout 函数负责让非 sizedByParent 的 render box 决定自身的尺寸，同时决定子节点的位置。

RenderBox 子节点的布局

performLayout 函数应调用每个（box）子节点的 layout 函数，并传入一个 BoxConstraints 对象，描述子节点可以在哪些约束范围内绘制。向子节点传递紧约束（参阅 BoxConstraints.isTight）可以让渲染库进行优化，因为约束为紧约束时，即使子节点自身的布局发生变化，其尺寸也不会改变。

如果 performLayout 函数会使用子节点的尺寸影响布局的其他部分，例如 render box 会根据子节点调整自身尺寸，或根据多个子节点的尺寸确定它们的位置，那么调用子节点的 layout 函数时，必须将 parentUsesSize 参数设为 true。

此标志会关闭一些优化；不依赖子节点尺寸的算法效率会更高。（具体来说，如果依赖子节点的尺寸，那么子节点被标记为需要重新布局时，父节点通常也会被标记为需要重新布局；但如果父节点传给子节点的是紧约束，则不一定如此。）

对于不继承 RenderProxyBox 的 RenderBox 类，子节点布局完成后，还应通过设置每个子节点 parentData 对象的 BoxParentData.offset 字段来确定子节点位置。

非 RenderBox 子节点的布局

RenderBox 的子节点本身不一定是 RenderBox。如果子节点使用其他协议（如 RenderObject 中所述），父节点就应传入适当的 Constraints 子类，而不是 BoxConstraints；父节点也应读取该布局协议中 layout 的输出，而不是读取子节点的尺寸。仍需使用 parentUsesSize 标志指明父节点是否会读取该输出；如果子节点的约束是紧约束（由 Constraints.isTight 定义），系统仍会进行优化。

绘制

要描述 render box 的绘制方式，请实现 paint 方法。该方法会接收一个 PaintingContext 对象和一个 Offset。绘制上下文提供了用于操作图层树的方法，以及可用于添加绘图指令的 PaintingContext.canvas。不要跨多次调用缓存 canvas 对象；每次调用 PaintingContext 的方法时，canvas 都可能更换实例。偏移量表示 box 左上角在 PaintingContext.canvas 坐标系中的位置。绘制上下文还提供了可用于添加绘图指令的画布。

要在 canvas 上绘制文本，请使用 TextPainter。

要在 canvas 上绘制图像，请使用 paintImage 方法。

如果 RenderBox 使用了会创建新图层的 PaintingContext 方法，就应重写 alwaysNeedsCompositing getter 并使其返回 true。如果对象有时需要合成、有时不需要，可以根据情况返回 true 或 false；返回值可能变化时，应调用 markNeedsCompositingBitsUpdate。（添加或移除子节点时会自动调用此方法，因此如果 alwaysNeedsCompositing getter 仅根据是否存在子节点来改变返回值，就无需显式调用。）

只要对象发生变化，导致 paint 方法的绘制结果不同（但布局不变），就应调用 markNeedsPaint。

绘制子节点

paint 方法的 context 参数提供了 PaintingContext.paintChild 方法。每个需要绘制的子节点都应调用此方法，并传入子节点引用以及一个 Offset，表示子节点相对于父节点的位置。

如果 paint 方法在绘制子节点前对绘制上下文应用了变换（或通常来说，应用了超出传入偏移量的额外偏移），那么也应重写 applyPaintTransform 方法。该方法必须以相同方式调整传入的矩阵，就像绘制给定子节点前对绘制上下文和偏移量所做的变换一样。globalToLocal 和 localToGlobal 方法会使用此变换。

命中测试

RenderBox 的命中测试由 hitTest 方法实现。此方法的默认实现会委托给 hitTestSelf 和 hitTestChildren。实现命中测试时，可以重写后两种方法，也可以忽略它们而直接重写 hitTest。

hitTest 方法本身会接收一个 Offset。如果对象或其某个子节点接收了这次命中（从而阻止其下方对象被命中），就必须返回 true；如果命中可以继续传递给下方对象，则返回 false。

对于每个 RenderBox 子节点，都应调用该子节点的 hitTest 方法，传入相同的 HitTestResult 参数，并将命中点转换到子节点的坐标空间（转换方式应与 applyPaintTransform 相同）。默认实现会委托给 hitTestChildren 来调用子节点。RenderBoxContainerDefaultsMixin 提供了 RenderBoxContainerDefaultsMixin.defaultHitTestChildren 方法，假定子节点未旋转、未变换，并且根据 parentData 中的 BoxParentData.offset 字段定位。更复杂的 box 可以相应地重写 hitTestChildren。

如果对象被命中，还应使用 HitTestResult.add 将自身添加到作为参数传入 hitTest 方法的 HitTestResult 对象中。默认实现会委托给 hitTestSelf 来判断 box 是否被命中。如果对象在子节点添加自身之前添加自身，效果就像对象位于子节点上方；如果在子节点之后添加，则效果就像对象位于子节点下方。添加到 HitTestResult 对象中的条目应使用 BoxHitTestEntry 类。系统随后会按添加顺序遍历这些条目，并对每个条目调用目标的 handleEvent 方法，同时传入 HitTestEntry 对象。

命中测试不能依赖绘制已经发生。

语义

要让 render box 支持无障碍访问，请实现 describeApproximatePaintClip、visitChildrenForSemantics 和 describeSemanticsConfiguration 方法。对于只影响布局的对象，默认实现已经足够；但代表交互组件或信息（例如图表、文本和图像）的节点应提供更完整的实现。详情请参阅这些成员的文档。

固有尺寸和基线

布局、绘制、命中测试和语义协议适用于所有渲染对象。RenderBox 对象还必须实现两个额外协议：固有尺寸计算和基线测量。

固有尺寸需要实现四个方法，用于计算 box 的最小和最大固有宽度与高度。这些方法的文档详细介绍了相关协议：computeMinIntrinsicWidth、computeMaxIntrinsicWidth、computeMinIntrinsicHeight、computeMaxIntrinsicHeight。

如果重写了上述任一方法，请务必在单元测试中将 debugCheckIntrinsicSizes 设为 true，以启用额外检查并帮助验证实现。

此外，如果 box 包含任何子节点，就必须实现 computeDistanceToActualBaseline。RenderProxyBox 提供了一个简单实现，会将调用转发给子节点；RenderShiftedBox 提供的实现会根据子节点相对于父节点的位置偏移基线信息。不过，如果没有继承这两个类中的任意一个，就必须自行实现该算法。
