markNeedsLayout 方法

void markNeedsLayout()
继承

将此渲染对象的布局信息标记为变脏，并根据此对象是否为 relayout boundary，选择向其 PipelineOwner 注册此对象，或将处理工作交由父对象。

背景

写入渲染对象时，我们不会立即更新布局信息，而是将布局信息标记为变脏，从而安排一次视觉更新。作为视觉更新的一部分，渲染流水线会更新该渲染对象的布局信息。

此机制会批量处理布局工作，将连续的多次写入合并，从而消除重复计算。

如果渲染对象的父对象表示，在计算布局信息时会使用某个渲染子对象的尺寸，那么对此子对象调用此函数时，也会将父对象标记为需要布局。在这种情况下，父对象和子对象都需要重新计算布局，因此流水线只会通知父对象；父对象完成布局时会调用子对象的 layout 方法，子对象也因此会重新布局。

对此渲染对象调用 markNeedsLayout 后，debugNeedsLayout 会对该对象返回 true，直到 pipeline owner 调用该对象的 layout 后才会恢复。

特殊情况

RenderObject 的某些子类（尤其是 RenderBox）还存在其他情况：子对象变脏时也需要通知父对象（例如子对象的固有尺寸或基线发生变化）。此类子类会重写 markNeedsLayout；在常规情况下调用 super.markNeedsLayout()，在父对象也需要布局时调用 markParentNeedsLayout。

如果 sizedByParent 已发生变化，请调用 markNeedsLayoutForSizedByParentChange，而不是 markNeedsLayout。

实现

void markNeedsLayout() {
  assert(_debugCanPerformMutations);
  if (_needsLayout) {
    assert(_debugRelayoutBoundaryAlreadyMarkedNeedsLayout());
    return;
  }
  _needsLayout = true;
  if (owner case final PipelineOwner owner? when (_isRelayoutBoundary ?? false)) {
    assert(() {
      if (debugPrintMarkNeedsLayoutStacks) {
        debugPrintStack(label: 'markNeedsLayout() called for $this');
      }
      return true;
    }());
    owner._nodesNeedingLayout.add(this);
    owner.requestVisualUpdate();
  } else if (parent != null) {
    markParentNeedsLayout();
  }
}
