MultiChildLayoutDelegate
description

MultiChildLayoutDelegate 类 抽象

用于控制多个子项布局的委托类。

与 widgets 库中的 CustomMultiChildLayout 和 rendering 库中的 RenderCustomMultiChildLayoutBox 搭配使用。

委托必须是幂等的。具体来说，如果两个委托相等，它们就必须产生相同的布局。若要更改布局，应替换为另一个实例，并确保新实例的 shouldRelayout 在传入旧实例时返回 true。

重写 getSize 可控制整体布局尺寸。布局尺寸不能取决于子项的布局属性。此设计决定是为了简化委托实现：这样，如果父级尺寸依赖子项，委托实现就不必同时处理各种固有尺寸计算函数。若要构建根据子项确定自身尺寸的自定义布局，则需要创建自定义渲染对象。可从 MultiChildRenderObjectWidget、ContainerRenderObjectMixin 和 RenderBoxContainerDefaultsMixin 入手，也可参考 RenderStack 的实现。

重写 performLayout 可确定子项的尺寸和位置。该方法必须对每个子项恰好调用一次 layoutChild，但调用顺序可以任意。委托通常会使用一个子项的 layoutChild 返回尺寸，来确定另一个子项布局时的约束，或确定该子项或其他子项传给 positionChild 的偏移量。对每个子项都要调用 layoutChild，并在 performLayout 中完成布局；布局其他子项时，也要继续在 performLayout 中安排布局。

重写 shouldRelayout，以确定委托发生变化时是否需要重新计算子项布局。

触发布局更新的最高效方式，是为 MultiChildLayoutDelegate 构造函数提供 relayout 参数。自定义布局会监听此值，并在 Listenable 通知其监听器时重新布局，例如 Animation 每帧产生更新时。这样，自定义布局就能跳过流水线中的构建阶段。

每个子项都必须包装在 LayoutId 组件中，以指定用于委托识别该子项的 id。同一个 CustomMultiChildLayout 管理的子项之间，LayoutId.id 必须唯一。

以下示例实现了 performLayout，使一个组件（跟随者）的尺寸与另一个组件（引导者）相同：
link 
// Define your own slot numbers, depending upon the id assigned by LayoutId.
// Typical usage is to define an enum like the one below, and use those
// values as the ids.
enum _Slot {
  leader,
  follower,
}

class FollowTheLeader extends MultiChildLayoutDelegate {
  @override
  void performLayout(Size size) {
    Size leaderSize = Size.zero;

    if (hasChild(_Slot.leader)) {
      leaderSize = layoutChild(_Slot.leader, BoxConstraints.loose(size));
      positionChild(_Slot.leader, Offset.zero);
    }

    if (hasChild(_Slot.follower)) {
      layoutChild(_Slot.follower, BoxConstraints.tight(leaderSize));
      positionChild(_Slot.follower, Offset(size.width - leaderSize.width,
          size.height - leaderSize.height));
    }
  }

  @override
  bool shouldRelayout(MultiChildLayoutDelegate oldDelegate) => false;
}

委托为 leader 组件提供宽松约束，这意味着子项可以自行确定尺寸（但不能超出给定尺寸）。随后，委托会记住该子项的尺寸，并将其放在左上角。

接着，委托为 follower 组件提供紧约束，强制其尺寸与 leader 相同，然后将 follower 放在右下角。

leader 和 follower 组件的绘制顺序由它们在子项列表中的顺序决定，与对它们调用 layoutChild 的顺序无关。
