getDryBaseline 方法

double? getDryBaseline(
  1. covariant BoxConstraints constraints,
  2. TextBaseline baseline
)

对于给定的 constraints，返回从盒子顶部到其内容第一条基线的距离；如果此 RenderBox 没有基线，则返回 null。

此方法在内部调用 computeDryBaseline 并缓存结果。RenderBox 子类通常不重写 getDryBaseline，而应考虑重写 computeDryBaseline，使其返回与 getDistanceToActualBaseline 一致的基线位置。详情请参阅 computeDryBaseline 方法的说明。

父 RenderBox 的 computeDryBaseline 或 computeDryLayout 实现通常会调用此方法，以获取 RenderBox 子对象的基线位置。与 getDistanceToBaseline 不同，此方法接收 BoxConstraints 参数，并计算假设父对象使用该 BoxConstraints 对 RenderBox 进行布局时的基线位置。

方法名中的“dry”（干运行）表示此方法与 getDryLayout 一样，调用时不会产生可观察到的副作用；这与 performLayout 这类“湿运行”布局方法不同，后者会更改此 RenderBox 的 size，以及其子对象（如果有）的偏移。由于此方法不依赖当前布局，因此与 getDistanceToBaseline 不同，即使此 RenderBox 的布局已过期，也可以调用此方法。

与固有宽高计算及 getDryLayout 类似，在 performLayout 中调用此函数开销较大，因为这可能导致 O(N^2) 的布局性能，其中 N 是渲染子树中的渲染对象数量。通常应仅由父 RenderBox 的 computeDryBaseline 或 computeDryLayout 实现调用此方法。

实现

double? getDryBaseline(covariant BoxConstraints constraints, TextBaseline baseline) {
  final double? baselineOffset = _computeIntrinsics(_CachedLayoutCalculation.baseline, (
    constraints,
    baseline,
  ), _computeDryBaseline).offset;
  // This assert makes sure computeDryBaseline always gets called in debug mode,
  // in case the computeDryBaseline implementation invokes debugCannotComputeDryLayout.
  // This check should be skipped when debugCheckingIntrinsics is true to avoid
  // slowing down the app significantly.
  assert(
    RenderObject.debugCheckingIntrinsics ||
        baselineOffset == computeDryBaseline(constraints, baseline),
  );
  return baselineOffset;
}
