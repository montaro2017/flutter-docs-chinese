computeMinIntrinsicWidth 方法

  1. @重写
double computeMinIntrinsicWidth(
  1. double height
)
重写

计算 getMinIntrinsicWidth 返回的值。不要直接调用此函数，而应调用 getMinIntrinsicWidth。

实现 performLayout 的子类应重写此方法。应返回此盒子在不裁剪内容、且仍能正确绘制内容的前提下可以采用的最小宽度。

如果布局算法与上下文无关（例如总是尝试采用特定尺寸）、遵循“输入宽度、输出高度”，或同时使用传入的宽度和高度约束（例如总是将自身尺寸设为 BoxConstraints.biggest），则应忽略 height 参数。

如果布局算法严格遵循“输入高度、输出宽度”，或者在宽度不受约束时遵循“输入高度、输出宽度”，则 height 参数就是应使用的高度。

height 参数不会为负数或 null，但可以为无穷大。

如果此算法依赖子节点的固有尺寸，应使用名称以 get 开头的函数获取，而不是使用以 compute 开头的函数。

此函数绝不能返回负值或无穷大。

如果重写此方法，请务必在单元测试中将 debugCheckIntrinsicSizes 设为 true，以启用额外检查并帮助验证实现。

示例

文本

英文文本是“输入宽度、输出高度”算法的典型示例。因此，此算法会忽略 height 参数。

以字符串 "Hello World" 为例。最大固有宽度（由 computeMaxIntrinsicWidth 返回）是该字符串不换行时所需的宽度。

最小固有宽度是最长单词（"Hello" 或 "World"）所需的宽度。不过，如果文本以更窄的宽度渲染，也可能仍不溢出。例如，渲染时也许会在单词中间换行，如 "Hel⁞lo⁞Wor⁞ld"。但这并不算正确的渲染；computeMinIntrinsicWidth 的定义是：返回盒子能够正确绘制自身内容而不发生裁剪时所需的最小宽度。

因此，对于小于最小固有宽度的给定宽度，其对应的最小固有高度可能大于最小固有宽度对应的最小固有高度。

视口（例如滚动列表）

某些渲染盒用于裁剪其子节点。例如，滚动列表的渲染盒可能总是将自身尺寸设为父对象的尺寸（或者更准确地说，设为传入的最大约束），而不考虑子节点尺寸；随后再裁剪子节点，并根据当前滚动偏移量定位它们。

在这些情况下，固有尺寸仍取决于子节点，尽管布局算法采用了与子节点无关的方式确定盒子尺寸。关键在于绘制盒子内容（此处即子节点）而不发生裁剪所需的尺寸。

无法确定固有尺寸时

某些情况下，渲染对象无法高效计算固有尺寸。例如，要实例化并测量延迟加载视口中的每个子节点，开销可能大到无法接受（视口通常只实例化实际可见的子节点）；也可能是通过某个回调计算尺寸，而渲染对象无法推断该回调的行为。

这时可能无法（或至少不切实际地）返回有效结果。如果启用了断言且 RenderObject.debugCheckingIntrinsics 为 false，则固有尺寸函数应抛出异常；否则应返回 0.0。

有关示例，请参阅 LayoutBuilder 或 RenderViewportBase 的实现，特别是 RenderViewportBase.debugThrowIfNotCheckingIntrinsics。

由宽高比决定尺寸的盒子

Some boxes always return a fixed size based on the constraints. For these boxes, the intrinsic functions should return the appropriate size when the incoming height or width argument is finite, treating that as a tight constraint in the respective direction and treating the other direction's constraints as unbounded. This is because the definitions of computeMinIntrinsicWidth 和 computeMinIntrinsicHeight are in terms of what the dimensions could be, and such boxes can only be one size in such cases.

如果传入的参数不是有限值，则应像其他盒子一样，根据内容返回实际的固有尺寸。

另请参阅：

  • computeMaxIntrinsicWidth，计算出这样一个最小宽度：超过该宽度后，继续增大宽度不会再降低首选高度。

实现

@override
double computeMinIntrinsicWidth(double height) {
  return getIntrinsicDimension(
    firstChild,
    (RenderBox child) => child.getMinIntrinsicWidth(height),
  );
}
