为指定的 url 创建并发送 URL 请求。

默认情况下，request 会执行 HTTP GET 请求；也可以通过指定 method 参数使用其他方法（例如 POST、PUT、DELETE 等）。（仅针对 POST 请求，也可参阅 HttpRequest.postFormData。）

响应可用时，Future 即会完成。

如果指定了 sendData，则会将 ByteBuffer、Blob、Document、String 或 FormData 格式的数据随 HttpRequest 一起发送。

如果指定了 responseType，则会设置请求所需的响应格式。默认值为 String，也可以是 arraybuffer、blob、document、json 或 text。详情请参阅 HttpRequest.responseType。

withCredentials 参数表示请求是否应携带凭据，例如已在标头中设置的 Cookie 或授权标头。使用凭据时请注意以下事项：

  • 使用凭据仅适用于跨源请求。
  • url 的 Access-Control-Allow-Origin 标头不能包含通配符（*）。
  • url 的 Access-Control-Allow-Credentials 标头必须设为 true。
  • 如果 Access-Control-Expose-Headers 未设为 true，调用 getAllResponseHeaders 时只会返回部分响应标头。

以下示例等价于上面的 getString 示例：

var name = Uri.encodeQueryComponent('John');
var id = Uri.encodeQueryComponent('42');
HttpRequest.request('users.json?name=$name&id=$id')
  .then((HttpRequest resp) {
    // Do something with the response.
});

以下示例展示如何使用 FormData 提交整个表单。

var myForm = querySelector('form#myForm');
var data = new FormData(myForm);
HttpRequest.request('/submit', method: 'POST', sendData: data)
  .then((HttpRequest resp) {
    // Do something with the response.
});

请注意，只有在清单中具有相应权限的 Chrome 扩展才支持针对 file:// URI 的请求。针对 file:// URI 的请求也永远不会失败：即使找不到文件，Future 仍会成功完成。

另请参阅：授权标头。

实现

static Future<HttpRequest> request(
  String url, {
  String? method,
  bool? withCredentials,
  String? responseType,
  String? mimeType,
  Map<String, String>? requestHeaders,
  sendData,
  void onProgress(ProgressEvent e)?,
}) {
  var completer = new Completer<HttpRequest>();

  var xhr = new HttpRequest();
  if (method == null) {
    method = 'GET';
  }
  xhr.open(method, url, async: true);

  if (withCredentials != null) {
    xhr.withCredentials = withCredentials;
  }

  if (responseType != null) {
    xhr.responseType = responseType;
  }

  if (mimeType != null) {
    xhr.overrideMimeType(mimeType);
  }

  if (requestHeaders != null) {
    requestHeaders.forEach((header, value) {
      xhr.setRequestHeader(header, value);
    });
  }

  if (onProgress != null) {
    xhr.onProgress.listen(onProgress);
  }

  xhr.onLoad.listen((e) {
    var status = xhr.status!;
    var accepted = status >= 200 && status < 300;
    var fileUri = status == 0; // file:// URIs have status of 0.
    var notModified = status == 304;
    // Redirect status is specified up to 307, but others have been used in
    // practice. Notably Google Drive uses 308 Resume Incomplete for
    // resumable uploads, and it's also been used as a redirect. The
    // redirect case will be handled by the browser before it gets to us,
    // so if we see it we should pass it through to the user.
    var unknownRedirect = status > 307 && status < 400;

    if (accepted || fileUri || notModified || unknownRedirect) {
      completer.complete(xhr);
    } else {
      completer.completeError(e);
    }
  });

  xhr.onError.listen(completer.completeError);

  if (sendData != null) {
    xhr.send(sendData);
  } else {
    xhr.send();
  }

  return completer.future;
}
