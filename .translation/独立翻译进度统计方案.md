# 独立翻译进度统计实施方案

## 1. 目标与边界

直接比较 `flutter.docs/` 原始 HTML 和 `flutter.docs.cn/` 中文 HTML，生成可追溯到具体页面、具体文本的统计报告。实现不导入现有统计脚本，不读取翻译映射、既有完成状态和模块进度清单，不沿用当前完成率。

允许读取 `.translation/case-paths.json` 作为文件定位数据；它只解决 Windows 大小写冲突，不提供翻译完成证据。新工具只写 `.translation/audit/`，不修改两个文档目录。

本期统计 API 文档的正文和成员摘要。首页、导航、页脚、代码示例、签名和资源文件不进入完成率；报告必须明确此范围。首页等界面文字以后作为独立维度统计，不混入正文分母。

## 2. 展示哪些指标

同时展示两种结果，避免把机器判断当成人工确认：

| 指标 | 用途 | 计算方式 |
| --- | --- | --- |
| 文本改动率 | 首次扫描即可观察的翻译改动范围 | 已对齐且发生文本改动的原文词数 / 全部待译原文词数 |
| 已确认翻译率 | 正式进度 | 人工确认 translated 或 reviewed 的原文词数 / 全部待译原文词数 |
| 已审核率 | 校对进度 | 人工确认 reviewed 的原文词数 / 全部待译原文词数 |
| 页面完成率 | 定位整页完成情况 | 全部有效单元已确认且无阻塞异常的页面数 / 有待译内容的页面数 |

文本改动率包括发生改动的可疑单元，因此不能命名为“自动翻译完成率”。首次没有确认记录时，已确认翻译率显示“未建立确认基线（0 个已确认单元）”；建立基线后按实际值展示。

目录和全站汇总先累加词数再相除，不平均页面百分比。部分翻译单元在确认前不贡献已确认词数。分母为零时显示“不适用”。同时展示各状态的单元数和原文词数。

## 3. 独立建立页面清单

1. 从原始 `flutter.docs/index.html` 开始遍历本地 HTML 链接，遵守 HTML 的 `base href`。
2. 使用 URL 解析和路径规范化去掉查询串与片段；跳过外站、邮件、脚本和越出原始根目录的路径。
3. 导航过程中允许经过根目录页面，最终只纳入 `flutter/` 下的 API HTML。记录所有断链，不静默丢弃。
4. 按原始逻辑路径保留大小写；文件读取前应用大小写路径映射。原文和译文分别记录逻辑路径、实际路径及文件哈希。
5. 对比物理 HTML 清单，额外输出“未从入口发现的页面”，供确认入口遍历是否遗漏；这些页面不自动进入统计分母。

找不到中文文件时，该页仍进入分母，标记 missing_target。找不到原始文件、映射存在冲突或无法解析原文时，报告为不完整，不能输出看似完整的全站结果。

## 4. 提取文本单元

使用 Python 标准库 `html.parser.HTMLParser` 建立轻量 DOM，不用正则解析 HTML。正文范围先以原文实际模板确认：`section.desc.markdown`，以及正文外的成员摘要 `dd`。未知模板记录 unsupported_template。

提取规则：

- 跳过 script、style、template、noscript、pre 和 code 子树，以及明确的签名、导航区域。
- 按 DOM 顺序提取标题、p、li、dt、dd、th、td 和未被这些节点涵盖的直接正文。
- 使用“文本归属”规则：每个可见文本节点只归属一个单元；遇到嵌套块，先输出父级直接文本，再递归处理子块。例如 li 中有 p 和子列表时，不再把整个 li 的全文重复提取。
- HTML 实体解码；统一 Unicode NFC 和空白。比较时保留大小写、标点和正文顺序，不用删除英文词的方法制造相同文本。
- 保留行内代码和 API 链接的位置占位信息供核查，但其内容不进入自然语言词数。
- 标题若只有 API 名称或没有自然语言词，记录为 excluded；固定英文短语不能因为全大写而自动排除。

每个单元保留页面、区域、最近的章节/成员锚点、结构路径、标签、原文、译文、词数和排除原因。结构路径仅用于本轮对齐，不作为跨版本稳定身份的唯一依据。

原文词数使用明确规则：英文单词允许内部撇号和连字符；代码及明确标注的 API 名称排除。普通链接文字保留。不以 camelCase 或大写形状单独决定排除，减少误删。规则版本写入报告；词数用于衡量原文工作量，不衡量翻译质量。

## 5. 对齐与异常处理

先匹配页面，再匹配原文与译文中相同的成员或章节锚点。区域内核对块标签序列、嵌套关系及链接目标/代码占位等结构信息，结构一致时按位置匹配。

对齐策略采用保守规则：

- 有唯一锚点的区域独立对齐，一个区域出错不影响其他区域。
- 无锚点区域只有在结构序列一致时才允许按位置对齐。
- 区域内增加、删除、移动块，或者存在多个可能匹配时，该区域标记 unaligned；不按文本相似度猜测译文归属。
- 译文缺页标记 missing_target，目标单元缺失标记 missing_unit；两者都保留原文词数。
- 链接或代码变化作为完整性异常保存，阻止该单元被确认，直至修复或人工记录有理由的例外。

同形段落被互换且没有可区分结构时，位置匹配仍可能出错；报告必须显示 source/target 上下文供审核。自动对齐不是语义正确性的证明。

## 6. 状态设计与确认失效

自动状态和人工状态分开保存。

| 自动状态 | 含义 |
| --- | --- |
| unchanged | 规范化文本与原文相同 |
| changed | 已对齐，译文非空，文本发生变化且含汉字 |
| suspicious | 空译文、改动后无汉字，或命中英文残留等规则 |
| unaligned | 结构无法可靠匹配 |
| missing_target / missing_unit | 页面或文本单元缺失 |
| excluded | 无需翻译，有具体排除原因 |

英文残留规则初始值：排除代码和明确 API 名称后，连续出现至少 4 个英文词即列为候选。阈值可配置，结果只触发核查。中文本身也不是完成证据。

人工状态为 pending、translated、reviewed、excluded。允许人工确认保留原文的专有名词，但必须填写理由。排除操作需记录原因，并同时展示调整前后的分母及排除词数，防止无痕改变进度。

确认记录绑定：逻辑页面、区域、单元身份、原文文本哈希、译文文本哈希、结构指纹、提取规则版本。文本或相关结构变化时，旧记录进入 stale，停止贡献完成率。只改变无关空白不应失效。

相同原文重复出现时使用区域和出现位置区分；重扫时若身份迁移不唯一，要求重新确认，不自动转移记录。不跨页面自动复用人工确认。

## 7. 文件和模块设计

```text
.translation/
  audit_progress.py          # CLI 入口
  progress_audit/
    inventory.py            # 链接遍历、路径和大小写处理
    extract.py              # DOM、文本单元、词数
    align.py                # 对齐与完整性异常
    classify.py             # 自动状态、残留候选
    review.py               # 人工记录和失效检查
    report.py               # 汇总、JSON、离线 HTML
  tests_progress_audit/      # 小型 HTML 固定样本和测试
  audit/
    config.json             # 范围、阈值、规则版本
    reviews.jsonl           # 人工确认事件，纳入版本管理
    runs/<run-id>/
      manifest.json         # 输入哈希、版本、范围、异常摘要
      pages.jsonl           # 页面结果
      units.jsonl           # 原文与译文及分类
      summary.json          # 汇总指标
      report.html           # 可离线使用的报告
```

示例单元（字段值仅说明格式）：

```json
{
  "unit_id": "sha256:...",
  "page": "widgets/Text-class.html",
  "region": "description",
  "locator": "p[0]",
  "source": "A run of text with a single style.",
  "target": "使用单一样式的一段文本。",
  "source_words": 9,
  "source_hash": "sha256:...",
  "target_hash": "sha256:...",
  "structure_hash": "sha256:...",
  "auto_status": "changed",
  "review_status": "pending",
  "issues": []
}
```

生成的 runs 目录不纳入 Git；确认记录和配置纳入 Git。写报告先写临时文件再原子替换。每次扫描生成独立目录，不能覆盖历史运行。

## 8. CLI 和人工操作流程

以下为待实现接口，不代表目前已有这些命令：

```powershell
# 首次全站扫描
python -X utf8 .translation/audit_progress.py scan

# 扫描单库，明确标记报告范围为局部
python -X utf8 .translation/audit_progress.py scan --page widgets/

# 导出待审核清单，包含原文、译文、上下文及异常
python -X utf8 .translation/audit_progress.py export-review --run <run-id> --out .translation/audit/review.jsonl

# 人工编辑清单中的 decision 和 reason 后导入
python -X utf8 .translation/audit_progress.py import-review --file .translation/audit/review.jsonl

# 使用原扫描快照和最新人工记录重建报告
python -X utf8 .translation/audit_progress.py report --run <run-id>
```

导入确认前核对导出批次、单元身份、当前文件和哈希；文件已变则拒绝对应记录并列明原因。整批先校验，再原子写入，不能只导入一部分却返回成功。报告页面是只读的，不设计浏览器直接写文件的隐式流程。

离线 HTML 提供库/页面筛选、状态筛选、原译文并排、异常定位、词数和指标说明。全站只先载入汇总，逐页明细另存为本地 HTML 并用普通相对链接访问，避免一次把所有文本装进浏览器，也避免 file:// 下 fetch 的限制。所有文档文本按纯文本转义，不能作为 HTML 执行。

## 9. 一致性、失败与性能

- 使用单进程逐页解析并流式输出 JSONL，内存不随全站文本总量增长；不在首版加入并行和复杂缓存。
- 扫描开始建立输入文件清单与哈希，处理时复核，结束再次核对输入集合和哈希；发现新增、删除或内容变化时标记 inconsistent，要求重扫。
- 退出码：0 表示扫描完整完成；1 表示输入缺失、损坏或运行失败；2 表示已生成报告但存在影响完整性的异常。普通未译和英文残留候选不导致失败。
- 缺失译文和未对齐内容保留在分母内。原文不能读取时分母无法确定，展示“报告不完整”，禁止拿局部值冒充全站完成率。
- 每次记录页面数、单元数、用时、输入字节数和规则版本。先测完整小库，再测全站，以实测结果决定是否需要增量缓存。

## 10. 实施顺序与验收

| 阶段 | 交付内容 | 验收条件 |
| --- | --- | --- |
| A：范围与提取 | 页面清单、轻量 DOM、单元 JSONL | 人工检查类页、成员页、库页，以及列表/表格样本；无文本重复、无代码混入；断链和大小写冲突可解释 |
| B：对齐与分类 | 自动扫描、词数、异常清单 | 插入/删除段落不造成后续错配；缺页保留分母；纯 API 名称不误判为待译正文 |
| C：确认与统计 | 导出/导入、状态失效、指标汇总 | 原译文变更后确认失效；重复原文不串用；分组汇总与全站词数一致；无基线时不宣称已确认完成率 |
| D：报告与全站验收 | 离线 HTML、运行快照、使用说明 | 浏览器断网可查到具体单元；扫描期间修改文件可检出；相同输入重复运行指标一致；两个文档目录未被修改 |

必须有固定样本测试：base URL、外链和路径越界、大小写碰撞、HTML 实体、嵌套列表/表格/摘要、直接文本、空正文、段落错位、缺页、零分母、重复文本、确认失效、导入拒绝、报告文本转义。

第一批人工抽查至少覆盖 30 页：类页、成员页、库页各 10 页，包含已有中文和完整英文页面；另逐一检查固定异常样本。发现提取或对齐错误先修规则，再全站重扫。抽查用于发现实现问题，不作为统计准确率证明。

## 11. 完成定义

在未修改文档正文、未使用旧统计结果的情况下，可以从一条扫描命令生成全站离线报告；每个汇总值可追溯到原文单元；人工确认可以保存、重扫复用并在内容变化时失效；缺失和异常不会被静默排除。满足这些条件后，再开始建立人工确认基线。
